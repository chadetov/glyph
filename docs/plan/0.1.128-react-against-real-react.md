# 0.1.128: React against real React (the plan)

The 0.1.126 dogfood round wrote a counter-and-todo app against real React 18 and
stopped at `useEffect(fn() { mut document.title = ... })`: browser globals are
E0103 in Glyph, and nothing in the stdlib wraps the page. On the way it found
that a hook's tuple cannot be destructured. The owner decided both on
2026-10-11 (G254: a typed `std/dom`; G255: `let [a, b] = expr`). This document
is the design an implementation starts from. It was produced by a read-only
design pass over the source; every claim about the compiler in it was read, and
the ones that still need a run to confirm are in the test plans.

The release is measured by the dogfood app: it builds with Vite, renders in a
headless browser, and every hook in it is React's own.

## What the source says today

- The checker's stdlib types come from per-module tables in
  `glyph-typechecker/src/stdlib.rs` (`fn_ty` dispatching to `timers_fn_ty`,
  `io_fn_ty`, ...). `glyph llms --json` reads the same tables, so a new module
  is published with no change there. A stdlib named type is real to the checker
  only when `stdlib_modeled_type` lists it; field sets come from
  `stdlib_type_fields`.
- Export names are seeded in `glyph-resolver/src/module_graph.rs::StdlibStubs`,
  type-only exports in `glyph-resolver/src/stdlib_types.rs::STDLIB_TYPE_ONLY`.
  Runtime files are embedded in `glyph-cli/src/runtime.rs::RUNTIME_FILES` and
  pruned per build by `reachable_std_modules`. The generated tsconfig always
  includes the DOM lib.
- `std/io` cannot load in a browser: it imports `node:fs` and
  `node:string_decoder` at module level. The prelude `print` is `console.log`
  and works anywhere. `std/timers` already works in a browser; `std/websocket`
  does not load there (it imports `node:crypto`).
- There is no target concept, and the G115 review refused one: "the moment
  `--target browser` exists, node, deno and workers follow and the stdlib grows
  a matrix."
- A TypeScript tuple never reaches Glyph's checker. `import react { useState }`
  types the value as `Unknown`; `gen dts` collects no function declarations and
  has no tuple case; `Ty` has no tuple variant, and `TypeExpr` has none on
  purpose (named records over positional tuples).

## Part 1: three small host modules

| Module | Host | Failure model |
|---|---|---|
| `std/dom` | a browser page | No document is a fact about where the code runs: a call throws, naming the function. Importing the module is safe anywhere. |
| `std/storage` | any host with `localStorage` | Per call: `get` is an `Option`, `set` a `Result`; nothing throws. |
| `std/console` | every host | Never fails. |

Three modules because these are three host profiles and two failure models.
Storage fails per call in ordinary production browsers (a full quota, storage
blocked by the user), which the `fs.write_text` convention makes a `Result`. A
page either has a document or it does not. A worker has `console` and no
document. One namespace mixing calls that throw under node with calls that
degrade would not tell the reader which is which.

### `std/dom`

| Glyph signature | Checker row |
|---|---|
| `dom.title() -> string` | `([], string)` |
| `dom.set_title(text: string) -> void` | `([required(string)], void)` |
| `dom.element_by_id(id: string) -> Option<Element>` | `option_ty(stdlib_named("dom", "Element"))` |
| `dom.location() -> url.Url` | `stdlib_named("url", "Url")` |
| `type Element` | opaque: modeled, with an empty field set |

- `element_by_id` is required for the first release: every React entry point
  mounts with `createRoot(document.getElementById("root"))`.
- `location()` returns `std/url`'s existing `Url` record, so a wrong field is
  E0210 listing the real ones.
- Text and attribute setters, event listeners and focus are deferred: React owns
  the DOM it renders, and writing to it underneath React is a bug.
- `Element` is `HTMLElement` in the TypeScript and opaque in Glyph (every member
  access is E0210, with a help line saying to hand it to a library or to
  `std/dom`). A branded opaque type was rejected because `createRoot(root)`
  would then fail `tsc`; a record and a `resource` were rejected because an
  element is a live host object, not data, and an `owned` consume means nothing
  for it.
- The title is set with `dom.set_title(s)`, not `mut dom.title = s`. Host effects
  go through namespaced calls (`store.set`, `timers.cancel`, `websocket.send`),
  `grep "dom\.set_"` audits page writes, and the `mut` audit stays an audit of
  Glyph values. The field-assignment form would assign to an ESM namespace
  object, which `tsc` rejects and strict mode throws on.
- Under node (`glyph run`, an `@example`, server-side rendering), importing
  `std/dom` is safe and a call throws
  `std/dom.title: this runtime has no browser document ...`. A compile-time
  error needs the target the G115 review refused; a `Result` on every call adds
  an `Err` arm for a state that cannot occur in a page.

### `std/storage` and `std/console`

- `storage.get(key) -> Option<string>`, `storage.set(key, value) ->
  Result<void, StorageError>`, `storage.remove(key) -> void`, with
  `type StorageError = { kind: "quota" | "unavailable", message: string }` and
  `kind` a string-literal union so a `match` on it is exhaustive. Under node,
  `get` is `None`, `set` is `Err(unavailable)` and `remove` does nothing.
- `console.log`, `console.warn`, `console.error`, each `(string) -> void`. The
  binding shadows the global `console` only inside the emitted module, which
  the emitter never names and Glyph code cannot name anyway.

### Also in Part 1

- E0103's help gains targeted arms: `document`, `window` to `std/dom`;
  `localStorage`, `sessionStorage` to `std/storage`; `console` to `std/console`;
  `setTimeout` and friends to `std/timers`; `globalThis` and `navigator` to "host
  features come through `std/*`".
- `docs/reference/stdlib.md` gains a host table: node-only, browser-only, any
  host.
- **An effect lambda returns its tail value.** `useEffect(fn() { storage.set(k,
  v) }, deps)` returns a `Result` from the effect, which React then calls as a
  cleanup function, and `tsc` refuses against `void | Destructor`. Every doc and
  example writes effects as `fn() -> void { ... }`.

### Test plan without a browser

1. The existing gates (stubs against the runtime, type-only exports, every
   runtime export documented, the pinned signature counts).
2. Negative cases: `dom.set_title(5)` E0211; `el.innerHTML` E0210;
   `match storage.get("k") { Some(v) => v }` E0200; `dom.location().pathname`
   E0210.
3. `glyph run` integration with an `extern/` fake that installs
   `globalThis.document` and `localStorage`, including a `setItem` that throws
   `QuotaExceededError`; a program that imports `std/dom` and never calls it
   exits 0 under node; a program that calls `dom.title()` with no fake exits
   non-zero with the precise message.
4. A host-free gate: no file in the closure of `dom`, `storage` and `console`
   imports `node:`.
5. A `tsc` fixture proving `createRoot(root)` type-checks with
   `root: dom.Element`, and a test that `{}` is not assignable to `dom.Element`
   through the empty field set.
6. The release gate: the dogfood app rendered in a headless browser.

## Part 2: `let [a, b] = expr` (D48)

> **D48. `let` destructures a fixed-length array, and only one that cannot
> fail.** `let [count, set_count] = useState(0)` binds each element. The
> pattern is D9's array pattern, limited to lowercase bindings, `_`, nested
> array patterns and a trailing `...rest`; a literal, a variant name, a
> constructor, an `is` guard or a field test can fail and is E0230. The length
> is proved, never assumed: a written array literal is counted by Glyph; an
> `Array<T>`, whose length is unknown, is E0230 with the `match` named in the
> help; a value only `tsc` can see is emitted with
> `satisfies readonly [unknown, ...]`, which `tsc` refuses for anything but a
> tuple of that arity. Each name is a `let` binding (D5 applies; `const` binds
> one name, D20). *[abstraction: the pair a library returns is written as a
> pair; verifiability: a destructured name never holds the `undefined` a short
> array leaves]*

| Initializer | Verdict |
|---|---|
| A written array literal with no spread | Glyph counts it; element types are read per element and widened as a `let` widens (D30) |
| `Array<T>` | E0230: it may be shorter; the help names `match xs { [a, b] => ..., else => ... }` |
| `Unknown` (an npm value such as `useState`) | Accepted; `tsc` proves the length through the emitted `satisfies` |
| Anything else (`unknown`, a record, a union, `string`) | E0230: it is not an array |

Emission writes `let`, not `const`, so `mut` can reassign a name:

```ts
let [count, set_count] = (useState(0)) satisfies readonly [unknown, unknown];
let [, set_count] = (useState(0)) satisfies readonly [unknown, unknown];
let [head, ...tail] = (f()) satisfies readonly [unknown, ...unknown[]];
```

`tsc` then infers `count: number` and `set_count:
Dispatch<SetStateAction<number>>`, and refuses a `string[]` initializer with
TS1360. A `match` initializer goes through the existing temp path. `satisfies`
needs TypeScript 4.9 or later, which becomes the documented minimum.

The checker computes a vector of element types for the pattern now. A
`Ty::Tuple` variant is added together with its first real producer (G257
typing React's `useState`, or `task.all` over a written literal) rather than
now, because nothing produces one today and the variant touches every
exhaustive match on `Ty`.

The AST changes `LetStmt.name` to `binding: LetBinding`, with
`enum LetBinding { Name(Ident), Pattern(Pattern) }`, so every site that read
the name fails to compile and is decided by hand. A separate statement variant
would be skipped silently at the `if let Stmt::Let` sites, including the
resolver's pending pre-pass that G92 depends on.

Not in this release: object destructuring in `let` (E0005 until it is
designed), `const [a, b]` (a targeted error: a `const` binds one name), a type
annotation on a pattern `let`, and `let owned [...]`.

### Test plan

Parser shapes and errors; formatter round-trip and the regenerated AST
snapshots; resolver visibility, the G92 forward reference and E0107 per unused
name; checker element types (`let [a, b] = [1, "x"]` then passing `b` where a
number is wanted is E0211), length mismatch, `Array<T>`, non-arrays; exact
emitted TypeScript for elision, rest, nesting, the `match` temp and `?`; a `tsc`
fixture proving `satisfies` did not widen inference to `unknown`
(`let n: string = count` must be TS2322); `glyph run` end to end; and a
`catches/` entry, `const [user, host] = s.split("@")`, which passes
`tsc --strict` and is E0230 in Glyph.

## Decisions taken with the plan

Taken by the orchestrator on 2026-10-11, following the design pass's
recommendations; each can be reopened by the owner.

- Three modules (`dom`, `storage`, `console`), not one.
- Console as `std/console`, not `std/io` made host-free (that would be
  breaking) and not `dom.log`.
- `dom.set_title(s)`, not a `mut` field assignment; `mut` before a namespace
  call stays as it is for every module.
- `Element` aliased to `HTMLElement`, opaque in the checker.
- Safe load and a throwing call under node; degrading storage.
- `storage.set` returns `Result<void, StorageError>`.
- `dom.location()` returns `url.Url`.
- `==` on an opaque host handle (`Element`, `Timer`, `Socket`) can recurse
  through a cyclic object; refusing it in the checker is its own item.
- `LetBinding` enum; element-type vector now, `Ty::Tuple` with its first
  producer; `Unknown` initializers accepted with `tsc` proving length; inline
  `satisfies`; identifiers, `_`, nesting and rest; one code E0230 raised at
  parse and check (the E0010 and E0101 precedent); no `const` destructuring;
  object destructuring later.
