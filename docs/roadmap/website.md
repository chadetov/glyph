# Website roadmap

The site at glyphlang.io has its own lifecycle, separate from the compiler's.
The compiler ships numbered releases to npm (see [releases.md](releases.md));
the site ships whenever a pull request merges to `main`, because the Pages
workflow deploys `web/` on every push. A site change needs no compiler release,
and a compiler release changes the site only where a generated number or a
version string moves.

## How the site is built and checked

- **Source of truth:** `site/` (pages, partials, styles, translations,
  release notes). `scripts/build_site.py` renders it into `web/`, which is
  committed. Nothing under `web/` is edited by hand.
- **Generated content:** the `/catches/` page, each TypeScript case's own
  page under it, and every count of checked cases come from `catches/`;
  release notes come from `site/releases/0.1.N.html`; sitemap dates come from
  content hashes in `site/lastmod.json`.
- **Gates on every pull request:** `check_site_built.py` (web/ matches the
  source), `check_site.py` (links, HTML, sub-nav, sitemap, JSON-LD, balanced
  CSS), `check_i18n.py` (translation structure, code identity, wording),
  `check_releases.py`, `check_docs_compile.py` (every code sample compiles),
  `check_scaffold_docs.py` and `check_catches.py`.
- **Languages:** English is the source. Brazilian Portuguese, Spanish,
  Japanese, Turkish, Simplified Chinese, Korean, German, Russian and Thai are
  translated page by page through segment files (`site/i18n/README.md`). When
  the English changes, the translation is reported stale and the page says so
  until the changed segments are redone. Release notes stay English.

**2026-11-21 · "Your agent can ask the compiler first"; generated release
counts.** The home page's `csvql` section became an agent's exchange with the
MCP server: `glyph_impact` on adding `Date` to the `Value` union, the ten
sites it names (eight `WILL_FAIL`, two `ABSORBS`), the change that turns a
catch-all into named arms, and the passing `glyph check`, all quoted from a run
against 0.1.152 and translated into the nine languages. `/teams/` now
generates its count of the newest month's releases and the dates it covers from
the release notes (`{{releases:month-count}}`, `{{releases:month-start}}`,
`{{releases:latest-date}}`) instead of writing them by hand.

**2026-11-21 · One pillar order everywhere.** The site's pillar menu, the pillar pages' numbering and previous/next links, the `/design/` cards and the README now follow the manifesto's order: verifiability, greppability, abstraction, diff stability.

**2026-11-21 · One page per catch.** Each of the 37 TypeScript cases has its
own page at `/catches/<slug>/`, generated by `scripts/site_catches.py` from the
case files, in English and the nine languages: the TypeScript and what it did,
the Glyph and what the compiler said with its error code, what a fully
configured TypeScript project catches, and previous/next in the ranked order.
Each is in the sitemap with a content-hashed date and carries a breadcrumb and
a TechArticle. Cards on `/catches/` link to their pages, and so do the home
hero, the home page's top cases and the refused table on `/hardening/`, which
linked to `/catches/#<slug>` before. Traps and holes have no page yet: they
carry only a one-line summary.

**2026-11-21 · The scannable answer format everywhere.** Every answer and the
four pillar pages follow the format piloted on `/answers/verifiability/` and
`/answers/typed-apis/`: the short answer, one visual under it, an "On this
page" list on the longer pages, sections that are a heading, a sentence or two
and one artifact, longer explanation and history in collapsed rows, and "Where
it stands" as one-line items. The sentences, code blocks and section anchors
are the ones the pages had. The translations in the nine languages follow the
new structure, including the answers that were behind their English
(`codegen`, `parse-errors`, `typed-apis`, `early-errors`).

## Next

1. **Launch readiness.** An FAQ that answers why the compiler is written in
   Rust and how Glyph was built; the README opening on a TypeScript-passes /
   Glyph-refuses pair; a 60 to 90 second demo. Done on 2026-11-21: an "Open
   in playground" link on each case the playground carries (21 of the 37
   TypeScript cases and the 5 traps), on `/catches/` and on each case's page.
2. **Search data.** The sitemap submitted to Search Console, indexing of all
   pages and languages checked, and the search queries that bring people in,
   read through seo-monster once its Google sign-in is set up.
3. **Translation polish.** Shorten translated descriptions that run past search
   result length; one number format policy across languages; remove the unused
   `Reference` menu key.
4. **Launch.** Show HN, then r/typescript and the other channels in the launch
   plan, posted by the author. Target: the week of 8 December 2026, or mid
   January.
5. **A React component on `/from-typescript/`.** One component written in
   Glyph beside the same component in TSX, conditional rendering included, so
   a React developer sees what `match` in JSX costs before reading further.
   With it, one line on editor support, debugging and hot reload that links
   `/answers/tooling/` and `/answers/debugging/`; check whether the Glyph half
   has a watch mode (G123) before the page claims hot reload for it. From two
   outside reviews read on 2026-11-22, both of which missed the tooling pages.
6. **A stability note on `/teams/`.** What a breaking release usually
   means here (the compiler starts refusing a program that was already wrong),
   how to pin an exact version, and that the emitted TypeScript stays as the
   fallback. The same reviews read the count of breaking releases as churn.
