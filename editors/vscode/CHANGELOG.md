# Changelog

## 0.1.3

The listing now says which Glyph this is. The description and the first line of
the README open with "Glyph, the language at glyphlang.io that compiles to
TypeScript", so a Marketplace or Open VSX search result can be told apart from
the unrelated `GlyphLang.glyphlang` without opening it. The README names that
extension once so a reader who wanted it knows where to go.

No change to highlighting or the language client.

## 0.1.2

First release on the VS Code Marketplace, as `chadetov.glyph-vscode`. Until now
the extension had to be packaged from this repository by hand.

It contains the same two things as 0.1.1: syntax highlighting for `.glyph`
files and a client that launches `glyph lsp`. The `glyph` binary is not
bundled; install it with `npm install -g @glyphlang/glyph`.

Changed:

- The minimum VS Code version is now 1.82. The language client library this
  extension uses refuses to start on anything older, so 0.1.1 installed on 1.75
  through 1.81 and then failed when it opened a `.glyph` file.
- The grammar is now regenerated by `scripts/gen_grammar.py` from the lexer's
  keyword table and the resolver's list of primitive types, and fails on a
  keyword it has no scope for. The colours are unchanged.
- The package carries a `LICENSE` naming both licenses, and leaves out the type
  declarations and READMEs of its dependencies.
- The README no longer lists `let x: string = 42` as something the editor
  misses. Compilers with the G149 fix report it while you type, as `E0204`.

## 0.1.1

Fixed: the extension could not start the language server. The client was
configured with an explicit stdio transport, which makes `vscode-languageclient`
append a `--stdio` argument, and `glyph lsp` rejected unknown arguments and
exited 2. VS Code retried five times and gave up with "The Glyph Language Server
server crashed 5 times in the last 3 minutes."

Stdio is already the default for a `command` server, so the argument is simply
not sent any more and the extension works against the compiler you already have.
Compilers from 0.1.96 also accept and ignore `--stdio`, which is what other LSP
clients send.

## 0.1.0

First release.

- Syntax highlighting for `.glyph` files. The grammar is generated from the
  compiler's own keyword table, so a keyword the compiler knows is a keyword the
  editor colours. Covers declarations, control flow, the primitive types
  including `int` and `bigint`, operators, string interpolation, annotations,
  member access, and a distinction between a variant constructor and a type.
- The language server. The extension launches `glyph lsp` from the `glyph`
  binary and speaks LSP over stdio: diagnostics, hover types, go-to-definition
  across modules, find-references, rename, completion, document and workspace
  symbols, inlay hints, code actions, and formatting.

Known limitation: the server runs Glyph's own analysis stages and does not run
`tsc`, so the errors only TypeScript catches do not appear until `glyph build`.
`let x: string = 42` is the smallest example. Tracked as G149.
