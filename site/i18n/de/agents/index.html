Für Agenten und Tool-Entwickler

Die Schnittstelle des Compilers für Agenten

Ein Agent kann Glyphs Compiler fragen, was ein Symbol ist, was eine Änderung kaputtmachen wird und warum ein Build fehlgeschlagen ist, und bekommt JSON zurück. glyph mcp stellt elf Tools über stdio bereit, jedes davon auch ein Verb von glyph query, und glyph llms gibt die Sprachreferenz offline aus.

Einrichten

glyph init schreibt diese .mcp.json in ein neues Projekt, und glyph agents schreibt sie (mit einer AGENTS.md, die auf glyph llms verweist) in ein bestehendes. Jeder MCP-Client, der die Datei liest, startet den Server; es gibt keinen Port und keinen Daemon.

.mcp.json, so wie glyph init sie schreibt 
{
  "mcpServers": {
    "glyph": {
      "command": "glyph",
      "args": ["mcp"]
    }
  }
}

Ein Aufruf, mit seiner echten Antwort

Eine Datei liest ein Feld, das ihr Record nicht deklariert (u.naem). Der Agent ruft glyph_diagnostics auf und bekommt die Diagnose des Compilers selbst, mit den Feldern, die der Record tatsächlich deklariert, und dem Record, zu dem sie gehören. Das ist die Ausgabe des Tools auf 0.1.149, nur an den markierten Stellen gekürzt.

Request 
{
  "method": "tools/call",
  "params": {
    "name": "glyph_diagnostics",
    "arguments": {
      "path": "src/user.glyph"
    }
  }
}
Ergebnis 
{
  "diagnostics": [ {
    "code": "E0210",
    "severity": "error",
    "stage": "typecheck",
    "message": "type `U` has no field
      `naem`; did you mean `name`?",
    "alternatives": ["name", "email"],
    "alternatives_kind": "fields",
    "cause": "user::U",
    "entity": "user::greet",
    "file": "user.glyph",
    "range": {
      "start": { "line": 9, "col": 10 },
      "end": { "line": 9, "col": 16 } },
    ...
  } ],
  "member": true,
  "module": "user",
  "not_run": [
    { "what": "tsc", ... },
    { "what": "E0104, ...", ... },
    { "what": "E0400, ...", ... } ],
  "path": "src/user.glyph",
  "project_root": "src",
  "unindexed": []
}

not_run nennt, was diese Prüfung nicht abgedeckt hat, damit eine leere diagnostics-Liste nicht mit einem vollständigen Build verwechselt werden kann. Ohne MCP-Client gibt glyph query diagnostics --path src/user.glyph dasselbe JSON aus. Die vollständige Liste der Tools mit jedem Verb steht auf der MCP-Seite.

Vor einer Änderung: Was wird sie kaputtmachen?

examples/apps/csvql ist eine CSV-Abfrage-Engine aus elf Dateien mit einer Union aus vier Fällen, Value. Auf die Frage, was ein fünfter Fall bewirkt, listet glyph_impact 10 match-Stellen in 4 Dateien: 8 WILL_FAIL und 2 ABSORBS, bei denen ein Catch-all-Arm den neuen Fall schluckt und weiter kompiliert. Fügt man den Fall tatsächlich hinzu, gibt es genau 8 E0200-Fehler an diesen 8 Stellen. Die 2 absorbierenden Stellen bleiben still, deshalb nennt die Antwort sie.

dieselbe Frage auf der Kommandozeile 
glyph query impact --path value.glyph --entity value::Value \
  --change add_variant --variant Blob

Nach einem roten Build: Was muss der Fix erhalten?

glyph check --agent gibt die Diagnosen von check --json mit zwei zusätzlichen Schlüsseln pro Eintrag aus. constraints listet, was eine reparierende Änderung nicht kaputtmachen darf; für den Tippfehler oben lautet es "the record's fields are closed: user::U declares name, email and no others". symbols enthält die Antwort von glyph_symbol für jedes Symbol, das die Diagnose nennt, sodass die nächste Änderung keinen zweiten Aufruf braucht. Wo der Fix vollständig feststeht, schreibt ihn glyph fix.

Die Sprache offline lesen

glyph llms gibt die Sprachreferenz aus, und /llms.txt auf dieser Website ist dasselbe Dokument. glyph llms --json ist dieses Wissen als Daten, gelesen aus den eigenen Tabellen des Compilers: 77 Diagnosecodes, 24 Prelude-Namen, 40 Stdlib-Module mit 340 Exports, 49 Sprachentscheidungen und die elf Tools. glyph llms --negative liefert 117 fehlerhafte Programme in 0.1.149 (139 ab dem nächsten Release) mit dem Code, den jedes auslöst, kompiliert, wenn du danach fragst. scripts/check_llms_sync.py schlägt fehl, wenn die Tabellen der Diagnosen und reservierten Wörter in der Referenz von denen des Compilers abweichen.

Einstiegspunkte offline 
glyph llms                  # the reference, as prose
glyph llms --json           # the same, as data from the compiler's tables
glyph llms --negative E0200 # wrong programs that draw E0200
glyph --explain E0200       # the long explanation of one code
