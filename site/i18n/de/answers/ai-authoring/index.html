07 · Die Prämisse

Kann eine KI zuverlässig eine Sprache schreiben, die sie kaum gesehen hat?

Größtenteils. Glyph liest sich wie TypeScript: dieselben primitiven und generischen Typen (string, number, Array<T>), größtenteils dieselben Ausdrücke und npm-Pakete, die über ihren Namen importiert werden. Es ist keine Teilmenge von TypeScript: match, Result und fn name(x: T) -> R sind Syntax, die TypeScript nicht hat, und if, der ternäre Operator und Casts sind kein Glyph. Das meiste, was ein Modell schon weiß, lässt sich übertragen, und der Compiler benennt die Stellen, an denen es nicht so ist.

Warum das wichtig ist

Das ist die berechtigte Frage eines Skeptikers: Ein LLM sagt das nächste Token aus der riesigen Menge an Code in bestehenden Sprachen vorher, also müsste eine Sprache fast ohne Trainingsdaten schwer zu schreiben sein. Die Antwort ist strukturell: Glyph ist nicht fremd. Es sieht aus wie TypeScript, also kennt das Modell das meiste schon; die Unterschiede sind wenige, aufzählbar, und jeder schlägt beim Kompilieren sofort fehl, statt stillschweigend durchzugehen.

So sieht es aus

Ein Agent, der falsch rät, liefert die Vermutung nicht aus. Er bekommt einen präzisen, behebbaren Fehler und korrigiert in derselben Schleife:

die Korrekturschleife, in einem Schritt 
// agent writes, reaching for a TypeScript habit:
if user.admin { grant() }

[E0006] Glyph has no `if`
   ╰─ `match` is the only conditional:
      match user.admin { true => grant(), false => void, }

Der Fehler nennt das Glyph-Konstrukt und zeigt die Form, also ist der Fix eine Änderung entfernt: kein Wühlen im Quellcode, kein Raten. Diese enge Schleife gleicht die fehlenden Trainingsdaten aus. Ein einziges Dokument, llms.txt, gibt einem Agenten die Form eines Programms, die Standardbibliothek und jede Diagnose mit ihrem Fix, und glyph llms gibt dieselbe Referenz offline aus.

Wo es steht

Heute verfügbar

Eine Syntax in der Form von TypeScript, Fehler mit stabilem Code, die den Fix nennen, und llms.txt / glyph llms als ein einziges Referenzdokument für jeden Agenten.

Wird belegt

Ein Benchmark zur Erfolgsquote (Versuche bis zur Korrektur, verglichen mit TypeScript bei derselben Aufgabe), um aus “es hat gehalten” eine gemessene Zahl zu machen.
