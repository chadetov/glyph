03 · Navigation per Suche

Kann ein Agent (oder ich) finden, wo etwas definiert ist?

Jedes Konstrukt hat genau eine Form, nach der man sucht. Ein einfaches grep (so navigieren Agenten tatsächlich) landet auf der einen Definition, nicht auf fünfzig Beinahe-Treffern.

Warum das wichtig ist

Ein Agent hat nicht dein ganzes Repo im Kopf; er sucht. Eine Form pro Konzept heißt, die Suche ist vollständig, also bearbeitet der Agent, was da ist, statt es zu duplizieren.

Wenn sich ein Konzept auf fünf verschiedene Arten schreiben lässt, übersieht die Suche Fälle, und ein selbstsicherer Agent, der die bestehende Definition nicht findet, erfindet eine zweite.

Details warum dieselbe Frage in TypeScript keine Antwort hat

In TypeScript kann sich eine Mutation hinter =, .push(), Object.assign, einem Setter oder einem Spread verstecken. Es gibt kein einzelnes Token zum Greppen, also hat “ändert irgendetwas das hier?” keine verlässliche Antwort.

Der Compiler hält die Suche vollständig

Eine Methode, die ihr Array ändert (push, pop, sort, splice und fünf weitere), steht nur als ganzer Aufruf einer mut-Anweisung. Überall sonst ist sie E0240, auch innerhalb eines Ausdrucks, wo eine Hilfsfunktion das Array ihres Aufrufers sortieren könnte, während sie ein Element liest:

glyph check 
[E0240] `xs.sort(cmp)` changes `xs` in place, and its value is used here
 4 │   return xs.sort(cmp)[0]
   │ Help: `array.sort(xs, cmp)` returns a sorted copy and leaves `xs` alone

xs.push(4) auf einer eigenen Zeile bekommt denselben Code, und glyph fix schreibt das mut für dich. Die andere Richtung ist E0241: mut xs.concat(ys) ändert nichts und verwirft das neue Array, also listet die Prüfung nie eine Zeile, die nichts schreibt.

Ganze Kategorien in einer Suche

Dieselbe Regel einer einzigen Form macht ganze Kategorien prüfbar:

eine Suche = eine vollständige Antwort 
# every UI component
grep -rn "^component " src/

# every function
grep -rn "^fn " src/

# the entire resource-ownership surface
grep -rn "owned" src/

Es gibt keine Kurzschreibweise für Objektliterale, keinen zweiten Weg, eine Komponente zu deklarieren, keine überladene Syntax, die man auflösen müsste. Weniger Wege, etwas zu schreiben, ist eine echte Einschränkung, und genau darum geht es: Das macht die Suche eines Agenten, und deine, vertrauenswürdig.

Die Konstrukte, die Glyph weglässt, damit man einer Suche vertrauen kann, und warum eine Lint-Regel nicht dieselbe Garantie ist, stehen auf der Seite zur Säule Durchsuchbarkeit.

Wo es steht

Heute verfügbar

  • Eine kanonische Form pro Konstrukt.
  • Mutation auf zwei greppbare Formen beschränkt (mut), und ein Schreibzugriff auf ein Array ohne dieses Präfix wird abgelehnt (E0240).
  • Prüfungen über ein einziges Schlüsselwort (fn, component, owned, type).

Darauf aufbauend

  • Schreibzugriffe über Set, Store und Deque der Standardbibliothek werden noch nicht auf mut geprüft
    Details

    Glyphs Checker kennt die Typen dieser Empfänger noch nicht, also werden seen.add(x) und mut seen.add(x) beide akzeptiert, und der Korpus verwendet beide Schreibweisen. Sie zu typisieren und ihre schreibenden Methoden zu markieren ist der nächste geplante Schritt. Ein Wert aus einem npm-Paket wird in keiner Richtung beurteilt: mut vor einem seiner Aufrufe ist erlaubt und nicht nötig.

  • Der Language Server ergänzt Go-to-Definition und Find-References über den ganzen Workspace: dieselbe Garantie, jetzt interaktiv in deinem Editor.
