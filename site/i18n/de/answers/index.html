Antworten

Was Entwickler über Glyph fragen.

Jede Antwort zeigt ein durchgearbeitetes Beispiel und endet mit dem, was noch nicht funktioniert. Fang dort an, wo deine Zweifel liegen. Neu bei Glyph? Das 10-Minuten-Hier-anfangen ist der schnellste erste Lauf.

Das Problem, das es löst

Was die Änderung eines Agenten kaputtmachen kann, ohne dass es jemand merkt, und was Glyph jeweils dagegen tut.

01Was hindert einen Agenten daran, meinen Code unbemerkt kaputtzumachen?

Kein any, keine Casts, erschöpfendes match, zur Laufzeit geprüfte Typen und Tests direkt neben dem Code, die bei jedem Build laufen.

 02Bleiben Änderungen von Agenten sauber, oder formatieren sie meine ganze Datei um?

Eine einzeilige Änderung ist ein einzeiliger Diff. Ein kanonisches Layout, nichts wird neu umbrochen.

 03Kann ein Agent (oder ich) finden, wo etwas definiert ist?

Ein Name, eine Deklarationsform. grep landet immer darauf.

Entscheiden, ob du es einsetzt

Warum eine Sprache statt mehr Tooling, und was es kostet, sie einzuführen.

04Warum TypeScript und nicht Go oder eine neue Sprache?

Weil dort dein Ökosystem ist, und deshalb geht die Einführung Datei für Datei.

 05Warum nicht einfach striktes TypeScript + zod + eslint + ts-pattern?

Nicht optional: die Sprache, deren Prüfungen der Agent nicht per Konfiguration abschalten kann.

 06Lohnt sich Glyph, wenn ich keine KI verwende?

Ja: Die Garantien sind ganz normale technische Vorteile, die ein Mensch direkt hat.

 07Kann eine KI zuverlässig eine Sprache schreiben, die sie kaum gesehen hat?

Das meiste, was ein Modell über TypeScript weiß, lässt sich übertragen, und der Compiler benennt die Stellen, an denen es nicht so ist.

 08Macht ein neues Glyph-Release meinen Build kaputt?

Projekte pinnen den Compiler exakt, also kommt kein Release versehentlich an. glyph doctor sagt, dass es eins gibt; glyph upgrade übernimmt es.

Einsatz mit deinem Stack

npm-Pakete, eine bestehende App, API-Grenzen, React.

09Kann ich meine bestehenden TypeScript-, JavaScript- und npm-Bibliotheken verwenden?

Ja: Importiere jedes npm-Paket, behalte einen handgeschriebenen .ts-Shim, wo du einen brauchst, und importiere Glyph wieder in .ts.

 10Kann ich Glyph in meiner bestehenden App einführen, oder heißt es alles oder nichts?

Kein Rewrite: der Domänenkern in Glyph, der Rest in TypeScript. Das erzeugte TypeScript wird von einer normalen Vite-App importiert wie jedes andere Modul.

 11Muss ich für jede API einen Validator von Hand schreiben?

Nein. Wenn du einen Typ deklarierst, wird sein Validator erzeugt.

 12Kann ich aus meiner API-Spezifikation einen typisierten Client und Server generieren?

glyph gen openapi/zod/dts: committeter, durchsuchbarer Code.

 13Funktioniert es mit React: Komponenten, Hooks und Context?

JSX, Hooks und erschöpfende Reducer-Actions als vollwertige Bestandteile.

 14Was kann Glyph bei React noch nicht?

Eine Zeile pro Gap-Nummer, mit dem, was man bis dahin schreibt.

 15Wie teile ich veränderlichen Zustand zwischen Funktionen?

Ein Store: eine const, deren .set/.update die Schreibschnittstelle sind.

Was du damit bauen kannst

Die Sprache und die Standardbibliothek, nach Art des Programms.

16Ist das eine echte Sprache oder ein Spielzeug mit Lücken?

Modul-Sichtbarkeit, Interface-Bounds, defer, ein match, das als beliebiger Wert funktioniert und seinen Typ mitbringt, und eine Standardbibliothek mit slice, pad_start und fold.

 17Kann ich ihm Geld anvertrauen und Eingaben, die ich nicht kontrolliere?

Exakte Dezimalzahlen und IDs, Invarianten als Typen, Injection als Compile-Fehler.

 18Kann ich eine Webseite ausliefern oder nur eine JSON-API?

HTML, Redirects, Response-Header und Formular-Posts, ohne handgeschriebenen Server.

 19Kann ich ein Programm schreiben, in das jemand etwas eintippt?

io.read_line antwortet auf eine Zeile, sobald sie ankommt, statt zu warten, bis stdin geschlossen wird, also funktioniert eine REPL oder eine Spielschleife.

 20Kann ich einen Server schreiben, oder beendet sich der Prozess einfach?

main richtet alles ein und kehrt zurück; der Prozess bleibt am Leben, solange Sockets und Timer ausstehen, dieselbe Regel, die Node verwendet.

 21Kann ich Binärdaten verarbeiten, oder ist alles ein String?

std/bytes ist eine Folge von Oktetten, mit Codecs, die fehlerhafte Eingaben ablehnen statt sie zu überspringen, und HMACs, die einen echten Schlüssel nehmen.

Mit einem Agenten arbeiten

Fragen, die ein Agent dem Compiler vor und nach einer Änderung stellt.

22Kann der Compiler mir sagen, was eine Änderung kaputtmachen wird, bevor ich sie mache?

glyph_impact: ein Urteil pro Stelle, aus einer festen Liste, mit Begründung, bevor du die Datei anfasst.

 23Kann mein Agent den Compiler fragen, was ein Symbol ist, bevor er Code schreibt?

glyph_symbol: die Varianten einer Union mit der Syntax, die jede erzeugt, in einem Aufruf. Elf Tools, jedes mit einem Verb von glyph query.

 24Wenn der Build fehlschlägt, sagt der Compiler meinem Agenten, wie er es behebt?

Die Diagnose enthält das schuldige Symbol, die zulässigen Alternativen und was eine reparierende Änderung nicht kaputtmachen darf. glyph fix schreibt die Fixes, die der Compiler selbst entscheiden kann.

 25Ist die Dokumentation, die mein Agent liest, generiert oder von Hand geschrieben und veraltet?

glyph llms --json gibt die Diagnosen, das Prelude, die Stdlib-Signaturen und das Tool-Handbuch aus den eigenen Tabellen des Compilers aus, und ein Gate schlägt fehl, wenn eine handgeschriebene Kopie davon abweicht.

 26Kann ich verhindern, dass ein Agent die rohe Bibliothek importiert, wenn wir einen Wrapper dafür haben?

Den Importpfad in package.json verbieten und den Ersatz nennen. Ein Import davon ist E0115, und die Hilfe verweist auf den Wrapper.

Fehler, Editoren und Produktion

Was du siehst, wenn etwas falsch ist, vom Editor bis zur Rufbereitschaft.

27Wie sieht es mit Editor, Debugging und Fehlermeldungen aus?

Ein Language Server für jeden LSP-Editor und Fehler mit stabilem Code, die den Fix nennen.

 28Warum findet Glyph, was tsc findet, nur früher?

await-Kontext, ein match-Arm ohne Wert und ein fehlendes mut, gemeldet an deinem Quellcode statt am erzeugten TypeScript.

 29Wenn das Parsen fehlschlägt, erfahre ich warum?

Welches Feld, welche Regel verletzt wurde, welches where-Prädikat nicht erfüllt ist, und einen code, auf den du verzweigen kannst.

 30Wenn es um 3 Uhr nachts in Produktion kaputtgeht, was sieht die Rufbereitschaft?

Lesbares TS, das dir gehört, Source Maps zurück zu deiner .glyph und ein run, das meldet, was build meldet.
