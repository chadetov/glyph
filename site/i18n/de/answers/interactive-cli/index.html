18 · Programme, in die man tippt

Kann ich ein Programm schreiben, in das jemand etwas eintippt?

Ja. io.read_line kehrt zurück, sobald eine vollständige Zeile ankommt, und wartet nicht darauf, dass stdin geschlossen wird, also beantwortet eine REPL, eine Spielschleife oder ein Chat-Client jede Zeile, bevor er die nächste liest. Bis 0.1.62 hat es gewartet, und das sollte man offen sagen, weil es jedes interaktive Programm unmöglich gemacht hat.

Warum das wichtig ist

Ein Zeilenleser, der erst am Ende der Eingabe zurückkehrt, ist ein Dateileser, der den Namen eines Zeilenlesers trägt. Eine Datei hindurchzuleiten funktioniert einwandfrei, und deshalb hat es nichts bemerkt: Jede App im Repository, die stdin las, las eine Pipe. Dann schrieb jemand einen Chat-Client, und der blieb still, während getippt wurde, und gab nach Ctrl-D alle Antworten auf einmal aus.

Diese App wurde als Session-Replayer über eine aufgezeichnete JSON-Datei ausgeliefert, mit einem Kommentar im Quellcode, der sagte, warum. Drei andere Apps waren um dasselbe Problem herum gebaut worden, ohne dass jemand es benannt hatte: Minesweeper konnte zwischen den Zügen nicht neu zeichnen, das Textadventure konnte nicht auf look antworten, und eine REPL wertete nichts aus, bis man auflegte.

So sieht es aus

Die ganze Live-Session-Schleife der Chat-App. Lesen, anwenden, ausgeben, wiederholen:

examples/apps/chat/main.glyph 
fn converse(limit: Option<int>) -> Server {
  let state = server.empty()
  io.println(LIVE_BANNER)
  loop {
    let text = match io.read_line() {
      Some(l) => l,
      None => { break },
    }
    match client_line(text) {
      None => { io.println(LIVE_HINT) },
      Some(sent) => {
        let done = turn(state, sent.from, sent.line)
        report(done.lines)
        mut state = done.state
      },
    }
  }
  return state
}

An einem echten Terminal gesteuert, jede Zeile etwa 0,6 Sekunden nacheinander getippt und stdin offen gelassen. Die linke Spalte sind Millisekunden seit dem Start des Prozesses:

Ein bis zwei Millisekunden von der getippten Zeile bis zur Antwort. Vor dem Fix wurde bis 6460ms nichts ausgegeben, dem Moment, in dem stdin geschlossen wurde. Die erste Antwort kommt bei einem vollständigen Lauf nach etwa 1,6 Sekunden, und das ist der Start von tsx, nicht die Leselatenz.

Was in der Praxis beißt

Ein abschließendes \r wird entfernt, also bekommst du aus einer CRLF-Datei und einer LF-Datei dieselben Zeilen und debuggst kein unsichtbares Zeichen in einer Windows-Eingabe. Eine Eingabe, die ohne abschließenden Zeilenumbruch endet, liefert diese letzte Zeile trotzdem einmal vor None, also geht die letzte Zeile einer Datei ohne abschließenden Zeilenumbruch nicht stillschweigend verloren. Mehrbyte-UTF-8, das über eine Lesegrenze hinweg geteilt wird, wird festgehalten und vervollständigt, statt zu Ersatzzeichen zu werden.

read_to_string leert denselben Puffer, also lassen sich die beiden kombinieren: read_line für eine Kopfzeile und dann read_to_string für den Body liefert dir den Rest, keine zweite Kopie und keinen leeren String. Zuerst aufgerufen, gibt es weiterhin das ganze stdin zurück. 200.000 durchgeleitete Zeilen werden in etwa 20ms gezählt, also ist zeilenweises Lesen kein Kompromiss beim Durchsatz.

Eine Kopfzeile, dann der Body 
let header = io.read_line()
let body = io.read_to_string()

Wo es steht

Heute verfügbar

io.read_line kehrt zurück, wenn eine Zeile ankommt, nicht wenn der Stream geschlossen wird, also funktionieren Prompt/Lesen/Antworten-Schleifen am Terminal und über eine Pipe gleichermaßen. CRLF wird normalisiert, eine letzte Zeile ohne Abschluss wird einmal geliefert, Mehrbyte-Zeichen überstehen Chunk-Grenzen, und read_to_string nimmt den Rest desselben Puffers. Ein Regressionstest hält stdin offen und verlangt das Echo, weil ein Test, der eine Datei durchleitet, auch mit der kaputten Implementierung besteht. io.print und io.eprint schreiben ohne Zeilenumbruch, sodass der Prompt > einer REPL auf der Zeile steht, auf der die Antwort getippt wird, und io.is_terminal / io.stdin_is_terminal sagen einem Programm, ob es mit einer Person oder einer Pipe spricht, also ist ein Flag wie --stdin der Chat-App nicht mehr der einzige Weg, das zu erfragen.

Noch holprig

Ein Programm, das einen Bildschirm neu zeichnen will, hat keine Cursorsteuerung: std/io hat keine Cursor- oder Bildschirmfunktionen, und kein anderes Stdlib-Modul ergänzt sie, also heißt eine Vollbild-Terminal-UI weiterhin, die Escape-Codes selbst zu schreiben.
