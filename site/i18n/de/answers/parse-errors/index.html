Wenn das Parsen fehlschlägt, erfahre ich warum?

Ja. Jedes Problem nennt das Feld, sagt, welche Regel der Wert verletzt hat, und enthält einen code, auf den du verzweigen kannst. Ein Feld, das durch ein where-Prädikat eingeschränkt ist, meldet das Prädikat selbst, also führt die Ablehnung per grep zurück zu der Zeile, die es festgelegt hat.

Warum das wichtig ist

Ein Validator, der sagt "dieser Payload ist ungültig", hat die halbe Arbeit gemacht.

Der Handler muss trotzdem entscheiden: Ist das ein Client, der ein Feld vergessen hat, oder ein Client, der ein Passwort mit vier Zeichen geschickt hat? Das eine ist ein 400, das andere ein 422, und wenn der Validator es nicht sagt, parst du am Ende denselben Body zweimal mit zwei verschiedenen Typen, um eine Information zurückzugewinnen, die der Validator schon hatte.

Geschichte wo das aufkam

Genau das ist beim Bau einer Auth-API in Glyph passiert. Eine Registrierung ganz ohne password-Schlüssel kam als weak_password zurück, weil fehlend und zu kurz denselben String erzeugten.

Verschachtelte Typen sprechen für sich selbst

Ein Feld, dessen Typ einen eigenen Deskriptor hat, wird vom parse dieses Typs validiert, und seine Probleme kommen mit dem Feldnamen vorn im Pfad zurück. Ein Password zwei Ebenen tief meldet also ["body", "password"] und bringt trotzdem seine eigene Meldung mit.

Der Code, nicht der String

Issue enthält ein optionales code: "missing", "type", "refinement", "unexpected" oder "depth". Verzweige darauf. Auf den Meldungstext zu matchen ist genau die Fragilität, die Glyph beseitigen soll, und die Meldung ist für den Menschen, der den Response-Body liest.

Eine Aufteilung in 400/422, die die Meldung nicht liest 
fn status_for(issues: Array<Issue>) -> number {
  let first = issues[0]
  return match first.code == "refinement" {
    true => 422,
    false => 400,
  }
}

code ist optional, also kompilieren ein Issue, das du von Hand baust, und jeder Konsument, der vor seiner Einführung geschrieben wurde, weiterhin unverändert.

Details der Code "depth"

"depth" ist die Antwort auf einen Body, der mehr als 1000 Objekte und Arrays tief verschachtelt ist (MAX_DEPTH in std/schema): ein Problem an dem Feld, an dem es passiert ist, wo die Prüfung vor 0.1.150 RangeError: Maximum call stack size exceeded warf und den Handler mitriss.

Wo es steht

Heute verfügbar

  • Records und where-Typen melden die verletzte Regel, nicht nur das fehlerhafte Feldmissingtyperefinementunexpecteddepth
    Details

    Records und where-Typen melden die verletzte Regel, nicht nur das fehlerhafte Feld: "missing" für ein fehlendes Pflichtfeld, "type" für die falsche Form (einschließlich eines Nicht-Objekts oder eines Arrays), "refinement" für einen Wert, der seinen Basistyp bestanden und das Prädikat verfehlt hat, "unexpected" für einen Schlüssel, den der Typ nicht deklariert, und "depth" für einen Wert, der mehr als 1000 Ebenen tief verschachtelt ist.

  • Eine Verfeinerung zitiert ihr Prädikat.
  • Ein Feld, dessen Typ einen Deskriptor hat, delegiert an ihn, also kommen verschachtelte Probleme mit dem vollständigen Pfad an.
  • Optionale Felder (f?: T) werden nie als fehlend gemeldet.

Wird schärfer 2

  • Ein Feld, dessen Typ keinen eigenen Deskriptor hat, bekommt weiterhin die flache Prüfung und ein "type"-Problem
    Details

    Zwei Grenzen. Ein Feld, dessen Typ keinen eigenen Deskriptor hat, ein uneingeschränkter Typparameter oder ein Typ aus einer handgeschriebenen .d.ts, bekommt weiterhin die flache Prüfung und ein "type"-Problem; der Compiler erzeugt für diese keinen Deskriptor, und glyph gen dts auf der Deklaration auszuführen gibt ihnen einen.

  • Ein eigener Typ namens Issue in einem Modul wird an der Zeile abgelehnt, die ihn nenntE0110seit 0.1.60
    Details

    Ein Modul, das einen eigenen Typ namens Issue deklariert, überdeckte früher den aus dem Prelude in der erzeugten Datei und machte jeden Deskriptor in diesem Modul kaputt; seit 0.1.60 ist diese Deklaration E0110 an der Zeile, die den Typ nennt, also erfährst du, wo das Problem liegt, statt einen tsc-Fehler über generierten Code zu lesen.
