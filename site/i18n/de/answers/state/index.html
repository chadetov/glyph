14 · Gemeinsamer Zustand

Wie teile ich veränderlichen Zustand zwischen Funktionen?

Mit einem Store. Glyph hat keine veränderlichen globalen Variablen. Modul-Bindings sind const. Gemeinsamer Zustand lebt in einem std/store: einer const auf Modulebene, die einen Wert hält, den du mit get() liest und mit set()/update() änderst. Das Binding bewegt sich nie; nur der Wert darin ändert sich, über einen Methodenaufruf, also ist jeder Schreibzugriff ein wörtliches .set( oder .update(, nach dem du greppen kannst.

So sieht es aus

Deklariere den Store einmal auf Modulebene. Jede Funktion im Modul teilt ihn. Kein let, das durch main gereicht wird, keine Closures, die etwas einfangen:

tasks.glyph 
import std/store { create }
import std/array

type Task = {
  id: number,
  title: string,
}

const tasks = create<Array<Task>>([])
const next_id = create(0)

fn add(title: string) -> Task {
  next_id.update(fn(n: number) -> number {
    return n + 1
  })
  let task = { id: next_id.get(), title: title }
  tasks.update(fn(cur: Array<Task>) -> Array<Task> {
    return array.push(cur, task)
  })
  return task
}

fn all() -> Array<Task> {
  return tasks.get()
}

Warum ein Store und keine veränderliche globale Variable

Das ist eine bewusste Design-Entscheidung. Glyph beschränkt mut auf lokale Zuweisungen und hält Modul-Bindings const, weil eine verstreute Menge beschreibbarer globaler Variablen genau das ist, was Zustand schwer nachvollziehbar und schwer zu finden macht. Ein Store braucht keine der beiden Regeln zu lockern: Das Binding const s ist unveränderlich, und der Wert darin ändert sich nur über set/update. Gemeinsamer Zustand kommt also als Bibliothek, nicht als neue Syntax (keine linearen Typen, keine aufgeweichten Mutationsregeln), und die Mutation lebt an genau einer geprüften Stelle, statt über dein Programm verstreut zu sein.

Eine scharfe Kante, die es auch in TypeScript gibt: Eine leere Collection kann ihren Elementtyp nicht ableiten, also gib ihr ein explizites Typargument mit: create<Array<Task>>([]). Ein skalarer Store (create(0)) wird problemlos abgeleitet.

Wo es steht

Heute verfügbar

std/store mit create, get, set und update: das einzige, durchsuchbare Zuhause für gemeinsamen veränderlichen Zustand.

In Arbeit

Komfortfunktionen über demselben Grundbaustein (abgeleitete/berechnete Stores, Subscriptions), aufgesetzt, ohne die Sprache zu ändern.
