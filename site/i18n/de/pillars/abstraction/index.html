Säule 03 · Der Feinschliff

Abstraktion

Sag, was du meinst, mit einem kleinen, orthogonalen Kern: Pattern Matching statt switch-Kaskaden, Result statt geworfener Exceptions, benannte Records statt Tupel. Ein guter Weg pro Konzept, nicht die angesammelten Schichten von TypeScript.

Zu viele Wege, dasselbe zu sagen

TypeScript ist durch Anlagerung gewachsen und hat jede Schicht behalten.

  • Feste FälleEine feste Menge von Fällen kannst du als enum, als Union von String-Literalen oder als const-Objekt modellieren.
  • FormenEine Form kannst du mit einem interface, einem type oder einer class beschreiben.
  • Alles andereEs gibt namespaces und Module, Decorators und Funktionen höherer Ordnung, fünf Idiome für fast alles, jedes mit eigenen Sonderfällen.

Für einen Menschen ist das Flexibilität. Für einen Agenten ist es ein Minenfeld: Mehr Wege, etwas auszudrücken, heißt mehr Wege, den mit der Falle zu erwischen, und mehr Idiome, die man dabei auseinanderhalten muss.

Glyphs Säule Abstraktion ist eine bewusste Subtraktion: ein scharfes Werkzeug pro Aufgabe, so gewählt, dass der naheliegende Weg auch der sichere ist.

01 match ist die einzige Bedingung

Es gibt keine if/else-Anweisung. Verzweigen ist überall match, und match ist ein Ausdruck: Es erzeugt einen Wert.

Ein Konstrukt deckt einen Boolean-Test, eine Union-Verzweigung und eine Wertetabelle ab, also musst du nicht entscheiden, welche Form der Verzweigung du nimmst.

02 Tagged Unions und Pattern Matching

"Eine dieser Formen" modelliert man mit einer Tagged Union, und zerlegt wird sie mit match, das den Payload im selben Schritt destrukturiert, in dem es den Fall auswählt.

feed.glyph 
type Feed =
  | Loading
  | Loaded(Array<Post>)
  | Failed(string)

fn view(feed: Feed) -> string {
  return match feed {
    Loading => "...",
    Loaded(posts) => render(posts),   // posts is Array<Post> here
    Failed(msg) => msg,               // msg is string here
  }
}
Details was du nicht mehr von Hand schreibst

Kein Diskriminator-Feld, das von Hand gepflegt werden muss, keine switch-Kaskade über einen String-Tag, kein Cast in jedem Zweig, um die Form zurückzugewinnen.

03 Result statt Exceptions

Ein Fehlschlag ist ein Wert, kein versteckter Sprung im Kontrollfluss. Eine Funktion, die fehlschlagen kann, sagt das in ihrem Rückgabetyp (Result<T, E>), und du setzt Fehlschläge mit dem Operator ? zusammen, statt Aufrufstellen in try/catch zu packen und zu hoffen, dass das Richtige die richtige Klasse wirft.

Der Fehlerpfad ist so sichtbar wie der Normalfall.

04 Benannte Records statt positionaler Tupel

Daten werden immer mit benannten Feldern beschrieben. Die Form liest sich an der Definition, bei der Konstruktion und bei der Verwendung gleich.

TypeScript: Was sind [0] und [1]? point.ts 
function origin(): [number, number] {
  return [0, 0];
}
const p = origin();
p[0]; p[1];  // x? y? row? col?
Glyph: Die Namen reisen mit dem Wert point.glyph 
type Point = { x: number, y: number }

fn origin() -> Point {
  return { x: 0, y: 0 }
}
Details keine Kurzschreibweise, keine anonymen Tupel

Es gibt keine Kurzschreibweise für Objektliterale und kein anonymes Tupel, bei dem du dir merken musst, was [0] und [1] sind.

05 Ein Grundbaustein pro Aufgabe

Wenn ein Konzept ein eigenes Werkzeug braucht, gibt Glyph ihm genau eins.

  • Gemeinsamer ZustandGemeinsamer veränderlicher Zustand lebt in einem std/store.
  • HandlesEin Datei- oder Socket-Handle, das genau einmal geschlossen werden muss, ist eine owned-Ressource.
  • IterationIteration ist for x in xs.

Jedes ist ein einzelner, benannter, zweckgebauter Grundbaustein, kein Muster, das du dir aus einer Kiste allgemeiner Teile neu herleitest und dabei subtil falsch machst.

Abstraktion heißt hier weniger, schärfere Werkzeuge, nicht mehr. Jedes Konzept hat eine naheliegende Form, und die naheliegende Form ist die, die du verwenden sollst.

Der Benchmark: kommt noch

Gemessen wird das über die Oberfläche: wie viele verschiedene Konzepte ein Leser im Kopf behalten muss, um ein Programm zu verstehen, und wie viel Code es braucht, eine übliche Aufgabe sauber auszudrücken.

Glyph ist noch nicht im echten Einsatz, also ist das Diagramm unten ein Platzhalter, der sich mit echten Messungen füllt, sobald es genug echte Programme zum Vergleichen gibt.

Ein kleinerer Kern ist für einen Menschen leichter einmal zu lernen und für ein Modell leichter jedes Mal richtig zu treffen. Das ist die ganze Feinschliff-Schicht in einem Satz: Nimm die Wahlmöglichkeiten weg, die nur Risiko hinzugefügt haben, und übrig bleibt eine Sprache, die sagt, was sie meint.
