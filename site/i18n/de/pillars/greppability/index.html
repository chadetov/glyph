Durchsuchbarkeit

Ein Name, eine Stelle. Jedes Symbol hat an der Stelle, an der es deklariert ist, genau eine syntaktische Form, also findet ein einfaches grep die Definition, immer, ohne Index, ohne Language Server und ohne Glück.

Warum "wo ist das definiert?" schwer ist

In einer ausgereiften TypeScript-Codebasis ist die einfachste Frage, woher kommt dieser Name?, oft die schwerste.

Details Overloads, Decorators, Zusammenführen, Erweiterung, Barrels

Die Sprache bietet ein halbes Dutzend Wege, ein Symbol über viele Stellen zu verteilen: Overloads teilen eine Funktion in mehrere Signaturen auf, Decorators packen sie in etwas anderes, das Zusammenführen von namespace und interface verstreut einen Typ über Dateien, declare module erweitert Code, der dir nicht gehört, und Barrel-Dateien index.ts re-exportieren alles, sodass der Pfad, aus dem du importierst, nicht dort ist, wo tatsächlich etwas lebt.

Ein Mensch kommt mit einem LSP und Gewohnheit zurecht. Ein Agent greppt: Er liest das Repo als Text, und jedes dieser Konstrukte ist eine Stelle, an der der Text darüber lügt, wo der Code ist.

Glyph entfernt sie. Das Ergebnis ist eine Sprache, in der die Suche ein verlässlicher Grundbaustein ist und keine Heuristik.

01 Eine Deklaration, eine Form

Eine Funktion, ein Typ oder eine Komponente wird genau einmal deklariert, mit einer Syntax. Es gibt keine Overloads, die eine Signatur aufteilen, und keinen Weg, einen Namen neu zu deklarieren: Zwei Dinge auf oberster Ebene mit demselben Namen sind ein harter Fehler (E0100).

E0100

Das Deklarationsschlüsselwort ist Teil des Namens, nach dem du suchst. grep "fn parseUser" kann keinen Aufruf, keinen Import und keinen Re-Export treffen, nur die eine Stelle, an der es definiert ist.

Die Suche nach einer Definition hat also genau eine Antwort.

02 Keine Barrel-Dateien: Der Importpfad ist der Ort

Glyph-Imports re-exportieren nie, und ein Modul, das nur aus Imports besteht, wird abgelehnt (E0102). Es gibt keine index.ts-Schicht, die die Herkunft verschleiert.

der Import sagt dir genau, wo du suchen musst 
import myapp/users { parseUser }
//     ^^^^^^^^^^^ the file is src/myapp/users.glyph.
//     not a re-export of a re-export of a barrel.
E0102

Ein Import nennt also das Modul, in dem das Symbol tatsächlich lebt: Der Pfad ist die Adresse.

03 Keine versteckten Wege, Verhalten anzuhängen

Es gibt keine Decorators, die eine Funktion in eine unsichtbare Schicht packen, kein Zusammenführen von namespace, das Member aus dem ganzen Baum sammelt, kein declare module, das einen Fremdtyp aus einer Datei erweitert, die du nie öffnen würdest, und kein implizites this, das umbindet, worauf eine Methode sich bezieht.

Ein Name löst sich zu einer Deklaration auf, und alles, was ihn formt, ist an dieser Deklaration sichtbar.

04 Sogar Mutation ist durchsuchbar

Bei Durchsuchbarkeit geht es nicht nur darum, Definitionen zu finden, sondern auch Wirkungen. Gemeinsamer Zustand lebt in einem std/store, und jede Änderung daran ist ein wörtlicher Aufruf von .set( oder .update(.

$ grep -rn 'tasks\.\(set\|update\)' src/ 
src/tasks.glyph:16:  tasks.update(fn(cur) { ... })
src/tasks.glyph:24:  tasks.set([])
# every place the task list can change, enumerated.
# nothing hides in an ordinary `x = ...` elsewhere.

Eine Suche zählt also die gesamte Schreibschnittstelle eines Zustands auf, statt nach Zuweisungen zu jagen, die über die Datei verstreut sind.

Eine Codebasis ist durchsuchbar, wenn ihr Text die Wahrheit über ihre Struktur sagt. Jede Einschränkung hier (eine Form pro Name, keine Re-Exports, kein Zusammenführen) ist dazu da, dass eine Suche die Antwort liefert und keinen Hinweis.

Der Benchmark: kommt noch

Die messbare Version dieser Aussage ist Präzision: Welcher Anteil der Treffer eines einfachen grep für ein bestimmtes Symbol ist das, was du tatsächlich gesucht hast, und wie viele Schritte braucht ein Agent bis zu einer Definition?

Glyph ist noch nicht im echten Einsatz, also ist das Diagramm unten ein Platzhalter, es füllt sich mit echten Zahlen, sobald es eine echte Codebasis zum Messen gibt.

Noch nicht gemessen Wir berichten Grep-Präzision und Schritte bis zur Definition aus einer echten Glyph-Codebasis, sobald es eine gibt, und veröffentlichen die Zahlen hier, egal wie sie ausfallen.

Der Gewinn wächst mit der Größe und mit der Autonomie. Ein Mensch lernt die Verstecke einer Codebasis; ein Agent, der kalt startet, nicht. Durchsuchbarkeit lässt ein Tool (oder ein neues Teammitglied) durch Lesen navigieren, so wie das Repo tatsächlich ist.

"Eine Lint-Regel kann Overloads und Decorators verbieten"

In deinem eigenen Repository, ja. ESLint kann Namespaces verbieten, und ein Team kann sich einigen, nicht zu überladen.

Die Sprache erlaubt trotzdem alles davon, also hält die Garantie so lange wie die Konfiguration und gilt nur für den Code, auf dem sie läuft. Ein grep über eine Abhängigkeit, eine generierte Datei oder das Repository von jemand anderem kann sich nicht darauf verlassen.

In Glyph gibt es die Konstrukte nicht, also funktioniert grep in jeder Glyph-Datei gleich, auch in denen, die niemand in deinem Team konfiguriert hat.

Wie das aus Sicht des Agenten aussieht, eine Definition oder jeden Schreibzugriff auf einen Wert mit einer Suche zu finden, beantwortet Kann ein Agent (oder ich) finden, wo etwas definiert ist?
