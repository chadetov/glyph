Hier anfangen · ~10 Minuten

Dein erstes Glyph-Programm

Ein Projekt anlegen, ausführen, dann absichtlich kaputtmachen und den Fehler lesen, den der Compiler ausgibt. Glyph-Vorkenntnisse sind nicht nötig. Wenn du schon ein bisschen TypeScript geschrieben hast, kannst du jeder Zeile folgen.

1 · Ein Projekt anlegen

Glyph wird über npm als vorkompiliertes Binary für macOS und Linux (x64 und ARM) und Windows (x64) ausgeliefert und braucht Node 18 oder neuer. Auf diesem Weg wird nichts global installiert: npx holt den Compiler, um das Projekt anzulegen, und das Projekt pinnt seine eigene Kopie zusammen mit tsx und typescript, die Glyph zum Ausführen und für die Typprüfung verwendet.

Terminal 
npx -y @glyphlang/glyph init hello
cd hello
npm install

Wenn du glyph lieber im PATH haben willst, installiere es global zusammen mit den beiden Tools, über die es läuft, und lass in den Befehlen auf dieser Seite das npx weg:

Terminal, die globale Alternative 
npm install -g @glyphlang/glyph tsx typescript
glyph doctor                    # confirms your toolchain is ready
glyph init hello
cd hello

2 · Ansehen, was angelegt wurde

glyph init legt ein lauffähiges Grundgerüst an: src/main.glyph, src/.types/README.md, das erklärt, dass ein typisiertes npm-Paket dort nichts braucht und das Verzeichnis für eines ohne eigene Typen gedacht ist, eine package.json, eine .gitignore und zwei Dateien, die Coding-Agenten von sich aus lesen: AGENTS.md, das auf glyph llms für die vollständige Sprachreferenz verweist, und .mcp.json, das glyph mcp registriert, damit ein Agent den Compiler nach Typen und Referenzen fragen kann, statt danach zu suchen. In einem bestehenden Projekt schreibt glyph agents diese beiden. Die package.json pinnt den Compiler, typescript und tsx in den devDependencies, sodass jeder, der das Projekt klont, es mit npm install ohne globale Installation bauen kann.

Öffne src/main.glyph. Es ist ein Hello World:

src/main.glyph 
module main

import std/io

fn main(argv: Array<string>) -> number {
  io.println("hello from glyph")
  return 0
}

Zwei Dinge fallen auf: Ein Programm führt seine main(argv) aus, und main gibt eine number zurück, den Exit-Code des Prozesses. Die Rückgabe setzt diesen Code, ohne den Prozess zum Beenden zu zwingen, also läuft ein Programm, das einen Server startet, weiter.

3 · Ausführen

Terminal 
npx glyph run
hello from glyph

glyph run hat es typgeprüft, zu TypeScript kompiliert und ausgeführt. Das ist die Schleife, die du für den Rest dieser Seite wiederholst.

4 · Etwas Echtes hinzufügen

Ersetze jetzt den Rumpf durch ein bisschen Logik: einen Aufgabenstatus und eine Funktion, die ihm ein Label gibt. Damit lernst du die beiden Dinge kennen, die du ständig benutzen wirst: eine Tagged Union (type Status = ...) und match, die einzige Bedingung in Glyph.

src/main.glyph 
module main

type Status = Todo | Doing | Done

fn label(s: Status) -> string {
  return match s {
    Todo => "not started",
    Doing => "in progress",
    Done => "finished",
  }
}

fn main(argv: Array<string>) -> number {
  print(label(Done))
  return 0
}
Terminal 
npx glyph run
finished

5 · Absichtlich kaputtmachen

Jetzt kommt der Teil, der zeigt, wofür Glyph da ist. Lösch den Arm Done aus dem match (so etwas macht ein Agent, wenn er irgendwo einen Fall hinzufügt und vergisst, ihn zu behandeln), und führ es noch einmal aus.

src/main.glyph (ohne den Done-Arm) 
fn label(s: Status) -> string {
  return match s {
    Todo => "not started",
    Doing => "in progress",
  }
}
$ npx glyph run 
[E0200] Error: typecheck: non-exhaustive match on `Status`: missing variants `Done`
   ╭─[main:6:10]
   │
 6 │ ╭─▶   return match s {
   ┆ ┆
 9 │ ├─▶   }
   │ ╰───────── missing variants `Done`
   │
   │  Help: Add an arm for each missing variant.
───╯

Es lief nicht. In TypeScript wird genau diese Funktion mit ausgeschriebenem Rückgabetyp ebenfalls abgelehnt (TS2366). Ein switch, der nur loggt oder Zustand aktualisiert, oder einer mit default:, kompiliert sauber und überspringt den neuen Fall stillschweigend. Hier ist jedes nicht erschöpfende match ein Compile-Fehler mit einem stabilen Code (E0200), der genauen Stelle und einem einzeiligen Fix. Führ glyph --explain E0200 aus, wann immer du die ausführliche Fassung willst.

6 · Beheben

Setz den Arm wieder ein (oder füg ein else hinzu), und es läuft wieder.

Terminal 
npx glyph run
finished

Das ist die Kernschleife: schreiben, ausführen, und wenn etwas falsch ist, sagt dir der Compiler genau was und wie, bevor dein Code ausgeliefert wird, nicht danach.
