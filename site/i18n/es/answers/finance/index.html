16 · Dinero y seguridad

¿Puedo confiarle dinero, y entradas que no controlo?

Sí. El dinero es exacto, un invariante como "no negativo" es un tipo que la frontera hace cumplir, y una entrada no fiable no puede llegar a un destino SQL o de shell sin sanearse. Cada una de estas cosas es un error de compilación o de parseo si te equivocas, no una convención que alguien tiene que recordar tres funciones más allá.

El dinero no es un float

Un sistema financiero sobre el number IEEE-754 es un bug esperando a que alguien lo reporte: 0.1 + 0.2 no es 0.3, y un valor por encima de 253 pierde precisión sin avisar. std/decimal es coma fija exacta en base 10 sobre BigInt. Sumar, restar y multiplicar son exactos; la división recibe una escala explícita y redondea la mitad alejándose de cero; una cantidad mal formada se parsea como un Err, nunca como un NaN silencioso.

std/decimal 
let price = decimal("10.50")?
let tax   = decimal("0.84")?
price.add(tax).to_string()      # "11.34", exact

decimal("2")?.div(decimal("3")?, 2)   # "0.67", half away from zero
el bug que elimina 
// JS number, the default everywhere:
0.1 + 0.2            // 0.30000000000000004
1_000_000_000_000.10 * 1.07   // rounding drift
9007199254740993     // === 9007199254740992

// None of these are your money anymore.

Los ids y los contadores siguen siendo exactos más allá de 253

Un id de cuenta o un contador de un libro contable que se sale del rango de los float y se redondea es otro tipo de catástrofe. bigint es un entero exacto de precisión arbitraria con literales 123n, y un campo de record tipado bigint valida typeof === "bigint" en la frontera, así que un id que llega como number de JSON se rechaza en lugar de truncarse sin avisar.

Un invariante es un tipo, no un comentario

"La cantidad no es negativa" y "la puntuación va de 1 a 5" son las comprobaciones que se escriben una vez y luego se olvidan. Un refinamiento where pone el invariante en el tipo, y el descriptor lo hace cumplir en la frontera. Un valor que no cumple el predicado nunca llega a ser un Amount.

refinements.glyph 
type Amount = int where value >= 0
type Rating = int where value >= 1 && value <= 5

Amount.parse(-1)   # Err  (not just "is a number")
Rating.parse(6)    # Err
Amount.parse(3.5)  # Err  (int check too)

La inyección es un error de compilación

El camino clásico hacia la ejecución remota de código es una entrada no fiable que llega a una consulta SQL, un comando de shell o una plantilla HTML. std/taint lo convierte en un error de tipos. Un valor que viene de fuera es Tainted; un destino que quieres proteger recibe Trusted. Los dos son estructuralmente distintos, así que la única forma de pasar de uno a otro es un sanitize explícito. Pásale a un destino el valor contaminado directamente y tsc se niega a compilarlo.

el camino seguro compila 
fn run_query(sql: Trusted<string>) -> void { ... }

let input: Tainted<string> = taint(req.body)
run_query(sanitize(input, escape))   # ok
el camino de la inyección no 
module query

import std/taint { Tainted, Trusted, taint, expose }

fn run_query(sql: Trusted<string>) -> string {
  return expose(sql)
}

pub fn handle(body: string) -> string {
  let input: Tainted<string> = taint(body)
  return run_query(input)
}

// [TS2345] Argument of type 'Tainted<string>'
//   is not assignable to parameter of type
//   'Trusted<string>'. (query.glyph:11)

Dónde está

Disponible hoy

std/decimal para dinero exacto, bigint para enteros grandes exactos, refinamientos where para que un invariante se valide en la frontera, y std/taint para que una entrada no fiable no pueda llegar a un destino protegido sin un sanitize explícito. Cada uno se comprueba: una cantidad o un id incorrectos fallan en parse, un invariante incumplido falla en parse, y un valor sin sanear falla en tsc.

Dónde se detiene

Hoy un refinamiento where cubre los tipos base primitivos; los invariantes de records y entre campos (where value.paid <= value.total) son una extensión planificada. Taint es una disciplina que adoptas al tipar un destino como Trusted, no un análisis de flujo automático: el compilador hace cumplir la frontera que declaras, no infiere la contaminación por ti en todo el programa.
