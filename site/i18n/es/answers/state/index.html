14 · Estado compartido

¿Cómo comparto estado mutable entre funciones?

Con un store. Glyph no tiene variables globales mutables. Los bindings de módulo son const. El estado compartido vive en un std/store: un const a nivel de módulo que guarda un valor que lees con get() y cambias con set()/update(). El binding nunca cambia; solo cambia el valor que contiene, mediante una llamada a un método, así que cada escritura es un .set( o un .update( literal que puedes buscar con grep.

Míralo

Declara el store una vez a nivel de módulo. Todas las funciones del módulo lo comparten. Sin un let pasado de mano en mano desde main, sin closures que lo capturen:

tasks.glyph 
import std/store { create }
import std/array

type Task = {
  id: number,
  title: string,
}

const tasks = create<Array<Task>>([])
const next_id = create(0)

fn add(title: string) -> Task {
  next_id.update(fn(n: number) -> number {
    return n + 1
  })
  let task = { id: next_id.get(), title: title }
  tasks.update(fn(cur: Array<Task>) -> Array<Task> {
    return array.push(cur, task)
  })
  return task
}

fn all() -> Array<Task> {
  return tasks.get()
}

Por qué un store, y no una variable global mutable

Es una decisión de diseño deliberada. Glyph restringe mut a las asignaciones locales y hace que los bindings de módulo sean const, porque un conjunto disperso de globales modificables es justo lo que hace que el estado sea difícil de razonar y difícil de encontrar. Un store no necesita relajar ninguna de las dos reglas: el binding const s es inmutable, y el valor que contiene solo cambia mediante set/update. Así que el estado compartido llega como una biblioteca, no como sintaxis nueva (sin tipos lineales, sin reglas de mutación más laxas), y la mutación vive en un único sitio auditado en lugar de repartida por todo el programa.

Un detalle a tener en cuenta, que también tiene TypeScript: una colección vacía no puede inferir el tipo de sus elementos, así que inicialízala con un argumento de tipo explícito: create<Array<Task>>([]). Un store escalar (create(0)) se infiere sin problemas.

Dónde está

Disponible hoy

std/store con create, get, set y update: el único sitio, fácil de buscar con grep, para el estado mutable compartido.

En camino

Utilidades sobre la misma primitiva (stores derivados o calculados, suscripciones), añadidas por encima sin cambiar el lenguaje.
