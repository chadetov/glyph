¿Una nueva versión de Glyph va a romper mi build?

No sin que lo pidas. Un proyecto de Glyph fija su compilador a una versión exacta, así que una versión publicada esta mañana no llega a tu build esta tarde. Antes de la 1.0, una versión puede añadir un diagnóstico que rechace código que ayer compilaba, y normalmente ese es el objetivo de la versión, así que la decisión de adoptarla es tuya y es un solo comando.

Por qué importa

La mayoría de las herramientas las fijas con un acento circunflejo, porque una versión de parche es una corrección de bugs. Un compilador antes de la 1.0 no es eso. Todo el trabajo de Glyph es rechazar programas, y mejorar en eso significa errores nuevos: una comprobación más estricta en un import, un hueco de exhaustividad que antes se colaba, un número de argumentos que el checker no había modelado. Esas versiones son las buenas. También son justo las que no quieres que lleguen a través de un npm install que ejecutaste para añadir una librería de fechas.

Así que glyph init no escribe ningún ^. En una versión 0.x el circunflejo sigue dejando flotar el parche, y esa es la trampa: ^0.1.9 acepta sin avisar cualquier 0.1.x posterior.

package.json, tal como se crea 
"devDependencies": {
  // exact. no caret, no tilde.
  "@glyphlang/glyph": "0.1.72",
  "typescript": "^6.0.0",
  "tsx": "^4.19.0"
}

Haz commit del package-lock.json a su lado y un clon nuevo compila con el toolchain que probaste, no con lo que se haya publicado después.

La otra mitad

Fijar la versión tiene un modo de fallo evidente: te quedas un año con un compilador viejo y nunca te enteras. Nada en tu máquina te lo diría, y una web que tienes que acordarte de visitar no es un canal. Así que te lo dice el compilador, cuando le preguntas cualquier cosa sobre tu configuración:

glyph doctor 
glyph — 0.1.72
  [update]   0.1.73 is published — `glyph --update` moves this compiler, `glyph upgrade` moves a project's pin
             what changed: https://glyphlang.io/versions/

glyph doctor — JavaScript toolchain
  [ok]       node: v22.1.0
  [ok]       tsx: tsx v4.19.0
  [ok]       tsc: Version 6.0.2
All good. `glyph run` and `glyph build --check` are ready.

Encontrar una versión más reciente nunca cambia el código de salida, así que es seguro ejecutarlo en CI. Una versión publicada no es un toolchain roto, y un pipeline en verde no debería ponerse en rojo porque alguien publicara hace diez minutos. Si la máquina no tiene conexión, la comprobación lo dice y sigue; --offline se la salta por completo y no hace ninguna llamada de red.

Nada más llega al registro. build, run y check nunca lo hacen. Un compilador que llama a casa en cada build es otro producto.

Actualizar

Cambia una línea, y tú decides cuándo 
$ glyph upgrade --dry-run
glyph upgrade: would move /app/package.json from 0.1.72 to 0.1.73 (nothing written).

$ glyph upgrade
glyph upgrade: /app/package.json now pins 0.1.73 (was 0.1.72).
glyph upgrade: what changed: https://glyphlang.io/versions/
glyph upgrade: build before you commit; a new release may report diagnostics
               this project did not have.

Reescribe una línea y ejecuta npm install. No toca tu código, y no finge que la actualización ha terminado: compilar después es justo lo importante, porque la versión que acabas de adoptar puede tener opiniones con las que tu código todavía no se ha encontrado. --to <version> indica una concreta, incluida una anterior cuando quieres volver atrás, y --no-install deja la instalación en tus manos.

Mover la herramienta, no el proyecto

upgrade mueve una versión fijada en un package.json. Ese es el comando equivocado cuando lo que está desactualizado es el compilador de tu PATH, y durante un tiempo doctor lo mostraba igualmente, apuntando una instalación global a un manifiesto que quizá no tenía. glyph --update es la otra mitad. La separación ahora es una regla y no una casualidad: los flags actúan sobre la herramienta, como hacen --version, --help y --explain, y los subcomandos actúan sobre tu código. --update-dry-run se detiene después de imprimir el comando de npm que habría ejecutado.

glyph --update 
$ glyph --update
glyph 0.1.72 is installed; 0.1.73 is published.
Release notes: https://glyphlang.io/versions/
A 0.1.x release may reject code that compiled before, so read the notes for anything between these two.

Running: npm install -g @glyphlang/glyph@0.1.73
   ... npm output ...

npm finished. Confirm with:
    glyph --version

Solo mueve una instalación que sabe identificar. A un compilador al que se llega por npx, compilado desde un árbol de fuentes de Glyph, o situado en una ruta que no reconoce, se le imprime el comando y no se sobrescribe nada, porque reemplazar a ciegas un binario de Homebrew o el cargo build de alguien deja el PATH apuntando a algo que nadie eligió. Tampoco llega a afirmar que la actualización se aplicó: npm puede salir con cero tras saltarse una optionalDependency que no pudo descargar, que es como una versión de Glyph se publicó una vez sin binario para la plataforma, así que la última línea indica glyph --version como comprobación en lugar de afirmar que funcionó.

Dónde está

Disponible hoy

Los proyectos creados fijan la versión exacta, así que ninguna versión llega a un build por accidente. glyph doctor compara tu compilador con el registro y enlaza las notas de la versión, sin afectar nunca a su código de salida ni ser accesible desde build/run/check. glyph upgrade mueve la versión fijada, la instala y lee el circunflejo de un proyecto antiguo, para que los proyectos que ya existían también puedan pasar a una versión exacta. glyph --update mueve el propio compilador, para una instalación global de npm, e informa en lugar de adivinar para cualquier otra forma en que pudiera haber llegado ahí.

Afinándose

Las notas de versión son una sola página para toda la línea, así que glyph upgrade enlaza la página y no la entrada de la versión a la que te mueves. Todavía nada te dice cuáles de los diagnósticos de la nueva versión va a disparar tu código: para saberlo hay que compilar, y por eso el comando te lo dice. Y actualizar saltando varias versiones a la vez es el mismo paso único que con una, sin un resumen de lo que se ha acumulado entre medias. glyph --update llama a npm y lee su código de salida, así que puede decirte que npm terminó pero no que el binario del PATH es la versión que pediste; por eso remite a glyph --version en lugar de decir que ha funcionado.
