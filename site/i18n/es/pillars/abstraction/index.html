Pilar 04 · El pulido

Abstracción

Di lo que quieres decir con un núcleo pequeño y ortogonal: pattern matching en lugar de escaleras de switch, Result en lugar de excepciones lanzadas, records con nombre en lugar de tuplas. Una buena forma por concepto, no las capas acumuladas de TypeScript.

Demasiadas formas de decir lo mismo

TypeScript creció por acumulación, y conservó todas las capas. Puedes modelar un conjunto fijo de casos como un enum, una unión de literales de string o un objeto const. Puedes describir una forma con una interface, un type o una class. Hay namespaces y módulos, decoradores y funciones de orden superior, cinco idiomas para casi todo, cada uno con sus casos límite.

Para una persona eso es flexibilidad. Para un agente es un campo de minas: más formas de expresar algo significan más formas de elegir la que tiene la trampa, y más idiomas que tener claros mientras lo hace. El pilar de abstracción de Glyph es una resta deliberada: una herramienta afilada por tarea, elegida para que la forma obvia sea también la segura.

01 match es el único condicional

No hay sentencia if/else. Bifurcar es match, en todas partes, y match es una expresión: produce un valor. Una construcción cubre una prueba booleana, un despacho sobre una unión y una tabla de valores, así que no hay que decidir qué forma de bifurcación usar.

TypeScript: una sentencia, no un valor grade.ts 
let label: string;
if (score > 90) label = "A";
else if (score > 80) label = "B";
else label = "C";
Glyph: una expresión grade.glyph 
let label = match score > 90 {
  true => "A",
  false => match score > 80 {
    true => "B",
    else => "C",
  },
}

02 Uniones etiquetadas y pattern matching

La forma de modelar "una de estas formas" es una unión etiquetada, y la forma de descomponerla es match, que desestructura el payload en el mismo paso en que elige el caso. No hay un campo discriminante que mantener a mano, ni una escalera de switch sobre una etiqueta de string, ni un cast dentro de cada rama para recuperar la forma.

feed.glyph 
type Feed =
  | Loading
  | Loaded(Array<Post>)
  | Failed(string)

fn view(feed: Feed) -> string {
  return match feed {
    Loading => "...",
    Loaded(posts) => render(posts),   // posts is Array<Post> here
    Failed(msg) => msg,               // msg is string here
  }
}

03 Result en lugar de excepciones

El fallo es un valor, no un salto oculto en el flujo de control. Una función que puede fallar lo dice en su tipo de retorno (Result<T, E>) y compones los fallos con el operador ? en lugar de envolver las llamadas en try/catch y esperar que lo que corresponde lance la clase que corresponde. El camino de error es tan visible como el camino feliz.

04 Records con nombre en lugar de tuplas posicionales

Los datos se describen siempre con campos con nombre. No hay abreviatura de objetos literales ni se recurre a una tupla anónima cuyos [0] y [1] tienes que recordar. La forma se lee igual en la definición, en la construcción y en el uso.

TypeScript: ¿qué son [0] y [1]? point.ts 
function origin(): [number, number] {
  return [0, 0];
}
const p = origin();
p[0]; p[1];  // x? y? row? col?
Glyph: los nombres viajan con el valor point.glyph 
type Point = { x: number, y: number }

fn origin() -> Point {
  return { x: 0, y: 0 }
}

05 Una primitiva por tarea

Cuando un concepto necesita su propia herramienta, Glyph le da exactamente una. El estado mutable compartido vive en un std/store. Un handle de archivo o de socket que hay que cerrar una vez es un recurso owned. La iteración es for x in xs. Cada uno es una primitiva única, con nombre y hecha a propósito, no un patrón que vuelves a construir a partir de un cajón de piezas genéricas y que te sale mal por poco.

Aquí abstracción significa menos herramientas y más afiladas, no más. Cada concepto tiene una forma obvia, y la forma obvia es la que se supone que debes usar.

El benchmark: en camino

La forma de medir esto es la superficie: cuántos conceptos distintos tiene que tener en la cabeza quien lee para entender un programa, y cuánto código hace falta para expresar limpiamente una tarea común. Glyph todavía no se usa en el mundo real, así que el gráfico de abajo es un marcador de posición que se rellenará con mediciones reales cuando haya un conjunto de programas reales que comparar.

Un núcleo más pequeño es más fácil de aprender una vez para una persona y más fácil de acertar cada vez para un modelo. Esa es toda la capa de pulido en una frase: quita las opciones que solo añadían riesgo, y lo que queda es un lenguaje que dice lo que quiere decir.
