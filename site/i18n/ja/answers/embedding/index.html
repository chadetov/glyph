10 · アプリに組み込む

既存のアプリの中で Glyph を導入できるか、それとも全面移行しかないのか

書き直しは不要です。アプリは TypeScript のままにして、間違えるわけにいかない部分（モデル、権限、状態遷移、金額計算）を Glyph で書きます。glyph build が出力するモジュールは、ローカルファイルと同じように アプリから import できます。バンドラの設定もパスエイリアスも要りません。

なぜ重要か

たいていのチームはアプリケーションを書き直せませんし、アプリケーションの大部分には Glyph は必要ありません。必要なのはドメインの中核です。来月 AI エージェントが編集することになり、黙って間違っていては誰も困るルールの部分です。その中核を Glyph にしておけば、網羅的な match、キャストのないコード、検証された境界を、効果のある場所にだけ導入できます。React コンポーネント、スタイル、インフラはふつうの TypeScript のままです。

実例

Glyph のソースを 1 つのディレクトリにまとめ、アプリにコンパイルして、UI から import します。

ハイブリッド構成：ドメインの中核は Glyph、それ以外はすべて TypeScript 
src/
  glyph/          # models.glyph, permissions.glyph, analytics.glyph
  generated/      # glyph build --out src/generated src/glyph
  components/     # hand-written React/TSX

// BoardContext.tsx: the app imports compiled Glyph like a local module
import { TaskCard, can_move } from "../generated/models";

const parsed = TaskCard.parse(payload);  // Result, not an exception

出力されたコードが必要とするものは、すべてコードと一緒に運ばれます。import は同梱の標準ライブラリも含めてすべて相対パスなので、プロジェクトの tsconfig.json にもバンドラにも何も追加する必要がありません。素の Vite の雛形がそのまま出力をコンパイル・バンドルでき、同じファイルはホスト側の tsc --strict も通ります。アプリから import するものには pub を付けます。付いていない宣言はそのモジュール内に閉じます。これは仮定の話ではありません。外部のエンジニアがこの方法で React のカンバンボードを作りました。RBAC のマトリクス、分析用の計算式、ステータス遷移を 4 つの Glyph モジュールに置き、その上に手書きの React UI を載せています。

現状

提供中

出力はそのままホストのプロジェクトに組み込めます。指定子はすべて相対パスで、prelude の型はコード自身が持ち運びます。素の Vite の雛形、ホスト側の tsc --strict、esbuild、tsx で検証済みです。ハイブリッド構成はデプロイガイドに記載しています。

予定

watch モードはまだありません。.glyph のソースを編集したら glyph build を再実行してください（dev スクリプトに組み込むと便利です）。std/fs や std/net を使うモジュールは、Node に触れる TypeScript と同じく、ホスト側に @types/node が必要です。
