16 · お金と安全性

お金や、自分で制御できない入力を任せられるか

任せられます。金額は正確に扱われ、「負でない」のような不変条件は境界で強制される型になり、信頼できない入力はサニタイズされないかぎり SQL やシェルのシンクに届きません。どれも、間違えればコンパイルエラーかパースエラーになります。3 つ離れた関数で誰かが覚えておかなければならない慣習ではありません。

お金は浮動小数点数ではない

IEEE-754 の number で作った金融システムは、報告されるのを待っているバグです。0.1 + 0.2 は 0.3 にならず、253 を超える値は黙って精度を失います。std/decimal は BigInt の上に作られた正確な 10 進固定小数点数です。加算、減算、乗算は正確で、除算は明示的なスケールを取り、ちょうど半分の端数は 0 から遠ざかる方向に丸めます。不正な金額は黙って NaN になるのではなく、Err としてパースされます。

std/decimal 
let price = decimal("10.50")?
let tax   = decimal("0.84")?
price.add(tax).to_string()      # "11.34", exact

decimal("2")?.div(decimal("3")?, 2)   # "0.67", half away from zero
取り除かれるバグ 
// JS number, the default everywhere:
0.1 + 0.2            // 0.30000000000000004
1_000_000_000_000.10 * 1.07   // rounding drift
9007199254740993     // === 9007199254740992

// None of these are your money anymore.

ID やカウンタは 253 を超えても正確

アカウント ID や台帳のカウンタが浮動小数点数の範囲を超えて丸められるのは、また別の種類の大惨事です。bigint は 123n リテラルを持つ正確な任意精度整数で、bigint 型のレコードフィールドは境界で typeof === "bigint" を検証します。そのため JSON の number として届いた ID は、黙って切り捨てられるのではなく拒否されます。

不変条件はコメントではなく型

「金額は負でない」や「評価は 1 から 5」は、一度書かれてその後忘れられるチェックです。where による絞り込みは不変条件を型に入れ、ディスクリプタがそれを境界で強制します。述語を満たさない値は、そもそも Amount になりません。

refinements.glyph 
type Amount = int where value >= 0
type Rating = int where value >= 1 && value <= 5

Amount.parse(-1)   # Err  (not just "is a number")
Rating.parse(6)    # Err
Amount.parse(3.5)  # Err  (int check too)

インジェクションはコンパイルエラー

リモートコード実行の典型的な経路は、信頼できない入力が SQL クエリ、シェルコマンド、HTML テンプレートに届くことです。std/taint はそれを型エラーにします。外部から来た値は Tainted で、保護したいシンクは Trusted を受け取ります。この 2 つは構造的に別物なので、一方から他方へ移る方法は明示的な sanitize しかありません。汚染された値をシンクに直接渡すと、tsc がコンパイルを拒否します。

安全な経路はコンパイルが通る 
fn run_query(sql: Trusted<string>) -> void { ... }

let input: Tainted<string> = taint(req.body)
run_query(sanitize(input, escape))   # ok
インジェクションの経路は通らない 
module query

import std/taint { Tainted, Trusted, taint, expose }

fn run_query(sql: Trusted<string>) -> string {
  return expose(sql)
}

pub fn handle(body: string) -> string {
  let input: Tainted<string> = taint(body)
  return run_query(input)
}

// [TS2345] Argument of type 'Tainted<string>'
//   is not assignable to parameter of type
//   'Trusted<string>'. (query.glyph:11)

現状

提供中

正確な金額のための std/decimal、正確な大きい整数のための bigint、不変条件を境界で検証する where による絞り込み、そして信頼できない入力が明示的な sanitize なしに保護されたシンクへ届かないようにする std/taint。どれも検査されます。不正な金額や ID は parse で失敗し、不変条件を満たさない値も parse で失敗し、サニタイズされていない値は tsc で失敗します。

限界

where による絞り込みは、現在はプリミティブの基底型に対応しています。レコードやフィールドをまたぐ不変条件（where value.paid <= value.total）は今後の拡張として計画しています。taint は、シンクを Trusted と型付けすることで自分から採用する規律であり、自動的なフロー解析ではありません。コンパイラは宣言した境界を強制しますが、プログラム全体にわたる汚染を推論してくれるわけではありません。
