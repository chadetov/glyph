14 · 共有状態

関数の間で可変の状態をどう共有するか

ストアを使います。Glyph には可変のグローバル変数がありません。モジュールの束縛は const です。共有状態は std/store に置きます。モジュールレベルの const が値を保持し、get() で読み、set()/update() で変更します。束縛そのものは動かず、メソッド呼び出しを通じて中の値だけが変わります。そのため、すべての書き込みは grep できる .set( か .update( という文字列になります。

実例

ストアはモジュールスコープで一度だけ宣言します。モジュール内のすべての関数がそれを共有します。main から let を引き回す必要も、クロージャで捕捉する必要もありません。

tasks.glyph 
import std/store { create }
import std/array

type Task = {
  id: number,
  title: string,
}

const tasks = create<Array<Task>>([])
const next_id = create(0)

fn add(title: string) -> Task {
  next_id.update(fn(n: number) -> number {
    return n + 1
  })
  let task = { id: next_id.get(), title: title }
  tasks.update(fn(cur: Array<Task>) -> Array<Task> {
    return array.push(cur, task)
  })
  return task
}

fn all() -> Array<Task> {
  return tasks.get()
}

なぜ可変のグローバルではなくストアなのか

これは意図的な設計です。Glyph は mut をローカルの代入に限定し、モジュールの束縛を const にしています。書き込み可能なグローバルがあちこちにあることこそ、状態を推論しにくく、見つけにくくする原因だからです。ストアはどちらのルールも緩めません。const s の束縛は不変で、中の値は set/update を通じてしか変わりません。つまり共有状態は新しい構文ではなくライブラリとして提供されます（線形型もなく、変更のルールも弱めていません）。変更はプログラム全体に散らばらず、監査済みの 1 か所に収まります。

TypeScript と共通の注意点が 1 つあります。空のコレクションは要素の型を推論できないので、明示的な型引数を渡してください：create<Array<Task>>([])。スカラーのストア（create(0)）は問題なく推論されます。

現状

提供中

create、get、set、update を備えた std/store。共有される可変状態を置く、grep で見つけられる唯一の場所です。
