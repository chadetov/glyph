なぜ Go や新しい言語ではなく TypeScript なのか

TypeScript は、エージェントがすでに最も多くのコードを書いている場所であり、あなたのエコシステム（npm、React、Node）がある場所だからです。Glyph を 1 ファイルずつ導入できるのは、ターゲットが TS だからこそです。

なぜ重要か

新しい言語が使われるかどうかは、ゼロから出荷までをどう進めるかで決まります。TypeScript にコンパイルされるので、今のコードベース、バンドラ、テストランナー、デプロイ環境から離れる必要がありません。Glyph は手元の .ts ファイルの隣に置けて、どちらの方向にもそのまま import できます。

同じプロジェクトに .glyph と .ts を並べて置く 
// cart.glyph: new, written in Glyph
import { formatPrice } from "./format.ts"

// checkout.ts: existing, untouched
import { total } from "./cart.glyph"

Go を TypeScript のコードベースに 1 ファイルずつ入れることはできません。ランタイムもモジュールシステムもエコシステムも違うからです。ターゲットが TS である理由は、この 1 点に尽きます。

Go について認めるべき点：キーワードが少なく安定しているので、エージェントが間違える余地が少ないことです。これには同意します。Glyph が意図的に小さなコアを保ち、1 つのことに 1 つのやり方しか用意していないのもそのためです。Go は比較のために、記述密度のベンチマークに含めています。

現状

提供中

読みやすい TypeScript 出力、既存の .ts との双方向 import、そして Node やブラウザのバンドルが動く場所ならどこでも動く小さなコア。

測定中

言語横断のベンチマーク（Glyph、TS、Go、Python、Rust）はコーパスの成長とともに拡大します。そのため「表面積が小さい」という主張は、主張のままではなく数値として扱われます。
