設計 · 比較

Glyph と Effect

どちらも、人とエージェントが頼れる TypeScript を目指しています。Effect はライブラリです。TypeScript を書き続けながら、型付きのエラー、追跡される依存関係、豊富な道具を手に入れられます。Glyph は TypeScript にコンパイルされる言語なので、TypeScript が許すもの、たとえばライブラリの保証を台無しにするキャストを拒否できます。成熟度では Effect のほうがはるかに上です。

Effect は自身をどう説明しているか

Effect のホームページは "Reliable TypeScript for the AI era" を掲げ、"declarative patterns and strong type system make it easier for LLMs to generate correct, production-ready code" と述べています（effect.website）。ドキュメントでは自身を "an ecosystem of tools that help you build better applications and libraries" と呼び、計算が何を返し、どう失敗しうるか、何を必要とするかを記録する Effect<Success, Error, Requirements> 型を中心に作られています（Why Effect）。TypeScript 5.4 以降と strict の有効化を求めています（Installation）。これらの引用は 2026-11-19 に確認したものです。

ライブラリと言語という違いから生じる差

Effect の型は tsc が検査するので、tsc が許すものはすべて、その隣でも許されたままです。次のコードは effect 4.1.4 と TypeScript 6 で、tsc --strict のコンパイルを通ります。キャストによってエラーチャネルから NotFound が消え、失敗しえないと型付けされた effect からプログラムが失敗を報告します。

eff.ts：tsc --strict は 0 で終了し、実行すると "Failure undefined" と出力される 
import { Effect } from "effect"

class NotFound {
  readonly _tag = "NotFound"
}

const find = (id: string): Effect.Effect<number, NotFound> =>
  id === "1" ? Effect.succeed(1) : Effect.fail(new NotFound())

// The error channel says NotFound can happen. A cast erases it.
const quiet = find("2") as unknown as Effect.Effect<number, never>

// And a parsed body still takes any type you name.
type User = { email: string }
const user = JSON.parse("{}") as User

console.log(Effect.runSyncExit(quiet)._tag, user.email)

Glyph で同じ関数を書くと Result を返し、書けるキャストはありません。2 つ目のモジュールは、TypeScript が出力される前に拒否されます。

find.glyph：ビルドが通り、tsc --strict も通過する 
module find

pub type NotFound = { id: string }

pub fn find(id: string) -> Result<number, NotFound> {
  return match id == "1" {
    true => Ok(1),
    false => Err({ id: id }),
  }
}
キャストを追加する：拒否 
module find

pub type NotFound = { id: string }

pub fn find(id: string) -> Result<number, NotFound> {
  return match id == "1" {
    true => Ok(1),
    false => Err({ id: id }),
  }
}

pub fn quiet() -> number {
  let n = find("2") as number
  return n
}

E0013 のヘルプには "Glyph has no as cast ... to turn an unknown into a type, validate it with T.parse(v) or narrow it with match and is." とあります。Effect のコードベースでも lint ルールでこれに近づけることはできます。誰かが無効にできるルールがなぜ別の保証なのかは、その比較で扱っています。

ライブラリにはできず、Glyph にできること

何を書けるかを決めるのは言語です。Glyph には any も、キャストも、非 null アサーションも、エラーを黙らせるコメントもなく、ユニオンに対する match はすべてのケースを扱わなければなりません。レコードとユニオンは宣言から生成された実行時の検査を持つので、json.parse<User>(body) は検証を行います。Effect の Schema も 1 つの記述から型を導出するので（その紹介ページの Schema.Schema.Type<typeof Person>）、そこでも型とバリデータがずれることはありません。違うのは、TypeScript にはコードベースにそれを使わせる仕組みが何もないことです。コンパイラはまた、変更が何を壊すかといったプログラムについての質問に、MCP やコマンドラインを通じてエージェントのために答えます。

このページでは Glyph のモジュールの中から Effect を使うことは試していないので、両者を組み合わせることについては何も主張しません。
