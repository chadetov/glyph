AI エージェントが書く。 コンパイラが検査する。

Glyph は TypeScript のように読めて、抜け道だけがありません。any もキャストも、検証されないデータもなく、すべてのケースを扱います。読みやすい TypeScript にコンパイルされるので、node も npm も既存のコードもそのまま使えます。

$ npx -y @glyphlang/glyph init hello && cd hello && npm install && npx glyph run

グローバルインストールは不要です。glyph を PATH に置く場合は npm install -g @glyphlang/glyph tsx typescript

実際のアプリケーションでの 1 つの変更

examples/apps/csvql はこのリポジトリにある CSV クエリエンジンで、中心に Value ユニオンがあります。ケースを追加する前に、その変更がどこに影響するかをコンパイラに聞いてみます。

glyph_variants { name: "Value" } 
10 match sites across 4 files
 8 will fail compilation
 2 contain a catch-all and will silently absorb it
次にケースを追加して glyph check を実行する 
8 errors, E0200 non-exhaustive match. The same eight.
The two catch-all sites report nothing at all.

予測は 8 か所すべてで当たりました。残りの 2 か所、 exec::total と render::literal_text はコンパイルが通ったまま、新しいケースを catch-all の行き先に流します。 8 つのエラーを直したところで手を止めたエージェントには、通ったビルドと生きたままの 2 つのバグが残ります。その 2 つを指し示すのがこのクエリです。

Glyph はまだすべてを検出できるわけではありません。既知の穴 {{catches:gap-count}} 件には再現コードと gap 番号が付いています。また、ロジックの誤りは TypeScript と同じく Glyph でも通ってしまいます。 まだ検出できないもの →
