差分の安定性

1 行の変更は 1 行の差分になります。唯一の正規フォーマット、末尾カンマ、そして全体が 1 行に収まるか、1 行に 1 要素ずつ並ぶかのどちらかで、決して詰め直されないリスト。そのためレビューには、周りの書き換えではなく、実際に行われた変更が表れます。

レビューとは差分を読むこと

変更について私たちが信頼しているもの（レビュー、blame、revert、bisect）のほとんどは差分の上に成り立っています。だから差分の S/N 比がそのまま価値になります。

詳細 ノイズの出どころ

多くのコードベースではそれがひどいものです。フォーマッタが折り返した行を組み直し、インポートの並べ替えツールがブロックを入れ替え、リネームがすべての呼び出し箇所の空白に触れ、重要な 1 行が関係のない 50 行に埋もれます。

エージェントはこれを大幅に悪化させます。小さなタスクを与えられても、モデルは 1 つのことを変えるために関数全体やファイル全体を平気で書き直します。ピンポイントで編集するより作り直すほうが楽だからです。レビューする人は、書き直されたものを元のものと比べて、本当の変更が意図したものだけであることを祈るしかありません。

Glyph は、レイアウトにモデルが書き換える余地がないように作られています。

01 唯一の正規レイアウト、選択肢なし

glyph fmt はすべてのファイルを 1 つの決まったレイアウトで出力し直します。インデントはスペース 2 つ、複数行のリストには必ず末尾カンマ、リストは 100 桁に収まる間は 1 行のままで、収まらなければ 1 行に 1 要素になります。選択は全部か無しかです。

詳細 詰め直しなし、合法な形は 1 つ

フォーマッタは行を埋めるために要素を詰め直すことがないので、リストが一部だけ 1 行目に、一部だけ次の行にあることはなく、フィールドの追加は 1 行の追加になります。合法な形がちょうど 1 つしかないので、議論することも、ツールが横から「直す」こともありません。

代償は幅のしきい値です。束縛の名前を変えて呼び出しが 100 桁を超えると、呼び出しは引数ごとに 1 行に展開されます。1 トークンの編集が 4 行の差分になります。その代わり、レイアウトはコードと開始桁だけで決まり、ほかの何にも左右されないので、同じファイルを編集する 2 つのエージェントは同じバイト列にたどり着きます。

末尾カンマは目立たない仕事をしています。最後の要素がすでにカンマで終わっているので、兄弟要素を追加しても上の行が編集されることは決してありません。1 つの挿入は 1 行です。

02 順序が安定しているので、履歴が読める

1 行に 1 要素なので、要素の並べ替え、挿入、削除はその要素の行にしか触れず、隣の行には触れません。

git blame は意味を保ちます。各行の最後のコミットは、たまたま同じ行を詰め直したフォーマットのコミットではなく、その要素を実際に変更したコミットです。

03 バレルファイルなし：インポートの書き換えなし

インポートは再エクスポートをせず、index.ts による集約の層もない（E0102）ので、シンボルを追加したり移動したりしても、すべての利用者がインポートするバレルファイルを通じて影響が広がることはありません。編集する依存関係は意図したものだけで、インポートグラフの残りは動きません。

04 生成は冪等で、塊ではない

同じ規律は生成コードにも及びます。glyph gen と glyph regen は出力を正規フォーマッタで出力し直すので、仕様の変更後に再生成すると、機械が書いたファイルを丸ごと置き換えるのではなく、数行が変わるだけの、実際にレビューできる最小限の差分になります。

仕様にフィールドを追加 → 再生成された差分 
  type Task = {
    id: number,
    title: string,
+   done: bool,
  }
// glyph regen re-ran the recorded command; this is the whole diff.

また、出力されるすべての .ts にはソースマップが付くので、コンパイル後の出力からも、変更した行まできれいにたどれます。

05 「TypeScript なら Prettier でできる」

フォーマットの多くについては、できます。trailingComma: "all" を設定した Prettier は最後の要素にカンマを付け、長いリストを 1 行に 1 要素で出力するので、セクション 01 の大部分は実現できます。違いは 3 か所にあります。

  • レイアウトはコードだけで決まります。Prettier は、書いた人が { の後で改行していればオブジェクトリテラルを展開したままにし、していなければ折りたたみます。そのため同じオブジェクトが、最初にどう入力されたかによって 2 通りに出力されえます。同じものを書く 2 つのエージェントは 2 つのレイアウトを生み、どちらかを次に編集すると組み直しとして差分に表れます。glyph fmt は、入力がどう折り返されていても { a: 1, b: 2 } を同じように出力します。
  • 設定するものがありません。Prettier の出力はリポジトリの設定ファイル次第で、設定ファイルがないリポジトリもあります。TypeScript のプロジェクトを渡り歩くエージェントは、プロジェクトごとに違うレイアウトに出会います。Glyph のファイルはどのプロジェクトでも同じレイアウトです。フォーマッタにオプションがないからです。
  • フォーマッタはファイルの内容を変えられません。glyph fmt は、自分の出力をパースして構文木を入力のものと比較する方法で、リポジトリのすべての例とファザーのもとでテストされています。レイアウト上に置き場所のない位置にコメントがある場合、そのコメントを関係のないコードの隣に動かすのではなく、ファイルを拒否します（E0500）。

このリストのうち 1 つはまだできていません。glyph fmt はインポートを並べ替えないので、2 つのエージェントが別々の場所にインポートを追加すると、インポートのブロックが異なるものになります（G358）。

差分の安定性があるから、「エージェントが何かを変えた」が「エージェントがまさにこれを変えた」になります。ノイズがゼロなら、レビューは速く、信頼は安く済みます。
