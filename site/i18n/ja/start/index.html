ここから始める · 約 10 分

最初の Glyph プログラム

プロジェクトを作って実行し、わざと壊して、コンパイラが出すエラーを読みます。Glyph の予備知識は不要です。TypeScript を少しでも書いたことがあれば、すべての行を追えます。

1 · プロジェクトを作る

Glyph は npm で、macOS と Linux（x64 と ARM）、Windows（x64）向けのビルド済みバイナリとして配布されており、Node 18 以降が必要です。この手順ではグローバルには何もインストールしません。npx がプロジェクトの雛形を作るためにコンパイラを取得し、プロジェクトは自分用のコンパイラを tsx と typescript と一緒にバージョン固定します。Glyph はこの 2 つを実行と型検査に使います。

ターミナル 
npx -y @glyphlang/glyph init hello
cd hello
npm install

glyph を PATH に置きたい場合は、Glyph が内部で使う 2 つのツールと一緒にグローバルにインストールし、このページのコマンドから npx を外してください。

ターミナル（グローバルにインストールする場合） 
npm install -g @glyphlang/glyph tsx typescript
glyph doctor                    # confirms your toolchain is ready
glyph init hello
cd hello

2 · 作られたものを見る

glyph init は実行できる雛形を作ります。中身は src/main.glyph、src/.types/README.md（型付きの npm パッケージならここには何も要らず、このディレクトリは型を同梱しないパッケージのためのものだと説明しています）、package.json、.gitignore、そしてコーディングエージェントが自分で読む 2 つのファイルです。AGENTS.md は言語リファレンスの全体として glyph llms を案内し、.mcp.json は glyph mcp を登録します。これでエージェントは、型や参照を検索して探す代わりにコンパイラに問い合わせられます。既存のプロジェクトでは、glyph agents がこの 2 つを書き出します。package.json はコンパイラ、typescript、tsx を devDependencies でバージョン固定しているので、プロジェクトを clone した人は誰でも、グローバルインストールなしに npm install だけでビルドできます。

src/main.glyph を開いてください。hello world です。

src/main.glyph 
module main

import std/io

fn main(argv: Array<string>) -> number {
  io.println("hello from glyph")
  return 0
}

注目する点は 2 つです。プログラムは main(argv) を実行し、main はプロセスの終了コードとなる number を返します。return は終了コードを設定するだけで、プロセスを強制的に止めはしないので、サーバーを起動するプログラムはそのままリクエストを受け付け続けます。

3 · 実行する

ターミナル 
npx glyph run
hello from glyph

glyph run は型検査をし、TypeScript にコンパイルして実行しました。このページの残りでは、このループを繰り返します。進めながらエディタでエラーや型を見たい場合は、エディタと連携に設定方法があります。

4 · 実際の処理を足す

本体を、意味のある判断に置き換えます。支払いの状態に応じて、注文を発送するかどうかを決める処理です。ここで、これからずっと使う 2 つのものが登場します。タグ付きユニオン（type Payment = ...）と、Glyph で唯一の条件分岐である match です。

src/main.glyph 
module main

type Payment = Pending | Paid | Failed

fn ship(p: Payment) -> string {
  return match p {
    Pending => "hold: waiting for the money",
    Paid => "ship it",
    Failed => "hold: payment failed",
  }
}

fn main(argv: Array<string>) -> number {
  print(ship(Paid))
  return 0
}
ターミナル 
npx glyph run
ship it

5 · わざと壊す

ここが、Glyph が何のためにあるかを示す部分です。チケットに「返金に対応する」とあるので、Payment に Refunded を追加し、ship には手を付けません。あるファイルで型を変え、その型で判断しているコードを一度も開かないとき、エージェントがすることです。もう一度実行します。

src/main.glyph（1 語追加） 
type Payment = Pending | Paid | Failed | Refunded
$ npx glyph run 
[E0200] Error: typecheck: non-exhaustive match on `Payment`: missing variants `Refunded`
    ╭─[ main:6:10 ]
    │
  6 │ ╭─▶   return match p {
    ┆ ┆
 10 │ ├─▶   }
    │ ╰───────── non-exhaustive match on `Payment`: missing variants `Refunded`
    │
    │     Help: Add an arm for each missing variant.
────╯

実行されませんでした。ほとんどのコードが書かれている TypeScript では逆になります。「hold」の 2 ケースを処理して default: return "ship it" で終わる switch は、新しいケースを追加した後も tsc --strict を通り、返金された注文をすべて発送します。Glyph では、ケースを取りこぼした match はすべてコンパイルエラーになり、安定したコード（E0200）、正確な位置、そのケースの名前が示されます。詳しい説明が欲しいときは、いつでも glyph --explain E0200 を実行してください。

6 · 直す

返金が発送にとって何を意味するかは、コンパイラには決められません。それはあなたが決めることです。アームを追加すれば、また実行できます。

src/main.glyph 
fn ship(p: Payment) -> string {
  return match p {
    Pending => "hold: waiting for the money",
    Paid => "ship it",
    Failed => "hold: payment failed",
    Refunded => "hold: refunded, nothing to ship",
  }
}
ターミナル（print(ship(Refunded)) にした場合） 
npx glyph run
hold: refunded, nothing to ship

これが基本のループです。書いて、実行し、何かがおかしければ、コードを出荷した後ではなく出荷する前に、何がどうおかしいのかをコンパイラが正確に教えてくれます。
