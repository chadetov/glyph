03 · 검색으로 탐색하기

에이전트가(또는 내가) 무엇이 어디에 정의되어 있는지 찾을 수 있나요?

모든 구문은 검색할 모양이 정확히 하나입니다. 평범한 grep(에이전트가 실제로 코드를 탐색하는 방식)은 비슷하지만 틀린 결과 쉰 개가 아니라 정의 하나에 닿습니다.

왜 중요한가

에이전트는 저장소 전체를 머릿속에 담고 있지 않습니다. 검색합니다. 개념 하나를 다섯 가지 방식으로 쓸 수 있다면 검색은 일부를 놓치고, 기존 정의를 찾지 못한 자신만만한 에이전트는 두 번째 정의를 만들어 냅니다. 개념마다 모양이 하나이면 검색이 완전해지므로, 에이전트는 중복을 만들지 않고 이미 있는 것을 편집합니다.

직접 보기

Glyph는 변경을 두 가지 형태(mut x = …와 mut x.method(…))로 제한하므로, 상태가 바뀌는 모든 곳이 검색 한 번으로 나옵니다.

grep -rn "mut " src/ (코드베이스의 모든 변경) 
src/cart.glyph:14:   mut items.push(item)
src/cart.glyph:22:   mut total = total + price
src/user.glyph:8:    mut session.token = fresh

변경 세 개, 전부가 검색 한 번에 나옵니다. TypeScript에서는 변경이 =, .push(), Object.assign, setter, spread 뒤에 숨을 수 있습니다. grep할 토큰이 하나로 정해져 있지 않으므로 “이것을 바꾸는 곳이 있는가?”에 믿을 만한 답이 없습니다. 같은 하나의 모양 규칙 덕분에 범주 전체를 감사할 수 있습니다.

검색 한 번 = 완전한 답 하나 
# every UI component
grep -rn "^component " src/

# every function
grep -rn "^fn " src/

# the entire resource-ownership surface
grep -rn "owned" src/

객체 리터럴 축약 문법도, 컴포넌트를 선언하는 두 번째 방법도, 구분해야 할 오버로드 문법도 없습니다. 작성 방법이 적다는 것은 실제 제약이고, 그것이 핵심입니다. 에이전트의 검색, 그리고 여러분의 검색을 믿을 수 있게 만드는 것이 바로 이것입니다.

검색을 믿을 수 있도록 Glyph가 넣지 않은 구문과, lint 규칙이 같은 보장이 아닌 이유는 검색 용이성 기둥 페이지에 있습니다.

현재 상태

지금 제공되는 것

구문마다 하나인 정해진 형태, grep할 수 있는 두 가지 모양(mut)으로 제한된 변경, 그리고 키워드 하나로 하는 감사(fn, component, owned, type).

그 위에 더해진 것

언어 서버가 워크스페이스 전체의 정의로 이동과 참조 찾기를 더합니다. 같은 보장을 이제 에디터에서 대화형으로 씁니다.
