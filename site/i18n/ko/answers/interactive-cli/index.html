18 · 입력을 받는 프로그램

사용자가 입력하는 프로그램을 작성할 수 있나요?

네. io.read_line은 한 줄이 완전히 도착하는 즉시 반환하고 stdin이 닫히기를 기다리지 않으므로, REPL, 게임 루프, 채팅 클라이언트가 다음 줄을 읽기 전에 각 줄에 응답합니다. 0.1.62까지는 기다렸고, 이 점은 분명히 말해 둘 만합니다. 그 때문에 모든 대화형 프로그램이 불가능했기 때문입니다.

왜 중요한가

입력이 끝날 때만 반환하는 줄 읽기는 이름만 줄 읽기인 파일 읽기입니다.

파일을 파이프로 넘기면 완벽하게 동작하므로 아무것도 이를 잡지 못했습니다. 저장소에서 stdin을 읽는 모든 앱이 파이프를 읽었습니다. 그러다 누군가 채팅 클라이언트를 만들었는데, 입력하는 동안 아무 반응이 없다가 Ctrl-D를 누른 뒤에 모든 답을 한꺼번에 출력했습니다.

이력 이에 맞춰 형태가 정해진 앱들

그 앱은 결국 녹화된 JSON 파일을 재생하는 세션 재생기로 배포되었고, 소스에 그 이유를 적은 주석이 남았습니다. 다른 앱 세 개도 아무도 이름 붙이지 않은 채 같은 문제에 맞춰 형태가 정해져 있었습니다. 지뢰찾기는 수마다 화면을 다시 그릴 수 없었고, 텍스트 어드벤처는 look에 답할 수 없었으며, REPL은 연결을 끊을 때까지 아무것도 평가하지 않았습니다.

실제로 문제가 되는 부분

  • CRLF줄 끝의 \r는 제거되므로 CRLF 파일과 LF 파일이 같은 줄을 주고, Windows 입력에서 보이지 않는 문자를 디버깅할 일이 없습니다.
  • 마지막 줄바꿈 없음마지막 줄바꿈 없이 끝나는 입력도 None 전에 마지막 줄을 한 번 돌려주므로, 줄바꿈으로 끝나지 않는 파일의 마지막 행이 조용히 버려지지 않습니다.
  • 나뉜 UTF-8읽기 경계에서 나뉜 멀티바이트 UTF-8은 대체 문자로 바뀌지 않고 보관했다가 완성됩니다.

read_line 다음에 read_to_string

read_to_string은 같은 버퍼를 비우므로 둘을 함께 쓸 수 있습니다. 헤더에 read_line을 쓰고 본문에 read_to_string을 쓰면 두 번째 사본이나 빈 문자열이 아니라 나머지를 받습니다. 먼저 호출하면 여전히 stdin 전체를 반환합니다.

헤더 한 줄, 그다음 본문 
let header = io.read_line()
let body = io.read_to_string()

파이프로 넘긴 200,000줄을 세는 데 약 20ms가 걸리므로, 한 줄씩 읽는다고 처리량을 희생하지 않습니다.

현재 상태

지금 제공되는 것

  • io.read_line은 스트림이 닫힐 때가 아니라 줄이 도착할 때 반환하므로, 프롬프트/읽기/응답 루프가 터미널에서도 파이프에서도 동작합니다.
  • CRLF는 정규화되고, 끝나지 않은 마지막 줄은 한 번 전달되며, 멀티바이트 문자는 청크 경계를 넘어도 유지되고, read_to_string은 같은 버퍼의 나머지를 가져갑니다.
  • 회귀 테스트는 stdin을 열어 둔 채 응답이 돌아오기를 요구합니다
    자세히

    파일을 파이프로 넘기는 테스트는 망가진 구현에서도 통과하므로, 회귀 테스트는 stdin을 열어 둔 채 응답이 돌아오기를 요구합니다.

  • io.print와 io.eprint는 줄바꿈 없이 씁니다
  • io.is_terminal / io.stdin_is_terminal은 프로그램이 사람과 대화하는지 파이프와 대화하는지 알려 줍니다
    자세히

    io.print와 io.eprint는 줄바꿈 없이 쓰므로 REPL의 > 프롬프트가 답을 입력하는 줄에 머물고, io.is_terminal / io.stdin_is_terminal은 프로그램이 사람과 대화하는지 파이프와 대화하는지 알려 주므로, 채팅 앱의 --stdin 같은 플래그가 더 이상 유일한 방법이 아닙니다.

아직 거친 부분

  • 화면을 다시 그리려는 프로그램에는 커서 제어가 없습니다
    자세히

    화면을 다시 그리려는 프로그램에는 커서 제어가 없습니다. std/io에는 커서나 화면 함수가 없고 다른 stdlib 모듈도 이를 추가하지 않으므로, 전체 화면 터미널 UI를 만들려면 여전히 이스케이프 코드를 직접 써야 합니다.
