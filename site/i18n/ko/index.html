AI 에이전트가 작성하고, 컴파일러가 검사합니다.

Glyph는 TypeScript처럼 읽히지만 우회로가 없습니다. any도, 캐스트도, 검증되지 않은 데이터도 없고, 모든 경우를 처리해야 합니다. 읽기 쉬운 TypeScript로 컴파일되므로 node, npm, 기존 코드를 그대로 씁니다.

$ npx -y @glyphlang/glyph init hello && cd hello && npm install && npx glyph run

전역 설치가 필요 없습니다. glyph를 PATH에 두려면: npm install -g @glyphlang/glyph tsx typescript

TypeScript의 어떤 도구도 잡지 못하는 사례

추가 플래그를 모두 켠 tsc --strict와 strict 모드의 typescript-eslint를 통과하는 사례 가운데, 에이전트가 얼마나 자주 작성하는지와 배포되었을 때 얼마나 심각한지를 기준으로 상위 세 개를 골랐습니다. 사례는 저장소에 있는 그대로 영어로 표시됩니다.

Glyph에서는 이 중 어느 것도 설정 옵션이 아닙니다. 확인된 사례는 모두 {{catches:total}}건입니다. 예측은 여덟 곳 모두 맞았습니다. 나머지 두 곳, exec::total과 render::literal_text는 계속 컴파일되면서 새 케이스를 catch-all이 가리키는 곳으로 보냅니다. 오류 여덟 개를 고치고 멈춘 에이전트에게는 초록색 빌드와 살아 있는 버그 두 개가 남고, 그 두 곳을 짚어 주는 것이 바로 이 쿼리입니다.
