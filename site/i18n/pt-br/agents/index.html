Para agentes e quem constrói ferramentas

A interface do compilador para agentes

Um agente pode perguntar ao compilador do Glyph o que é um símbolo, o que uma edição vai quebrar e por que um build falhou, e receber JSON de volta. glyph mcp serve onze ferramentas via stdio, cada uma também um verbo do glyph query, e glyph llms imprime a referência da linguagem offline.

Configuração

glyph init grava este .mcp.json num projeto novo, e glyph agents o grava (com um AGENTS.md apontando para glyph llms) num projeto existente. Qualquer cliente MCP que leia o arquivo inicia o servidor; não há porta nem daemon.

.mcp.json, como o glyph init o grava 
{
  "mcpServers": {
    "glyph": {
      "command": "glyph",
      "args": ["mcp"]
    }
  }
}

Uma chamada, com a resposta real

Um arquivo lê um campo que seu record não declara (u.naem). O agente chama glyph_diagnostics e recebe o diagnóstico do próprio compilador, com os campos que o record declara e o record a que eles pertencem. Esta é a saída da ferramenta na 0.1.149, cortada só onde está marcado.

requisição 
{
  "method": "tools/call",
  "params": {
    "name": "glyph_diagnostics",
    "arguments": {
      "path": "src/user.glyph"
    }
  }
}
resultado 
{
  "diagnostics": [ {
    "code": "E0210",
    "severity": "error",
    "stage": "typecheck",
    "message": "type `U` has no field
      `naem`; did you mean `name`?",
    "alternatives": ["name", "email"],
    "alternatives_kind": "fields",
    "cause": "user::U",
    "entity": "user::greet",
    "file": "user.glyph",
    "range": {
      "start": { "line": 9, "col": 10 },
      "end": { "line": 9, "col": 16 } },
    ...
  } ],
  "member": true,
  "module": "user",
  "not_run": [
    { "what": "tsc", ... },
    { "what": "E0104, ...", ... },
    { "what": "E0400, ...", ... } ],
  "path": "src/user.glyph",
  "project_root": "src",
  "unindexed": []
}

not_run diz o que esta verificação não cobriu, então uma lista diagnostics vazia não pode ser confundida com um build completo. Sem um cliente MCP, glyph query diagnostics --path src/user.glyph imprime o mesmo JSON. A lista completa de ferramentas, com todos os verbos, está na página do MCP.

Antes de uma edição: o que ela vai quebrar?

examples/apps/csvql é um motor de consultas CSV de onze arquivos com uma union de quatro casos, Value. Perguntado sobre o efeito de adicionar um quinto caso, o glyph_impact lista 10 locais de match em 4 arquivos: 8 WILL_FAIL e 2 ABSORBS, em que um braço catch-all vai engolir o caso novo e continuar compilando. Adicionar o caso de verdade dá exatamente 8 erros E0200, nesses 8 locais. Os 2 locais que absorvem ficam em silêncio, e é por isso que a resposta os nomeia.

a mesma pergunta na linha de comando 
glyph query impact --path value.glyph --entity value::Value \
  --change add_variant --variant Blob

Depois de um build vermelho: o que o conserto precisa preservar?

glyph check --agent imprime os diagnósticos do check --json com duas chaves a mais em cada um. constraints lista o que uma edição de conserto não pode quebrar; para o erro de digitação acima, diz "the record's fields are closed: user::U declares name, email and no others". symbols traz a resposta do glyph_symbol para cada símbolo que o diagnóstico nomeia, então a próxima edição não precisa de uma segunda chamada. Quando o conserto é totalmente determinado, o glyph fix o escreve.

Lendo a linguagem offline

glyph llms imprime a referência da linguagem, e /llms.txt neste site é o mesmo documento. glyph llms --json é esse conhecimento em forma de dados, lido das tabelas do próprio compilador: 77 códigos de diagnóstico, 24 nomes do prelude, 40 módulos da stdlib com 340 exports, 49 decisões da linguagem e as onze ferramentas. glyph llms --negative devolve 117 programas errados na 0.1.149 (139 a partir da próxima release) com o código que cada um provoca, compilados na hora em que você pede. scripts/check_llms_sync.py falha quando as tabelas de diagnósticos e de palavras reservadas da referência divergem das do próprio compilador.

pontos de entrada offline 
glyph llms                  # the reference, as prose
glyph llms --json           # the same, as data from the compiler's tables
glyph llms --negative E0200 # wrong programs that draw E0200
glyph --explain E0200       # the long explanation of one code
