07 · A premissa

Uma IA consegue escrever de forma confiável uma linguagem que mal viu?

Na maior parte, sim. O Glyph se lê como TypeScript: os mesmos tipos primitivos e genéricos (string, number, Array<T>), a maioria das mesmas expressões e pacotes do npm importados pelo nome. Ele não é um subconjunto de TypeScript: match, Result e fn name(x: T) -> R são sintaxe que o TypeScript não tem, e if, o ternário e os casts não existem em Glyph. A maior parte do que um modelo já sabe vale aqui também, e o compilador aponta os lugares onde não vale.

Por que isso importa

É a pergunta do cético justo: um LLM prevê o próximo token a partir do enorme volume de código em linguagens que já existem, então uma linguagem quase sem dados de treino deveria ser difícil de escrever. A resposta é estrutural: o Glyph não é estranho. Ele se parece com TypeScript, então o modelo já conhece a maior parte; as diferenças são poucas, dá para listá-las, e cada uma falha cedo, na compilação, em vez de passar em silêncio.

Veja na prática

Um agente que chuta errado não manda o chute para produção. Ele recebe um erro preciso, que dá para corrigir, e corrige no mesmo ciclo:

o ciclo de correção, em um passo 
// agent writes, reaching for a TypeScript habit:
if user.admin { grant() }

[E0006] Glyph has no `if`
   ╰─ `match` is the only conditional:
      match user.admin { true => grant(), false => void, }

O erro nomeia a construção do Glyph e mostra o formato, então a correção está a uma edição de distância: sem cavar o código-fonte, sem chutar. Esse ciclo curto é o que compensa a falta de dados de treino. Um único documento, llms.txt, dá ao agente o formato de um programa, a biblioteca padrão e todos os diagnósticos com a correção de cada um, e glyph llms imprime a mesma referência offline.

Situação atual

Disponível hoje

Uma sintaxe no formato de TypeScript, erros com um código estável que indicam a correção, e llms.txt / glyph llms como um único documento de referência para qualquer agente.

Em comprovação

Um benchmark de taxa de sucesso (tentativas até acertar, comparado com TypeScript na mesma tarefa) para transformar “funcionou bem” em um número medido.
