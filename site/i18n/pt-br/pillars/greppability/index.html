Pilar 02 · A cunha

Buscabilidade

Um nome, um lugar. Todo símbolo tem exatamente uma forma sintática no ponto onde é declarado, então um grep simples encontra a definição, sempre, sem índice, sem language server e sem depender de sorte.

Por que "onde isso está definido?" é difícil

Num codebase TypeScript maduro, a pergunta mais simples, de onde vem esse nome?, costuma ser a mais difícil. A linguagem oferece meia dúzia de jeitos de espalhar um símbolo por vários lugares: overloads dividem uma função em várias assinaturas, decorators a embrulham em outra coisa, o merging de namespace e interface espalha um tipo por vários arquivos, declare module estende código que não é seu, e arquivos barrel index.ts re-exportam tudo, então o caminho de onde você importa não é onde algo de fato está.

Uma pessoa se vira com um LSP e memória muscular. Um agente usa grep: lê o repositório como texto, e cada uma dessas construções é um lugar onde o texto mente sobre onde o código está. O Glyph remove todas elas. O resultado é uma linguagem em que a busca é uma primitiva confiável, não uma heurística.

01 Uma declaração, uma forma

Uma função, um tipo ou um componente é declarado exatamente uma vez, com uma sintaxe. Não existem overloads para dividir uma assinatura nem como redeclarar um nome: duas coisas de nível superior com o mesmo nome são um erro (E0100). Então a busca por uma definição tem exatamente uma resposta.

TypeScript: quatro resultados, um deles é o corpo $ grep -n "parseUser" src/ 
users.ts:4:  export function parseUser(
users.ts:9:  export function parseUser(
index.ts:2: export { parseUser } from
api.ts:7:   import { parseUser } from
Glyph: o primeiro resultado é a definição $ grep -n "fn parseUser" src/ 
users.glyph:12:fn parseUser(
  raw: unknown,
) -> Result<User, string> {

A palavra-chave da declaração faz parte do nome que você busca. grep "fn parseUser" não casa com uma chamada, um import ou um re-export, só com o único lugar onde ela é definida.

02 Sem arquivos barrel: o caminho do import é a localização

Imports do Glyph nunca re-exportam, e um módulo cujo único conteúdo são imports é recusado (E0102). Não existe uma camada index.ts lavando a origem. Então um import nomeia o módulo onde o símbolo de fato mora: o caminho é o endereço.

o import diz exatamente onde procurar 
import myapp/users { parseUser }
//     ^^^^^^^^^^^ the file is src/myapp/users.glyph.
//     not a re-export of a re-export of a barrel.

03 Nenhum jeito escondido de acoplar comportamento

Não há decorators embrulhando uma função numa camada invisível, nem merging de namespace juntando membros de toda a árvore, nem declare module estendendo um tipo de terceiros a partir de um arquivo que você nunca pensaria em abrir, nem this implícito mudando aquilo a que um método se refere. Um nome resolve para uma declaração, e tudo o que o molda está visível nessa declaração.

04 Até a mutação é buscável

Buscabilidade não é só achar definições, é achar efeitos. Estado compartilhado vive em um std/store, e toda mudança nele é uma chamada literal a .set( ou .update(. Então uma busca lista toda a superfície de escrita de um pedaço de estado, em vez de você caçar atribuições espalhadas pelo arquivo.

$ grep -rn 'tasks\.\(set\|update\)' src/ 
src/tasks.glyph:16:  tasks.update(fn(cur) { ... })
src/tasks.glyph:24:  tasks.set([])
# every place the task list can change, enumerated.
# nothing hides in an ordinary `x = ...` elsewhere.

Um codebase é buscável quando o texto diz a verdade sobre a estrutura. Cada restrição aqui (uma forma por nome, sem re-exports, sem merging) existe para que uma busca devolva a resposta, não uma pista.

O ganho cresce com a escala e com a autonomia. Uma pessoa aprende os esconderijos de um codebase; um agente começando do zero não. A buscabilidade é o que permite a uma ferramenta (ou a alguém novo no time) navegar lendo, do jeito que o repositório realmente é.

"Uma regra de lint pode proibir overloads e decorators"

No seu próprio repositório, sim. O ESLint pode proibir namespaces, e um time pode combinar de não usar overload. A linguagem ainda permite tudo isso, então a garantia dura enquanto durar a config e cobre só o código em que ela roda. Um grep numa dependência, num arquivo gerado ou no repositório de outra pessoa não pode contar com isso. No Glyph essas construções não existem, então o grep funciona igual em todo arquivo Glyph, inclusive nos que ninguém do seu time configurou.
