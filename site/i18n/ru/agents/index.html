Для агентов и разработчиков инструментов

Интерфейс компилятора для агентов

Агент может спросить у компилятора Glyph, что такое символ, что сломает правка и почему упала сборка, и получить ответ в JSON. glyph mcp отдаёт одиннадцать инструментов через stdio, каждый из них также доступен как команда glyph query, а glyph llms печатает справочник по языку без сети.

Настройка

glyph init записывает этот .mcp.json в новый проект, а glyph agents записывает его (вместе с AGENTS.md, который отсылает к glyph llms) в существующий. Любой MCP-клиент, который читает этот файл, запускает сервер; ни порта, ни демона нет.

.mcp.json в том виде, в каком его пишет glyph init 
{
  "mcpServers": {
    "glyph": {
      "command": "glyph",
      "args": ["mcp"]
    }
  }
}

Один вызов и его настоящий ответ

Файл читает поле, которого нет в его записи (u.naem). Агент вызывает glyph_diagnostics и получает собственную диагностику компилятора с полями, которые запись объявляет, и записью, которой они принадлежат. Это вывод инструмента на 0.1.149, сокращённый только в отмеченных местах.

запрос 
{
  "method": "tools/call",
  "params": {
    "name": "glyph_diagnostics",
    "arguments": {
      "path": "src/user.glyph"
    }
  }
}
результат 
{
  "diagnostics": [ {
    "code": "E0210",
    "severity": "error",
    "stage": "typecheck",
    "message": "type `U` has no field
      `naem`; did you mean `name`?",
    "alternatives": ["name", "email"],
    "alternatives_kind": "fields",
    "cause": "user::U",
    "entity": "user::greet",
    "file": "user.glyph",
    "range": {
      "start": { "line": 9, "col": 10 },
      "end": { "line": 9, "col": 16 } },
    ...
  } ],
  "member": true,
  "module": "user",
  "not_run": [
    { "what": "tsc", ... },
    { "what": "E0104, ...", ... },
    { "what": "E0400, ...", ... } ],
  "path": "src/user.glyph",
  "project_root": "src",
  "unindexed": []
}

not_run называет то, что эта проверка не покрыла, поэтому пустой список diagnostics нельзя принять за полную сборку. Без MCP-клиента glyph query diagnostics --path src/user.glyph печатает тот же JSON. Полный список инструментов со всеми командами есть на странице MCP.

До правки: что она сломает?

examples/apps/csvql это движок запросов к CSV из одиннадцати файлов с union Value на четыре варианта. На вопрос, что сделает добавление пятого варианта, glyph_impact перечисляет 10 мест с match в 4 файлах: 8 WILL_FAIL и 2 ABSORBS, где ветка catch-all проглотит новый вариант и код продолжит компилироваться. Реальное добавление варианта даёт ровно 8 ошибок E0200 в этих 8 местах. Два поглощающих места молчат, поэтому ответ их и называет.

тот же вопрос в командной строке 
glyph query impact --path value.glyph --entity value::Value \
  --change add_variant --variant Blob

После красной сборки: что исправление должно сохранить?

glyph check --agent печатает диагностики check --json с двумя дополнительными ключами у каждой. constraints перечисляет, что исправляющая правка не должна сломать; для опечатки выше там написано «the record's fields are closed: user::U declares name, email and no others». symbols содержит ответ glyph_symbol для каждого символа, упомянутого в диагностике, так что следующей правке не нужен второй вызов. Где исправление определено полностью, его записывает glyph fix.

Справочник по языку без сети

glyph llms печатает справочник по языку, и /llms.txt на этом сайте это тот же документ. glyph llms --json отдаёт те же знания как данные, прочитанные из собственных таблиц компилятора: 77 кодов диагностик, 24 имени прелюдии, 40 модулей стандартной библиотеки с 340 экспортами, 49 решений по языку и одиннадцать инструментов. glyph llms --negative возвращает 117 неверных программ в 0.1.149 (139 начиная со следующего выпуска) с кодом, который выдаёт каждая, и компилирует их по запросу. scripts/check_llms_sync.py падает, когда таблицы диагностик и зарезервированных слов в справочнике расходятся с таблицами компилятора.

точки входа без сети 
glyph llms                  # the reference, as prose
glyph llms --json           # the same, as data from the compiler's tables
glyph llms --negative E0200 # wrong programs that draw E0200
glyph --explain E0200       # the long explanation of one code
