10 · Внутри вашего приложения

Можно ли внедрить Glyph в моё существующее приложение, или только всё или ничего?

Без переписывания. Приложение остаётся на TypeScript, а часть, в которой нельзя ошибиться (модели, права доступа, переходы состояний, денежные расчёты), пишется на Glyph. glyph build генерирует модули, которые приложение импортирует как любой локальный файл, без настройки бандлера и без алиасов путей.

Почему это важно

Большинство команд не могут переписать приложение, и большей части приложения Glyph не нужен. Нужен он ядру предметной области: правилам, которые ИИ-агент будет править в следующем месяце и которые никто не хочет получить тихо сломанными. Если держать это ядро на Glyph, исчерпывающий match, отсутствие приведений типов и проверенные границы будут ровно там, где они окупаются, а компоненты React, стили и инфраструктура останутся обычным TypeScript.

Посмотрите сами

Одна папка с исходниками Glyph, скомпилированная в приложение и импортируемая интерфейсом:

Гибридная раскладка: ядро предметной области на Glyph, всё остальное на TypeScript 
src/
  glyph/          # models.glyph, permissions.glyph, analytics.glyph
  generated/      # glyph build --out src/generated src/glyph
  components/     # hand-written React/TSX

// BoardContext.tsx: the app imports compiled Glyph like a local module
import { TaskCard, can_move } from "../generated/models";

const parsed = TaskCard.parse(payload);  // Result, not an exception

Всё, что нужно сгенерированному коду, идёт вместе с ним. Импорты относительные, включая встроенную стандартную библиотеку, поэтому в tsconfig.json и бандлер вашего проекта ничего добавлять не нужно: стандартный шаблон Vite компилирует и собирает результат как есть, и те же файлы проходят tsc --strict основного проекта. Помечайте то, что импортирует приложение, через pub; объявление без него приватно для своего модуля. Это не гипотеза: сторонний инженер так и построил Kanban-доску на React, где матрица RBAC, формулы аналитики и переходы статусов лежат в четырёх модулях Glyph под написанным вручную интерфейсом на React.

Текущее состояние

Уже работает

Сгенерированный код встраивается в основной проект без изменений: везде относительные пути импорта, типы прелюдии несёт сам код, проверено на стандартном шаблоне Vite, tsc --strict основного проекта, esbuild и tsx. Гибридная раскладка описана в руководстве по развёртыванию.

В работе

Режима наблюдения пока нет: после правки исходников .glyph запускайте glyph build заново (добавьте это в свой скрипт dev). Модулям, использующим std/fs или std/net, нужен @types/node в основном проекте, как любому TypeScript, который работает с Node.
