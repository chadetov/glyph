18 · Интерактивные программы

Можно ли написать программу, в которую пользователь вводит текст?

Да. io.read_line возвращает строку, как только она пришла целиком, и не ждёт закрытия stdin, поэтому REPL, игровой цикл или чат-клиент отвечают на каждую строку, прежде чем читать следующую. До 0.1.62 он ждал, и об этом стоит сказать прямо, потому что из-за этого никакая интерактивная программа была невозможна.

Почему это важно

Чтение строк, которое возвращает результат только в конце ввода, это чтение файла под чужим именем. Если пропустить через него файл по конвейеру, всё работает идеально, и поэтому никто ничего не заметил: все приложения в репозитории, которые читали stdin, читали из pipe. Потом кто-то написал чат-клиент, и он молчал, пока человек печатал, а после Ctrl-D выдал все ответы разом.

То приложение вышло как проигрыватель сессии по записанному JSON-файлу, с комментарием в исходнике, объясняющим почему. Ещё три приложения были подогнаны под то же самое, и никто это не назвал: сапёр не мог перерисовываться между ходами, текстовое приключение не могло ответить на look, а REPL ничего не вычислял, пока вы не отключались.

Посмотрите сами

Весь цикл живой сессии чат-приложения. Прочитать, применить, вывести, повторить:

examples/apps/chat/main.glyph 
fn converse(limit: Option<int>) -> Server {
  let state = server.empty()
  io.println(LIVE_BANNER)
  loop {
    let text = match io.read_line() {
      Some(l) => l,
      None => { break },
    }
    match client_line(text) {
      None => { io.println(LIVE_HINT) },
      Some(sent) => {
        let done = turn(state, sent.from, sent.line)
        report(done.lines)
        mut state = done.state
      },
    }
  }
  return state
}

Запуск в настоящем терминале: строки вводятся примерно с интервалом 0.6 секунды, stdin остаётся открытым. В левом столбце миллисекунды с момента запуска процесса:

От введённой строки до ответа одна-две миллисекунды. До исправления ничего не выводилось до 6460ms, то есть до закрытия stdin. Первый ответ в полном прогоне приходит примерно через 1.6 секунды, и это запуск tsx, а не задержка чтения.

Что мешает на практике

Завершающий \r отбрасывается, поэтому файл с CRLF и файл с LF дают одинаковые строки, и вам не придётся отлаживать невидимый символ во вводе из Windows. Если ввод заканчивается без последнего перевода строки, эта последняя строка всё равно возвращается один раз перед None, так что последняя строка файла без завершающего перевода строки не теряется молча. Многобайтовый символ UTF-8, разрезанный границей чтения, удерживается и дособирается, а не превращается в символы замены.

read_to_string читает из того же буфера, поэтому они сочетаются: read_line для заголовка, а затем read_to_string для тела даёт оставшуюся часть, а не вторую копию и не пустую строку. Если вызвать его первым, он по-прежнему возвращает весь stdin. 200,000 строк из pipe считаются примерно за 20ms, так что чтение по одной строке не жертвует пропускной способностью.

Строка заголовка, затем тело 
let header = io.read_line()
let body = io.read_to_string()

Текущее состояние

Уже работает

io.read_line возвращает результат, когда приходит строка, а не когда закрывается поток, поэтому циклы «приглашение, чтение, ответ» работают и в терминале, и через pipe. CRLF нормализуется, последняя строка без завершения выдаётся один раз, многобайтовые символы переживают границы фрагментов, а read_to_string забирает остаток того же буфера. Регрессионный тест держит stdin открытым и требует эхо в ответ, потому что тест, который подаёт файл через pipe, проходит и на сломанной реализации. io.print и io.eprint пишут без перевода строки, поэтому приглашение REPL > стоит на той строке, где вводится ответ, а io.is_terminal / io.stdin_is_terminal сообщают программе, говорит ли она с человеком или с pipe, так что флаг вроде --stdin в чат-приложении больше не единственный способ это узнать.

Пока шероховато

У программы, которой нужно перерисовывать экран, нет управления курсором: в std/io нет функций для курсора или экрана, и ни один другой модуль стандартной библиотеки их не добавляет, так что полноэкранный терминальный интерфейс по-прежнему означает самостоятельно писать escape-последовательности.
