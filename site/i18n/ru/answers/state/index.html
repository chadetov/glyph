14 · Общее состояние

Как разделять изменяемое состояние между функциями?

Через store. В Glyph нет изменяемых глобальных переменных. Привязки модуля это const. Общее состояние живёт в std/store: const на уровне модуля, который хранит значение; читаете его через get(), меняете через set()/update(). Сама привязка никогда не меняется, меняется только значение внутри неё, через вызов метода, поэтому каждая запись это буквальный .set( или .update(, который можно найти grep.

Посмотрите сами

Объявите store один раз на уровне модуля. Все функции модуля пользуются им вместе. Никакого let, протаскиваемого через main, никаких захватывающих замыканий:

tasks.glyph 
import std/store { create }
import std/array

type Task = {
  id: number,
  title: string,
}

const tasks = create<Array<Task>>([])
const next_id = create(0)

fn add(title: string) -> Task {
  next_id.update(fn(n: number) -> number {
    return n + 1
  })
  let task = { id: next_id.get(), title: title }
  tasks.update(fn(cur: Array<Task>) -> Array<Task> {
    return array.push(cur, task)
  })
  return task
}

fn all() -> Array<Task> {
  return tasks.get()
}
вся поверхность записи одним grep

Почему store, а не изменяемая глобальная переменная

Это сознательное решение. Glyph ограничивает mut локальными присваиваниями, а привязки модуля делает const, потому что разбросанный набор изменяемых глобальных переменных именно то, из-за чего о состоянии трудно рассуждать и его трудно найти. Store не требует ослаблять ни одно из правил: привязка const s неизменяема, а значение внутри меняется только через set/update. Поэтому общее состояние появляется как библиотека, а не новый синтаксис (без линейных типов, без ослабленных правил изменения), и изменения живут ровно в одном проверяемом месте, а не разбросаны по программе.

Есть один острый угол, общий с TypeScript: пустая коллекция не может вывести тип элемента, поэтому задайте его явным аргументом типа: create<Array<Task>>([]). Скалярный store (create(0)) выводится без проблем.
