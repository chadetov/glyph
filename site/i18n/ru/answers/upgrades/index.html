Сломает ли новый выпуск Glyph мою сборку?

Нет, пока вы сами об этом не попросите. Проект на Glyph фиксирует компилятор на точной версии, поэтому выпуск, опубликованный утром, не попадёт в вашу сборку днём. До 1.0 выпуск может добавить диагностику, которая отклоняет код, компилировавшийся вчера, и обычно в этом и есть смысл выпуска, поэтому решение его взять за вами, и это одна команда.

Почему это важно

Большинство инструментов фиксируют с caret, потому что патч-выпуск это исправление ошибок. Компилятор до 1.0 устроен иначе. Вся работа Glyph в том, чтобы отклонять программы, а становиться в этом лучше значит выдавать новые ошибки: более строгую проверку импорта, дыру в исчерпываемости, которая раньше проскальзывала, арность, которую проверка ещё не моделировала. Это хорошие выпуски. И это ровно те выпуски, которые вы не хотите получить через npm install, запущенный ради библиотеки для дат.

Поэтому glyph init не пишет ^. На версии 0.x caret всё равно пропускает патчи, и в этом ловушка: ^0.1.9 тихо принимает любой более поздний 0.1.x.

package.json в том виде, в каком его создаёт шаблон 
"devDependencies": {
  // exact. no caret, no tilde.
  "@glyphlang/glyph": "0.1.72",
  "typescript": "^6.0.0",
  "tsx": "^4.19.0"
}

Закоммитьте рядом package-lock.json, и свежий клон будет собираться тем набором инструментов, который вы тестировали, а не тем, что вышло с тех пор.

Вторая половина

У фиксации версии есть очевидный способ провалиться: вы год сидите на старом компиляторе и не узнаёте об этом. На вашей машине об этом ничто не скажет, а сайт, который нужно не забывать проверять, это не канал. Поэтому компилятор сообщает сам, когда вы спрашиваете его о своей настройке:

glyph doctor 
glyph — 0.1.72
  [update]   0.1.73 is published — `glyph --update` moves this compiler, `glyph upgrade` moves a project's pin
             what changed: https://glyphlang.io/versions/

glyph doctor — JavaScript toolchain
  [ok]       node: v22.1.0
  [ok]       tsx: tsx v4.19.0
  [ok]       tsc: Version 6.0.2
All good. `glyph run` and `glyph build --check` are ready.

Найденный новый выпуск никогда не меняет код выхода, поэтому команду безопасно запускать в CI. Опубликованный выпуск не означает сломанный набор инструментов, и зелёный пайплайн не должен краснеть из-за того, что кто-то выпустил что-то десять минут назад. Если машина без сети, проверка так и пишет и идёт дальше; --offline пропускает её полностью и вообще не обращается к сети.

Больше ничто не обращается к реестру. build, run и check этого никогда не делают. Компилятор, который звонит домой при каждой сборке, это другой продукт.

Как обновиться

Меняется одна строка, и когда, решаете вы 
$ glyph upgrade --dry-run
glyph upgrade: would move /app/package.json from 0.1.72 to 0.1.73 (nothing written).

$ glyph upgrade
glyph upgrade: /app/package.json now pins 0.1.73 (was 0.1.72).
glyph upgrade: what changed: https://glyphlang.io/versions/
glyph upgrade: build before you commit; a new release may report diagnostics
               this project did not have.

Команда переписывает одну строку и запускает npm install. Ваш исходный код она не трогает и не делает вид, что обновление завершено: собрать проект после этого и есть суть, потому что только что взятый выпуск вправе иметь мнения, с которыми ваш код ещё не встречался. --to <version> указывает конкретную версию, в том числе более старую, если хотите вернуться, а --no-install оставляет установку вам.

Обновить инструмент, а не проект

upgrade переносит фиксацию в package.json. Это не та команда, когда отстаёт компилятор в вашем PATH, а doctor какое-то время всё равно её советовал, отправляя глобальную установку к манифесту, которого у неё может не быть. glyph --update это вторая половина. Теперь это правило, а не совпадение: флаги действуют на инструмент, как --version, --help и --explain, а подкоманды действуют на ваш код. --update-dry-run останавливается, напечатав команду npm, которую запустил бы.

glyph --update 
$ glyph --update
glyph 0.1.72 is installed; 0.1.73 is published.
Release notes: https://glyphlang.io/versions/
A 0.1.x release may reject code that compiled before, so read the notes for anything between these two.

Running: npm install -g @glyphlang/glyph@0.1.73
   ... npm output ...

npm finished. Confirm with:
    glyph --version

Он обновляет только установку, которую может распознать. Для компилятора, запущенного через npx, собранного из исходников Glyph или лежащего по пути, который он не узнаёт, команда только печатается, и ничего не перезаписывается, потому что заменить наугад бинарник из Homebrew или чей-то cargo build значит оставить PATH указывать на то, что никто не выбирал. Он также не утверждает, что обновление прошло: npm может завершиться с кодом ноль, пропустив optionalDependency, которую не смог скачать, и именно так однажды вышел выпуск Glyph без бинарника для платформы, поэтому последняя строка называет проверкой glyph --version, а не заявляет об успехе.

Текущее состояние

Уже работает

Проекты из шаблона фиксируют точную версию, поэтому ни один выпуск не попадает в сборку случайно. glyph doctor сравнивает ваш компилятор с реестром и даёт ссылку на заметки к выпуску, никогда не влияя на свой код выхода и не вызываясь из build/run/check. glyph upgrade переносит фиксацию, устанавливает версию и понимает caret из более старого проекта, так что существующие проекты тоже можно перевести на точную фиксацию. glyph --update обновляет сам компилятор при глобальной установке через npm, а при любом другом способе установки сообщает, что делать, а не угадывает.

Что ещё улучшается

Заметки к выпускам это одна страница на всю линейку, поэтому glyph upgrade даёт ссылку на страницу, а не на запись о версии, на которую вы переходите. Пока ничто не говорит, какие из диагностик нового выпуска сработают на вашем коде: чтобы узнать, нужно собрать проект, поэтому команда так и советует. А обновление сразу через несколько выпусков делается тем же одним шагом, что и через один, без сводки о том, что накопилось между ними. glyph --update вызывает npm и читает его код выхода, поэтому может сказать, что npm закончил, но не что бинарник в PATH имеет запрошенную версию; поэтому он отсылает к glyph --version, а не говорит, что всё получилось.
