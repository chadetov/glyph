Glyph и Effect

Оба нацелены на TypeScript, на который могут положиться люди и агенты. Effect это библиотека: вы продолжаете писать на TypeScript и получаете типизированные ошибки, отслеживаемые зависимости и большой набор инструментов. Glyph это язык, который компилируется в TypeScript, поэтому он может отклонять то, что TypeScript разрешает, включая приведения типов, отменяющие гарантии библиотеки. Effect гораздо зрелее.

Как Effect описывает себя

Главная страница Effect начинается со слов «Reliable TypeScript for the AI era» и говорит, что его «declarative patterns and strong type system make it easier for LLMs to generate correct, production-ready code» (effect.website). Документация называет его «an ecosystem of tools that help you build better applications and libraries», построенной вокруг типа Effect<Success, Error, Requirements>, который фиксирует, что вычисление возвращает, как оно может завершиться ошибкой и что ему нужно (Why Effect). Он требует TypeScript 5.4 или новее с включённым strict (Installation). Эти цитаты прочитаны 2026-11-19.

Разница, которая следует из выбора между библиотекой и языком

Типы Effect проверяет tsc, поэтому всё, что разрешает tsc, рядом с ними по-прежнему разрешено. Этот код компилируется под tsc --strict с effect 4.1.4 и TypeScript 6. Приведение убирает NotFound из канала ошибок, и программа сообщает об ошибке от эффекта, типизированного как неспособный завершиться ошибкой.

eff.ts: tsc --strict завершается с кодом 0; запуск печатает "Failure undefined" 
import { Effect } from "effect"

class NotFound {
  readonly _tag = "NotFound"
}

const find = (id: string): Effect.Effect<number, NotFound> =>
  id === "1" ? Effect.succeed(1) : Effect.fail(new NotFound())

// The error channel says NotFound can happen. A cast erases it.
const quiet = find("2") as unknown as Effect.Effect<number, never>

// And a parsed body still takes any type you name.
type User = { email: string }
const user = JSON.parse("{}") as User

console.log(Effect.runSyncExit(quiet)._tag, user.email)

Та же функция на Glyph возвращает Result, а приведения, которое можно было бы написать, нет. Второй модуль отклоняется до того, как сгенерирован какой-либо TypeScript.

find.glyph: собирается, проходит tsc --strict 
module find

pub type NotFound = { id: string }

pub fn find(id: string) -> Result<number, NotFound> {
  return match id == "1" {
    true => Ok(1),
    false => Err({ id: id }),
  }
}
добавление приведения: отклонено 
module find

pub type NotFound = { id: string }

pub fn find(id: string) -> Result<number, NotFound> {
  return match id == "1" {
    true => Ok(1),
    false => Err({ id: id }),
  }
}

pub fn quiet() -> number {
  let n = find("2") as number
  return n
}

Подсказка к E0013 гласит: «Glyph has no as cast ... to turn an unknown into a type, validate it with T.parse(v) or narrow it with match and is.» В кодовой базе на Effect команда может приблизиться к этому правилами линтера, а это сравнение объясняет, почему правило, которое кто-то может выключить, это другая гарантия.

Что Glyph делает, а библиотека не может

Язык решает, что можно написать. В Glyph нет any, нет приведений типов, нет утверждения non-null и нет комментария, который глушит ошибку, а каждый match по union обязан покрыть все варианты. Записи и union несут проверку во время выполнения, сгенерированную из объявления, поэтому json.parse<User>(body) валидирует данные. Schema из Effect тоже выводит тип из одного описания (Schema.Schema.Type<typeof Person> в его введении), так что и там тип и валидатор не расходятся; разница в том, что ничто в TypeScript не заставляет кодовую базу им пользоваться. Компилятор также отвечает агенту на вопросы о программе, например что сломает изменение, через MCP или в командной строке.

На этой странице не проверялось использование Effect изнутри модуля Glyph, поэтому о сочетании этих двух ничего не утверждается.
