Принцип 04 · Шлифовка

Абстракция

Говорите, что имеете в виду, с помощью маленького ортогонального ядра: сопоставление с образцом вместо лестниц switch, Result вместо брошенных исключений, именованные записи вместо кортежей. Один хороший способ на каждое понятие, а не наслоения TypeScript.

Слишком много способов сказать одно и то же

TypeScript рос наслоениями и сохранил каждый слой. Фиксированный набор вариантов можно описать как enum, как union строковых литералов или как const-объект. Форму можно описать через interface, type или class. Есть namespace и модули, декораторы и функции высшего порядка, по пять идиом почти на всё, и у каждой свои пограничные случаи.

Для человека это гибкость. Для агента это минное поле: чем больше способов выразить вещь, тем больше шансов выбрать тот, где спрятана ловушка, и тем больше идиом нужно держать в голове. Принцип абстракции в Glyph это намеренное вычитание: один острый инструмент на каждую задачу, выбранный так, чтобы очевидный способ был и безопасным.

01 match единственная условная конструкция

Оператора if/else нет. Ветвление везде делается через match, а match это выражение: оно возвращает значение. Одна конструкция покрывает булеву проверку, диспетчеризацию по union и таблицу значений, так что не нужно решать, какую форму ветвления выбрать.

TypeScript: оператор, а не значение grade.ts 
let label: string;
if (score > 90) label = "A";
else if (score > 80) label = "B";
else label = "C";
Glyph: одно выражение grade.glyph 
let label = match score > 90 {
  true => "A",
  false => match score > 80 {
    true => "B",
    else => "C",
  },
}

02 Размеченные объединения и сопоставление с образцом

«Одна из этих форм» моделируется размеченным объединением, а разбирается через match, который деструктурирует данные на том же шаге, где выбирает вариант. Не нужно вручную поддерживать поле-дискриминант, строить лестницу switch по строковому тегу или приводить тип в каждой ветке, чтобы восстановить форму.

feed.glyph 
type Feed =
  | Loading
  | Loaded(Array<Post>)
  | Failed(string)

fn view(feed: Feed) -> string {
  return match feed {
    Loading => "...",
    Loaded(posts) => render(posts),   // posts is Array<Post> here
    Failed(msg) => msg,               // msg is string here
  }
}

03 Result вместо исключений

Ошибка это значение, а не скрытый переход в потоке управления. Функция, которая может завершиться ошибкой, говорит об этом в возвращаемом типе (Result<T, E>), а ошибки комбинируются оператором ?, вместо того чтобы оборачивать места вызова в try/catch и надеяться, что нужное место бросит исключение нужного класса. Путь ошибки виден так же хорошо, как и успешный.

04 Именованные записи вместо позиционных кортежей

Данные всегда описываются именованными полями. Нет сокращённой записи объектных литералов и нет анонимных кортежей, где нужно помнить, что такое [0] и [1]. Форма читается одинаково в определении, при создании и при использовании.

TypeScript: что такое [0] и [1]? point.ts 
function origin(): [number, number] {
  return [0, 0];
}
const p = origin();
p[0]; p[1];  // x? y? row? col?
Glyph: имена путешествуют вместе со значением point.glyph 
type Point = { x: number, y: number }

fn origin() -> Point {
  return { x: 0, y: 0 }
}

05 Один примитив на задачу

Когда понятию нужен собственный инструмент, Glyph даёт ровно один. Общее изменяемое состояние живёт в std/store. Дескриптор файла или сокета, который нужно закрыть ровно один раз, это ресурс owned. Итерация это for x in xs. Каждый из них это единственный именованный примитив, созданный для своей цели, а не шаблон, который вы заново собираете из набора общих деталей и незаметно делаете неправильно.

Абстракция здесь означает меньше инструментов, но острее, а не больше. У каждого понятия есть очевидная форма, и именно ею и нужно пользоваться.
