Начните здесь · ~10 минут

Ваша первая программа на Glyph

Создайте проект, запустите его, а затем намеренно сломайте и прочитайте ошибку, которую выдаст компилятор. Знать Glyph заранее не нужно. Если вы хоть немного писали на TypeScript, вы поймёте каждую строку.

1 · Создайте проект

Glyph распространяется через npm как готовый бинарный файл для macOS и Linux (x64 и ARM) и Windows (x64) и требует Node 18 или новее. Этот способ ничего не устанавливает глобально: npx скачивает компилятор, чтобы создать проект, а проект фиксирует собственную копию вместе с tsx и typescript, которые Glyph использует для запуска и проверки типов.

терминал 
npx -y @glyphlang/glyph init hello
cd hello
npm install

Если вы хотите, чтобы glyph был в PATH, установите его глобально вместе с двумя инструментами, через которые он работает, и уберите npx из команд на этой странице:

терминал, глобальная установка 
npm install -g @glyphlang/glyph tsx typescript
glyph doctor                    # confirms your toolchain is ready
glyph init hello
cd hello

2 · Посмотрите, что получилось

glyph init создаёт готовую к запуску заготовку: src/main.glyph; src/.types/README.md, где объясняется, что типизированному пакету из npm там ничего не нужно, а каталог предназначен для пакетов без типов; package.json; .gitignore; и два файла, которые агенты читают сами: AGENTS.md, который отсылает к glyph llms за полным справочником по языку, и .mcp.json, который регистрирует glyph mcp, чтобы агент мог спрашивать у компилятора типы и ссылки, а не искать их. В уже существующем проекте эти два файла пишет glyph agents. package.json фиксирует компилятор, typescript и tsx в devDependencies, поэтому любой, кто клонирует проект, соберёт его через npm install без глобальной установки.

Откройте src/main.glyph. Это hello world:

src/main.glyph 
module main

import std/io

fn main(argv: Array<string>) -> number {
  io.println("hello from glyph")
  return 0
}

Обратите внимание на две вещи: программа запускает свою функцию main(argv), а main возвращает number, код завершения процесса. Возврат задаёт этот код, но не останавливает процесс принудительно, поэтому программа, которая запускает сервер, продолжает его обслуживать.

3 · Запустите

терминал 
npx glyph run
hello from glyph

glyph run проверил типы, скомпилировал код в TypeScript и выполнил его. Этот цикл вы будете повторять до конца страницы.

4 · Добавьте что-нибудь настоящее

Теперь замените тело решением, которое имеет значение: отправлять ли заказ в зависимости от состояния оплаты. Здесь появляются две вещи, которыми вы будете пользоваться постоянно: размеченное объединение (type Payment = ...) и match, единственная условная конструкция в Glyph.

src/main.glyph 
module main

type Payment = Pending | Paid | Failed

fn ship(p: Payment) -> string {
  return match p {
    Pending => "hold: waiting for the money",
    Paid => "ship it",
    Failed => "hold: payment failed",
  }
}

fn main(argv: Array<string>) -> number {
  print(ship(Paid))
  return 0
}
терминал 
npx glyph run
ship it

5 · Сломайте намеренно

Эта часть показывает, зачем нужен Glyph. В задаче написано «поддержать возвраты», поэтому добавьте в Payment вариант Refunded и не трогайте ship. Так поступает агент, когда меняет тип в одном файле и не открывает код, который по этому типу принимает решение. Запустите снова.

src/main.glyph (добавлено одно слово) 
type Payment = Pending | Paid | Failed | Refunded
$ npx glyph run 
[E0200] Error: typecheck: non-exhaustive match on `Payment`: missing variants `Refunded`
    ╭─[ main:6:10 ]
    │
  6 │ ╭─▶   return match p {
    ┆ ┆
 10 │ ├─▶   }
    │ ╰───────── non-exhaustive match on `Payment`: missing variants `Refunded`
    │
    │     Help: Add an arm for each missing variant.
────╯

Не запустилось. TypeScript, на котором написана большая часть кода, ведёт себя наоборот: switch, который обрабатывает два случая "hold" и заканчивается на default: return "ship it", проходит tsc --strict и после добавления нового варианта, а затем отправляет каждый возвращённый заказ. Здесь каждый match, в котором пропущен вариант, это ошибка компиляции со стабильным кодом (E0200), точным местом и названием варианта. Запускайте glyph --explain E0200, когда нужна подробная версия.

6 · Исправьте

Что возврат означает для отправки, компилятор решить не может, это решаете вы. Добавьте ветку, и программа снова запустится.

src/main.glyph 
fn ship(p: Payment) -> string {
  return match p {
    Pending => "hold: waiting for the money",
    Paid => "ship it",
    Failed => "hold: payment failed",
    Refunded => "hold: refunded, nothing to ship",
  }
}
терминал (с print(ship(Refunded))) 
npx glyph run
hold: refunded, nothing to ship

Это и есть основной цикл: пишете, запускаете, а если что-то не так, компилятор точно говорит, что и как исправить, до того как код попадёт в продакшен, а не после.
