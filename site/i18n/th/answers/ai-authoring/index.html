07 · หลักคิด

AI เขียนภาษาที่แทบไม่เคยเห็นได้อย่างน่าเชื่อถือหรือ?

ส่วนใหญ่ได้ Glyph อ่านแล้วเหมือน TypeScript: type พื้นฐานและ generic แบบเดียวกัน (string, number, Array<T>) expression ส่วนใหญ่แบบเดียวกัน และ import แพ็กเกจ npm ด้วยชื่อ แต่มันไม่ใช่ subset ของ TypeScript: match, Result และ fn name(x: T) -> R เป็น syntax ที่ TypeScript ไม่มี และ if, ternary และ cast ก็ไม่ใช่ Glyph สิ่งที่โมเดลรู้อยู่แล้วส่วนใหญ่ใช้ต่อได้ และคอมไพเลอร์บอกจุดที่ใช้ไม่ได้

ทำไมเรื่องนี้สำคัญ

นี่คือคำถามที่ยุติธรรมของคนขี้สงสัย: LLM ทำนาย token ถัดไปจากโค้ดจำนวนมหาศาลของภาษาที่มีอยู่ ภาษาที่แทบไม่มีข้อมูลฝึกก็น่าจะเขียนยาก

คำตอบอยู่ที่โครงสร้าง: Glyph ไม่ได้แปลกประหลาด มันหน้าตาเหมือน TypeScript โมเดลจึงรู้เกือบทั้งหมดอยู่แล้ว ความต่างมีไม่กี่ข้อ นับได้ และแต่ละข้อจะ fail ทันทีตอนคอมไพล์ ไม่ใช่ผ่านไปแบบเงียบๆ

แก้ได้ในการแก้ครั้งเดียว

error ระบุ construct ของ Glyph และแสดงรูปแบบ การแก้จึงห่างไปแค่การแก้ครั้งเดียว ไม่ต้องขุดซอร์ส ไม่ต้องเดา loop ที่กระชับนี้คือสิ่งที่ชดเชยข้อมูลฝึกที่ขาดไป

เอกสารเดียวคือ llms.txt ให้เอเจนต์ได้รูปแบบของโปรแกรม standard library และทุก diagnostic พร้อมวิธีแก้ และ glyph llms พิมพ์เอกสารอ้างอิงเดียวกันแบบออฟไลน์

สถานะตอนนี้

ใช้ได้วันนี้

  • syntax ที่หน้าตาแบบ TypeScript
  • error ที่มีรหัสคงที่ซึ่งบอกวิธีแก้
  • llms.txt / glyph llms เป็นเอกสารอ้างอิงเดียวสำหรับเอเจนต์ทุกตัว

กำลังพิสูจน์

  • benchmark อัตราความสำเร็จ (จำนวนครั้งที่ต้องแก้เทียบกับ TypeScript บนงานเดียวกัน) เพื่อเปลี่ยน “มันใช้ได้” ให้เป็นตัวเลขที่วัดได้
