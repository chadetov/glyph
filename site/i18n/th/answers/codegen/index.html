12 · จากสเปกของคุณ

generate client และ server ที่มี type จากสเปก API ได้ไหม?

ได้ ชี้ glyph gen openapi ไปที่สเปก OpenAPI: --client emit HTTP client ที่มี type หนึ่งฟังก์ชันต่อหนึ่ง operation ส่วน --handlers emit server stub และ dispatcher route ที่ใช้งานได้ ถ้าแหล่งความจริงของคุณคือ schema ของ zod glyph gen zod ก็ทำแบบเดียวกัน ทุกอย่างออกมาเป็นGlyph ที่ commit ได้และ grep หาได้ ซึ่งคุณเป็นเจ้าของและแก้ได้ ไม่ใช่ขั้นตอน codegen ที่ซ่อนอยู่

ในหน้านี้

  1. ทำไมต้อง generate
  2. router ฝั่ง server
  3. จาก schema ของ zod
  4. สิ่งที่มัน map
  5. การรักษาให้ตรงกัน
  6. สถานะตอนนี้

ทำไมเรื่องนี้สำคัญ

API client ที่เขียนเองและ DTO ของมันเพี้ยนไปจากสเปก และความเพี้ยนนั้นเป็นบั๊กประเภทที่ไม่มีใครชอบ

เพราะ Glyph generate โค้ดจริง (ฟังก์ชันที่มี type, declaration type จริงพร้อม runtime descriptor) สเปกจึงยังเป็นแหล่งความจริง และการ generate ใหม่คือ diff ที่ให้ผลเท่าเดิมเมื่อรันซ้ำและรีวิวได้ ไม่ใช่กล่องดำ

router ของ --handlers

router ของ --handlers match path ด้วย array pattern /tasks/{id} จึงกลายเป็น ["tasks", id] และ bind parameter ให้คุณ

  1. /tasks/{id}
  2. ["tasks", id]
  3. getTask(req, id)

stub แต่ละตัวเริ่มเป็น 501 พร้อม comment ที่แสดงการ parse body คุณเติมให้ครบแล้วผูกด้วย await serve(PORT, route)

generate จาก schema ของ zod แทน

ถ้าทีมของคุณนิยามรูปร่างด้วย zod อยู่แล้ว ก็ generate จากตรงนั้นได้เลย schema จะกลายเป็น type ของ Glyph เต็มตัวพร้อม descriptor ของตัวเอง:

schemas.ts 
export const Task = z.object({
  id: z.number(),
  title: z.string(),
  done: z.boolean(),
})
$ glyph gen zod schemas.ts --out src/ 
type Task = {
  id: number,
  title: string,
  done: bool,
}
// + a runtime descriptor, so
// Task.parse(value) validates.

สิ่งที่มัน map

discriminated union แบบ polymorphic (discriminator ของ OpenAPI) ออกมาเป็น tagged union ของ Glyph จริงๆ บวกกับ parse_<Name> ที่ generate ขึ้นมาเพื่ออ่าน property ที่เป็น discriminator และ validate เข้า variant ที่ถูกต้อง

รายละเอียด ทำไมต้อง generate dispatcher

เพราะ Glyph ใช้ชื่อ constructor เป็น tag ไม่ใช่ property ใดก็ได้ dispatcher ที่ generate จึงเชื่อม object จาก wire เข้ากับ union ให้คุณ

จุดที่ยังไม่พอ

การ generate ซื่อตรงต่อข้อมูลบน wire จึง map ส่วนที่พบบ่อย 80%: object, primitive, array, reference, field ที่ไม่บังคับและ nullable (แยกกัน: field ที่ nullable กลายเป็น Nullable<T> และ field ที่ schema ไม่ได้บังคับได้ ? ซึ่งไม่รับ null) และ discriminated union สิ่งที่มันแทนได้ไม่ตรงทั้งหมด (string enum, union ที่ไม่มี discriminator) จะถูกทำให้แคบลงพร้อมพิมพ์หมายเหตุ แทนที่จะสร้าง validator ที่ปฏิเสธข้อมูลจริง enum ที่ละเอียดกว่านี้คือสิ่งถัดไป

รายละเอียด generator ต้องติดตั้งอะไรบ้าง

และเครื่องมือมี dependency จริง: gen dts/gen zod ต้องใช้ Node และ typescript/zod gen dts ใช้ได้กับ TypeScript ทุกรุ่น (5, 6 หรือ native port 7.x) โดย resolve จากโปรเจกต์ของคุณก่อน และจะบอกชัดเจนว่าต้องติดตั้งอะไรถ้าขาด

รักษาให้ตรงกัน

ทุกไฟล์ที่ generate บันทึกคำสั่งที่สร้างมันไว้ใน header เมื่อสเปกเปลี่ยน คุณไม่ต้องไล่หาว่าต้องรันคำสั่งไหนซ้ำ: glyph regen สแกนหา header เหล่านั้นและรันแต่ละคำสั่งซ้ำ เขียน output ทับ

มันให้ผลเท่าเดิมเมื่อรันซ้ำ regen ที่สเปกไม่เปลี่ยนจึงไม่แตะอะไรเลย และใส่ใน pre-commit hook หรือ CI check ที่ fail เมื่อโค้ดที่ commit ไว้เพี้ยนจากสเปกได้ง่าย

สถานะตอนนี้

ใช้ได้วันนี้

  • glyph gen openapi (type, --client, --handlers พร้อม router จริง), glyph gen dts, glyph gen zod และ glyph regen สำหรับรีเฟรชทั้งหมดจากต้นทาง: ทุกคำสั่ง emit Glyph ที่ commit ได้ มี descriptor และ generate ใหม่ได้ผลเท่าเดิม
  • type สองตัวที่จะถูกเขียนใต้ชื่อ Glyph เดียวกันจะหยุด generator แทนที่จะสร้างไฟล์ที่คอมไพล์ไม่ได้: มันระบุทุกต้นทางที่ชนกัน ไม่เขียนอะไรเลย และ --rename Source=GlyphName แก้ได้
  • ตัวเลือกนั้นถูกบันทึกไว้ใน header ที่ generate glyph regen จึงเล่นซ้ำได้

กำลังมา

  • การ map enum ที่ละเอียดขึ้นและการครอบคลุม OpenAPI ที่กว้างขึ้น แต่ละอย่างมาภายใต้กฎเดียวกันคือซื่อตรงต่อ wire และมีหมายเหตุเมื่อทำให้แคบลง
  • การ generate จาก .d.ts ของแพ็กเกจอ่าน declaration interface และ type ของมัน ไลบรารีที่ API เป็น class หรือที่ field ใช้ type ที่คำนวณอย่าง Omit จึงเหลือ reference ที่ generator ระบุไว้ในหมายเหตุ และ glyph build รายงานว่า resolve ไม่ได้
  • การ import class แบบนั้นแล้วสร้างด้วย new ไม่ต้อง generate และถูกตรวจโดย tsc เส้นทางนั้นจึงไม่ได้รับผลกระทบ
