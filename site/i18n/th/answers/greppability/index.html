03 · นำทางด้วยการค้นหา

เอเจนต์ (หรือฉัน) หาได้ไหมว่าอะไรถูกนิยามไว้ที่ไหน?

ทุก construct มีรูปแบบเดียวเท่านั้นให้ค้นหา grep ธรรมดา (ซึ่งเป็นวิธีที่เอเจนต์ใช้นำทางจริงๆ) เจอนิยามเดียว ไม่ใช่ห้าสิบจุดที่เกือบใช่

ทำไมเรื่องนี้สำคัญ

เอเจนต์ไม่ได้จำทั้ง repo ไว้ในหัว มันค้นหา รูปแบบเดียวต่อแนวคิดหมายความว่าการค้นหาครบถ้วน เอเจนต์จึงแก้สิ่งที่มีอยู่แทนที่จะทำซ้ำ

ถ้าแนวคิดหนึ่งเขียนได้ห้าแบบ การค้นหาก็จะพลาดบางกรณี และเอเจนต์ที่มั่นใจแต่หานิยามที่มีอยู่ไม่เจอก็จะสร้างตัวที่สองขึ้นมา

รายละเอียด ทำไมคำถามเดียวกันจึงไม่มีคำตอบใน TypeScript

ใน TypeScript การแก้ค่าซ่อนอยู่หลัง =, .push(), Object.assign, setter หรือ spread ได้ ไม่มี token เดียวให้ grep คำถาม “มีอะไรเปลี่ยนค่านี้ไหม?” จึงไม่มีคำตอบที่เชื่อถือได้

คอมไพเลอร์ทำให้การค้นหาครบถ้วนเสมอ

เมธอดที่เปลี่ยนอาร์เรย์ของตัวเอง (push, pop, sort, splice และอีกห้าตัว) เขียนได้เฉพาะเป็นการเรียกทั้งหมดของคำสั่ง mut เท่านั้น ที่อื่นทั้งหมดเป็น E0240 รวมถึงในนิพจน์ ซึ่งฟังก์ชันช่วยอาจเรียงอาร์เรย์ของผู้เรียกไปพร้อมกับอ่านสมาชิกตัวเดียว:

glyph check 
[E0240] `xs.sort(cmp)` changes `xs` in place, and its value is used here
 4 │   return xs.sort(cmp)[0]
   │ Help: `array.sort(xs, cmp)` returns a sorted copy and leaves `xs` alone

xs.push(4) ที่อยู่บรรทัดเดียวโดด ๆ ก็ได้รหัสเดียวกัน และ glyph fix จะเติม mut ให้ ส่วนทิศทางกลับกันคือ E0241: mut xs.concat(ys) ไม่เปลี่ยนอะไรและทิ้งอาร์เรย์ใหม่ไป การตรวจสอบจึงไม่มีวันแสดงบรรทัดที่ไม่ได้เขียนอะไรเลย

ทั้งหมวดในการค้นหาครั้งเดียว

กฎรูปแบบเดียวกันนี้ทำให้ตรวจสอบได้ทั้งหมวด:

ค้นหาหนึ่งครั้ง = คำตอบที่ครบหนึ่งชุด 
# every UI component
grep -rn "^component " src/

# every function
grep -rn "^fn " src/

# the entire resource-ownership surface
grep -rn "owned" src/

ไม่มี object-literal shorthand ไม่มีวิธีที่สองในการประกาศ component ไม่มี syntax แบบ overload ที่ต้องแยกความหมาย การมีวิธีเขียนน้อยลงเป็นข้อจำกัดจริง และนั่นคือประเด็น: มันคือสิ่งที่ทำให้การค้นหาของเอเจนต์และของคุณเชื่อถือได้

construct ที่ Glyph ตัดออกไปเพื่อให้การค้นหาเชื่อถือได้ และเหตุผลที่กฎ lint ไม่ใช่การรับประกันแบบเดียวกัน อยู่ในหน้าเสาหลักเรื่องค้นหาได้ด้วย grep

สถานะตอนนี้

ใช้ได้วันนี้

  • รูปแบบมาตรฐานเดียวต่อ construct
  • การแก้ค่าจำกัดไว้สองรูปแบบที่ grep หาเจอ (mut) และการเขียนลงอาร์เรย์โดยไม่มีคำนำหน้านี้ถูกปฏิเสธ (E0240)
  • ตรวจสอบได้ด้วย keyword เดียว (fn, component, owned, type)

วางซ้อนอยู่ด้านบน

  • การเขียนผ่าน Set, Store และ Deque ของไลบรารีมาตรฐานยังไม่ถูกตรวจเรื่อง mut
    รายละเอียด

    ตัวตรวจของ Glyph ยังไม่รู้ชนิดของตัวรับเหล่านี้ seen.add(x) และ mut seen.add(x) จึงผ่านทั้งคู่ และในคอร์ปัสก็มีทั้งสองแบบ การให้ชนิดและทำเครื่องหมายเมธอดที่เขียนค่าคือขั้นต่อไปที่วางแผนไว้ ค่าจากแพ็กเกจ npm ไม่ถูกตัดสินทั้งสองทาง: ใส่ mut หน้าการเรียกของมันได้ แต่ไม่บังคับ
