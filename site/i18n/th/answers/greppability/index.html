03 · นำทางด้วยการค้นหา

เอเจนต์ (หรือฉัน) หาได้ไหมว่าอะไรถูกนิยามไว้ที่ไหน?

ทุก construct มีรูปแบบเดียวเท่านั้นให้ค้นหา grep ธรรมดา (ซึ่งเป็นวิธีที่เอเจนต์ใช้นำทางจริงๆ) เจอนิยามเดียว ไม่ใช่ห้าสิบจุดที่เกือบใช่

ทำไมเรื่องนี้สำคัญ

เอเจนต์ไม่ได้จำทั้ง repo ไว้ในหัว มันค้นหา ถ้าแนวคิดหนึ่งเขียนได้ห้าแบบ การค้นหาก็จะพลาดบางกรณี และเอเจนต์ที่มั่นใจแต่หานิยามที่มีอยู่ไม่เจอก็จะสร้างตัวที่สองขึ้นมา รูปแบบเดียวต่อแนวคิดหมายความว่าการค้นหาครบถ้วน เอเจนต์จึงแก้สิ่งที่มีอยู่แทนที่จะทำซ้ำ

ดูของจริง

Glyph จำกัดการแก้ค่าไว้สองรูปแบบ (mut x = … และ mut x.method(…)) ทุกจุดที่ state เปลี่ยนจึงหาเจอได้ด้วยการค้นหาครั้งเดียว:

grep -rn "mut " src/ (ทุกการแก้ค่าใน codebase) 
src/cart.glyph:14:   mut items.push(item)
src/cart.glyph:22:   mut total = total + price
src/user.glyph:8:    mut session.token = fresh

สามการแก้ค่า ครบทุกตัว ในการค้นหาครั้งเดียว ใน TypeScript การแก้ค่าซ่อนอยู่หลัง =, .push(), Object.assign, setter หรือ spread ได้ ไม่มี token เดียวให้ grep คำถาม “มีอะไรเปลี่ยนค่านี้ไหม?” จึงไม่มีคำตอบที่เชื่อถือได้ กฎรูปแบบเดียวกันนี้ทำให้ตรวจสอบได้ทั้งหมวด:

ค้นหาหนึ่งครั้ง = คำตอบที่ครบหนึ่งชุด 
# every UI component
grep -rn "^component " src/

# every function
grep -rn "^fn " src/

# the entire resource-ownership surface
grep -rn "owned" src/

ไม่มี object-literal shorthand ไม่มีวิธีที่สองในการประกาศ component ไม่มี syntax แบบ overload ที่ต้องแยกความหมาย การมีวิธีเขียนน้อยลงเป็นข้อจำกัดจริง และนั่นคือประเด็น: มันคือสิ่งที่ทำให้การค้นหาของเอเจนต์และของคุณเชื่อถือได้

construct ที่ Glyph ตัดออกไปเพื่อให้การค้นหาเชื่อถือได้ และเหตุผลที่กฎ lint ไม่ใช่การรับประกันแบบเดียวกัน อยู่ในหน้าเสาหลักเรื่องค้นหาได้ด้วย grep
