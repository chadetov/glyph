19 · โปรแกรมที่พิมพ์โต้ตอบ

เขียนโปรแกรมที่ผู้ใช้พิมพ์โต้ตอบได้ไหม?

ได้ io.read_line คืนค่าทันทีที่บรรทัดเต็มเข้ามา และไม่รอให้ stdin ปิด REPL, game loop หรือ chat client จึงตอบแต่ละบรรทัดก่อนอ่านบรรทัดถัดไป จนถึง 0.1.62 มันเคยรอ และเรื่องนี้ควรพูดออกมาตรงๆ เพราะมันทำให้โปรแกรมแบบโต้ตอบทุกตัวเป็นไปไม่ได้

ทำไมเรื่องนี้สำคัญ

ตัวอ่านบรรทัดที่คืนค่าเฉพาะตอนจบ input คือตัวอ่านไฟล์ที่ใช้ชื่อตัวอ่านบรรทัด

การ pipe ไฟล์ผ่านมันใช้ได้สมบูรณ์ ซึ่งเป็นเหตุผลที่ไม่มีอะไรจับได้: ทุกแอปใน repository ที่อ่าน stdin อ่านจาก pipe แล้ววันหนึ่งมีคนเขียน chat client และมันเงียบไปขณะที่เขาพิมพ์ แล้วพิมพ์คำตอบทั้งหมดออกมาพร้อมกันหลัง Ctrl-D

ที่มา แอปที่ถูกปรับรูปให้เลี่ยงมัน

แอปนั้นถูกปล่อยออกไปเป็นตัวเล่นซ้ำ session จากไฟล์ JSON ที่บันทึกไว้ พร้อม comment ในซอร์สบอกเหตุผล อีกสามแอปถูกปรับรูปให้หลบเรื่องเดียวกันโดยไม่มีใครเรียกชื่อมัน: minesweeper วาดใหม่ระหว่างการเดินไม่ได้ เกมผจญภัยแบบข้อความตอบ look ไม่ได้ และ REPL ไม่ประมวลผลอะไรเลยจนกว่าคุณจะวางสาย

ส่วนที่มักเจอปัญหาจริง

  • CRLF\r ท้ายบรรทัดถูกตัดออก ไฟล์ CRLF กับไฟล์ LF จึงให้บรรทัดเหมือนกัน และคุณไม่ต้องมาดีบักอักขระที่มองไม่เห็นจาก input บน Windows
  • ไม่มีขึ้นบรรทัดใหม่ปิดท้ายinput ที่จบโดยไม่มีขึ้นบรรทัดใหม่ตัวสุดท้ายยังคืนบรรทัดสุดท้ายนั้นหนึ่งครั้งก่อน None แถวสุดท้ายของไฟล์ที่ไม่มีขึ้นบรรทัดใหม่ปิดท้ายจึงไม่หายไปเงียบๆ
  • UTF-8 ที่ถูกแบ่งUTF-8 แบบหลายไบต์ที่ถูกแบ่งข้ามขอบเขตการอ่านจะถูกเก็บไว้และต่อให้ครบ แทนที่จะกลายเป็นอักขระแทนที่

read_line แล้วตามด้วย read_to_string

read_to_string ดึงจาก buffer เดียวกัน ทั้งสองจึงใช้ร่วมกันได้: read_line สำหรับบรรทัด header แล้ว read_to_string สำหรับ body จะได้ส่วนที่เหลือ ไม่ใช่สำเนาที่สอง และไม่ใช่ string ว่าง ถ้าเรียกมันก่อน ก็ยังคืน stdin ทั้งหมด

บรรทัด header แล้วตามด้วย body 
let header = io.read_line()
let body = io.read_to_string()

การนับ 200,000 บรรทัดที่ pipe เข้ามาใช้เวลาประมาณ 20ms การอ่านทีละบรรทัดจึงไม่ได้แลกกับ throughput

สถานะตอนนี้

ใช้ได้วันนี้

  • io.read_line คืนค่าเมื่อบรรทัดเข้ามา ไม่ใช่เมื่อ stream ปิด loop แบบถาม อ่าน ตอบ จึงใช้ได้ทั้งใน terminal และผ่าน pipe
  • CRLF ถูกปรับให้เป็นมาตรฐาน บรรทัดสุดท้ายที่ไม่มีตัวจบถูกส่งหนึ่งครั้ง อักขระหลายไบต์รอดข้ามขอบ chunk และ read_to_string รับส่วนที่เหลือของ buffer เดียวกัน
  • regression test เปิด stdin ค้างไว้และต้องได้ echo กลับมา
    รายละเอียด

    regression test เปิด stdin ค้างไว้และต้องได้ echo กลับมา เพราะเทสต์ที่ pipe ไฟล์เข้าไปก็ผ่านกับ implementation ที่พังได้เหมือนกัน

  • io.print และ io.eprint เขียนโดยไม่ขึ้นบรรทัดใหม่
  • io.is_terminal / io.stdin_is_terminal บอกโปรแกรมว่ากำลังคุยกับคนหรือ pipe
    รายละเอียด

    io.print และ io.eprint เขียนโดยไม่ขึ้นบรรทัดใหม่ prompt > ของ REPL จึงอยู่บนบรรทัดเดียวกับที่พิมพ์คำตอบ และ io.is_terminal / io.stdin_is_terminal บอกโปรแกรมว่ากำลังคุยกับคนหรือ pipe flag อย่าง --stdin ของแอป chat จึงไม่ใช่วิธีเดียวที่จะถามอีกต่อไป

ยังหยาบอยู่

  • โปรแกรมที่ต้องการวาดหน้าจอใหม่ยังไม่มีการควบคุม cursor
    รายละเอียด

    โปรแกรมที่ต้องการวาดหน้าจอใหม่ไม่มีการควบคุมเคอร์เซอร์: std/io ไม่มีฟังก์ชันเกี่ยวกับเคอร์เซอร์หรือหน้าจอ และไม่มี module อื่นใน stdlib เพิ่มให้ terminal UI แบบเต็มจอจึงยังต้องเขียน escape code เอง
