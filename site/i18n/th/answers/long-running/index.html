19 · server และ daemon

เขียน server ได้ไหม หรือ process จะจบไปเลย?

คุณเขียน server ได้ main เตรียมการแล้ว return และ process ยังทำงานต่อตราบที่ยังมี socket และ timer ค้างอยู่ ซึ่งเป็นกฎเดียวกับที่ Node ใช้ จนถึง 0.1.63 ยังไม่ใช่แบบนี้: ตัวรันปิด process ทันทีที่ main return server จึง bind port แล้วตายใน tick เดียวกัน

ทำไมเรื่องนี้สำคัญ

นี่คือความต่างระหว่างภาษาที่รันสคริปต์ได้กับภาษาที่รัน service ได้ server, file watcher, bot ที่ถือ connection กับ gateway, job runner ไม่มีตัวไหนจบภายใน main พวกมันตั้ง handler แล้วส่ง process ต่อให้ event

พฤติกรรมเดิมล้มเหลวในแบบที่แย่ที่สุด คือแบบเงียบๆ glyph run app.glyph --serve 4100 ไม่พิมพ์อะไรเลย แม้แต่บรรทัดใน callback ของ listen แล้ว exit 0 ไม่มีอะไรในซอร์สดูผิด และตรวจ type ผ่าน เอเจนต์ที่เจอแบบนั้นไม่มี error ให้รายงาน และไม่มีเหตุผลให้คิดว่าอะไรล้มเหลว

ดูของจริง

TCP server แบบเต็ม main return ทันที callback รันไปตลอดที่ process ยังอยู่:

server ตั้งแต่ต้นจนจบ 
module main

import std/io
import std/process
import net { createServer }

fn main(argv: Array<string>) -> number {
  let server = createServer(fn(socket) {
    mut socket.write("hello\n")
    mut socket.end()
  })

  mut server.on("error", fn(err) {
    io.eprintln("cannot listen: ${err.message}")
    process.exit(1)
  })

  mut server.listen(4000, fn() {
    io.println("listening on 4000")
  })
  return 0
}

net เป็น builtin ของ Node จึงเป็น import ธรรมดา แต่มันไม่ใช่หนึ่งในหกตัวที่คอมไพเลอร์มี type แบบ ambient มาให้ (fs, http, path, os, crypto, url) ให้ติดตั้ง @types/node แล้ว build จะเลือกใช้มัน หรือวาง declaration ไว้ใน .types/net.d.ts ข้างซอร์ส ซึ่งเป็นสิ่งที่แอป chat ทำเพื่อไม่ต้องมี dependency เลย

สองเรื่องที่ควรรู้ return 0 รันก่อนที่ client แรกจะเชื่อมต่อด้วยซ้ำ: มันคือรหัสที่ process จะใช้ตอนออกในที่สุด ไม่ใช่การบอกว่าจะออกเมื่อไร และอะไรก็ตามที่ล้มเหลวหลัง main return ไปแล้วต้องตั้ง exit code เอง เพราะค่าที่ main return ถูกใช้ไปแล้ว นั่นคือหน้าที่ของ handler error ถ้าไม่มี server ที่ bind port ไม่ได้จะปล่อย event loop ให้ว่างแล้ว exit 0 รายงานว่าสำเร็จ

bot คือรูปแบบเดียวกันที่หันออกไปข้างนอก examples/apps/discord คือ client ของ Discord gateway: เชื่อมต่อผ่าน WebSocket ยืนยันตัว ส่ง heartbeat ตามช่วงที่ server กำหนด ติดตามเลขลำดับเพื่อให้ connection ที่หลุดกลับมาต่อได้แทนที่จะเริ่มใหม่ สังเกตเมื่อ connection เปิดอยู่แต่ตายแล้ว และถอยรอระหว่างการเชื่อมต่อใหม่

สถานะตอนนี้

ใช้ได้วันนี้

การ return จาก main ตั้ง exit code โดยไม่หยุด process server, watcher และ event loop จึงรันได้ โปรแกรมที่แค่คำนวณยังออกทันทีที่ main return ด้วยรหัสเดิม จึงไม่มีอะไรเปลี่ยนสำหรับโปรแกรมสั้นๆ builtin ของ Node อย่าง net เป็น import ธรรมดา และโปรแกรมที่ throw ระหว่างเตรียมการยังจบการทำงาน โดยตอนนี้จบหลังจากที่ diagnostic ไปถึง stderr ที่ pipe ไว้แล้ว แทนที่จะอาจถูกตัดทิ้งตอน exit std/timers ตั้งเวลางาน (after, every, cancel, unref) และ std/websocket เปิด connection ทั้งสองจึงไม่ต้องมี declaration ที่เขียนเอง

กำลังคมขึ้น

listener ที่ bind ไม่ได้หลัง main return ไปแล้วจะ exit 0 ถ้าโปรแกรมไม่ได้บอกเป็นอย่างอื่น: process.set_exit_code(1) บันทึกความล้มเหลวโดยไม่ทิ้งงานที่ยังทำอยู่ และ process.exit(1) หยุดทันที คอมไพเลอร์ยังเตือนไม่ได้ว่าคุณลืม และยังไม่มีวิธีเขียนบอกว่าฟังก์ชันไม่ return main ของ server จึงมี return 0 ที่ไม่มีวันไปถึง
