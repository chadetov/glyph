14 · state ที่ใช้ร่วมกัน

จะแชร์ state ที่เปลี่ยนค่าได้ระหว่างฟังก์ชันอย่างไร?

ด้วย store Glyph ไม่มีตัวแปร global ที่เปลี่ยนค่าได้ binding ระดับ module เป็น const state ที่ใช้ร่วมกันอยู่ใน std/store: const ระดับ module ที่ถือค่าซึ่งคุณอ่านด้วย get() และเปลี่ยนด้วย set()/update() binding ไม่เคยย้าย มีแค่ค่าภายในที่เปลี่ยน ผ่านการเรียก method ทุกการเขียนจึงเป็นข้อความ .set( หรือ .update( ที่ grep หาได้

ดูของจริง

ประกาศ store ครั้งเดียวที่ระดับ module ทุกฟังก์ชันใน module ใช้ร่วมกัน ไม่ต้องส่ง let ผ่าน main ไม่ต้องใช้ closure ที่จับตัวแปร:

tasks.glyph 
import std/store { create }
import std/array

type Task = {
  id: number,
  title: string,
}

const tasks = create<Array<Task>>([])
const next_id = create(0)

fn add(title: string) -> Task {
  next_id.update(fn(n: number) -> number {
    return n + 1
  })
  let task = { id: next_id.get(), title: title }
  tasks.update(fn(cur: Array<Task>) -> Array<Task> {
    return array.push(cur, task)
  })
  return task
}

fn all() -> Array<Task> {
  return tasks.get()
}

ทำไมต้องเป็น store ไม่ใช่ global ที่เปลี่ยนค่าได้

นี่เป็นการตัดสินใจออกแบบโดยเจตนา Glyph จำกัด mut ไว้ที่การ assign ระดับ local และให้ binding ระดับ module เป็น const เพราะ global ที่เขียนได้กระจายอยู่ทั่วคือสิ่งที่ทำให้ state ยากจะเข้าใจและยากจะหาเจอ

  • binding ไม่เคยย้ายstore ไม่ต้องผ่อนกฎข้อไหนเลย: binding const s เปลี่ยนไม่ได้ และค่าภายในเปลี่ยนได้แค่ผ่าน set/update
  • เป็นไลบรารี ไม่ใช่ syntaxstate ที่ใช้ร่วมกันจึงมาในรูปไลบรารี ไม่ใช่ syntax ใหม่ (ไม่มี linear type ไม่มีกฎการแก้ค่าที่อ่อนลง) และการแก้ค่าอยู่ในที่เดียวที่ตรวจสอบแล้ว แทนที่จะกระจายไปทั่วโปรแกรม

มีมุมคมอยู่หนึ่งจุด ซึ่งเหมือนใน TypeScript: collection ว่างอนุมาน type ของ element ไม่ได้ จึงต้องใส่ type argument ให้ชัด: create<Array<Task>>([]) store ที่เป็นค่าเดี่ยว (create(0)) อนุมานได้ปกติ

สถานะตอนนี้

ใช้ได้วันนี้

  • std/store ที่มี create, get, set และ update: ที่อยู่เดียวที่ grep หาได้สำหรับ state ที่ใช้ร่วมกันและเปลี่ยนค่าได้

กำลังมา

  • ความสะดวกที่สร้างบน primitive เดียวกัน (store ที่ derive หรือคำนวณจากตัวอื่น, subscription) วางซ้อนอยู่ด้านบนโดยไม่ต้องเปลี่ยนภาษา
