08 · การอัปเกรด

รุ่นใหม่ของ Glyph จะทำให้ build ของฉันพังไหม?

ไม่ ถ้าคุณไม่ได้ขอ โปรเจกต์ Glyph pin คอมไพเลอร์ไว้ที่เวอร์ชันที่แน่นอน รุ่นที่เผยแพร่เมื่อเช้าจึงไม่มาถึง build ของคุณตอนบ่าย ก่อน 1.0 รุ่นใหม่ได้รับอนุญาตให้เพิ่ม diagnostic ที่ปฏิเสธโค้ดที่เมื่อวานยังคอมไพล์ผ่าน และนั่นมักเป็นจุดประสงค์ของรุ่นนั้น การตัดสินใจรับมันจึงเป็นของคุณ และใช้คำสั่งเดียว

ทำไมเรื่องนี้สำคัญ

เครื่องมือส่วนใหญ่คุณ pin ด้วย caret เพราะรุ่น patch คือการแก้บั๊ก คอมไพเลอร์ก่อน 1.0 ไม่ใช่แบบนั้น งานทั้งหมดของ Glyph คือการปฏิเสธโปรแกรม และการทำได้ดีขึ้นหมายถึง error ใหม่: การตรวจ import ที่เข้มขึ้น ช่องโหว่เรื่องความครบถ้วนที่เคยหลุดไป จำนวน argument ที่ตัวตรวจไม่เคย model ไว้ รุ่นเหล่านั้นคือรุ่นที่ดี และก็เป็นรุ่นที่คุณไม่อยากให้มาถึงผ่าน npm install ที่คุณรันเพื่อเพิ่มไลบรารีจัดการวันที่

glyph init จึงไม่เขียน ^ บนเวอร์ชัน 0.x caret ยังปล่อยให้ patch ลอยอยู่ ซึ่งเป็นกับดัก: ^0.1.9 ยอมรับ 0.1.x ทุกตัวที่ตามมาแบบเงียบๆ

package.json ตามที่สร้างไว้ 
"devDependencies": {
  // exact. no caret, no tilde.
  "@glyphlang/glyph": "0.1.72",
  "typescript": "^6.0.0",
  "tsx": "^4.19.0"
}

commit package-lock.json ไว้ข้างๆ แล้ว clone ใหม่จะ build ด้วย toolchain ที่คุณทดสอบแล้ว ไม่ใช่อะไรก็ตามที่ออกมาหลังจากนั้น

อีกครึ่งหนึ่ง

การ pin มีรูปแบบความล้มเหลวที่ชัดเจนแบบเดียว: คุณค้างอยู่กับคอมไพเลอร์เก่าเป็นปีโดยไม่รู้ตัว ไม่มีอะไรในเครื่องของคุณบอก และเว็บไซต์ที่คุณต้องจำไปเปิดดูก็ไม่ใช่ช่องทาง คอมไพเลอร์จึงบอกคุณเองเมื่อคุณถามอะไรก็ตามเกี่ยวกับการตั้งค่าของคุณ:

glyph doctor 
glyph — 0.1.72
  [update]   0.1.73 is published — `glyph --update` moves this compiler, `glyph upgrade` moves a project's pin
             what changed: https://glyphlang.io/versions/

glyph doctor — JavaScript toolchain
  [ok]       node: v22.1.0
  [ok]       tsx: tsx v4.19.0
  [ok]       tsc: Version 6.0.2
All good. `glyph run` and `glyph build --check` are ready.

การเจอรุ่นที่ใหม่กว่าไม่เคยเปลี่ยน exit code จึงรันใน CI ได้อย่างปลอดภัย รุ่นที่เผยแพร่ไม่ได้หมายถึง toolchain ที่พัง และ pipeline ที่เขียวไม่ควรกลายเป็นแดงเพราะมีคนปล่อยรุ่นใหม่เมื่อสิบนาทีก่อน ถ้าเครื่องออฟไลน์ การตรวจจะบอกแล้วทำต่อ --offline ข้ามมันทั้งหมดและไม่เรียก network เลย

ไม่มีอย่างอื่นติดต่อ registry build, run และ check ไม่เคยทำ คอมไพเลอร์ที่โทรกลับบ้านทุกครั้งที่ build เป็นผลิตภัณฑ์อีกแบบ

รับการอัปเกรด

เปลี่ยนบรรทัดเดียว และคุณเป็นคนตัดสินว่าเมื่อไร 
$ glyph upgrade --dry-run
glyph upgrade: would move /app/package.json from 0.1.72 to 0.1.73 (nothing written).

$ glyph upgrade
glyph upgrade: /app/package.json now pins 0.1.73 (was 0.1.72).
glyph upgrade: what changed: https://glyphlang.io/versions/
glyph upgrade: build before you commit; a new release may report diagnostics
               this project did not have.

มันเขียนบรรทัดเดียวใหม่แล้วรัน npm install ไม่แตะซอร์สของคุณ และไม่ทำทีว่าการอัปเกรดเสร็จแล้ว: การ build หลังจากนั้นคือประเด็น เพราะรุ่นที่คุณเพิ่งรับมาได้รับอนุญาตให้มีความเห็นที่โค้ดของคุณยังไม่เคยเจอ --to <version> ระบุรุ่นที่ต้องการ รวมถึงรุ่นที่เก่ากว่าเมื่อคุณอยากย้อนกลับ และ --no-install ปล่อยการติดตั้งให้คุณทำเอง

ย้ายเครื่องมือ ไม่ใช่โปรเจกต์

upgrade ย้าย pin ใน package.json ซึ่งเป็นคำสั่งที่ผิดเมื่อสิ่งที่ล้าหลังคือคอมไพเลอร์ใน PATH ของคุณ และช่วงหนึ่ง doctor ก็พิมพ์มันออกมาอยู่ดี ชี้การติดตั้งแบบ global ไปที่ manifest ที่อาจไม่มีอยู่ glyph --update คืออีกครึ่ง ตอนนี้การแยกเป็นกฎแล้ว ไม่ใช่เรื่องบังเอิญ: flag ทำงานกับเครื่องมือ แบบเดียวกับ --version, --help และ --explain และคำสั่งย่อยทำงานกับโค้ดของคุณ --update-dry-run หยุดหลังพิมพ์คำสั่ง npm ที่มันจะรัน

glyph --update 
$ glyph --update
glyph 0.1.72 is installed; 0.1.73 is published.
Release notes: https://glyphlang.io/versions/
A 0.1.x release may reject code that compiled before, so read the notes for anything between these two.

Running: npm install -g @glyphlang/glyph@0.1.73
   ... npm output ...

npm finished. Confirm with:
    glyph --version

มันย้ายเฉพาะการติดตั้งที่มันระบุได้ คอมไพเลอร์ที่เรียกผ่าน npx, build จาก source tree ของ Glyph หรืออยู่ใน path ที่มันไม่รู้จัก จะได้คำสั่งพิมพ์ออกมาและไม่มีอะไรถูกเขียนทับ เพราะการแทนที่ binary ของ Homebrew หรือ cargo build ของใครสักคนด้วยการเดา จะทำให้ PATH ชี้ไปที่สิ่งที่ไม่มีใครเลือก มันยังไม่อ้างว่าการอัปเดตสำเร็จ: npm อาจ exit ศูนย์ทั้งที่ข้าม optionalDependency ที่ดึงมาไม่ได้ ซึ่งเป็นวิธีที่ Glyph รุ่นหนึ่งเคยออกไปโดยไม่มี binary ของแพลตฟอร์ม บรรทัดสุดท้ายจึงระบุ glyph --version เป็นการตรวจ แทนที่จะยืนยันว่าสำเร็จ

สถานะตอนนี้

ใช้ได้วันนี้

โปรเจกต์ที่สร้างขึ้น pin แบบตายตัว จึงไม่มีรุ่นไหนมาถึง build โดยบังเอิญ glyph doctor รายงานคอมไพเลอร์ของคุณเทียบกับ registry และลิงก์ไปที่บันทึกประจำรุ่น โดยไม่เคยกระทบ exit code และไม่ถูกเรียกจาก build/run/check glyph upgrade ย้าย pin ติดตั้ง และอ่าน caret จากโปรเจกต์เก่า โปรเจกต์ที่มีอยู่ก่อนจึงย้ายมาใช้ pin แบบตายตัวได้ด้วย glyph --update ย้ายตัวคอมไพเลอร์เองสำหรับการติดตั้ง npm แบบ global และรายงานแทนที่จะเดาสำหรับวิธีอื่นๆ ที่มันอาจถูกติดตั้งมา

กำลังคมขึ้น

บันทึกประจำรุ่นเป็นหน้าเดียวสำหรับทั้งสาย glyph upgrade จึงลิงก์ไปที่หน้านั้น ไม่ใช่รายการของรุ่นที่คุณกำลังย้ายไป ยังไม่มีอะไรบอกคุณว่า diagnostic ไหนของรุ่นใหม่ที่โค้ดของคุณกำลังจะโดน: การรู้หมายถึงต้อง build ซึ่งเป็นเหตุผลที่คำสั่งบอกให้ทำ และการอัปเกรดข้ามหลายรุ่นในครั้งเดียวก็เป็นขั้นตอนเดียวเหมือนรุ่นเดียว โดยไม่มีสรุปว่ามีอะไรสะสมมาในระหว่างนั้น glyph --update เรียก npm และอ่าน exit code ของมัน จึงบอกคุณได้ว่า npm ทำเสร็จ แต่บอกไม่ได้ว่า binary ใน PATH เป็นเวอร์ชันที่คุณขอ นั่นคือเหตุผลที่มันชี้ไปที่ glyph --version แทนที่จะบอกว่าสำเร็จ
