17 · ให้บริการเว็บ

ให้บริการหน้าเว็บได้ไหม หรือได้แค่ JSON API?

หน้าเว็บได้ std/http ตั้ง response header ได้ หน้า text/html, redirect แบบ 302, header สำหรับ cache และ form post ของ HTML จึงเป็น Glyph ธรรมดาทั้งหมด ไม่มี Express ไม่มี shim TypeScript ที่เขียนเอง

ทำไมเรื่องนี้สำคัญ

จนถึง 0.1.46 response คือ { status, body } และ server เลือก content type จากรูปร่างของ body: string เป็น text/plain อย่างอื่นเป็น JSON ซึ่งใช้ได้กับ API แต่ไร้ประโยชน์กับอะไรก็ตามที่เบราว์เซอร์แสดงผล ทางออกคือเขียน server ของคุณเองบน node:http ในไฟล์ .ts ที่เขียนเอง ซึ่งทำให้เส้นทางของ request ทั้งหมดอยู่นอก type checker constructor สองตัวที่ขาดไปทำให้เสียขอบเขตของแอปไปทั้งหมด

ดูของจริง

นี่คือ router ของ examples/apps/shortlink/main.glyph ตัวย่อ URL ที่อยู่ใน repo ฟอร์ม HTML สร้างรหัส POST ตอบกลับด้วย redirect เพื่อให้การ reload ในเบราว์เซอร์ไม่ส่งซ้ำ และการตามรหัสคือ 302 ไปยังปลายทาง:

shortlink.glyph: หน้า HTML, form post และ 302 
fn handle_home(req: Request) -> Response {
  return match req.method {
    "GET" => html(200, home_page(links.get(), query_param(req, "error"))),
    "POST" => {
      let fields = form(req)
      match create_link(form_field(fields, "url"), form_field(fields, "alias")) {
        Ok(link) => redirect(303, "/${link.code}+"),
        Err(message) => redirect(303, "/?error=${url_encode(message)}"),
      }
    },
    else => html(405, page("405", "<h1>405</h1>")),
  }
}

fn route(req: Request) -> Result<Response, string> {
  return match segments(req) {
    [] => Ok(handle_home(req)),
    [one] => match stats_code(percent_decode(one)) {
      Some(code) => Ok(handle_stats(code)),
      None => Ok(handle_code(percent_decode(one))),
    },
    else => Ok(html(404, not_found_page(path(req)))),
  }
}

async fn main(argv: Array<string>) -> number {
  let outcome = await serve(8138, route)
  return match outcome { Ok(_) => 0, Err(_) => 1, }
}

แอปเดียวกันนี้อยู่ใน repo เมื่อรุ่นก่อนด้วยขนาด 615 บรรทัด 121 บรรทัดในนั้นเป็น server node:http ที่เขียนเองในไฟล์ .ts ข้างๆ เพราะ Location และ body แบบ text/html ไม่มีวิธีเขียน ตอนนี้เหลือ 494 บรรทัดและไม่ import อะไรนอก std handler คืนค่า Result<Response, string> 404 จึงเป็น Ok ธรรมดา และ Err สงวนไว้สำหรับสิ่งที่แอปตอบไม่ได้ ซึ่ง server เปลี่ยนเป็น 500 serve ค้างอยู่ระหว่างที่ listen จึงไม่ต้องมีอะไรคอยทำให้ process ยังทำงานเอง และการ bind ที่ล้มเหลวกลับมาเป็นค่า

Response มี headers: Record<string, string> ที่บังคับ บังคับ ไม่ใช่ไม่บังคับ: ทุก constructor ใส่ให้ การอ่าน resp.headers จึงไม่ต้องตรวจว่ามีหรือไม่ และช่องทางนี้ถูกลืมไม่ได้ with_header(resp, "cache-control", "no-store") คืน response ใหม่แทนที่จะแก้ตัวเดิม เพราะ Glyph ไม่มีการแก้ field ของ record type checker รู้ว่า constructor ทั้งสามคืน Response handler ที่ประกาศ return type ว่า Result<Response, string> จึงถูกตรวจใน Glyph ไม่ใช่โดย tsc บน output ที่ generate

สองรายละเอียดที่ถ้าทำเองมักทำผิด อักขระใดก็ตามที่ Node ไม่ยอมเขียนลง header จะถูกตัดออกจากค่าตอนส่งออก location ที่สร้างจาก query parameter จึง inject header ที่สองหรือ response ที่สองไม่ได้ และอีโมจิใน URL ที่ย่อก็ทำให้ server ล่มไม่ได้ และ form(req) ถอด + เป็นช่องว่างพร้อมกับ percent escape ซึ่งเป็นคู่ที่การ parse ฟอร์มเองมักพลาด มันอ่าน body ดิบ req.body จึงไม่ถูกแตะสำหรับ handler ที่ parse เอง

สถานะตอนนี้

ใช้ได้วันนี้

html, redirect, with_header, json, text และ form response header ถูกส่งจริงบน wire โดยอนุมาน content type เฉพาะเมื่อคุณไม่ได้ตั้งเอง request header, query parameter, path segment และ body ดิบฝั่งขาเข้า และ client รายงาน response header ที่ได้รับ

กำลังมา

percent encoding คือช่องว่างที่โค้ดข้างบนแสดงให้เห็น: form ถอด body ของฟอร์มได้ แต่ไม่มี encode_component สำหรับสร้าง URL ตัวย่อ URL จึงเขียนเอง ฝั่ง client ยังขาด: timeout, นโยบาย redirect, head และ URL สุดท้ายที่ redirect ไปถึง ไม่มี server สำหรับไฟล์ static และไม่มี template engine และไม่มีแผนจะทำทั้งสองอย่าง
