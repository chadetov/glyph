ทำไมต้อง TypeScript ไม่ใช่ Go หรือภาษาใหม่?

เพราะ TypeScript คือที่ที่เอเจนต์เขียนโค้ดมากที่สุดอยู่แล้ว และเป็นที่อยู่ของ ecosystem ของคุณ (npm, React, Node) Glyph นำมาใช้ทีละไฟล์ได้ก็เพราะเป้าหมายของมันคือ TS เท่านั้น

ทำไมเรื่องนี้สำคัญ

ภาษาใหม่จะรอดหรือไม่ขึ้นกับว่าคุณไปจากศูนย์ถึงการปล่อยของจริงได้อย่างไร การคอมไพล์เป็น TypeScript หมายความว่าคุณไม่ต้องออกจาก codebase, bundler, test runner หรือวิธี deploy ของคุณเลย Glyph เสียบเข้าไปข้างไฟล์ .ts ที่คุณมีอยู่แล้ว และ import กันได้สะอาดทั้งสองทาง:

โปรเจกต์เดียวกัน: .glyph และ .ts วางคู่กัน 
// cart.glyph: new, written in Glyph
import { formatPrice } from "./format.ts"

// checkout.ts: existing, untouched
import { total } from "./cart.glyph"

คุณใส่ Go ลงใน codebase TypeScript ทีละไฟล์ไม่ได้: runtime ต่างกัน ระบบ module ต่างกัน ecosystem ต่างกัน ข้อเท็จจริงข้อเดียวนี้คือเหตุผลที่เป้าหมายเป็น TS

ข้อที่ยุติธรรมเกี่ยวกับ Go: keyword ที่มีน้อยและคงที่ของมันทำให้เอเจนต์มีทางผิดพลาดน้อยลง เราเห็นด้วย และนั่นคือเหตุผลที่ Glyph ตั้งใจรักษา core ให้เล็ก มีวิธีเดียวในการทำแต่ละอย่าง Go รวมอยู่ในbenchmark ความหนาแน่นของเราเพื่อเปรียบเทียบกันตรงๆ
