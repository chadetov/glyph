Glyph และ Effect

ทั้งคู่มุ่งไปที่ TypeScript ที่คนและเอเจนต์พึ่งพาได้ Effect เป็นไลบรารี: คุณยังเขียน TypeScript ต่อไปและได้ error แบบมี type, dependency ที่ถูกติดตาม และชุดเครื่องมือขนาดใหญ่ Glyph เป็นภาษาที่คอมไพล์เป็น TypeScript จึงปฏิเสธสิ่งที่ TypeScript ยอมได้ รวมถึง cast ที่ทำลายการรับประกันของไลบรารี Effect เติบโตเต็มที่กว่ามาก

Effect อธิบายตัวเองอย่างไร

หน้าแรกของ Effect เปิดด้วย "Reliable TypeScript for the AI era" และบอกว่า "declarative patterns and strong type system make it easier for LLMs to generate correct, production-ready code" (effect.website) เอกสารของมันเรียกตัวเองว่า "an ecosystem of tools that help you build better applications and libraries" ซึ่งสร้างขึ้นรอบ type Effect<Success, Error, Requirements> ที่บันทึกว่าการคำนวณคืนอะไร ล้มเหลวได้อย่างไร และต้องการอะไร (Why Effect) มันต้องใช้ TypeScript 5.4 ขึ้นไปและเปิด strict (Installation) ข้อความที่ยกมานี้อ่านเมื่อวันที่ 2026-11-19

ความต่างที่ตามมาจากการเป็นไลบรารีกับการเป็นภาษา

type ของ Effect ถูกตรวจโดย tsc ทุกอย่างที่ tsc ยอมจึงยังใช้ได้ข้างๆ มัน โค้ดนี้คอมไพล์ผ่าน tsc --strict กับ effect 4.1.4 และ TypeScript 6 cast เอา NotFound ออกจาก error channel และโปรแกรมรายงานความล้มเหลวจาก effect ที่มี type บอกว่าล้มเหลวไม่ได้

eff.ts: tsc --strict exit 0 และเมื่อรันจะพิมพ์ "Failure undefined" 
import { Effect } from "effect"

class NotFound {
  readonly _tag = "NotFound"
}

const find = (id: string): Effect.Effect<number, NotFound> =>
  id === "1" ? Effect.succeed(1) : Effect.fail(new NotFound())

// The error channel says NotFound can happen. A cast erases it.
const quiet = find("2") as unknown as Effect.Effect<number, never>

// And a parsed body still takes any type you name.
type User = { email: string }
const user = JSON.parse("{}") as User

console.log(Effect.runSyncExit(quiet)._tag, user.email)

ฟังก์ชันเดียวกันใน Glyph คืนค่าเป็น Result และไม่มี cast ให้เขียน module ที่สองถูกปฏิเสธก่อนที่จะ emit TypeScript ใดๆ ออกมา

find.glyph: build ผ่าน ผ่าน tsc --strict 
module find

pub type NotFound = { id: string }

pub fn find(id: string) -> Result<number, NotFound> {
  return match id == "1" {
    true => Ok(1),
    false => Err({ id: id }),
  }
}
เพิ่ม cast: ถูกปฏิเสธ 
module find

pub type NotFound = { id: string }

pub fn find(id: string) -> Result<number, NotFound> {
  return match id == "1" {
    true => Ok(1),
    false => Err({ id: id }),
  }
}

pub fn quiet() -> number {
  let n = find("2") as number
  return n
}

ข้อความช่วยเหลือของ E0013 อ่านว่า: "Glyph has no as cast ... to turn an unknown into a type, validate it with T.parse(v) or narrow it with match and is." ทีมหนึ่งทำให้ใกล้เคียงแบบนี้ได้ใน codebase ที่ใช้ Effect ด้วยกฎ lint และการเปรียบเทียบนั้นอธิบายว่าทำไมกฎที่ใครก็ปิดได้จึงเป็นการรับประกันคนละแบบ

สิ่งที่ Glyph ทำได้แต่ไลบรารีทำไม่ได้

ภาษาเป็นตัวกำหนดว่าอะไรเขียนได้ Glyph ไม่มี any ไม่มี cast ไม่มี non-null assertion และไม่มี comment ที่ปิดปาก error และทุก match บน union ต้องครอบคลุมทุก case record และ union มีการตรวจตอนรันที่ generate จาก declaration json.parse<User>(body) จึง validate ได้ Schema ของ Effect ก็ derive type จากคำอธิบายเดียวเช่นกัน (Schema.Schema.Type<typeof Person> ในบทนำของมัน) type กับ validator จึงไม่เพี้ยนออกจากกันเหมือนกัน สิ่งที่ต่างคือไม่มีอะไรใน TypeScript บังคับให้ codebase ใช้มัน คอมไพเลอร์ยังตอบคำถามเกี่ยวกับโปรแกรมให้เอเจนต์ได้ด้วย เช่นการเปลี่ยนแปลงจะทำอะไรพัง ผ่าน MCP หรือ command line

หน้านี้ยังไม่ได้ทดสอบการใช้ Effect จากภายใน module ของ Glyph จึงไม่อ้างอะไรเกี่ยวกับการใช้สองอย่างร่วมกัน
