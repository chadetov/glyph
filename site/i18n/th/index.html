เอเจนต์ AI ของคุณเป็นคนเขียน คอมไพเลอร์เป็นคนตรวจ

Glyph อ่านแล้วเหมือน TypeScript แต่ไม่มีทางหนีทีไล่: ไม่มี any ไม่มีการ cast ไม่มีข้อมูลที่ยังไม่ได้ตรวจ และต้องจัดการทุกกรณี คอมไพล์เป็น TypeScript ที่อ่านง่าย คุณจึงใช้ node, npm และโค้ดที่มีอยู่ได้ตามเดิม

$ npm install -g @glyphlang/glyph

ไปต่อทางไหนดี

เขียน TypeScript อยู่แล้วอะไรเปลี่ยน อะไรเหมือนเดิม และแพ็กเกจ npm ใช้ต่อได้อย่างไร กำลังตัดสินใจแทนทีมรับประกันอะไร ไม่รับประกันอะไร และถ้าจะเลิกใช้ต้องแลกกับอะไร สร้างเอเจนต์และเครื่องมือเซิร์ฟเวอร์ MCP คิวรีที่ตอบได้ และรูปแบบของ diagnostic ขอดูหลักฐานแต่ละข้อกล่าวอ้างถูกตรวจสอบอย่างไร และจะทำซ้ำเองได้อย่างไร ทำไมต้องมีภาษาใหม่เหตุผลเบื้องหลังการออกแบบ และสิ่งที่ตั้งใจตัดออกไป
ขอลองเลยเริ่มได้ใน 10 นาที หรือเปิด playground

กรณีที่ไม่มีอะไรใน TypeScript จับได้

กรณีสามอันดับแรกที่ผ่าน tsc --strict ได้ แม้จะเปิด flag เสริมทุกตัวและใช้ typescript-eslint แบบ strict เรียงตามความถี่ที่เอเจนต์เขียนออกมาและความเสียหายเมื่อหลุดขึ้น production ตัวอย่างแต่ละกรณีแสดงเป็นภาษาอังกฤษตามที่อยู่ใน repository

ตัวอย่าง TypeScript ทุกตัวในรายการผ่าน tsc --strict โดยไม่มี error และแต่ละตัวยังถูกตรวจกับโปรเจกต์ที่ตั้งค่าเข้มที่สุดอีกชั้น คือเปิด compiler flag ทุกตัวที่เข้มกว่า --strict และใช้ typescript-eslint strictTypeChecked ด้วย จาก {{catches:count}} ข้อ มี {{catches:none}} ข้อที่ไม่มีอะไรในการตั้งค่านั้นจับได้เลย compiler flag ที่ปิดอยู่โดยค่าเริ่มต้นจับได้ {{catches:flag}} ข้อ และกฎ lint จับได้ {{catches:lint}} ข้อ ทั้งสองอย่างโปรเจกต์ต้องเปิดเอง และเอเจนต์ก็ปิดกลับได้ ใน Glyph ไม่มีข้อไหนเป็นตัวเลือกในการตั้งค่า

การเปลี่ยนแปลงหนึ่งครั้ง ในแอปพลิเคชันจริง

examples/apps/csvql เป็น query engine สำหรับไฟล์ CSV ที่อยู่ใน repository นี้ โดยมี union Value เป็นแกนกลาง ก่อนจะเพิ่ม case ใหม่เข้าไป ให้ถามคอมไพเลอร์ก่อนว่าจะกระทบจุดไหนบ้าง

glyph_variants { name: "Value" } 
10 match sites across 4 files
 8 will fail compilation
 2 contain a catch-all and will silently absorb it
จากนั้นเพิ่ม case แล้วรัน glyph check 
8 errors, E0200 non-exhaustive match. The same eight.
The two catch-all sites report nothing at all.

ที่คาดการณ์ไว้ถูกครบทั้งแปดจุด อีกสองจุดคือ exec::total และ render::literal_text ยังคอมไพล์ผ่าน และส่ง case ใหม่ไปตามที่ catch-all ของแต่ละจุดกำหนดไว้ เอเจนต์ที่แก้ error ครบแปดจุดแล้วหยุดจะได้ build สีเขียวพร้อมบั๊กที่ยังอยู่อีกสองตัว และคิวรีนี้คือสิ่งที่ชี้ให้เห็นว่าอยู่ตรงไหน
