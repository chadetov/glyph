สำหรับเอเจนต์ · Model Context Protocol

เชื่อมเอเจนต์ของคุณเข้ากับคอมไพเลอร์ของ Glyph

glyph mcp รันเซิร์ฟเวอร์ Model Context Protocol ที่มีสิบเอ็ดเครื่องมือบนโปรเจกต์ของคุณ: สัญลักษณ์คืออะไร ถ้าเปลี่ยนแล้วอะไรพัง ค่าของ type หนึ่งไปอยู่ในที่ที่ประกาศเป็นอีก type ได้ไหม declaration หนึ่งพึ่งพาอะไร module หนึ่ง export อะไร diagnostic ที่ตรวจภายในโปรเจกต์ type ที่ตำแหน่งเคอร์เซอร์ ชื่อหนึ่งถูกนิยามไว้ที่ไหน การอ้างอิงถึงมันทุกจุด ทุกจุดที่ match บน union และการค้นหาสัญลักษณ์ แต่ละตัวเป็นคำสั่งย่อยของ glyph query ด้วย เอเจนต์ที่ไม่มี MCP client จึงถามคำถามเดียวกันและได้ไบต์ชุดเดียวกัน

ทำไมเอเจนต์ถึงต้องการสิ่งนี้

เอเจนต์ที่แก้ codebase ปกติทำงานแบบมองไม่เห็น มันอ่านไฟล์ เดา type และรู้ว่าทำอะไรพังหรือเปล่าก็ต่อเมื่อ build แล้ว Glyph ตอบคำถามเหล่านี้ให้ editor อยู่แล้ว glyph mcp ให้คำตอบเดียวกันกับเอเจนต์ตรงจากคอมไพเลอร์ โดยไม่ต้องขูด output ของ build หรืออ่านทุกไฟล์เพื่อหาว่าใครเรียกอะไร มีสองเครื่องมือที่ตอบคำถามที่ editor ไม่เคยถาม: glyph_symbol คืน variant ของ union พร้อม syntax ที่ใช้สร้างแต่ละตัว ซึ่งเป็นสิ่งที่เอเจนต์ต้องรู้ก่อนเขียน match และ glyph_impact ตอบว่าการแก้จะทำอะไรพังก่อนที่การแก้นั้นจะเกิดขึ้น

ตั้งค่า

MCP client ไหนก็เปิดมันได้ ชี้ client ไปที่ binary glyph พร้อมคำสั่งย่อย mcp แล้วส่ง root ของโปรเจกต์เป็น argument หรือรันจากไดเรกทอรีของโปรเจกต์ มันสื่อสาร MCP ผ่าน stdio จึงไม่มี port และไม่มี daemon

config ของ mcp client (แบบทั่วไป) 
{
  "mcpServers": {
    "glyph": {
      "command": "glyph",
      "args": ["mcp", "/path/to/your/project"]
    }
  }
}

เมื่อเชื่อมต่อครั้งแรก client จะเรียก initialize และ tools/list แล้วเซิร์ฟเวอร์จะรายงานสิบเอ็ดเครื่องมือด้านล่าง ตำแหน่งที่คุณส่งไปใช้ตามแบบของ LSP: line เริ่มจาก 0 และ character เริ่มจาก 0 นับเป็นหน่วย UTF-16 ช่วงของ diagnostic กลับมาแบบเดียวกับที่ glyph check --json พิมพ์ คือ line และ col เริ่มจาก 1 พร้อม offset เป็นไบต์

คำอธิบายของแต่ละเครื่องมือมีข้อตกลงที่คุณต้องใช้ตอนเรียก และคู่มือฉบับเต็มอยู่ใน glyph llms --json ใต้ tools โดยใช้ชื่อเครื่องมือเป็น key และมีคำสั่งย่อย glyph query ของแต่ละตัวอยู่ข้างๆ เดิม reply นั้นเคยมีคู่มือทุกตัว: สิบเอ็ดเครื่องมือ คำอธิบาย 31,446 ไบต์ ใน reply ขนาด 45,509 ไบต์ ตอนนี้เหลือ 8,627 ใน reply ขนาด 20,386 ไบต์ และไม่มีอะไรถูกลบทิ้ง ทุก session จ่ายค่า tools/list ตอนเชื่อมต่อ และจ่ายค่าคู่มือเฉพาะเมื่อขอ เอกสารนั้น generate จากตารางของคอมไพเลอร์เอง และมีเทสต์ที่ทำให้ build fail ถ้าเอกสารอ้างถึงเครื่องมือที่เซิร์ฟเวอร์นี้ไม่ได้ให้บริการ

สิบเอ็ดเครื่องมือ

เครื่องมือที่ glyph mcp เปิดให้ใช้ 
// everything the compiler holds about one symbol: kind, identity,
// visibility, a record's fields, a union's variants with payloads and
// construction syntax, parameters and return, interface members,
// whether a `match` over it must be exhaustive, its `@example`.
// The identity reaches the stdlib: std/result::Result answers with
// Ok(T) and Err(E), and `path` is null beside the reason why
glyph_symbol(entity)                       // or (path, line, character)

// what breaks if you make one named change to one declaration:
// add_variant, remove_variant, rename, change_arity,
// change_signature_type, remove. One verdict per site
glyph_impact(entity, change)

// can a value of `from` go where a `to` is declared? Asked of the
// checker's own comparison. Each side is a `module::name` or a
// Glyph type spelling read in the scope of `path`
glyph_assignable(path, from, to)

// every diagnostic for one file, checked inside its project, in the
// shape `glyph check --json` prints, plus what was not checked
glyph_diagnostics(path)

// the type at a position: an expression, a declaration name, a
// parameter, an annotation, a variant, or a binding
glyph_hover(path, line, character)

// where the name is defined, following imports across modules,
// with the `module::name` so the answer chains into glyph_impact
glyph_definition(path, line, character)

// every edge into a symbol across the project, split by relation
// (CALLS, REFERENCES, GENERATED_FROM), each with its provenance
glyph_references(path, name)               // or by position

// every `match` site over one tagged union and which variants each
// site's arms name, with the union's own variants
glyph_variants(path, name)

// search top-level declarations and union variants by name, each
// entry with its identity, `pub`, kind and one-line signature
glyph_symbols(query)

// what one declaration depends on: every declaration its own source
// names, split by relation (CALLS, REFERENCES, FIELD_ACCESS), each
// edge with both ends and its provenance. The mirror of references
glyph_dependencies(entity)

// what one module makes visible to an importer: every `pub`
// declaration and every variant a `pub` union hoists, each with
// its identity, kind and signature
glyph_exports(module)

ดูของจริง

tools/call ไปที่ glyph_diagnostics กับไฟล์ที่มีชื่อ field พิมพ์ผิด จะคืน diagnostic ของคอมไพเลอร์เอง ซึ่งเป็น type ของ Rust ตัวเดียวกับที่ glyph check --json serialize อยู่ภายใน envelope ที่บอกด้วยว่าการตรวจไม่ได้ครอบคลุมอะไร

request 
{
  "method": "tools/call",
  "params": {
    "name": "glyph_diagnostics",
    "arguments": { "path": "src/user.glyph" }
  }
}
ผลลัพธ์ (เนื้อหา JSON ของเครื่องมือ) 
{
  "path": "src/user.glyph",
  "module": "user",
  "project_root": "src",
  "member": true,
  "diagnostics": [
    {
      "code": "E0210",
      "severity": "error",
      "stage": "typecheck",
      "message": "type `U` has no field `naem`; did you mean `name`?",
      "help": "Check the field name for a typo,
        or add the field to the type.",
      "entity": "user::greet",
      "file": "user",
      "range": {
        "start": { "line": 9, "col": 10, "offset": 99 },
        "end":   { "line": 9, "col": 16, "offset": 105 }
      },
      "union": null,
      "missing_variants": null
    }
  ],
  "unindexed": [],
  "not_run": [ ... ]
}

ไฟล์ถูกตรวจภายในโปรเจกต์ของมัน field ที่ผิดบน record ที่ import มา และ match ที่ขาด arm บน union ที่ import มา จึงถูกรายงานที่นี่แบบเดียวกับที่ glyph check รายงาน สิ่งที่เครื่องมือครอบคลุมไม่ได้อยู่ในคำตอบ ไม่ได้ปล่อยให้คุณเดาเอง: member บอกว่าการไล่โปรเจกต์ไปถึงไฟล์นี้หรือไม่ unindexed ระบุไฟล์ในโปรเจกต์ที่ parse ไม่ผ่าน และ not_run ระบุสามการตรวจที่ glyph check ทำแต่ตัวนี้ไม่ทำ: tsc, E0104 สำหรับ import ที่อ้างถึง module ที่ไม่มีอยู่ ซึ่งต้องใช้มุมมอง node_modules ของ build และ E0400 สำหรับ @example ที่ fail ซึ่งตัดสินโดยการรันโปรเจกต์ที่ emit ออกมา มีเทสต์ที่รันทั้งสองช่องทางบนหกโปรเจกต์และเทียบ JSON ทีละ key ทั้งสองจึงไม่มีทางเพี้ยนออกจากกัน

glyph_references ครอบคลุมทั้ง workspace: ถามถึงสัญลักษณ์หนึ่งแล้วคุณจะได้ declaration ของมัน ทุกจุดที่ใช้ และ binding ของ import ในแต่ละ module ที่ import มัน ข้ามทุกไฟล์ มันใช้ตัวตนข้ามไฟล์แบบเดียวกับที่การ rename ใน editor ใช้ คำตอบจึงครอบคลุมทั้งโปรเจกต์ ไม่ใช่แค่ไฟล์ที่คุณถามมา

ไม่มี MCP client? ถามคำถามเดียวกันบน command line

ทุกเครื่องมือมีคำสั่งย่อยของ glyph query ที่รับ argument ของเครื่องมือเป็น flag และพิมพ์ JSON ของเครื่องมือออกทาง stdout คำถามที่ได้คำตอบจะ exit 0 คำถามที่ถูกปฏิเสธจะเขียนเหตุผลลง stderr และ exit 2 คำสั่งย่อยวิ่งผ่าน entry point เดียวกับที่ MCP client ใช้ และมี integration test ที่ถามคำถามเดียวกันกับทั้งสองช่องทางแล้วเทียบคำตอบเป็นข้อความ คำสั่งย่อยที่จัดรูปแบบใหม่หรือสรุปคำตอบจะทำให้เทสต์ fail

สิบเอ็ดคำถามเดียวกัน โดยไม่ต้องมี client 
glyph query symbol       --path src/main.glyph --entity orders::OrderStatus
glyph query impact       --entity orders::OrderStatus --change add_variant --variant Refunded
glyph query assignable   --path src/main.glyph --from 'Nullable<int>' --to int
glyph query diagnostics  --path src/main.glyph
glyph query hover        --path src/main.glyph --line 9 --character 6
glyph query definition   --path src/main.glyph --line 9 --character 6
glyph query references   --path src/orders.glyph --name create
glyph query variants     --path src/orders.glyph --name OrderStatus
glyph query symbols      --query order
glyph query dependencies --path src/main.glyph --entity main::build
glyph query exports      --path src/main.glyph --module orders

// the same two, asked about a module the compiler carries
glyph query symbol       --path src/main.glyph --entity std/result::Result
glyph query exports      --path src/main.glyph --module std/result

เมื่อ build แดงไปแล้ว

เครื่องมือเหล่านี้ตอบคำถามที่ถามก่อนแก้ หลังแก้ สิ่งที่ต้องอ่านคือ glyph check --agent ซึ่งพิมพ์ diagnostic ของ check --json โดยเพิ่ม key อีกสองตัวในแต่ละข้อ: constraints คือ invariant ที่การแก้ต้องรักษาไว้ และ symbols คือคำตอบของ glyph_symbol สำหรับทุกสัญลักษณ์ที่ diagnostic อ้างถึง การแก้ครั้งถัดไปจึงไม่ต้องเรียกซ้ำ สำหรับ match ที่ขาด arm นั่นหมายความว่า variant ของ union พร้อม payload มาพร้อมกับ error ที่ต้องการมัน รวมถึงประโยคที่บอกว่า arm แบบ else จะทำให้เสียการรับประกันที่ diagnostic นั้นมีไว้ปกป้อง ในกรณีที่วิธีซ่อมถูกกำหนดไว้ชัดเจน glyph fix จะเขียนให้ และบอกว่ามันปฏิเสธอะไรไปบ้าง มีตัวอย่างทีละขั้นของทั้ง loop พร้อม output จริง

สถานะตอนนี้

ใช้ได้วันนี้

เซิร์ฟเวอร์ glyph mcp [root] ผ่าน stdio ที่มีสิบเอ็ดเครื่องมือ: glyph_symbol, glyph_impact, glyph_assignable, glyph_diagnostics, glyph_hover, glyph_definition, glyph_references (ทั้ง workspace), glyph_variants, glyph_symbols, glyph_dependencies และ glyph_exports แต่ละตัวมีคำสั่งย่อย glyph query ที่พิมพ์ JSON เดียวกัน คำตอบมาจากคิวรีของคอมไพเลอร์เอง และทุกข้อเท็จจริงที่เครื่องมือไม่มีจะเป็น null โดยมีประโยค <key>_absent อยู่ข้างๆ บอกเหตุผล hover ตอบได้ที่ชื่อที่ประกาศไว้ใน module อื่น ฟังก์ชันที่ import มา ณ จุดที่เรียก และ field ที่อ่านจาก record ที่ import มา จึงมี type ทั้งคู่ ตัวตนของ entity ไปถึง stdlib: Result ใน prelude คือ std/result::Result ซึ่งเป็น module ที่ resolver ลงทะเบียนมันไว้ และเป็น module ที่ emitter เขียน import มาจาก glyph_symbol บนมันจึงตอบด้วย Ok(T) และ Err(E) และ glyph_exports บน std/result แสดงรายการ API ไม่มีซอร์ส Glyph อยู่เบื้องหลัง path และ range จึงเป็น null พร้อมเหตุผลนั้น แทนที่จะหายไปเฉยๆ

กำลังมา

เครื่องมือทำได้แค่อ่าน: คุณ rename หรือแก้ไขผ่าน MCP ไม่ได้ ฝั่งเขียนอยู่บน command line แทน ในชื่อ glyph fix เซิร์ฟเวอร์สแกนโปรเจกต์ใหม่ทุกครั้งที่เรียกแทนที่จะเก็บ index ไว้ใน cache และข้ามไฟล์ที่ parse ไม่ผ่าน reply ของ tools/list มีขนาด 20,386 ไบต์ ลดลงจาก 45,509 และนั่นก็ยังเป็น context ที่ทุก session ต้องจ่ายตอนเชื่อมต่อ

นอกจากเครื่องมือ เอเจนต์ยังอ่านภาษาและชุด diagnostic แบบออฟไลน์ได้: llms.txt คือฉบับร้อยแก้ว glyph llms --json คือความรู้เดียวกันในรูปข้อมูลจากตารางของคอมไพเลอร์เอง และ glyph build --json คือทางสำหรับรับ diagnostic ที่มีรหัสทั้ง tree แบบ batch
