เสาหลัก 02 · จุดหลัก

ค้นหาได้ด้วย grep

หนึ่งชื่อ หนึ่งที่ ทุกสัญลักษณ์มีรูปแบบทาง syntax เพียงแบบเดียวตรงจุดที่ประกาศ grep ธรรมดาจึงเจอนิยามเสมอ ไม่ต้องมี index ไม่ต้องมี language server และไม่ต้องอาศัยโชค

ในหน้านี้

  1. ทำไมถึงยาก
  2. declaration เดียว รูปแบบเดียว
  3. ไม่มีไฟล์ barrel
  4. ไม่มีพฤติกรรมที่ซ่อนอยู่
  5. การแก้ค่าที่ grep เจอ
  6. benchmark
  7. "กฎ lint ก็ทำได้"

ทำไม "สิ่งนี้นิยามไว้ที่ไหน?" ถึงตอบยาก

ใน codebase TypeScript ที่โตแล้ว คำถามที่ง่ายที่สุด ชื่อนี้มาจากไหน? มักตอบยากที่สุด

รายละเอียด overload, decorator, การ merge, การเสริม module, barrel

ภาษามีหลายวิธีให้กระจายสัญลักษณ์เดียวไปหลายที่: overload แยกฟังก์ชันเป็นหลาย signature, decorator ครอบมันด้วยอย่างอื่น, การ merge namespace และ interface กระจาย type ไปหลายไฟล์, declare module เสริมโค้ดที่คุณไม่ได้เป็นเจ้าของ และไฟล์ barrel index.ts re-export ทุกอย่าง path ที่คุณ import จึงไม่ใช่ที่ที่อะไรอยู่จริง

คนรับมือได้ด้วย LSP และความเคยชิน เอเจนต์ ใช้ grep: มันอ่าน repo เป็นข้อความ และทุก construct เหล่านั้นคือจุดที่ข้อความโกหกว่าโค้ดอยู่ที่ไหน

Glyph เอาพวกมันออก ผลคือภาษาที่การค้นหาเป็น primitive ที่เชื่อถือได้ ไม่ใช่การเดาแบบ heuristic

01 หนึ่ง declaration หนึ่งรูปแบบ

ฟังก์ชัน type หรือ component ถูกประกาศครั้งเดียวด้วย syntax เดียว ไม่มี overload ที่แยก signature และไม่มีทางประกาศชื่อซ้ำ: สองสิ่งระดับบนสุดที่ชื่อเดียวกันเป็น error ที่หยุด build (E0100)

E0100

keyword ของ declaration เป็นส่วนหนึ่งของชื่อที่คุณค้นหา grep "fn parseUser" ไม่มีทาง match การเรียก การ import หรือการ re-export มี match แค่ที่เดียวที่มันถูกนิยาม

การค้นหานิยามจึงมีคำตอบเดียวพอดี

02 ไม่มีไฟล์ barrel: path ของ import คือตำแหน่ง

import ของ Glyph ไม่เคย re-export และ module ที่มีแต่ import จะถูกปฏิเสธ (E0102) ไม่มีชั้น index.ts ที่ฟอกที่มา

import บอกคุณว่าต้องไปดูที่ไหนพอดี 
import myapp/users { parseUser }
//     ^^^^^^^^^^^ the file is src/myapp/users.glyph.
//     not a re-export of a re-export of a barrel.
E0102

import จึงระบุ module ที่สัญลักษณ์อยู่จริง: path คือที่อยู่

03 ไม่มีทางแอบผูกพฤติกรรม

ไม่มี decorator ที่ครอบฟังก์ชันด้วยชั้นที่มองไม่เห็น ไม่มีการ merge namespace ที่รวม member จากทั่ว tree ไม่มี declare module ที่เสริม type ของ third-party จากไฟล์ที่คุณไม่มีวันคิดจะเปิด และไม่มี this แบบแฝงที่เปลี่ยนสิ่งที่ method อ้างถึง

ชื่อหนึ่ง resolve ไปที่ declaration เดียว และทุกอย่างที่กำหนดรูปของมันมองเห็นได้ที่ declaration นั้น

04 แม้แต่การแก้ค่าก็ grep หาได้

การค้นหาด้วย grep ไม่ได้เกี่ยวแค่การหานิยาม แต่เกี่ยวกับการหาผลกระทบด้วย state ที่ใช้ร่วมกันอยู่ใน std/store และทุกการเปลี่ยนแปลงคือการเรียก .set( หรือ .update( ตรงตัว

$ grep -rn 'tasks\.\(set\|update\)' src/ 
src/tasks.glyph:16:  tasks.update(fn(cur) { ... })
src/tasks.glyph:24:  tasks.set([])
# every place the task list can change, enumerated.
# nothing hides in an ordinary `x = ...` elsewhere.

การค้นหาครั้งเดียวจึงแจกแจงช่องทางเขียนทั้งหมดของ state ได้ แทนที่จะไล่หาการ assign ที่กระจายอยู่ทั่วไฟล์

codebase ค้นหาได้ด้วย grep เมื่อข้อความของมันบอกความจริงเกี่ยวกับโครงสร้าง ทุกข้อจำกัดที่นี่ (รูปแบบเดียวต่อชื่อ ไม่มี re-export ไม่มีการ merge) มีไว้เพื่อให้การค้นหาได้คำตอบ ไม่ใช่แค่เบาะแส

benchmark: กำลังมา

รูปแบบที่วัดได้ของข้อกล่าวอ้างนี้คือ precision: สำหรับสัญลักษณ์หนึ่ง ผลลัพธ์จาก grep ธรรมดากี่เปอร์เซ็นต์ที่เป็นสิ่งที่คุณตามหาจริง และเอเจนต์ต้องใช้กี่ขั้นถึงจะไปถึงนิยาม

Glyph ยังไม่ได้ใช้งานจริงในโลกภายนอก กราฟด้านล่างจึงเป็นที่ว่างรอไว้ ซึ่งจะเติมด้วยตัวเลขจริงเมื่อมี codebase จริงให้วัด

precision ของ grep ในการหานิยาม · ยิ่งสูงยิ่งดี

ยังไม่ได้วัด เราจะรายงาน precision ของ grep และจำนวนขั้นที่ใช้ไปถึงนิยามจาก codebase Glyph จริงทันทีที่มี และเผยแพร่ตัวเลขที่นี่ไม่ว่าจะออกมาเป็นอย่างไร

ผลตอบแทนทวีขึ้นตามขนาดและความเป็นอิสระ คนจะเรียนรู้ที่ซ่อนของ codebase เอเจนต์ที่เริ่มจากศูนย์ไม่ได้เรียน การค้นหาได้ด้วย grep คือสิ่งที่ทำให้เครื่องมือ (หรือเพื่อนร่วมทีมคนใหม่) นำทางได้ด้วยการอ่าน ตามที่ repo เป็นจริง

"กฎ lint ห้าม overload และ decorator ได้"

ใน repository ของคุณเอง ได้ ESLint ห้าม namespace ได้ และทีมตกลงกันไม่ใช้ overload ได้

ภาษายังอนุญาตทั้งหมด การรับประกันจึงอยู่ได้นานเท่าที่ config อยู่ และครอบคลุมแค่โค้ดที่มันรัน grep บน dependency ไฟล์ที่ generate หรือ repository ของคนอื่นพึ่งพามันไม่ได้

ใน Glyph construct เหล่านั้นไม่มีอยู่ grep จึงทำงานเหมือนกันกับทุกไฟล์ Glyph รวมถึงไฟล์ที่ไม่มีใครในทีมคุณเป็นคนตั้งค่า

สิ่งนี้เป็นอย่างไรจากมุมของเอเจนต์ คือการหานิยามหรือทุกการเขียนค่าด้วยการค้นหาครั้งเดียว ตอบไว้ใน เอเจนต์ (หรือฉัน) หาได้ไหมว่าอะไรถูกนิยามไว้ที่ไหน?
