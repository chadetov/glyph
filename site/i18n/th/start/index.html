เริ่มที่นี่ · ประมาณ 10 นาที

โปรแกรม Glyph แรกของคุณ

สร้างโปรเจกต์ รัน แล้วตั้งใจทำให้พัง และอ่าน error ที่คอมไพเลอร์ให้มา ไม่ต้องรู้จัก Glyph มาก่อน ถ้าเคยเขียน TypeScript มาบ้าง คุณจะตามได้ทุกบรรทัด

1 · สร้างโปรเจกต์

Glyph เผยแพร่บน npm เป็น binary ที่ build ไว้แล้วสำหรับ macOS และ Linux (x64 และ ARM) และ Windows (x64) และต้องใช้ Node 18 ขึ้นไป วิธีนี้ไม่ติดตั้งอะไรแบบ global: npx ดึงคอมไพเลอร์มาสร้างโปรเจกต์ และโปรเจกต์จะ pin สำเนาของตัวเองไว้พร้อมกับ tsx และ typescript ซึ่ง Glyph ใช้ในการรันและตรวจ type

terminal 
npx -y @glyphlang/glyph init hello
cd hello
npm install

ถ้าอยากให้ glyph อยู่ใน PATH ให้ติดตั้งแบบ global พร้อมเครื่องมือสองตัวที่มันใช้ แล้วตัด npx ออกจากคำสั่งในหน้านี้:

terminal แบบติดตั้ง global 
npm install -g @glyphlang/glyph tsx typescript
glyph doctor                    # confirms your toolchain is ready
glyph init hello
cd hello

2 · ดูว่ามันสร้างอะไรให้

glyph init สร้างโปรเจกต์ตั้งต้นที่รันได้: src/main.glyph, src/.types/README.md ที่อธิบายว่าแพ็กเกจ npm ที่มี type ไม่ต้องใส่อะไรไว้ตรงนั้น และไดเรกทอรีนี้มีไว้สำหรับแพ็กเกจที่ไม่มี type มาด้วย, package.json, .gitignore และไฟล์สองไฟล์ที่เอเจนต์เขียนโค้ดอ่านเองได้: AGENTS.md ซึ่งชี้ไปที่ glyph llms สำหรับเอกสารอ้างอิงภาษาฉบับเต็ม และ .mcp.json ซึ่งลงทะเบียน glyph mcp ไว้ เอเจนต์จึงถามคอมไพเลอร์เรื่อง type และการอ้างอิงได้แทนที่จะไล่ค้นเอง ในโปรเจกต์ที่มีอยู่แล้ว glyph agents จะเขียนสองไฟล์นี้ให้ package.json pin คอมไพเลอร์ typescript และ tsx ไว้ใน devDependencies ใครที่ clone โปรเจกต์ไปก็ build ได้ด้วย npm install โดยไม่ต้องติดตั้ง global

เปิด src/main.glyph มันคือ hello-world:

src/main.glyph 
module main

import std/io

fn main(argv: Array<string>) -> number {
  io.println("hello from glyph")
  return 0
}

สองอย่างที่ควรสังเกต: โปรแกรมจะรัน main(argv) ของมัน และ main คืนค่าเป็น number ซึ่งคือ exit code ของ process การ return จะตั้ง exit code โดยไม่บังคับให้ process หยุด โปรแกรมที่เปิด server จึงยังให้บริการต่อได้

3 · รัน

terminal 
npx glyph run
hello from glyph

glyph run ตรวจ type คอมไพล์เป็น TypeScript แล้วรันมัน นี่คือ loop ที่คุณจะทำซ้ำไปตลอดหน้านี้ ถ้าอยากเห็น error และ type ใน editor ระหว่างทำตาม ดูวิธีตั้งค่าได้ที่ Editor และการเชื่อมต่อ

4 · เพิ่มของจริงเข้าไป

ทีนี้แทนที่ body ด้วยการตัดสินใจที่สำคัญ: จะส่งคำสั่งซื้อหรือไม่ ตามสถานะการชำระเงิน นี่คือการแนะนำสองสิ่งที่คุณจะใช้ตลอด: tagged union (type Payment = ...) และ match ซึ่งเป็นเงื่อนไขแบบเดียวของ Glyph

src/main.glyph 
module main

type Payment = Pending | Paid | Failed

fn ship(p: Payment) -> string {
  return match p {
    Pending => "hold: waiting for the money",
    Paid => "ship it",
    Failed => "hold: payment failed",
  }
}

fn main(argv: Array<string>) -> number {
  print(ship(Paid))
  return 0
}
terminal 
npx glyph run
ship it

5 · ตั้งใจทำให้พัง

ส่วนนี้แสดงให้เห็นว่า Glyph มีไว้เพื่ออะไร ticket หนึ่งบอกว่า "รองรับการคืนเงิน" ให้เพิ่มกรณี Refunded ใน Payment และไม่ต้องแตะ ship นี่คือสิ่งที่ agent ทำเมื่อแก้ type ในไฟล์หนึ่งแล้วไม่เคยเปิดโค้ดที่ตัดสินใจตาม type นั้น แล้วรันอีกครั้ง

src/main.glyph (เพิ่มหนึ่งคำ) 
type Payment = Pending | Paid | Failed | Refunded
$ npx glyph run 
[E0200] Error: typecheck: non-exhaustive match on `Payment`: missing variants `Refunded`
    ╭─[ main:6:10 ]
    │
  6 │ ╭─▶   return match p {
    ┆ ┆
 10 │ ├─▶   }
    │ ╰───────── non-exhaustive match on `Payment`: missing variants `Refunded`
    │
    │     Help: Add an arm for each missing variant.
────╯

มันไม่รัน TypeScript ที่โค้ดส่วนใหญ่เขียนด้วยกลับทำตรงกันข้าม: switch ที่จัดการสองกรณี "hold" แล้วจบด้วย default: return "ship it" ยังผ่าน tsc --strict หลังเพิ่มกรณีใหม่ และส่งทุกคำสั่งซื้อที่คืนเงินไปแล้ว ที่นี่ match ทุกตัวที่ขาดกรณีใดไปจะเป็น compile error พร้อมรหัสที่คงที่ (E0200) ตำแหน่งที่แน่นอน และชื่อของกรณีนั้น รัน glyph --explain E0200 เมื่อใดก็ได้ที่อยากอ่านฉบับยาว

6 · แก้

compiler ตัดสินไม่ได้ว่าการคืนเงินมีความหมายอย่างไรต่อการส่งของ นั่นเป็นการตัดสินใจของคุณ เพิ่ม arm แล้วมันจะรันได้อีกครั้ง

src/main.glyph 
fn ship(p: Payment) -> string {
  return match p {
    Pending => "hold: waiting for the money",
    Paid => "ship it",
    Failed => "hold: payment failed",
    Refunded => "hold: refunded, nothing to ship",
  }
}
terminal (เมื่อใช้ print(ship(Refunded))) 
npx glyph run
hold: refunded, nothing to ship

นี่คือ loop หลัก: เขียน รัน และเมื่อมีอะไรผิด คอมไพเลอร์จะบอกคุณว่าผิดอะไรและแก้อย่างไร ก่อนโค้ดจะขึ้น production ไม่ใช่หลังจากนั้น
