Ajanlar ve araç geliştiriciler için

Derleyicinin ajanlara yönelik arayüzü

Bir ajan Glyph derleyicisine bir sembolün ne olduğunu, bir düzenlemenin neyi bozacağını ve bir build'in neden başarısız olduğunu sorabilir ve JSON olarak yanıt alır. glyph mcp, stdio üzerinden on bir araç sunar; her biri aynı zamanda bir glyph query fiilidir. glyph llms ise dil referansını çevrimdışı yazdırır.

Kurulum

glyph init bu .mcp.json dosyasını yeni bir projeye yazar; glyph agents ise onu (glyph llms'i gösteren bir AGENTS.md ile birlikte) mevcut bir projeye yazar. Dosyayı okuyan herhangi bir MCP istemcisi sunucuyu başlatır; port da daemon da yoktur.

.mcp.json, glyph init'in yazdığı hâliyle 
{
  "mcpServers": {
    "glyph": {
      "command": "glyph",
      "args": ["mcp"]
    }
  }
}

Tek bir çağrı ve gerçek yanıtı

Bir dosya, record'unun tanımlamadığı bir alanı okuyor (u.naem). Ajan glyph_diagnostics'i çağırır ve derleyicinin kendi diagnostic'ini, record'un tanımladığı alanlar ve bu alanların ait olduğu record ile birlikte alır. Bu, aracın 0.1.149'daki çıktısıdır; yalnızca işaretli yerlerde kırpıldı.

istek 
{
  "method": "tools/call",
  "params": {
    "name": "glyph_diagnostics",
    "arguments": {
      "path": "src/user.glyph"
    }
  }
}
sonuç 
{
  "diagnostics": [ {
    "code": "E0210",
    "severity": "error",
    "stage": "typecheck",
    "message": "type `U` has no field
      `naem`; did you mean `name`?",
    "alternatives": ["name", "email"],
    "alternatives_kind": "fields",
    "cause": "user::U",
    "entity": "user::greet",
    "file": "user.glyph",
    "range": {
      "start": { "line": 9, "col": 10 },
      "end": { "line": 9, "col": 16 } },
    ...
  } ],
  "member": true,
  "module": "user",
  "not_run": [
    { "what": "tsc", ... },
    { "what": "E0104, ...", ... },
    { "what": "E0400, ...", ... } ],
  "path": "src/user.glyph",
  "project_root": "src",
  "unindexed": []
}

not_run, bu kontrolün neyi kapsamadığını söyler; böylece boş bir diagnostics listesi tam bir build ile karıştırılamaz. MCP istemcisi olmadan glyph query diagnostics --path src/user.glyph aynı JSON'u yazdırır. Tüm fiilleriyle birlikte tam araç listesi MCP sayfasında.

Düzenlemeden önce: neyi bozacak?

examples/apps/csvql, dört durumlu bir union'a (Value) sahip, on bir dosyalık bir CSV sorgu motorudur. Beşinci bir durum eklemenin ne yapacağı sorulduğunda glyph_impact, 4 dosyada 10 match yeri listeler: 8 WILL_FAIL ve 2 ABSORBS; ikincisi, bir catch-all arm'ın yeni durumu yutacağı ve derlenmeye devam edeceği yerlerdir. Durumu gerçekten eklemek, tam olarak o 8 yerde 8 E0200 hatası verir. Yutan 2 yer sessiz kalır; yanıtın onları adıyla belirtmesinin nedeni budur.

aynı soru komut satırında 
glyph query impact --path value.glyph --entity value::Value \
  --change add_variant --variant Blob

Kırmızı bir build'den sonra: düzeltme neyi korumalı?

glyph check --agent, check --json'un diagnostic'lerini her birine iki anahtar daha ekleyerek yazdırır. constraints, onarıcı bir düzenlemenin bozmaması gerekenleri listeler; yukarıdaki yazım hatası için "the record's fields are closed: user::U declares name, email and no others" der. symbols, diagnostic'in adını verdiği her sembol için glyph_symbol yanıtını taşır, böylece sonraki düzenleme ikinci bir çağrıya ihtiyaç duymaz. Düzeltmenin tamamen belirli olduğu yerlerde glyph fix onu yazar.

Dili çevrimdışı okumak

glyph llms dil referansını yazdırır; bu sitedeki /llms.txt de aynı belgedir. glyph llms --json, derleyicinin kendi tablolarından okunan aynı bilgiyi veri olarak verir: 77 diagnostic kodu, 24 prelude ismi, 340 export içeren 40 stdlib modülü, 49 dil kararı ve on bir araç. glyph llms --negative, 0.1.149'da 117 hatalı program (sonraki sürümden itibaren 139) ve her birinin tetiklediği kodu döndürür; programlar siz istediğinizde derlenir. scripts/check_llms_sync.py, referanstaki diagnostic ve ayrılmış kelime tabloları derleyicinin kendi tablolarından saptığında başarısız olur.

çevrimdışı giriş noktaları 
glyph llms                  # the reference, as prose
glyph llms --json           # the same, as data from the compiler's tables
glyph llms --negative E0200 # wrong programs that draw E0200
glyph --explain E0200       # the long explanation of one code
