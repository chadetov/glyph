Glyph ve Effect

İkisi de insanların ve ajanların güvenebileceği TypeScript'i hedefliyor. Effect bir kütüphane: TypeScript yazmaya devam edersiniz ve tipli hatalar, takip edilen bağımlılıklar ve geniş bir araç kutusu elde edersiniz. Glyph ise TypeScript'e derlenen bir dil; bu yüzden TypeScript'in izin verdiklerini, bir kütüphanenin garantilerini geri alan cast'ler dahil, reddedebilir. Effect çok daha olgun.

Effect kendini nasıl tanımlıyor

Effect'in ana sayfası "Reliable TypeScript for the AI era" ile açılıyor ve "declarative patterns and strong type system make it easier for LLMs to generate correct, production-ready code" diyor (effect.website). Dokümanları onu "an ecosystem of tools that help you build better applications and libraries" olarak tanımlıyor; bir hesaplamanın ne döndürdüğünü, nasıl başarısız olabileceğini ve neye ihtiyaç duyduğunu kaydeden bir Effect<Success, Error, Requirements> tipi etrafında kurulu (Why Effect). strict açık olarak TypeScript 5.4 ya da daha yenisini istiyor (Installation). Bu alıntılar 2026-11-19'da okundu.

Kütüphane ile dil farkından doğan sonuç

Effect'in tiplerini tsc kontrol eder; bu yüzden tsc'nin izin verdiği her şeye onların yanında da izin verilir. Bu kod effect 4.1.4 ve TypeScript 6 ile tsc --strict altında derlenir. Cast, NotFound'u hata kanalından çıkarır ve program, başarısız olamayacak şekilde tiplenmiş bir effect'ten bir başarısızlık bildirir.

eff.ts: tsc --strict 0 ile çıkar; çalıştırıldığında "Failure undefined" yazdırır 
import { Effect } from "effect"

class NotFound {
  readonly _tag = "NotFound"
}

const find = (id: string): Effect.Effect<number, NotFound> =>
  id === "1" ? Effect.succeed(1) : Effect.fail(new NotFound())

// The error channel says NotFound can happen. A cast erases it.
const quiet = find("2") as unknown as Effect.Effect<number, never>

// And a parsed body still takes any type you name.
type User = { email: string }
const user = JSON.parse("{}") as User

console.log(Effect.runSyncExit(quiet)._tag, user.email)

Glyph'teki aynı fonksiyon bir Result döndürür ve yazılacak bir cast yoktur. İkinci modül, herhangi bir TypeScript üretilmeden reddedilir.

find.glyph: build edilir, tsc --strict'ten geçer 
module find

pub type NotFound = { id: string }

pub fn find(id: string) -> Result<number, NotFound> {
  return match id == "1" {
    true => Ok(1),
    false => Err({ id: id }),
  }
}
bir cast eklemek: reddedilir 
module find

pub type NotFound = { id: string }

pub fn find(id: string) -> Result<number, NotFound> {
  return match id == "1" {
    true => Ok(1),
    false => Err({ id: id }),
  }
}

pub fn quiet() -> number {
  let n = find("2") as number
  return n
}

E0013'ün yardım metni şöyle: "Glyph has no as cast ... to turn an unknown into a type, validate it with T.parse(v) or narrow it with match and is." Bir ekip Effect kullanan bir kod tabanında lint kurallarıyla buna yaklaşabilir; birinin kapatabileceği bir kuralın neden farklı bir garanti olduğunu o karşılaştırma anlatıyor.

Glyph'in yapıp bir kütüphanenin yapamadıkları

Neyin yazılabileceğine dil karar verir. Glyph'te any, cast, non-null assertion ya da bir hatayı susturan yorum yoktur ve bir union üzerindeki her match her durumu kapsamak zorundadır. Record'lar ve union'lar, tanımdan üretilen bir çalışma zamanı kontrolü taşır; bu yüzden json.parse<User>(body) doğrulama yapar. Effect'in Schema'sı da tipi tek bir tanımdan türetir (giriş sayfasındaki Schema.Schema.Type<typeof Person>), yani orada da tip ve validator birbirinden sapmaz; fark şu ki TypeScript'te hiçbir şey bir kod tabanını onu kullanmaya zorlamaz. Derleyici ayrıca bir ajan için bir program hakkındaki soruları da yanıtlar, örneğin bir değişikliğin neyi bozacağını, MCP ya da komut satırı üzerinden.

Bu sayfa Effect'i bir Glyph modülünün içinden kullanmayı test etmedi, bu yüzden ikisini birleştirmek hakkında bir iddiada bulunmuyor.
