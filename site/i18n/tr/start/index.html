Buradan başlayın · ~10 dakika

İlk Glyph programınız

Bir proje oluşturun, çalıştırın, sonra bilerek bozun ve derleyicinin verdiği hatayı okuyun. Önceden Glyph bilgisi gerekmez. Biraz TypeScript yazdıysanız her satırı takip edebilirsiniz.

1 · Bir proje oluşturun

Glyph, npm'de macOS ve Linux (x64 ve ARM) ile Windows (x64) için önceden derlenmiş bir binary olarak dağıtılır ve Node 18 ya da üstünü gerektirir. Bu yol global olarak hiçbir şey kurmaz: npx, projeyi oluşturmak için derleyiciyi indirir; proje de kendi kopyasını, Glyph'in çalıştırmak ve tip kontrolü için kullandığı tsx ve typescript ile birlikte sabitler.

terminal 
npx -y @glyphlang/glyph init hello
cd hello
npm install

glyph'in PATH'inizde olmasını tercih ederseniz, onu üzerinden çalıştığı iki araçla birlikte global olarak kurun ve bu sayfadaki komutlardan npx'i çıkarın:

terminal, global alternatif 
npm install -g @glyphlang/glyph tsx typescript
glyph doctor                    # confirms your toolchain is ready
glyph init hello
cd hello

2 · Neler oluşturduğuna bakın

glyph init, çalıştırılabilir bir başlangıç projesi oluşturur: src/main.glyph; tipli bir npm paketinin orada hiçbir şeye ihtiyaç duymadığını ve dizinin tip içermeyen paketler için olduğunu açıklayan src/.types/README.md; bir package.json; bir .gitignore; ve kodlama ajanlarının kendiliğinden okuduğu iki dosya: dilin tam referansı için glyph llms'i gösteren AGENTS.md ve bir ajanın tipleri ve referansları aramak yerine derleyiciye sorabilmesi için glyph mcp'yi kaydeden .mcp.json. Zaten var olan bir projede bu ikisini glyph agents yazar. package.json, derleyiciyi, typescript'i ve tsx'i devDependencies içinde sabitler; böylece projeyi klonlayan herkes, global bir kurulum olmadan npm install ile build edebilir.

src/main.glyph'i açın. Bir hello-world:

src/main.glyph 
module main

import std/io

fn main(argv: Array<string>) -> number {
  io.println("hello from glyph")
  return 0
}

Dikkat edilecek iki şey: bir program kendi main(argv)'ini çalıştırır ve main, sürecin çıkış kodu olan bir number döndürür. Return, süreci durmaya zorlamadan bu kodu ayarlar; böylece bir sunucu başlatan program hizmet vermeye devam eder.

3 · Çalıştırın

terminal 
npx glyph run
hello from glyph

glyph run onu tip kontrolünden geçirdi, TypeScript'e derledi ve çalıştırdı. Bu sayfanın geri kalanında tekrarlayacağınız döngü bu.

4 · Gerçek bir şey ekleyin

Şimdi gövdeyi küçük bir mantıkla değiştirin: bir görev durumu ve onu etiketleyen bir fonksiyon. Bu, sürekli kullanacağınız iki şeyi tanıtır: bir tagged union (type Status = ...) ve Glyph'in tek koşul yapısı olan match.

src/main.glyph 
module main

type Status = Todo | Doing | Done

fn label(s: Status) -> string {
  return match s {
    Todo => "not started",
    Doing => "in progress",
    Done => "finished",
  }
}

fn main(argv: Array<string>) -> number {
  print(label(Done))
  return 0
}
terminal 
npx glyph run
finished

5 · Bilerek bozun

Glyph'in ne için olduğunu gösteren kısım burası. match'ten Done arm'ını silin (bir ajanın bir yere yeni bir case ekleyip onu ele almayı unuttuğunda yaptığı türden bir şey) ve tekrar çalıştırın.

src/main.glyph (Done arm'ı silinmiş hâli) 
fn label(s: Status) -> string {
  return match s {
    Todo => "not started",
    Doing => "in progress",
  }
}
$ npx glyph run 
[E0200] Error: typecheck: non-exhaustive match on `Status`: missing variants `Done`
   ╭─[main:6:10]
   │
 6 │ ╭─▶   return match s {
   ┆ ┆
 9 │ ├─▶   }
   │ ╰───────── missing variants `Done`
   │

Çalışmadı. TypeScript'te dönüş tipi açıkça yazılmış bu fonksiyonun aynısı da reddedilir (TS2366). Ama yalnızca log yazan ya da durumu güncelleyen bir switch, veya default: içeren bir tanesi temiz derlenir ve yeni case'i sessizce atlar. Burada kapsamı eksik her match, kararlı bir kodu (E0200), tam yeri ve tek satırlık bir düzeltmesi olan bir derleme hatasıdır. Uzun açıklamayı istediğiniz zaman glyph --explain E0200 çalıştırın.

6 · Düzeltin

Arm'ı geri koyun (ya da bir else ekleyin), program yine çalışır.

terminal 
npx glyph run
finished

Temel döngü bu: yazın, çalıştırın; bir şey yanlışsa derleyici, kodunuz yayına çıkmadan önce, sonra değil, tam olarak neyin yanlış olduğunu ve nasıl düzeltileceğini söyler.
