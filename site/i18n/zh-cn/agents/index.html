面向智能体和工具开发者

编译器面向智能体的接口

智能体可以问 Glyph 编译器：某个符号是什么，一次编辑会破坏什么，构建为什么失败，并得到 JSON 结果。glyph mcp 通过 stdio 提供十一个工具，每个工具同时也是一个 glyph query 子命令；glyph llms 可以离线打印语言参考。

配置

glyph init 会在新项目里写入这个 .mcp.json，glyph agents 会把它（连同指向 glyph llms 的 AGENTS.md）写入已有项目。任何读取这个文件的 MCP 客户端都会启动服务器；没有端口，也没有守护进程。

.mcp.json，glyph init 写入的内容 
{
  "mcpServers": {
    "glyph": {
      "command": "glyph",
      "args": ["mcp"]
    }
  }
}

一次调用，附真实结果

某个文件读取了记录中没有声明的字段（u.naem）。智能体调用 glyph_diagnostics，得到编译器自己的诊断，其中列出该记录确实声明的字段，以及拥有这些字段的记录。这是该工具在 0.1.149 上的输出，只在标注处有删节。

请求 
{
  "method": "tools/call",
  "params": {
    "name": "glyph_diagnostics",
    "arguments": {
      "path": "src/user.glyph"
    }
  }
}
结果 
{
  "diagnostics": [ {
    "code": "E0210",
    "severity": "error",
    "stage": "typecheck",
    "message": "type `U` has no field
      `naem`; did you mean `name`?",
    "alternatives": ["name", "email"],
    "alternatives_kind": "fields",
    "cause": "user::U",
    "entity": "user::greet",
    "file": "user.glyph",
    "range": {
      "start": { "line": 9, "col": 10 },
      "end": { "line": 9, "col": 16 } },
    ...
  } ],
  "member": true,
  "module": "user",
  "not_run": [
    { "what": "tsc", ... },
    { "what": "E0104, ...", ... },
    { "what": "E0400, ...", ... } ],
  "path": "src/user.glyph",
  "project_root": "src",
  "unindexed": []
}

not_run 列出这次检查没有覆盖的部分，所以空的 diagnostics 列表不会被误认为是完整的构建。没有 MCP 客户端时，glyph query diagnostics --path src/user.glyph 会打印同样的 JSON。完整的工具列表及所有子命令见 MCP 页面。

编辑之前：它会破坏什么？

examples/apps/csvql 是一个由十一个文件组成的 CSV 查询引擎，其中有一个包含四种情况的联合类型 Value。问它新增第五种情况会怎样，glyph_impact 列出了 4 个文件中的 10 处 match：8 处 WILL_FAIL，2 处 ABSORBS，后者是兜底分支会吞掉新情况并继续编译的地方。真正加上这种情况后，恰好在这 8 处出现 8 个 E0200 错误。那 2 处吞掉新情况的位置不会报错，这正是答案要把它们点出来的原因。

在命令行上问同一个问题 
glyph query impact --path value.glyph --entity value::Value \
  --change add_variant --variant Blob

构建失败之后：修复必须保持什么？

glyph check --agent 打印 check --json 的诊断，并在每条诊断上多加两个键。constraints 列出修复性编辑不能破坏的东西；对上面的拼写错误，它写的是“the record's fields are closed: user::U declares name, email and no others”。symbols 带有诊断中提到的每个符号的 glyph_symbol 结果，所以下一次编辑不需要再调用一次。修复方式完全确定时，glyph fix 会直接写入。

离线阅读语言

glyph llms 打印语言参考，本站的 /llms.txt 是同一份文档。glyph llms --json 把这些知识以数据形式给出，读自编译器自己的表：77 个诊断码、24 个 prelude 名称、40 个标准库模块共 340 个导出、49 项语言决策，以及十一个工具。glyph llms --negative 在 0.1.149 中返回 117 个错误程序（从下一个版本起是 139 个），附上每个程序触发的错误码，在你请求时编译。scripts/check_llms_sync.py 会在参考文档中的诊断表和保留字表与编译器自己的表不一致时失败。

离线入口 
glyph llms                  # the reference, as prose
glyph llms --json           # the same, as data from the compiler's tables
glyph llms --negative E0200 # wrong programs that draw E0200
glyph --explain E0200       # the long explanation of one code
