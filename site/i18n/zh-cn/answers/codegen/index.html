12 · 从你的规范生成

能根据 API 规范生成类型化的客户端和服务端吗？

能。把 glyph gen openapi 指向一份 OpenAPI 规范：--client 生成类型化的 HTTP 客户端，每个操作一个函数；--handlers 生成服务端桩代码和一个可用的 route 分派器。如果你的权威数据源是 zod schema，glyph gen zod 也能做同样的事。所有输出都是提交到仓库、可以 grep 的 Glyph 代码，归你所有，由你编辑，而不是一个隐藏的代码生成步骤。

为什么这很重要

手写的 API 客户端及其 DTO 会与规范逐渐偏离，这种偏离是一类没人喜欢的 bug。

由于 Glyph 生成的是真正的代码（类型化的函数、带运行时描述符的真正 type 声明），规范始终是权威来源，重新生成是一个幂等、可审查的 diff，而不是一个黑盒。

--handlers 路由器

--handlers 生成的路由器用数组模式匹配路径，所以 /tasks/{id} 变成 ["tasks", id]，并替你绑定参数。

  1. /tasks/{id}
  2. ["tasks", id]
  3. getTask(req, id)

每个桩函数一开始返回 501，并带有一段展示如何解析请求体的注释；你把它们填写完整，再用 await serve(PORT, route) 接上即可。

改为从 zod schema 生成

如果你的团队已经用 zod 定义数据形态，可以直接从它们生成。schema 会变成一个一等的 Glyph 类型，带有自己的描述符：

schemas.ts 
export const Task = z.object({
  id: z.number(),
  title: z.string(),
  done: z.boolean(),
})
$ glyph gen zod schemas.ts --out src/ 
type Task = {
  id: number,
  title: string,
  done: bool,
}
// + a runtime descriptor, so
// Task.parse(value) validates.

它映射什么

多态的可辨识联合（OpenAPI 的 discriminator）会生成一个真正的 Glyph 标签联合，外加一个生成的 parse_<Name>，它读取判别属性并校验为正确的变体。

详情 为什么要生成分派器

由于 Glyph 按构造函数名而不是任意属性来打标签，生成的分派器会替你把传输对象桥接到联合类型。

不足之处

生成忠实于传输格式，所以它映射的是常见的 80%：对象、原始类型、数组、引用、可选和可为空的字段（两者分开处理：可为空的字段变成 Nullable<T>，schema 不要求的字段带 ?，它不接受 null），以及可辨识联合。对于无法精确表示的内容（字符串枚举、不可辨识的联合），它会收窄处理并打印一条说明，而不是生成一个会拒绝真实数据的校验器。下一步是更丰富的枚举。

详情 生成器需要安装什么

工具链也有实际的依赖：gen dts/gen zod 需要 Node 加上 typescript/zod。gen dts 支持任何 TypeScript（5、6 或 7.x 原生移植版），优先从你的项目中解析，缺少时会明确告诉你需要安装什么。

保持同步

每个生成的文件都会在文件头中记录生成它的确切命令。规范变化时，你不需要去找该重新运行哪些命令：glyph regen 会扫描这些文件头，逐个重新运行并重写输出。

它是幂等的，所以规范没有变化时 regen 不会改动任何东西；它可以直接放进 pre-commit hook，或者放进一个在提交的代码偏离规范时失败的 CI 检查。

当前状态

现已提供

  • glyph gen openapi（类型、--client、带真正路由器的 --handlers）、glyph gen dts、glyph gen zod，以及从源头刷新全部生成代码的 glyph regen：每个命令生成的都是提交到仓库、带描述符、可幂等重新生成的 Glyph 代码。
  • 如果两个类型会以同一个 Glyph 名字写出，生成器会停下，而不是产出一个无法编译的文件：它列出每个冲突的来源，不写任何文件，用 --rename Source=GlyphName 即可解决。
  • 这个选择会记录在生成的文件头中，所以 glyph regen 会重放它。

正在进行

  • 更丰富的枚举映射和更广的 OpenAPI 覆盖，每一项都遵循同样的规则：忠实于传输格式，收窄时给出说明。
  • 从包自带的 .d.ts 生成时，读取的是其中的 interface 和 type 声明，所以如果一个库的 API 是类，或者字段使用了 Omit 这样的计算类型，就会留下一些引用，生成器会在说明中列出它们，glyph build 会把它们报告为未解析。
  • 导入这样的类并用 new 构造它不需要生成，由 tsc 检查，所以这条路径不受影响。
