16 · 金额 & 安全

涉及金额、以及我无法控制的输入时，能信任它吗？

能。金额计算是精确的，像“非负”这样的不变式是由边界强制检查的类型，不可信输入未经清洗无法到达 SQL 或 shell 汇点。其中任何一项写错，都会是编译错误或解析错误，而不是一条需要有人在三个函数之外记住的约定。

本页内容

  1. 金额不是浮点数
  2. id 与计数器
  3. 不变式即类型

金额不是浮点数

std/decimal 是基于 BigInt 的精确十进制定点数。

  • 精确运算加、减、乘都是精确的。
  • 除法除法需要显式指定小数位数，并按四舍五入（远离零）舍入。
  • 错误输入格式错误的金额会解析为 Err，绝不会悄悄变成 NaN。

id 和计数器在超过 253 后仍然精确

账户 id 或账本计数器超出浮点数范围后被舍入，是另一种灾难。

bigint 是精确的任意精度整数，字面量写作 123n，类型为 bigint 的记录字段会在边界上校验 typeof === "bigint"，所以以 JSON number 到达的 id 会被拒绝，而不是被悄悄截断。

不变式是类型，不是注释

“金额非负”和“评分在 1 到 5 之间”是那种写过一次就被遗忘的检查。where 精化把不变式放进类型，描述符在边界上强制检查它。

refinements.glyph 
type Amount = int where value >= 0
type Rating = int where value >= 1 && value <= 5

Amount.parse(-1)   # Err  (not just "is a number")
Rating.parse(6)    # Err
Amount.parse(3.5)  # Err  (int check too)

不满足谓词的值从一开始就不会成为 Amount。

注入是编译错误

典型的远程代码执行路径，是不可信输入到达 SQL 查询、shell 命令或 HTML 模板。std/taint 把这变成了类型错误。

  • 两种类型来自外部的值是 Tainted；你想保护的汇点接受 Trusted。
  • 唯一的转换途径两者在结构上不同，所以从一个变成另一个的唯一途径是显式的 sanitize。
安全的路径能编译 
fn run_query(sql: Trusted<string>) -> void { ... }

let input: Tainted<string> = taint(req.body)
run_query(sanitize(input, escape))   # ok
注入的路径不能 
module query

import std/taint { Tainted, Trusted, taint, expose }

fn run_query(sql: Trusted<string>) -> string {
  return expose(sql)
}

pub fn handle(body: string) -> string {
  let input: Tainted<string> = taint(body)
  return run_query(input)
}

// [TS2345] Argument of type 'Tainted<string>'
//   is not assignable to parameter of type
//   'Trusted<string>'. (query.glyph:11)

直接把被污染的值交给汇点，tsc 会拒绝编译。

当前状态

现已提供

  • 用于精确金额的 std/decimal
  • 用于精确大整数的 bigint
  • 让不变式在边界上被校验的 where 精化
  • 让不可信输入在没有显式 sanitize 的情况下无法到达受保护汇点的 std/taint
  • 每一项都会被检查：错误的金额或 id 会在 parse 时失败，违反不变式会在 parse 时失败，未经清洗的值会在 tsc 时失败。

边界在哪里

  • 目前 where 精化只覆盖原始基础类型；记录级和跨字段的不变式（where value.paid <= value.total）是计划中的扩展。
  • 污点检查是一种你通过把汇点类型声明为 Trusted 而主动采用的约束，而不是自动的数据流分析
    详情

    污点检查是一种你通过把汇点类型声明为 Trusted 而主动采用的约束，而不是自动的数据流分析：编译器强制执行你声明的边界，但不会替你在整个程序中推断污点。
