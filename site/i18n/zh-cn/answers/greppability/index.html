03 · 靠搜索导航

智能体（或者我）能找到任何东西的定义位置吗？

每种结构都只有一种形式可供搜索。普通的 grep（智能体实际导航代码的方式）会落在唯一的定义上，而不是五十个似是而非的结果。

为什么重要

智能体不会把整个仓库记在脑子里，它靠搜索。如果一个概念有五种写法，搜索就会漏掉一些情况，而一个找不到现有定义却很自信的智能体会再造一个。一个概念只有一种形式，意味着搜索是完整的，所以智能体会修改已有的东西，而不是复制一份。

看看实际效果

Glyph 把修改限制为两种形式（mut x = … 和 mut x.method(…)），所以状态发生变化的每一个地方都能通过一次搜索找到：

grep -rn "mut " src/（代码库中的每一处修改） 
src/cart.glyph:14:   mut items.push(item)
src/cart.glyph:22:   mut total = total + price
src/user.glyph:8:    mut session.token = fresh

三处修改，全部在一次搜索中找到。在 TypeScript 中，修改可能藏在 =、.push()、Object.assign、setter 或展开运算之后。没有一个能 grep 的标记，所以“有没有东西会改动它？”这个问题没有可靠的答案。同样的单一形式规则让许多类别都可以审计：

一次搜索 = 一个完整的答案 
# every UI component
grep -rn "^component " src/

# every function
grep -rn "^fn " src/

# the entire resource-ownership surface
grep -rn "owned" src/

没有对象字面量简写，没有声明组件的第二种方式，也没有需要消歧的重载语法。写法更少确实是一种约束，而这正是目的：它让智能体的搜索和你的搜索都值得信赖。

Glyph 为了让搜索可信而舍弃了哪些结构，以及为什么 lint 规则不能提供同样的保证，见可检索性支柱页面。

当前状态

现已提供

每种结构只有一种标准形式，修改限制为两种可以 grep 的形式（mut），并且用一个关键字就能完成审计（fn、component、owned、type）。

在此之上

语言服务器增加了覆盖整个工作区的跳转到定义和查找引用：同样的保证，现在可以在编辑器中交互使用。
