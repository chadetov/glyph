能和 React 一起用吗：组件、hooks 和 Context？

能。component 编译成 React 函数组件，JSX 转换为 createElement，React 自己的 hooks 按名字导入并解构它们返回的二元组，reducer 的状态还能得到普通 TypeScript 没有的穷尽性检查。页面本身（标题、挂载点、保存的状态）通过 std/dom 和 std/storage 访问。首先值得了解的 gap：Glyph 自己的检查器不会推断 hook 返回值的类型，这些值由 tsc 检查。

为什么这很重要

智能体写的代码有很大一部分是 React。Glyph 把它当作一等目标，而不是外挂：component 是独立的关键字（所以 grep "^component " 就能审查整个 UI）。

React 的 hooks 从 react 导入，用它们真实的名字和类型调用，由 tsc 对照 React 自己的类型声明检查。

Reducer 与 hooks

加一个 Double action，reducer 就会编译失败，报 E0200 并指出它的名字，而普通 TypeScript 的 switch 会让它直接上线。

E0200

Glyph 自己的检查器不推断来自 React 的值的类型，所以传给 dispatch 或状态 setter 的错误参数，是在构建时由 tsc 报告的，而不是在编辑器里或 --no-tsc 时报告。

详情 hook 返回的二元组如何解构

二元组用 let [count, dispatch] 解构，生成的 TypeScript 会加上 satisfies readonly [unknown, unknown]，所以 tsc 会证明 hook 返回的是二元组，同时仍然推断每个元素的类型。

Context 与库

React Context 现在可以通过 createContext / useContext 使用，成员表达式形式的元素名（<ThemeContext.Provider>）也可以直接使用，不需要变通。

  • 属性展开JSX 属性展开同样可用：<input {...register("email")} /> 会转换为 props 中的对象展开，所以 react-hook-form 的惯用写法不需要适配层。
  • Zod 类型Zod 的值派生类型是一等支持的：type FormData = z.infer<typeof schema> 可以直接使用，不需要逃生口。

唯一的区别是：组件只接受一个 props 记录，而不是多个位置参数。这条边界具体在哪里，见使用你的库和加固页面。

props 会在 tsc 之前检查吗？

会。Glyph 自己把每个元素与其组件的 props 记录进行比对，所以错误的值、拼错的 prop 和缺少的必需 prop 都是指出该 prop 的 Glyph 错误。无论组件是按名字导入还是通过模块导入，效果都一样：

main.glyph，Card 声明在 ui.glyph 中 
import ui

pub component App() {
  return <div>
    <ui.Card title="Q3" />
    <ui.Card title="Q4" cout={2} />
  </div>
}

// E0211 argument type mismatch: expected `CardProps`, found `record`: missing field `count`
// E0210 type `CardProps` has no field `cout`; did you mean `count`?
// E0211 argument type mismatch: expected `CardProps`, found `record`: missing field `count`

你在编辑器里和通过 MCP 都能看到它们，而不只是在完整构建中。

详情 --json 中的 missing_fields，以及只有一个 props 记录（E0229）

--json 会把缺少的名字放在 missing_fields 列表里，所以智能体不用解析信息就能补上 props。组件还必须以一个记录接收 props：component Greeting(name: string) 会在参数处报 E0229，因为 React 只会传入 props 对象，这样的元素永远无法通过类型检查。如果你是把它当函数调用而不是渲染它，就用 fn 声明。

JSX 中的 <match> 会像 match 一样被检查吗？

它们就是同一个东西。每个 <case> 接受与 match 分支相同的模式，编译器用处理分支的同一套代码来处理它。

  • 负载类型case 绑定的名字具有负载的类型，访问负载记录中不存在的字段是 E0210，缺少变体是 E0200。
  • 部分覆盖的 case对值做判断的 case 只覆盖其变体的一部分，所以需要一个同级 case 或 <case else> 来处理其余情况。
results.glyph 
type Page =
  | Loading
  | Loaded({ users: Array<User>, total: number })
  | Failed(string)

component Results(props: { page: Page }) {
  return <match value={props.page}>
    <case Loading><p>Loading...</p></case>
    <case Loaded({ users, totl })><p>{users.length} of {totl}</p></case>
    <case Failed(message)><p>{message}</p></case>
  </match>
}

// E0210 type `{ users: Array<User>, total: number }` has no field `totl`; did you mean `total`?

页面怎么启动它？

Glyph 没有顶层语句，所以由页面自己调用导出的 main。应用由两个模块组成：一个放组件，另一个通过 std/dom 和 react-dom 的 createRoot 把组件挂载到 #root 上。

事件属性使用蛇形命名（on_change 生成 React 的 onChange），处理函数是一个 lambda，输入框的文本是 e.currentTarget.value。

app.glyph 
module app

import react { useState }

pub component App() {
  let [name, set_name] = useState("")
  return <main>
    <input value={name} on_change={fn(e) { set_name(e.currentTarget.value) }} />
    <p>Hello, {name}</p>
  </main>
}
main.glyph 
module main

import react-dom/client { createRoot }
import std/dom
import std/console
import std/option { Some, None }
import app { App }

pub fn main() -> void {
  match dom.element_by_id("root") {
    Some(root) => createRoot(root).render(<App />),
    None => console.error("the page has no #root element"),
  }
}
index.html，与两个模块放在一起 
<div id="root"></div>
<script type="module">
  import { main } from "./dist/gen/main.ts";
  main();
</script>

详情 构建过程、这个 main 为什么不接受参数、完整演练

npx glyph build . --out dist/gen 检查模块，对照 React 的类型声明运行 tsc --strict，并把 TypeScript 写到 dist/gen。然后 npx vite build --outDir dist/web 读取 index.html，跟随导入，把它和 React 打包在一起。这个 main 不接受参数也不返回值，因为脚本调用它时不传参数；glyph init 生成的 main(argv) -> number 是 glyph run 在 node 下调用的那个。完整的演练（包括 package.json 和安装命令）见 glyph llms 打印的参考文档中的在浏览器页面中运行 Glyph。CI 以同样的方式构建 examples/apps/todo，并在无头 Chromium 中渲染它。

当前状态

现已提供

  • 组件、JSX、片段（<>...</>）
  • 成员表达式形式的元素名（<Ctx.Provider>）
  • JSX 属性展开（{...register()}）
  • 在任何导入写法下都会在 tsc 之前对照组件检查的 props
  • 按名字导入的 React 自己的 hooks（useState、useReducer、useEffect），由 tsc 检查类型并解构二元组（let [count, set_count] = useState(0)）
  • 带有穷尽标签联合 action 的 useReducer
  • 作为 match 检查和转换并使用分支模式的 <match>/<case>
  • 通过 createContext/useContext 使用的 Context
  • 通过 std/dom（标题、挂载点、地址）、std/storage 和 std/console 访问的页面
  • JSX 文本按 TSX 的方式读取，所以 <p>Don't stop</p> 是普通文本；文本中的 }、>、// 以及 &amp; 这样的 HTML 实体会被拒绝（E0012），并给出应该使用的写法。E0012
  • 数组上的成员读取会被检查，所以对 Array<string> 写 {items.foo} 是 E0210。E0210
  • examples/apps/todo 是一个基于 React 18 的完整应用，用 Vite 打包并在浏览器中渲染。

正在进行

  • Glyph 的检查器不推断 hook 结果的类型，所以对数字状态调用 set_count("x") 是构建中的 tsc 错误，而不是编辑器里的 Glyph 错误。
  • std/dom 只能读取页面和设置标题：React 掌管它渲染的 DOM，所以没有元素 setter，也没有事件监听器。
  • effect 必须写成 fn() -> void { ... }，因为 lambda 会返回它的最后一个表达式，React 会把它当作清理函数调用。
  • 内联写的 props 类型在这些信息中仍然显示为 record；具名的类型会显示它的名字。
  • 把 Glyph 的输出嵌入现有的 Vite 应用、UI 用 TypeScript 编写的做法，见部署指南。
