14 · 共享状态

怎样在函数之间共享可变状态？

用 store。Glyph 没有可变的全局变量，模块绑定都是 const。共享状态放在 std/store 中：一个模块级的 const，持有一个值，用 get() 读取，用 set()/update() 修改。绑定本身永远不变，变的只有它里面的值，而且只能通过方法调用，所以每一次写入都是一个可以 grep 到的 .set( 或 .update(。

看看实际效果

在模块作用域声明一次 store，模块中的每个函数都共享它。不需要在 main 里层层传递 let，也不需要捕获变量的闭包：

tasks.glyph 
import std/store { create }
import std/array

type Task = {
  id: number,
  title: string,
}

const tasks = create<Array<Task>>([])
const next_id = create(0)

fn add(title: string) -> Task {
  next_id.update(fn(n: number) -> number {
    return n + 1
  })
  let task = { id: next_id.get(), title: title }
  tasks.update(fn(cur: Array<Task>) -> Array<Task> {
    return array.push(cur, task)
  })
  return task
}

fn all() -> Array<Task> {
  return tasks.get()
}

为什么用 store，而不用可变的全局变量

这是有意的设计选择。Glyph 把 mut 限制在局部赋值上，并让模块绑定保持 const，因为散落各处的可写全局变量正是让状态难以推理、难以找到的原因。store 不需要放宽其中任何一条规则：const s 绑定是不可变的，里面的值只能通过 set/update 改变。所以共享状态是以库而不是新语法的形式提供的（没有线性类型，也没有放宽修改规则），修改集中在一个经过审查的地方，而不是分散在整个程序中。

有一个和 TypeScript 相同的坑：空集合无法推断元素类型，所以要用显式的类型参数来初始化：create<Array<Task>>([])。标量 store（create(0)）可以正常推断。

当前状态

现已提供

std/store，提供 create、get、set 和 update：共享可变状态唯一的、可以 grep 的归属地。

正在进行
