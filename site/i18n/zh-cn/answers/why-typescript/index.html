为什么是 TypeScript，而不是 Go 或者一门全新的语言？

因为智能体写得最多的代码就是 TypeScript，你的生态（npm、React、Node）也在这里。Glyph 能逐个文件地引入，正是因为它的目标语言是 TS。

为什么重要

一门新语言的成败，取决于从零到上线的路有多长。编译成 TypeScript 意味着你不用离开自己的代码库、打包工具、测试运行器或部署流程。Glyph 直接放在你已有的 .ts 文件旁边，两个方向的导入都很顺畅：

同一个项目：.glyph 与 .ts 并存 
// cart.glyph: new, written in Glyph
import { formatPrice } from "./format.ts"

// checkout.ts: existing, untouched
import { total } from "./cart.glyph"

你没法把 Go 逐个文件地放进 TypeScript 代码库：它是不同的运行时、不同的模块系统、不同的生态。仅这一点，就决定了目标语言是 TS。

关于 Go 的合理观点：它的关键字少而稳定，智能体出错的方式也就更少。我们同意：这正是 Glyph 有意保持一个小核心、每件事只有一种做法的原因。我们的密度基准测试中包含了 Go，可以直接比较。

当前状态

现已提供

干净的 TypeScript 输出，与你现有 .ts 文件的双向导入，以及一个能在任何 Node 或浏览器打包环境中运行的小核心。

正在测量

跨语言基准测试（Glyph、TS、Go、Python、Rust）随语料库一起扩充，所以“语法面小”这个说法始终是一个数字，而不是一句断言。
