设计 · 比较

Glyph 与 Effect

两者的目标都是让人和智能体都能信赖的 TypeScript。Effect 是一个库：你继续写 TypeScript，并获得类型化的错误、可追踪的依赖和一个很大的工具箱。Glyph 是一门编译到 TypeScript 的语言，所以它可以拒绝 TypeScript 允许的写法，包括那些会抵消库所提供保证的类型断言。Effect 要成熟得多。

Effect 如何描述自己

Effect 首页的标题是 "Reliable TypeScript for the AI era"，并称它的 "declarative patterns and strong type system make it easier for LLMs to generate correct, production-ready code"（effect.website）。它的文档称它是 "an ecosystem of tools that help you build better applications and libraries"，围绕 Effect<Success, Error, Requirements> 类型构建，这个类型记录一次计算返回什么、可能怎样失败、需要什么（Why Effect）。它要求 TypeScript 5.4 或更新版本，并打开 strict（Installation）。这些引文读取于 2026-11-19。

库与语言之别带来的差异

Effect 的类型由 tsc 检查，所以凡是 tsc 允许的，在它旁边照样允许。下面这段代码在 effect 4.1.4 和 TypeScript 6 下能通过 tsc --strict。类型断言把 NotFound 从错误通道中去掉了，于是一个类型上声明不会失败的 effect，程序却报告了失败。

eff.ts：tsc --strict 退出码为 0；运行后打印 "Failure undefined" 
import { Effect } from "effect"

class NotFound {
  readonly _tag = "NotFound"
}

const find = (id: string): Effect.Effect<number, NotFound> =>
  id === "1" ? Effect.succeed(1) : Effect.fail(new NotFound())

// The error channel says NotFound can happen. A cast erases it.
const quiet = find("2") as unknown as Effect.Effect<number, never>

// And a parsed body still takes any type you name.
type User = { email: string }
const user = JSON.parse("{}") as User

console.log(Effect.runSyncExit(quiet)._tag, user.email)

同一个函数在 Glyph 中返回 Result，而且没有类型断言可写。第二个模块在生成任何 TypeScript 之前就被拒绝了。

find.glyph：能构建，能通过 tsc --strict 
module find

pub type NotFound = { id: string }

pub fn find(id: string) -> Result<number, NotFound> {
  return match id == "1" {
    true => Ok(1),
    false => Err({ id: id }),
  }
}
加上类型断言：被拒绝 
module find

pub type NotFound = { id: string }

pub fn find(id: string) -> Result<number, NotFound> {
  return match id == "1" {
    true => Ok(1),
    false => Err({ id: id }),
  }
}

pub fn quiet() -> number {
  let n = find("2") as number
  return n
}

E0013 的帮助信息是："Glyph has no as cast ... to turn an unknown into a type, validate it with T.parse(v) or narrow it with match and is." 在 Effect 代码库中，团队可以用 lint 规则做到接近的效果，那篇比较说明了为什么一条可以被关掉的规则是另一种性质的保证。

Glyph 能做而库做不到的事

语言决定了什么能写出来。Glyph 没有 any，没有类型断言，没有非空断言，也没有能屏蔽错误的注释，而且对联合类型的每个 match 都必须覆盖每种情况。记录和联合类型带有根据声明生成的运行时检查，所以 json.parse<User>(body) 会做校验。Effect 的 Schema 也是从一份描述推导出类型（见它的介绍中的 Schema.Schema.Type<typeof Person>），所以在那里类型和校验器也不会出现偏差；区别在于，TypeScript 中没有任何东西强制代码库使用它。编译器还能为智能体回答关于程序的问题，比如某个改动会破坏什么，通过 MCP 或命令行都可以。

本页没有测试过在 Glyph 模块内部使用 Effect，所以对两者结合使用不做任何断言。
