在真实应用里做一次改动

examples/apps/csvql 是本仓库里的一个 CSV 查询引擎，核心是一个 Value 联合类型。给它加一个新 case 之前，先问编译器这会影响到哪些地方。

glyph_variants { name: "Value" } 
10 match sites across 4 files
 8 will fail compilation
 2 contain a catch-all and will silently absorb it
然后加上这个 case，运行 glyph check 
8 errors, E0200 non-exhaustive match. The same eight.
The two catch-all sites report nothing at all.

预测的八处全部命中。另外两处，exec::total 和 render::literal_text，仍然能编译通过，并把新的 case 交给各自的 catch-all 分支处理。一个修完这八个错误就停手的智能体，会得到一个通过的构建和两个仍然存在的 bug，而指出这两处的正是那次查询。
