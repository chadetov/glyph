支柱 03 · 打磨

抽象

用一个小而正交的核心表达你的本意：用模式匹配代替一长串 switch，用 Result 代替抛出异常，用具名记录代替元组。每个概念一种好的写法，而不是 TypeScript 那样层层堆积的特性。

同一件事有太多种写法

TypeScript 是一层层堆积起来的，而且每一层都保留了下来。

  • 固定的情况一组固定的情况，你可以用 enum、字符串字面量联合或 const 对象来建模。
  • 结构一个结构，你可以用 interface、type 或 class 来描述。
  • 其他一切有 namespace 和模块，有装饰器和高阶函数，几乎每件事都有五种惯用写法，每种都有自己的边界情况。

对人来说这是灵活性。对智能体来说这是雷区：表达一件事的方式越多，选中那个有坑的方式的可能就越大，同时要分清的惯用法也越多。

Glyph 的抽象支柱是一次有意的做减法：每项工作一把趁手的工具，选择的标准是让最直观的写法同时也是安全的写法。

01 match 是唯一的条件结构

没有 if/else 语句。分支一律用 match，而 match 是表达式：它会产生一个值。

一种结构就涵盖了布尔判断、联合类型分派和值查找表，所以不需要纠结该用哪种分支形式。

02 标签联合与模式匹配

表达“这几种结构之一”的方式是标签联合，拆开它的方式是 match，它在选择情况的同一步就解构了负载。

feed.glyph 
type Feed =
  | Loading
  | Loaded(Array<Post>)
  | Failed(string)

fn view(feed: Feed) -> string {
  return match feed {
    Loading => "...",
    Loaded(posts) => render(posts),   // posts is Array<Post> here
    Failed(msg) => msg,               // msg is string here
  }
}
详情 你不再需要手写的东西

不需要手动维护判别字段，不需要对字符串标签写一长串 switch，也不需要在每个分支里做类型断言来恢复结构。

03 用 Result 代替异常

失败是一个值，而不是隐藏的控制流跳转。可能失败的函数会在返回类型中写明（Result<T, E>），你用 ? 运算符组合各种失败，而不是把调用处包进 try/catch，然后指望正确的地方抛出正确的类。

出错路径和正常路径一样清晰可见。

04 用具名记录代替按位置的元组

数据总是用具名字段来描述。结构在定义处、构造处和使用处读起来都一样。

TypeScript：[0] 和 [1] 是什么？ point.ts 
function origin(): [number, number] {
  return [0, 0];
}
const p = origin();
p[0]; p[1];  // x? y? row? col?
Glyph：名字跟着值走 point.glyph 
type Point = { x: number, y: number }

fn origin() -> Point {
  return { x: 0, y: 0 }
}
详情 没有简写，没有匿名元组

没有对象字面量简写，也不会去用一个匿名元组，让你记住它的 [0] 和 [1] 分别是什么。

05 每项工作一个基础构件

当一个概念需要专门的工具时，Glyph 只给它一个。

  • 共享状态共享的可变状态放在 std/store 中。
  • 句柄必须且只能关闭一次的文件或 socket 句柄是 owned 资源。
  • 迭代迭代用 for x in xs。

每一个都是单一、具名、专门设计的基础构件，而不是一种要从一堆通用零件里重新拼凑、又容易出细微错误的模式。

这里的抽象指的是更少、更趁手的工具，而不是更多。每个概念都有一种直观的形式，而这种直观的形式就是你应该用的那种。
