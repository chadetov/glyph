支柱 02 · 切入点

可检索性

一个名字，一个位置。每个符号在声明处都只有一种语法形式，所以普通的 grep 总能找到定义，不需要索引，不需要语言服务器，也不需要运气。

为什么“这是在哪里定义的？”很难回答

在一个成熟的 TypeScript 代码库中，最简单的问题，这个名字是从哪里来的？，往往最难回答。语言提供了五六种把一个符号分散到多处的方式：重载把一个函数拆成好几个签名，装饰器把它包进别的东西里，namespace 和 interface 合并把一个类型分散到多个文件，declare module 扩充你并不拥有的代码，barrel index.ts 文件重新导出一切，所以你导入的路径并不是任何东西真正所在的地方。

人可以靠 LSP 和肌肉记忆应付。智能体则用 grep：它把仓库当文本来读，而上面每一种结构都是文本在代码位置上撒谎的地方。Glyph 去掉了它们。结果是一门搜索可以作为可靠基础操作、而不是靠猜测的语言。

01 一个声明，一种形式

函数、类型或组件只声明一次，用一种语法。没有拆分签名的重载，也无法重新声明一个名字：两个同名的顶层定义是硬错误（E0100）。所以查找定义只有唯一的答案。

TypeScript：四个匹配，其中一个是函数体 $ grep -n "parseUser" src/ 
users.ts:4:  export function parseUser(
users.ts:9:  export function parseUser(
index.ts:2: export { parseUser } from
api.ts:7:   import { parseUser } from
Glyph：第一个匹配就是定义 $ grep -n "fn parseUser" src/ 
users.glyph:12:fn parseUser(
  raw: unknown,
) -> Result<User, string> {

声明关键字是你搜索的名字的一部分。grep "fn parseUser" 不会匹配到调用、导入或重新导出，只会匹配它被定义的那一处。

02 没有 barrel 文件：导入路径就是位置

Glyph 的导入从不重新导出，只包含导入的模块会被拒绝（E0102）。没有 index.ts 那样的中转层。所以导入写的就是符号真正所在的模块：路径就是地址。

导入准确告诉你该去哪里找 
import myapp/users { parseUser }
//     ^^^^^^^^^^^ the file is src/myapp/users.glyph.
//     not a re-export of a re-export of a barrel.

03 没有隐藏的方式附加行为

没有把函数包进看不见的一层的装饰器，没有从整个目录树汇集成员的 namespace 合并，没有在一个你绝不会想到去打开的文件里扩充第三方类型的 declare module，也没有改变方法所指对象的隐式 this。一个名字只解析到一个声明，塑造它的一切都在那个声明处可见。

04 连修改都能 grep 到

可检索性不只是找到定义，还包括找到副作用。共享状态放在 std/store 中，对它的每次修改都是字面上的 .set( 或 .update( 调用。所以一次搜索就能列出一份状态的全部写入点，而不用去找散落在文件各处的赋值。

$ grep -rn 'tasks\.\(set\|update\)' src/ 
src/tasks.glyph:16:  tasks.update(fn(cur) { ... })
src/tasks.glyph:24:  tasks.set([])
# every place the task list can change, enumerated.
# nothing hides in an ordinary `x = ...` elsewhere.

当一个代码库的文本如实反映它的结构时，它就是可检索的。这里的每项限制（每个名字一种形式、不重新导出、不合并）都是为了让搜索返回答案，而不只是线索。

规模越大、自主程度越高，收益越明显。人会慢慢摸清一个代码库的隐藏角落；从零开始的智能体则不会。可检索性让工具（或新同事）可以通过阅读来导航，看到的就是仓库真实的样子。

“一条 lint 规则就能禁止重载和装饰器”

在你自己的仓库里，可以。ESLint 能禁止命名空间，团队也可以约定不用重载。但语言仍然允许这一切，所以这个保证只在配置存在时有效，而且只覆盖配置作用到的代码。对依赖、生成的文件或别人的仓库做 grep 时，不能指望它。在 Glyph 中这些结构根本不存在，所以 grep 在每个 Glyph 文件上都一样有效，包括你们团队没人配置过的文件。

从智能体的角度看会是什么样，用一次搜索找到定义或找到对某个值的每次写入，在智能体（或者我）能找到任何东西的定义位置吗？中有解答。
