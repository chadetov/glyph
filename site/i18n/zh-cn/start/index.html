从这里开始 · 约 10 分钟

你的第一个 Glyph 程序

创建一个项目并运行，然后故意把它改错，读一读编译器给出的报错。不需要任何 Glyph 基础。只要写过一点 TypeScript，每一行你都能看懂。

1 · 创建项目

Glyph 以预编译二进制的形式发布在 npm 上，支持 macOS 和 Linux（x64 和 ARM）以及 Windows（x64），需要 Node 18 或更高版本。这种方式不会全局安装任何东西：npx 临时获取编译器来创建项目，项目自己固定一份编译器副本，以及 Glyph 用来运行和类型检查的 tsx 和 typescript。

终端 
npx -y @glyphlang/glyph init hello
cd hello
npm install

如果你更想让 glyph 出现在 PATH 里，可以把它和它依赖的两个工具一起全局安装，然后去掉本页命令里的 npx：

终端，全局安装的方式 
npm install -g @glyphlang/glyph tsx typescript
glyph doctor                    # confirms your toolchain is ready
glyph init hello
cd hello

2 · 看看它生成了什么

glyph init 会创建一个可以直接运行的起始项目：src/main.glyph；src/.types/README.md，说明带类型的 npm 包在这里什么都不需要，这个目录是给不带类型的包用的；一个 package.json；一个 .gitignore；以及两个编码智能体会自己读取的文件：AGENTS.md，它指向 glyph llms 以获取完整的语言参考，和 .mcp.json，它注册了 glyph mcp，让智能体可以直接向编译器查询类型和引用，而不用自己去搜索。在已有的项目里，glyph agents 会写入这两个文件。package.json 在 devDependencies 中固定了编译器、typescript 和 tsx 的版本，所以任何人克隆项目后，只需 npm install 就能构建，不需要全局安装。

打开 src/main.glyph。这是一个 hello-world：

src/main.glyph 
module main

import std/io

fn main(argv: Array<string>) -> number {
  io.println("hello from glyph")
  return 0
}

有两点值得注意：程序运行的是它的 main(argv)，而 main 返回一个 number，也就是进程的退出码。返回只是设置退出码，并不会强制进程停止，所以启动了服务器的程序会继续提供服务。

3 · 运行

终端 
npx glyph run
hello from glyph

glyph run 对它做了类型检查，编译成 TypeScript，然后执行。本页接下来就是重复这个循环。

4 · 加点真东西

现在把函数体换成一小段逻辑：一个任务状态，以及一个给它打标签的函数。这里引入了两个你会经常用到的东西：标签联合（type Status = ...）和 match，后者是 Glyph 唯一的条件分支结构。

src/main.glyph 
module main

type Status = Todo | Doing | Done

fn label(s: Status) -> string {
  return match s {
    Todo => "not started",
    Doing => "in progress",
    Done => "finished",
  }
}

fn main(argv: Array<string>) -> number {
  print(label(Done))
  return 0
}
终端 
npx glyph run
finished

5 · 故意改错

这一部分会告诉你 Glyph 是用来做什么的。从 match 中删掉 Done 分支（智能体在某处新增了一种情况却忘了处理时，做的就是这种事），然后再运行一次。

src/main.glyph（删掉了 Done 分支） 
fn label(s: Status) -> string {
  return match s {
    Todo => "not started",
    Doing => "in progress",
  }
}
$ npx glyph run 
[E0200] Error: typecheck: non-exhaustive match on `Status`: missing variants `Done`
   ╭─[main:6:10]
   │
 6 │ ╭─▶   return match s {
   ┆ ┆
 9 │ ├─▶   }
   │ ╰───────── missing variants `Done`
   │
   │  Help: Add an arm for each missing variant.
───╯

它没有运行。在 TypeScript 中，写明了返回类型的同一个函数也会被拒绝（TS2366）。但只记日志或更新状态、或者带有 default: 的 switch 能顺利编译，并悄悄跳过新增的情况。在这里，每个不穷尽的 match 都是编译错误，带有稳定的错误码（E0200）、准确的位置和一行修复建议。想看详细说明时，随时运行 glyph --explain E0200。

6 · 修好它

把分支加回去（或者加一个 else），它就又能运行了。

终端 
npx glyph run
finished

这就是核心循环：写代码、运行，出问题时编译器会在代码上线之前，而不是之后，准确告诉你哪里错了、该怎么改。
