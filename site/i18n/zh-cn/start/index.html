从这里开始 · 约 10 分钟

你的第一个 Glyph 程序

创建一个项目并运行，然后故意把它改错，读一读编译器给出的报错。不需要任何 Glyph 基础。只要写过一点 TypeScript，每一行你都能看懂。

1 · 创建项目

Glyph 以预编译二进制的形式发布在 npm 上，支持 macOS 和 Linux（x64 和 ARM）以及 Windows（x64），需要 Node 18 或更高版本。这种方式不会全局安装任何东西：npx 临时获取编译器来创建项目，项目自己固定一份编译器副本，以及 Glyph 用来运行和类型检查的 tsx 和 typescript。

终端 
npx -y @glyphlang/glyph init hello
cd hello
npm install

如果你更想让 glyph 出现在 PATH 里，可以把它和它依赖的两个工具一起全局安装，然后去掉本页命令里的 npx：

终端，全局安装的方式 
npm install -g @glyphlang/glyph tsx typescript
glyph doctor                    # confirms your toolchain is ready
glyph init hello
cd hello

2 · 看看它生成了什么

glyph init 会创建一个可以直接运行的起始项目：src/main.glyph；src/.types/README.md，说明带类型的 npm 包在这里什么都不需要，这个目录是给不带类型的包用的；一个 package.json；一个 .gitignore；以及两个编码智能体会自己读取的文件：AGENTS.md，它指向 glyph llms 以获取完整的语言参考，和 .mcp.json，它注册了 glyph mcp，让智能体可以直接向编译器查询类型和引用，而不用自己去搜索。在已有的项目里，glyph agents 会写入这两个文件。package.json 在 devDependencies 中固定了编译器、typescript 和 tsx 的版本，所以任何人克隆项目后，只需 npm install 就能构建，不需要全局安装。

打开 src/main.glyph。这是一个 hello-world：

src/main.glyph 
module main

import std/io

fn main(argv: Array<string>) -> number {
  io.println("hello from glyph")
  return 0
}

有两点值得注意：程序运行的是它的 main(argv)，而 main 返回一个 number，也就是进程的退出码。返回只是设置退出码，并不会强制进程停止，所以启动了服务器的程序会继续提供服务。

3 · 运行

终端 
npx glyph run
hello from glyph

glyph run 对它做了类型检查，编译成 TypeScript，然后执行。本页接下来就是重复这个循环。

4 · 加点真东西

现在把函数体换成一个要紧的决定：根据付款状态，决定是否发货。这里引入了两个你会经常用到的东西：标签联合（type Payment = ...）和 match，后者是 Glyph 唯一的条件分支结构。

src/main.glyph 
module main

type Payment = Pending | Paid | Failed

fn ship(p: Payment) -> string {
  return match p {
    Pending => "hold: waiting for the money",
    Paid => "ship it",
    Failed => "hold: payment failed",
  }
}

fn main(argv: Array<string>) -> number {
  print(ship(Paid))
  return 0
}
终端 
npx glyph run
ship it

5 · 故意改错

这一部分说明 Glyph 是为了什么而存在的。一个工单写着“支持退款”，于是给 Payment 加上 Refunded，不去动 ship。智能体在一个文件里改了类型、却从没打开根据这个类型做判断的代码时，做的正是这件事。再运行一次。

src/main.glyph（多了一个词） 
type Payment = Pending | Paid | Failed | Refunded
$ npx glyph run 
[E0200] Error: typecheck: non-exhaustive match on `Payment`: missing variants `Refunded`
    ╭─[ main:6:10 ]
    │
  6 │ ╭─▶   return match p {
    ┆ ┆
 10 │ ├─▶   }
    │ ╰───────── non-exhaustive match on `Payment`: missing variants `Refunded`
    │
    │     Help: Add an arm for each missing variant.
────╯

它没有运行。大多数代码所用的 TypeScript 则相反：一个处理了两种 "hold" 情况、以 default: return "ship it" 结尾的 switch，在加入新情况后依然能通过 tsc --strict，并把每一笔已退款的订单都发出去。在这里，任何漏掉情况的 match 都是编译错误，带有稳定的错误码（E0200）、确切的位置和漏掉的情况名。想看详细说明时，随时运行 glyph --explain E0200。

6 · 修好它

退款对发货意味着什么，编译器无法替你决定，这由你来定。加上这个分支，程序就又能运行了。

src/main.glyph 
fn ship(p: Payment) -> string {
  return match p {
    Pending => "hold: waiting for the money",
    Paid => "ship it",
    Failed => "hold: payment failed",
    Refunded => "hold: refunded, nothing to ship",
  }
}
终端（改为 print(ship(Refunded)) 时） 
npx glyph run
hold: refunded, nothing to ship

这就是核心循环：写代码、运行，出问题时编译器会在代码上线之前，而不是之后，准确告诉你哪里错了、该怎么改。
