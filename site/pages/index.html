Your AI agent writes it. The compiler checks it.

Glyph reads like TypeScript, with the escape hatches removed: no any, no casts, no unchecked data, every case handled. It compiles to readable TypeScript, so you keep node, npm and the code you already have.

$ npx -y @glyphlang/glyph init hello && cd hello && npm install && npx glyph run

No global install needed. To put glyph on your PATH instead: npm install -g @glyphlang/glyph tsx typescript

Your agent can ask the compiler first

examples/apps/csvql is a CSV query engine in this repository, with a Value union at its centre. Before adding a Date case to it, an agent asks the compiler's MCP server what that edit breaks. The answer, trimmed here to verdict, site and function, names ten match sites across four files.

ABSORBS    exec.glyph:130    exec::total
ABSORBS    render.glyph:128  render::literal_text

WILL_FAIL  value.glyph:32    value::key

the change at an ABSORBS site: the catch-all becomes named arms 
 fn literal_text(v: Value) -> string {
   return match v {
     Text({ text }) => "'${text}'",
-    else => value.render(v),
+    Date({ iso }) => "'${iso}'",
+    Num({ n }) => value.render(v),
+    Bool({ flag }) => value.render(v),
+    Null => value.render(v),
   }
 }

Each WILL_FAIL entry comes with the error it will raise, and adding the case alone gave exactly those eight E0200 errors. The two ABSORBS sites raise nothing: render::literal_text would have printed a date literal without its quotes, and exec::total would have counted every date as zero. An agent working from compiler errors alone fixes eight sites and stops with a green build. Asked again after the fix, the compiler answers WILL_FAIL at all ten, so the next case cannot slip past either.
