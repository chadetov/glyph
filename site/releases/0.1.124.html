--- version: 0.1.124 month: 2026-09 tags: breaking ---

This release closes the holes a two-agent experiment would have found first, so that the study the roadmap gates 0.2.0 on measures the language rather than a checker that still leaned on tsc. It is breaking in four places, each established by running 0.1.123 and this build on the same program: an object literal that does not fit its declared type, a JSX attribute that does not fit its component's props, a wrong argument type to one of eleven stdlib modules, and a single-file check of a nested file in a tree with no package.json marker, which now agrees with the project build. All four went from exit 0 to exit 1 under glyph check --no-tsc.

An object literal has a type

Until now the checker typed { x: 1 } as nothing at all. let g: string = { x: 1 }, a literal missing a field the declared record requires, and a literal passed to a parameter it does not fit all passed glyph check and were caught by tsc at the end of the build, which means the editor, the MCP tools and --no-tsc were blind to them.

glyph check --no-tsc 
type User = { name: string, age: int }
fn takes(u: User) -> int { return u.age }

let g: string = { x: 1 }
let u: User = { name: "a" }
let c = { name: "a" }
takes(c)
// 0.1.123: nothing                                    (exit 0)
// 0.1.124: [E0204] expected `string`, found `record`
//          [E0204] expected `User`, found `record`
//          [E0211] expected `User`, found `record`       (exit 1)

A spread-free object literal is the structural record of the fields it writes, compared structurally at a let, a const, a return and a call argument, with the declared type named. The type survives a binding: let c = { name: "a" } carries { name: string }, with a fresh string literal widened the way TypeScript widens it, so a misspelled key read back off it is E0210. Every refusal was established against tsc --strict one shape at a time, and every accepted shape but one still passes it. Two things deliberately do not change: a literal holding a spread has no type, because its fields are not enumerable there, and an extra field the record does not declare is still accepted, which is the width rule the record comparison has always applied and which tsc does not share on a fresh literal (TS2353); that divergence predates this release and is pinned by a test so it cannot move silently. What still stops short is the message for a missing field, found `record` where tsc names the property; that is the first item of the next release.

A JSX attribute is checked against the props record

With component Button(props: { variant: Variant, label: string }) over a "primary" | "danger" union, all of variant="danger", variant="nope" and variant={42} passed glyph check --no-tsc. An attribute list never reached the assignability relation.

glyph check --no-tsc 
<Button variant="nope" label="go" />
<Button variant="danger" labl="go" />
// 0.1.123: nothing                                    (exit 0)
// 0.1.124: [E0211] expected `Variant`, found `"nope"`
//          [E0210] type `Props` has no field `labl`      (exit 1)

A component element's written attributes go through the same argument-versus-parameter check a call does, so a wrong value is E0211 carrying the values a string-literal union accepts, and an undeclared attribute is E0210 with the record's field list, which glyph fix renames when one declared field is a character away. It holds across an import, where the props record keeps its own name. Three readings were settled by running the equivalent TypeScript under React 18's types: children ride as createElement arguments and are not a prop; an element carrying a spread may get its props from the spread, so it is not asked about a missing attribute, but what it writes explicitly is still checked; and an optional field may be omitted. A missing required attribute is still caught only by tsc, for the same reason as the record literal above. The work also found two holes it did not fix, recorded as G242 and G243: a component reached through a lowercase namespace alias, <ui.Button />, is classified by its first character and emitted as a string tag that React never calls while tsc accepts it, and component Greeting(name: string) is accepted although no element can ever render it. Both are in 0.1.125.

The editor answers across a module boundary

glyph query hover answered at every name declared in another module and the language server did not: its overlay registered the buffers the editor had opened, not a project, so hovering an imported function at its call site, or a field read off an imported record, came back null where the tool answered.

textDocument/hover, over the protocol, at the call to an imported create 
// 0.1.123: null
// 0.1.124: fn(string) -> Order

The server now holds one database per project the session touches, with the open buffers layered over the files on disk rather than standing in for them. A file is placed in the project its imports are counted from, which is the root glyph query uses and glyph build compiles from, so the two surfaces ask the same question and hover, definition, references and diagnostics agree with the tool. A buffer the editor has open outranks the bytes on disk everywhere, not only in the file the request is about: retyping a signature in an unsaved orders.glyph changes what hovering its call site in main.glyph says, and closing it without saving puts disk back in charge. A keystroke writes one input and re-registers nothing, and a body edit leaves a module's export surface content-equal so no sibling is re-analysed; measured on the latency lane's three files, a keystroke costs between one and nine percent more than it did single-file. Hover itself is now one function both surfaces call, which is how they came to give one answer.

Eleven stdlib modules carry a type in every position

The stdlib tables modeled a function's arity and its return and left every parameter unknown, so fs.read_text(42) passed glyph check --no-tsc and only tsc refused it. std/fs, std/math, std/regex and std/io now carry a type in every position of every function, and std/array, std/string, std/record, std/path, std/process, std/time and std/timers in every position but four, each of which says so on its row. Fully modeled exports go from 24 to 117 of 327; exports with no signature at all from 227 to 164. Every type was read off the TypeScript in the runtime, so a call these refuse is a call tsc refuses; eight such calls are pinned in the negative corpus, each exit 0 under 0.1.123 and refused here. Three exports of std/fs are new rather than retyped, because the old table could only describe a function returning a Result: exists, is_dir and close_lines have a row now, and io.read_line and process.env answer Option<string>, so the end of input and an unset variable are values a match has to cover. The four positions left unknown are a T the unifier has already bound from an earlier argument (array.push, array.contains, array.index_of, record.set), where writing the declared type would refuse array.contains(["a", "b"], s); the unifier change that fixes that is its own release.

A diagnostic says what kind of names it lists, and a file has one name

alternatives carried a record's fields, a union's variants, a string-literal union's literals or a module's exports with nothing in the object saying which, so check --agent re-read glyph_symbol to find out and dropped its sentence for an inline union. Every diagnostic now carries alternatives_kind beside it, one of fields, variants, literals or exports, set where the error is raised and null exactly when alternatives is. alternatives itself is unchanged. Separately, a nested file in a tree with no package.json marker was sub/deep to glyph check and deep to the tools, because the build keyed it from the nearest src/ and the tools from its own directory. One rule on every surface now, written into D41: the nearest marked ancestor, else the nearest ancestor named src, else the file's own directory. That is the fourth breaking change: checking src/sub/deep.glyph alone used to accept an import the project build rejected, and now agrees with it.

Smaller things

glyph fmt no longer writes a file its own parser refuses: the formatter prints every unary operand in parentheses, and the parser charged a nesting level for the operand and another for the parentheses, so a run of forty minuses came back at eighty levels and the next pass drew E0011 on output the previous pass had produced. Parentheses around an operand are now that operand's level, so -(x) nests as deep as -x; the limit is still 64 and a run of bare parentheses is still counted one per bracket. The spec numbered two decisions D43; the mut-across-await rule keeps the number the shipped notes cite, and never as the bottom type is D47, with the old number noted on it, so glyph llms --json reports no duplicate. And the benchmarks page on this site had kept a withdrawn token figure for two weeks after the fixtures were made to compile; it now carries the measured 436 to TypeScript's 478, and the doc-claims gate reads the newest results file so the two cannot disagree again.

One planned item did not ship. The publish workflow was to move to npm trusted publishing before this tag; a trusted publisher is configured per package on npmjs.com by the account owner, and that was not done in time, so this release publishes on the token path and the move heads 0.1.125.
