--- version: 0.1.125 month: 2026-10 tags: breaking ---

This release is about React components. Three programs passed glyph check with tsc in the loop under 0.1.124 and were broken when they ran: a component reached through import ui was emitted as a string tag and never called, an element with no attributes passed null as its props, and an unexported component reached through a namespace was accepted. All three are Glyph diagnostics now. It is breaking for that reason, and for two more programs that 0.1.124 left to tsc: a component whose parameter is not a record, and an element missing a required prop. Each was established by running 0.1.124 and this build on the same program.

A dotted element is a component

An element was classified by the first character of its name, so <ui.Button /> under import ui was treated like <div> and emitted as createElement("ui.Button", ...). React rendered an unknown tag, tsc accepted a string tag with any props, and the only diagnostic was a wrong "unused import ui".

import ui, then a wrong attribute 
<ui.Button variant="nope" label="go" />
// 0.1.124: [E0106] unused import `ui`     tsc --strict passed  (exit 0)
//          renders <ui.Button variant="nope" label="go"></ui.Button>
// 0.1.125: [E0211] expected `Variant`, found `"nope"`           (exit 1)
//          renders <button>go</button> once the value is fixed

A dotted name is a component whatever the case of its base, which is TypeScript's rule for a member-expression tag. One classifier now decides it, where the resolver and the emitter each kept their own copy. The base resolves like any name, the props check reaches the component through a namespace or an aliased import, and the member goes through the same export check ui.Button does as a value, so <ui.Nope /> and an unexported component are E0105.

A missing required prop is named, even with no attributes

A record literal or an element missing a required field was refused as found `record`, or at the element not at all. The diagnostic now names what is missing, in the message and in a missing_fields list on --json, --agent and the MCP diagnostics.

glyph check, with tsc 
<Button label="go" />
<Button />
// 0.1.124: first line caught by tsc only; second line passes  (exit 0)
// 0.1.125: [E0211] expected `Props`, found `record`: missing field `variant`
//          [E0211] expected `Props`, found `record`: missing fields `variant`, `label`

The second line is the one that mattered. An element with no attributes was emitted with null props, and React's types accept null for any component, so <Button /> against required props passed tsc --strict and the component read undefined when it rendered. It passes {} now, so tsc refuses it too, and Glyph asks every component element without a spread for its required props. A ? prop may be left out. A required children prop is reported missing even when children are written between the tags, because they are passed outside the props object; tsc says the same, and the message should explain it and does not yet.

A component takes one props record

component Greeting(name: string) was accepted, and no element could ever render it: React hands a component the one props object its element builds. It is E0229 at the parameter now, for a primitive, a string-literal union, a tagged union, an array, a Nullable or a function type. A record, an alias of one, an imported record and an interface are props records. unknown and a bare generic draw nothing, because the checker cannot prove they are not records. A function that returns JSX and is called directly is an fn.

References, rename and impact see an element at its name

After the classification fix, glyph query references on a component still listed a use written <Button> under a named import and missed the same use written <ui.Button>, so the answer depended on how the component was imported, and glyph_impact missed the site. The named case was wrong too: it recorded the whole element, so a rename wrote the new name over the attributes and children, and the closing tag was never recorded. Every element is now recorded at its name, in the opening and closing tag alike. Rename rewrites both tags, and impact counts one site per element. Hover on Button in <ui.Button> answers the component's type instead of null. Two explanations in the impact table were false for an element and an import line, and each now has its own; the verdicts did not change.

Smaller things

Two glyph check runs at the same time could fail each other with io error reading .../glyph-check-scratch/<pid>-0/: Invalid argument: each staged under a shared temp directory and removed it on the way out. 2,000 concurrent checks gave 3 such failures; each check now owns its own directory, and 4,000 gave none. Publishing moved to npm trusted publishing, so no npm token is stored anywhere, and before the first package is published the release job proves each of the six packages' publisher through the same OIDC exchange a publish makes. Across the 31 apps and the examples, every exit code and diagnostic code is the same under both versions, with and without tsc.
