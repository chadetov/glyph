--- version: 0.1.126 month: 2026-10 tags: breaking ---

This release finishes what 0.1.125 started on React components: the type a component returns now means something to tsc, go-to-definition works through a namespace import, and impact answers the same for a call however its callee was imported. It is breaking in two places, each established by running 0.1.125 and this build on the same program: a component whose parameter is unknown or an unbounded type parameter is E0229, and ? inside a component body is E0201.

A component returns a type tsc can read

Component is a prelude name, and -> Component is how a component declares that it returns a rendered element. The emitter wrote the bare word into the TypeScript, which tsc could not resolve. The flagship React example only got past that by importing React's Component class over the prelude name, which tsc refuses for a different reason.

glyph check, with React 18's types 
fn view() -> Component { return <p>hi</p> }
pub component App() -> Component { return <div>{view()}</div> }
// 0.1.125: [TS2304] Cannot find name 'Component'      (twice, exit 1)
// 0.1.126: tsc --strict passed                         (exit 0)

The prelude Component now lowers to React.ReactNode. It was picked by running tsc on every value a component can return in Glyph: an element, a fragment, an <if> without an <else> (which yields null), a <match> and a <for> list. ReactNode is the narrowest type that accepts all of them. A component with no annotation now returns Component too, where the checker used to record void, so hover and glyph_symbol read fn(Props) -> Component. A module whose JSX lives only in plain functions now gets its import * as React line. One edge: React's types before 18.2.8 refuse a function component that returns ReactNode.

Two things a component cannot be

A component whose parameter is unknown or an unbounded type parameter receives a props object it can read nothing from, and tsc refuses its elements once they write attributes. Both are E0229 now, like a primitive. A type parameter bounded by a record or interface is still allowed. And ? in a component body used to compile and hand React the Err object to render; now that a component's return type is Component, it is E0201 like ? anywhere that does not return a Result.

glyph check --no-tsc 
component G(p: unknown) { return <p>x</p> }
pub component App() {
  let v = get()?
  return <p>{v}</p>
}
// 0.1.125: nothing                                            (exit 0)
// 0.1.126: [E0229] ... parameter `p` is `unknown`, which gives it nothing it can read
//          [E0201] ...                                         (exit 1)

Go-to-definition through a namespace

Under import ui, go-to-definition on Button in ui.Button or <ui.Button> answered nothing, and on Props in ui.Props it jumped to the import line. It now answers the declaration in ui.glyph, as the named import import ui { Button } always did, in the editor and in glyph_definition alike. A test drives it over the language server protocol under all three import spellings.

Impact, and a missing children prop

A call written ui.fmt(1) was filed as a reference and answered "not indexed", where fmt(1) under a named import was a call that will fail. Both are calls now, with the same verdict and reason. An import line under an edit that keeps the name (a changed parameter type, an added parameter) is SAFE: an import checks only that the name exists and is exported, which was confirmed by reading every check at an import line and by making the edits. And when a required children prop is reported missing on an element that writes children, the help now says why: children between the tags are passed outside the props object, so declare children?: or pass children={...}.

The React page, corrected

The React answer page showed hooks named use_state and use_reducer. They existed only in a stub this repository uses for CI, not in React. A round that built a small app against real React 18 found it, along with what does not work yet. Browser globals such as document can't be named, so an effect that sets the page title can't be written. And a hook's tuple has to be read by index. The page now shows React's real useReducer and says both of those plainly. A typed std/dom module and let [a, b] = ... are planned. Across the 31 apps and the examples, the only verdict that changed is the React example, which went from failing tsc to passing.
