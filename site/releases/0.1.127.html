--- version: 0.1.127 month: 2026-10 tags: breaking ---

This release is about records. Glyph checked the top level of a record against its declaration and then compared what was inside it with a weaker rule, so a record nested in another record could be the wrong shape and pass glyph check --no-tsc. It is breaking for that reason: programs that 0.1.126 accepted and tsc refuses are now refused by Glyph too. That was established by running 0.1.126 and this build on each program below.

Records are compared all the way down

Every field of a record is now compared by the same rule as the record itself, so a nested record, a declared type and a string-literal union inside a record are checked the way they are at the top. The same gap reached four other places, and they are closed too: a field the value may not have (a?: number) where the declaration requires it, a declared record passed where an inline one is declared, a function whose return type doesn't fit, and an interface's members.

glyph check --no-tsc 
type Other = { a: number, }
fn tx(x: { o: Other, }) -> number { return 1 }
pub fn g() -> number {
  let v = { o: { b: "x", }, }
  return tx(v)
}
// 0.1.126: nothing                                         (exit 0)
// 0.1.127: [E0211] argument type mismatch: expected `record`, found `record`
//                                                           (exit 1)

The message still calls both sides record when neither has a name, which is a known display gap. One program goes the other way: a record that refers to itself through a field, such as type Node = { kids: Array<Node>, }, passed to an interface shaped the same way used to be refused by name one level down. tsc accepts it, and now Glyph does too.

A record of only optional fields

A record whose fields are all optional accepts almost anything, so TypeScript refuses a value that shares none of its fields (TS2559). Glyph now applies the same rule, with the same edges: an empty value is accepted, and one shared field is enough.

glyph check --no-tsc 
fn ti(x: { hint?: string, }) -> number { return 1 }
pub fn g() -> number {
  let v = { x: 1, }
  return ti(v)
}
// 0.1.126: nothing                                         (exit 0)
// 0.1.127: [E0211] ... it has no field in common with `record`, whose fields
//          are all optional                                 (exit 1)

An extra field on a fresh object literal is still accepted. tsc refuses it (TS2353) and Glyph doesn't yet; that's recorded as G273.

Impact on components

glyph_impact answered "not indexed" for a JSX element under a change to a component's props. It now treats <Card title="x" /> as the call it compiles to, one props record passed to Card, and lists each attribute against the field it is checked against. An attribute and a call argument of the same types now get the same verdict, because they go through the same code. With the record rule complete, glyph_assignable answers COMPATIBLE or WILL_FAIL for a record against a declared record, where it used to say it had no rule.

Breaking, measured

Across the 31 apps and examples/, with and without tsc, every exit code and every list of diagnostic codes is the same under 0.1.126 and this build. An early cut of this release refused two of the apps, shortlink and zipper: array.fold(xs, "", ...) inferred the accumulator as the literal type "" instead of string. That was fixed before release, and it is now inferred as string, which is what tsc infers.
