--- version: 0.1.128 month: 2026-11 date: 2026-11-01 tags: breaking ---

This release is about writing a React app in Glyph against real React. The last attempt stopped at document.title, because browser globals are unresolved names in Glyph and nothing in the standard library reached the page. Now a counter and a todo list using React 18's own hooks builds, bundles with Vite and runs in a browser. It's in the repo as examples/apps/todo, and CI now drives it in headless Chromium and checks the text on the page.

The page, through the standard library

Three small modules. std/dom reads and sets the title, finds an element by id and gives you the page's address. std/storage wraps localStorage: a read is an Option and a write is a Result, because a full or blocked store is an ordinary failure in a real browser. std/console writes a line at three levels. An element is opaque to Glyph: you hand it to React, you don't poke at it.

main.glyph 
pub fn main() -> void {
  match dom.element_by_id("root") {
    Some(root) => createRoot(root).render(<App />),
    None => console.error("the page has no #root element"),
  }
}

Writing document or localStorage is still E0103, and the message now names the module to import.

A hook's pair, destructured

let [count, set_count] = useState(0) works now. The pattern can't test anything, so it always matches, and the length has to be provable: a written array is counted, an Array<T> is refused because it might be shorter, and a value from npm gets a satisfies clause in the emitted TypeScript so tsc checks it is really a pair. That makes const [user, host] = s.split("@"), which tsc --strict accepts, an error in Glyph (E0230).

Two formatter and parser fixes in JSX

glyph fmt trimmed JSX text, so <p>{n} left</p> came back as {n}left and the page read "2left". It now keeps every space JSX renders. Separately, text on its own line below an element kept its indentation in the output; it's dropped now, as in TSX. Neither fix changes the TypeScript emitted for any example.

Breaking, measured

An import of a std/ module that doesn't exist exits 0 under 0.1.127 with --no-tsc and is E0104 here; with tsc it failed under both. Across the 31 apps that existed before this release, with and without tsc, every exit code and list of diagnostic codes is the same under both versions. The new todo app and the rewritten React example use the new syntax and modules, so 0.1.127 refuses them (E0002 and E0105) and this build passes them.
