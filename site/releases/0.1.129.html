--- version: 0.1.129 month: 2026-11 date: 2026-11-02 tags: breaking ---

Before announcing a preview I had two agents start from npx @glyphlang/glyph init with nothing but the shipped docs, one building a small React page and one a Node CLI. Both got to a clean tsc build. This release fixes what they ran into, and one bug the Node run found that matters more than any of it.

Examples now run in a module that imports an npm package

In a module that imported an npm package, a failing @example passed. The example gate builds a copy of the project in a temp directory, the package could not be found from there, and the test harness died before running anything. The runner took the absence of a failure as success. The copy now resolves packages from your project, and a harness that does not report a result for every example it was given fails the build as "not run". The same check now covers glyph bench, which reported zero benchmarks and exited 0 when its module threw.

<case> takes a match pattern

<case Loaded bind={items}> read a field called items whatever the payload was, so on a positional payload it bound undefined, and the checker never typed the name. A case now takes the pattern a match arm takes:

view.glyph 
<match value={props.load}>
  <case Loading><p>loading</p></case>
  <case Loaded({ users, total })><p>{total} users</p></case>
  <case Failed(message)><p>{message}</p></case>
</match>

The bindings are typed, and a case that only matches some values of its variant does not count as covering it. bind= is now E0231, and its help writes the pattern for you. The same change closed a hole in ordinary match arms: Loaded({ totl }) on a record with no totl field passed the checker and only tsc complained. It is E0210 now, listing the fields the record has.

glyph fix no longer writes match arms

On a non-exhaustive match, glyph fix used to add one arm per missing case that printed the case and exited the process. The program then passed every check, and the match counted as exhaustive in glyph query variants. The compiler knows which cases are missing, not what your program should do in them, so fix now reports them and writes nothing. The E0200 help also stopped suggesting an else arm.

The docs the agents needed

The agent docs (what glyph llms prints and glyph init copies) now show a whole browser page: the app module, the entry that mounts it, the index.html, and building then bundling with Vite. Both modules are compiled against React's types in CI. An HTTP recipe that imported a serve std/http does not export is fixed, and every std import written in those docs is now compiled by a CI check. The scaffold's .types README no longer tells you to write .d.ts files for packages that ship their own types, and the getting-started guide begins with glyph init.

glyph run -- in.json now runs the current project with in.json as an argument, and a new scaffold's start script is glyph run --, so npm start -- in.json works. In a project made before this release, change the start script to glyph run --.

Smaller fixes

A U+E000 character inside a string compiled to $, because the lexer used that codepoint as an internal marker; the scheduled fuzzer found it. The catches/ folder is down to five programs, each one the same program in TypeScript and Glyph, after a review found four that compared two different programs or that tsc also catches. Tests that need tsc or node now fail in CI when the tool is missing instead of quietly passing, and on their first run they found ten glyph gen dts tests that had been skipping: gen dts replaced the caller's NODE_PATH with the global npm root, so a TypeScript found only through NODE_PATH was reported missing. It now adds the global root after it.

This release is breaking. A bind= case, an arm naming a field the record does not have, a failing example in a module that imports an npm package, and a benchmark that throws all exit 0 under 0.1.128 and 1 here. One spelling changes meaning without an error: glyph run -- tools/other.glyph ran that file under 0.1.128, and now runs the current project with tools/other.glyph as an argument. Write the path before the --.
