--- version: 0.1.130 month: 2026-11 date: 2026-11-06 tags: breaking ---

The preview announcement makes five claims of the form "TypeScript accepts this and Glyph refuses it". A review of the draft against 0.1.129 found two of them weaker than they read: one held only inside the module that declared the type, and one was refused by tsc rather than by Glyph. This release makes both hold, and fixes the things a newcomer would hit first.

An unverifiable parse is refused across an import

E0304 refuses Doc.parse(v) when a field of Doc has no runtime check, because the validator would report success for a value it never looked at. It only fired in the module that declared Doc. Called from a module that imported it, the same call compiled and returned Ok. The refusal now follows the record across modules, including records a field check hands off to.

Glyph's own checker refuses an unchecked boundary read

user.glyph 
let user: User = json.parse(body)

json.parse returns a Result, so this was always an error, but only tsc reported it. glyph check --no-tsc, the editor and the playground said nothing. It is E0204 now: a Result, Option, Array, Record or Nullable where a declared record or union is expected is a type mismatch in the checker. All five catches/ programs are now refused by Glyph itself, and all five reproduce in the playground.

Member reads on arrays and strings

xs.lenght on an array was left to tsc. It is E0210 with "did you mean length", checked against the members TypeScript's library declares for arrays and strings. A CI check compares those lists with the TypeScript the project pins, in both directions, so moving the pin to a release that adds a method fails CI until the lists catch up. A TypeScript newer than the pin can still have a member Glyph does not know yet.

Errors point at the expression

A tsc error in Glyph code used to underline the whole statement it came from: a wrong argument marked the entire let, and a typo in a JSX handler marked eight lines. The emitter now maps every expression it writes, so the caret lands on the argument. The emitted TypeScript is unchanged.

let where = 1 now says where is a reserved word instead of giving a generic parse error, and glyph llms lists the 32 reserved words. A match on string literals whose type the checker cannot see is E0232, which says that, instead of E0218 suggesting an else arm, which would have switched the check off.

The playground and the docs

The playground opens on a program it refuses, has a picker of the catches/ cases, and can share a program by URL. The docs check now compiles fences whose point is a tsc error, and fences that import zod, pg or mongodb against those packages' real types. E0400 to E0404 have glyph --explain pages, and a test requires every code the compiler can emit to have one.

This release is breaking. Bag.parse(v) on an imported record with an Array<unknown> field exits 0 under glyph check in 0.1.129 and 1 here. let s: Sized = xs, where Sized is the record { length: number } and xs is an array, exits 0 in 0.1.129 and 1 here, although tsc accepts it: a declared record is its own type, and Sized.parse(xs) already refused the array. Declaring interface Sized { length: number } instead keeps the program. A misspelled array or string member was already a tsc error; under --no-tsc it exits 0 in 0.1.129 and 1 here.
