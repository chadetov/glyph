--- version: 0.1.133 month: 2026-11 tags: breaking ---

This release finishes what 0.1.132 started on json.parse: it never casts now, however it is spelled or reached. It also checks ?. on an Option or a Result, types the methods of arrays and strings, and makes glyph/applyEdit check the whole project.

json.parse never casts

read.glyph 
fn read<T>(s: string) -> Result<T, Array<Issue>> {
  return json.parse(s)
}

let user = read<User>("42")   // Ok, and then a crash

That program passed glyph check and tsc in 0.1.132 and crashed on the first field read. The emitter wrote json.parse(s) with no type argument, and tsc inferred T from the return type, which made the unchecked read a cast with no as anywhere. A call with no type argument is now emitted as json.parse<unknown>(s), so tsc refuses it there, at a let annotated Result<User, ...>, at an argument and in a record field. glyph check --no-tsc does not refuse an unknown value where another type is declared yet; that is 0.1.158.

json.parse<T> with a T nothing can check at run time is E0304: a type parameter, an extern_ts or package type, an interface, Result, a generic union, an Option, Nullable or Record of one, or a generic record applied to one (Pair<Shape>, whose check tested a only for being there). The note says which. A container of unknown is checked by its shape, so json.parse<Array<unknown>>("{}") is an Err. An Array alias imported from another module validates when its body names types that module declares. If it names one the module imports, that is E0304 for now. It used to look the name up in your module, and validate against your own User if you had one. Assigning json.parse to a variable gives you the unchecked read: let p = json.parse takes no type arguments.

?. on an Option or a Result

An Option and a Result are never null, so ?. on one never skips anything; it reads off the wrapper. An agent writing csvql wrote bind_agg(...)?.label meaning "propagate the error, then read the field", and the error was not propagated. That is E0236 now, with help that says to bind first (let a = bind_agg(...)?) or to match. A plain . on them is still unchecked; that is 0.1.139.

Methods of arrays and strings

The checker knows what xs.indexOf(2) and s.trim() return, from a table generated out of TypeScript's own declarations and checked for drift in CI. A method read without calling it, let up = s.toUpperCase, is E0234: the read loses its receiver and throws when called. .bind(s) is refused the same way; write fn() -> string { return s.toUpperCase() }. Type arguments on a function you stored in a variable are read now: let g = id then g<number>("x") is an error, as it is on id itself.

The editor and agents

glyph/applyEdit checks every module of the project, not just the edited file, so an edit that breaks an importer is refused, and the other files' diagnostics come back under elsewhere. An edit can span files through the new changes form, checked as one. A pre-existing error elsewhere whose suggestion the edit happened to change (adding an export rewrites another file's "did you mean") stays pre-existing. glyph fix repairs a misspelled string-literal arm the way it repairs a variant, and declines when the repair is not determined: when the error that lists the missing case belongs to another match, or two arms would take the same value.

Fixes

glyph fmt cut a run of spaces at the edge of JSX text to one, which changed what the page renders; it writes such a text as one string child now, and formatting leaves the emitted TypeScript byte for byte the same. It also moved a comment written between the operands of a multi-line expression below the statement; the comment stays with its operand. A match with no arms crashed the playground. The nightly fuzzer, which had been failing unread for fifteen days, found all three; it now keeps fuzzing past a crash, and a new target checks that formatting never changes the emitted TypeScript.

This release is breaking. Each line below was established by running 0.1.132 and 0.1.133 on the same program. The list is what that testing found; it is not every program that could change.

Under glyph check, these exit 0 in 0.1.132 and 1 here, although tsc accepts them: a built-in method read without a call, .bind included (E0234); type arguments on a json.parse value (E0233); o?.tag, r?.tag, r?.value, r?.map(..) and r?.map_err(..) (E0236); and json.parse<T> for a type parameter, an interface, Result, a generic union or an Option of an interface, for a generic record applied to one of those (json.parse<Pair<Shape>>, Pair.parse<Shape>(v)), and for an alias whose body names a type another module imports (E0304); an is Pair<Shape> pattern (E0300); and a method's result where a record it does not match is declared, such as xs.slice(0) returned as a { length: number } record (E0204), since method results are typed now.

Under full glyph check only, because tsc now sees the type: json.parse(text) with no type argument, or a call of a json.parse value, where a Result<T, ...> other than Result<unknown, ...> is declared, a generic wrapper included. These were casts that crashed at run time.

Under --no-tsc only, programs tsc already refused now exit 1: type arguments on a function value that has none, an interface member or a function-typed record field included; o?.name on an Option; and a method's result where a different type is declared, such as s.trim() returned as a string-literal union.

At run time: json.parse<Array<unknown>>("{}") and json.parse<Record<string, unknown>>("[1]") returned Ok in 0.1.132 and return Err here. A program that passed a record holding an Array<unknown> field to parse was refused and now compiles.

In the editor protocol: an edit that breaks another module is refused, where 0.1.132 checked only the edited file.

The emitted TypeScript changes in two places, with the same behaviour: json.parse(s) is written json.parse<unknown>(s), and a comparison of a method's result, s.trim() == "x", is a plain ===. No program in the examples, the apps, the catches or the test corpora changes exit code apart from the two new negative cases.
