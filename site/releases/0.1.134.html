--- version: 0.1.134 month: 2026-11 date: 2026-11-11 ---

This release changes how the parser reads a file and nothing about what a program means. It is the groundwork for reading JSX text as text in 0.1.135, which today goes through the ordinary token lexer: that is why <p>don't stop</p> does not compile and // inside JSX text is read as a comment.

The lexer runs on demand

The whole file used to be split into tokens before parsing started. The parser now asks the lexer for each token as it needs one, and the lexer can resume from any point in the file. A lex error waits until the parser reaches it, so a lookahead that strays into one backs off without failing.

For every program that compiles, nothing changes. We checked that by running 0.1.133 and 0.1.134 on every .glyph file in the repository and on all 32 example apps, built as projects: the emitted TypeScript (2795 files for the single files, 616 for the apps) and the glyph fmt output are byte for byte the same, and no exit code changes.

Changed: which error you see first

A file with two errors reports the first one the parser reaches. Before, a lex error (an unterminated string, a stray character) was always reported first, even when a parse error came earlier in the file. So x = 1 # 2 in a function body used to report the # (E0001) and now reports the missing mut (E0008), which is the earlier mistake. The program fails either way; the message is what changed. One file in our test corpus changed this way, and it turned out to hold a second error the old order hid.

One case reads worse than before. When the parser looks ahead to decide what it is reading and runs into a lex error, it backs off and tries the other reading, and that reading can fail on code that is fine. In let x = f<a, "\q">(x) the invalid escape \q used to be reported; now the parser reports an unexpected ,, because it read f < a as a comparison. If an error points at code that looks correct, look for a bad string or character further along the line. It is filed as G329.

This release is not breaking: no program that compiled stops compiling, and no exit code changes.
