--- version: 0.1.141 month: 2026-11 date: 2026-11-18 tags: breaking ---

json.parse now checks a generic record's own fields and a union's variant payloads, and refuses with E0304 when one of them has no runtime check. Before, such a field was only tested for being present, so a document with the wrong value in it came back Ok:

page.glyph 
pub type Page<T> = { items: Array<T>, h: Handle }

let page = json.parse<Page<User>>(body)
cannot validate `Page<User>`: `Page`'s field `h` has type `Handle`, which has no runtime check

Here Handle is an extern_ts type, which Glyph cannot check at run time. A record with the same field was already refused; a generic one and a union variant carrying it now get the same answer, whether you call json.parse, Page.parse, U.is or json.parse_with with its schema, put the type inside another record, an Option or an Array, pass it as a generic's type argument, or reach it through another module.

Breaking

We ran 0.1.140 and this build on each refused shape: every one exited 0 before and exits 1 now, with and without tsc, and tsc accepts all of them. One case is refused although it was safe: an imported generic whose field is a record its module keeps private. This module cannot see into that record, so it refuses rather than guess; the message says so, and marking the record pub fixes it. 0.1.144 will judge it from the module that declares it instead. Nothing else changes. On every .glyph file in the repository and all 32 example apps, glyph check, glyph fmt and the emitted TypeScript are identical to 0.1.140.

A match arm written is Page is not covered by this check yet; that is 0.1.143.
