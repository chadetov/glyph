--- version: 0.1.142 month: 2026-11 tags: breaking ---

Lint warnings (unused import, unused binding, unreachable code, unreachable module) now show up on a file that has a type error, as long as it parses and its names resolve. Before, they appeared only after the last type error was fixed, so an edit could add an unused binding to a broken file and nothing said so until later. This applies in glyph check, glyph build, the editor and the playground. No exit code changes.

glyph/applyEdit follows the same rule. It now refuses an edit that adds one of those warnings to a file with a type error, and every answer carries stages, the stages that ran on the edited file, so an agent can see when the emitter did not run. An edit that adds a _ => arm is no longer refused because of import warnings the file already had.

If an import is unused only because a missing match arm would use it, glyph --explain E0106 now says to write the arm rather than delete the import. And when glyph fix declines to rename an arm head, it now names the arm that already handles the case.

Breaking

For the applyEdit protocol, as above, and for anything that counts warnings: a file that already fails glyph check can now print more of them. We compared the published 0.1.141 with this build on every .glyph file in the repository and on all 32 example apps: the only differences are 32 added warnings on 27 files that already had a type error. Formatting, builds and the emitted TypeScript are identical.

Still open: return h() { k: 2 } is read as return h() followed by an object literal that never runs, and only warns (G351); the playground still shows emitted TypeScript for a file with a type error (G352); and applyEdit refuses an edit that writes one of several missing match arms (G353).
