--- version: 0.1.150 month: 2026-11 date: 2026-11-20 tags: breaking headline: A check refuses a value nested more than 1000 deep instead of crashing ---

A generated check walked its input with plain recursion, so a value nested a few thousand levels deep threw RangeError: Maximum call stack size exceeded out of is, T.parse or json.parse<T>, taking the process down with it. A request body is enough to do that.

Every check now counts the objects and arrays it enters and stops at 1000. Past that, is answers false and a parse returns one issue, code: "depth", at the path a type issue for that part would have:

[{"path":["kids"],"message":"nested more than 1000 objects and arrays deep","code":"depth"}]

The limit is MAX_DEPTH in std/schema. It is exact on all 29 paths and shapes we measured, under node and tsx, with the default stack and with half of it. A 10,000,000-level document returns the depth error, and a value that contains itself is refused the same way instead of throwing. Issue.code gains "depth". The helpers that carry the refusal live in an internal runtime module Glyph code cannot import, so a program cannot fake one.

It costs nothing on the common case. On a 960k-node tree, Tree.is takes 117 ms against 126 ms in 0.1.149, because the array walk no longer builds a closure per node. Tree.parse is 5% slower (119 ms against 113).

Breaking

At run time only. json.parse<Tree> of a value 1202 levels deep returns Ok in 0.1.149 and the depth error here, and anything between 1001 levels and the depth where 0.1.149 used to overflow is refused where it was accepted. glyph check gives the same answer on every program as before. Every descriptor's emitted TypeScript changes; Glyph sources do not.
