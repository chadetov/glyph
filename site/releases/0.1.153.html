--- version: 0.1.153 month: 2026-11 date: 2026-11-21 tags: breaking headline: A Record's key type has to match exactly ---

A Record<string, int> used to stand wherever a Record<Tier, int> was declared, with type Tier = "a" | "b", and the reverse worked too. Either direction lets a key outside Tier into a map whose type promises none: fn narrow(r: Record<string, int>) -> Record<Tier, int> { return r } compiled, and so did passing a Record<Tier, int> on as a Record<string, int> and writing "zzz" into it. Since 0.1.148 the run-time check refuses such a map, so the type and the check disagreed.

Now a Record's key type has to match. string matches string and its aliases, two string-literal unions match when they have the same members, a refined type matches only itself, and a type parameter only itself. The value type stays covariant, as for Array. The error explains the direction it found:

[E0204] type mismatch: expected `Record<Tier, number>`, found `Record<string, number>`
Help: Check it with `is Record<Tier, int>` or `json.parse<Record<Tier, int>>`.
Note: a `Record`'s key type must match exactly. A `Record` keyed by `string` may hold keys outside `Tier` or lack one of its members, and a `Record` keyed by `Tier` passed on as one keyed by `string` can be written a key outside `Tier`.

The headline still prints int as number; giving int its own identity in the checker is the next piece of this work (G373b).

std/record keeps the key

record.get, set and remove take a key of the record's own key type, set and remove return a Record with the same key, and keys returns Array<Tier> for a Tier key. record.remove on a map keyed by a string-literal union is refused, because removing a member leaves a map of no declared type; the help suggests a record with optional fields instead, and that suggestion compiles.

Breaking

Each of these exits 0 under 0.1.152 and 1 here, under check --no-tsc and full check: Record<string, V> into Record<Tier, V> and back; the same against a refined string key; a generic key widened to string; an alias of a Record<Tier, V> passed on as Record<string, V>; record.set or record.get with a key outside the record's key type; and record.remove on a literal-union key. No tracked .glyph file and none of the 32 example apps changed exit code. A map keyed by int against one keyed by number is still accepted until G373b.

Fixed

std/http now compiles on TypeScript 5.x in a project without @types/node. Its query and form parsing iterated a URLSearchParams in a way that needs dom.iterable before TypeScript 6. A new release gate compiles the whole runtime on TypeScript 4.9, with and without @types/node, so this kind of break is caught before it ships.
