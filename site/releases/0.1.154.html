--- version: 0.1.154 month: 2026-11 date: 2026-11-21 tags: breaking headline: An async call nothing waits for is refused, and task.detach starts work on purpose ---

Calling an async fn without await starts the work and moves on. If it fails, nothing sees the error, and anything that runs after it may run before it. Glyph's checker used to type such a call as the value it would eventually produce, so let n: number = load() passed without tsc, and a bare save(1) on its own line passed everywhere.

Now an un-awaited call to an async function is a pending value, and using it anywhere other than await or return from an async function is E0238:

[E0238] `save(1)` is never awaited: `save` is async, so this starts it and moves on without waiting, and if it fails nothing sees the error
Help: Write `await save(1)`.

That covers a call on its own line, the last line of a block, let _ = save(1), a let that is never read, a typed let, a match on the call, an argument, an operand, and a sync function returning the call. A sync lambda whose last expression is an un-awaited call is refused too, with help that depends on where the lambda goes: task.detach gets async fn() -> void { … }, a timer callback gets a task.detach inside the callback, and array.map gets a loop. Every suggested snippet compiles. Hover shows the type as a pending number.

task.detach

Sometimes a sync context really does want to start work and not wait, like a timer callback. task.detach(async fn() -> void { await save(1) }) in std/task says so in the code, and a failure is reported on stderr instead of disappearing.

Breaking

Programs that drop an async call no longer compile. In the repository, two example apps did, and both were real bugs: the chat server's main started daemon.serve(port) and returned before the server bound, and the job queue's timer dropped each drain. Both are fixed. No other tracked .glyph file changed.

Not yet

E0238 knows a call is async only when Glyph's checker has its signature, so a promise from an npm package or a node builtin can still be dropped silently. An async callback given to forEach or a timer is not refused yet; that is planned.
