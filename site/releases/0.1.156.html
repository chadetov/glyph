--- version: 0.1.156 month: 2026-11 date: 2026-11-21 tags: breaking headline: A lambda parameter has the type you wrote, and is arms narrow ---

A lambda parameter written : unknown used to be indistinguishable from one with no annotation at all. The parser filled in unknown for the omitted form, so glyph fmt erased an unknown you wrote, the emitted TypeScript dropped it, and fn(p: unknown) -> number { return p + 1 } compiled. Now the two are kept apart. A written unknown is formatted back as written, emitted as (p: unknown), and full check refuses p + 1. An omitted annotation still emits (p), and hovering one of its uses says it is not typed here instead of claiming unknown.

Inside a match arm whose pattern is is T, the value being matched now has type T, when it is a parameter, a let or a module const and T is a primitive or a declared type. Glyph's own checker refuses a misspelled field there without waiting for tsc:

match v {
    is User => v.nmae,   // E0210: type `User` has no field `nmae`
    else => "",
}

A name that any mut reassigns, including from inside a lambda, is not narrowed, because a call inside the arm could rebind it. That rule is one function, and the constant-query check for sqlite.Sql from 0.1.155 now reads the same function, so the two cannot disagree about which names are fixed. Container patterns such as is Array<X> do not narrow yet (G415), and an omitted annotation does not take its type from the call it is passed to yet (G414).

Breaking

A lambda written with : unknown that uses the parameter as something else now fails full check (0.1.155 exits 0, 0.1.156 exits 1). A misspelled field inside an is arm now fails check --no-tsc too; full check already refused it through tsc. No tracked .glyph file or example app is affected: all 32 apps give identical diagnostics and byte-identical TypeScript under both versions.
