--- version: 0.1.161 month: 2026-11 date: 2026-11-22 tags: breaking headline: A method that returns undefined when nothing is there is refused, and the Option form is named ---

users.find(fn(u: User) -> bool { u.id == id }).name passed Glyph's own checker. Only tsc refused it, so the editor, the MCP tools and the applyEdit gate, which run without tsc, saw nothing wrong. The stdlib spelling, array.find(users, ...), has always returned an Option<User> and was caught.

Now a call to a built-in method whose TypeScript return can be undefined is E0242, and the help names the std function that returns an Option:

[E0242] `xs.at(-1)` returns `number | undefined`; Glyph writes a value that may be missing as an `Option`
Help: write `match array.get(xs, array.len(xs) - 1) { Some(v) => v, None => 0, }` (with `import std/array`)

The methods are find, findLast and at on arrays, and at, codePointAt and match on strings. The list is read from the return types in TypeScript's own library, and a check fails if a new TypeScript adds such a method before someone names its Option form. pop and shift were already covered by 0.1.160's rule.

Three stdlib functions are new, so every refusal has somewhere to go: array.find_last, string.char_at and string.code_point_at. The string ones still count in UTF-16 units, but they return the whole character that starts at the index, or None when the index is past the end or lands on the second half of an emoji. They never hand back half of a character. The spec had ruled out a character accessor for exactly that reason, and this is the form it allows.

glyph fix rewrites xs.find(f) to array.find(xs, f), adding the import, but only where the Option is used up on the spot: a match, a ?? default (rewritten as a match), a statement, or a place declared Option. Elsewhere, an untyped let for example, it declines and says why, because a later u ?? 0 on an Option would quietly hand back the object. It never rewrites the string methods, since the new functions answer None where the old ones answered half a character.

That last case, ?? on an Option, passes both checkers today and is G429, scheduled next.

Breaking

A program that calls one of these methods now fails to compile, under full check as well as --no-tsc. let n = xs.at(-1) ?? 0 passes tsc --strict on 0.1.160 (exit 0) and is refused on 0.1.161 (exit 1). Across the 97 example apps and standalone files, nothing changes except the catch case for this mistake.
