--- version: 0.1.162 month: 2026-11 date: 2026-11-22 tags: breaking headline: A ?? on an Option is refused, and glyph fix stops writing inside ${} ---

An Option and a Result are tagged objects at run time, never null or undefined. So let v = array.find(xs, f) ?? 0 never used its default: v was the Option itself, and ${v} printed [object Object]. Both Glyph's checker and tsc passed it. 0.1.161 steered every lookup onto Option, which made this spelling more likely, so it is refused now, with the same code as ?. on these types:

[E0236] `??` on an `Option<number>`: an `Option` is never null or undefined, so `?? 0` never applies and the value is the `Option` itself
Help: Open it with `match u { Some(n) => n, None => 0 }`

A left side that can itself be missing, a ?. chain or an optional field, may still take a container default such as b.o ?? None. That ?? is now typed as the Option, so a match over it with no None arm is caught. An array index read is not one of these: Glyph's index throws when it is out of range, so xs[5] ?? None is refused instead of looking handled.

glyph fix rewrites the Option case into the match and says what changes (`u ?? 0` handed back the `Option`; it now gives its value or `0`). The type of the expression changes too, so the fix checks the file again after each rewrite and puts it back if a new error appears. It does not rewrite a Result, because whether to drop an error is a decision.

A fix that could corrupt a template string

Positions inside a ${} are reported one column early. In 0.1.161 two fixes wrote at those positions, and every check passed afterwards. The E0242 rewrite turned "t=${xs.find(f) ?? 0}" into t=$match array.find({x, ... inside the string, and the field-rename fix turned "v=${b.name} w=${b.nikc}" into b.nickc. If you ran glyph fix on 0.1.161 over a file with interpolations, check those lines.

Now the rewrites decline inside a ${} and the help says to bind the value with let first. Every fix rule also re-reads the text it is about to replace and declines if it does not parse to the expression the fix was planned against. The position bug itself is G435, scheduled for 0.1.164.

Breaking

A ?? on an Option or Result that cannot be absent now fails to compile, under full check as well as --no-tsc. The probe with array.find(...) ?? 0 and its neighbours exits 0 under 0.1.161 and 1 under 0.1.162. Across the 285 example apps, standalone files, catch cases and test programs, the only new diagnostic is on the catch case for this mistake.
