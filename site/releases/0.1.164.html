--- version: 0.1.164 month: 2026-11 date: 2026-11-22 headline: Positions inside ${} point at the text they name ---

Every position inside a ${} was off. In "n=${b.nik} end", E0210 underlined {b.ni instead of b.nik, because each interpolation was placed from the opening quote plus its index in the decoded string, which skipped the quote. An escape, a \${ or a non-ASCII character earlier in the string pushed it further. The editor's ranges, hover and go-to-definition inside a template were off by the same amount, and so were the ranges agents edit against.

The lexer now records which source bytes produced each character of a string, and each interpolation is placed at its exact bytes. Underlines, hover, definition and glyph fix land on the right text after an escape, a \${, accented text, an emoji or a line break, in plain and triple-quoted strings. A one-letter typo inside a template is now renamed by glyph fix instead of declined.

It also fixes a crash. A diagnostic inside a ${} after an emoji made 0.1.162 and 0.1.163 panic with "end byte index ... is not a char boundary" (exit 101). It is now reported normally.

One case is left: an escape written inside the interpolation itself, such as "a${f(\"x\") + zz}", still leaves later positions early, and glyph fix declines there. That spelling only exists to get a nested string past the rule that says to bind it with let first, so 0.1.168 makes it a parse error (G441).

Not breaking

Nothing that compiled before is refused. Across 283 example apps, files, catch cases and test programs, every diagnostic's code and message is the same as on 0.1.163; four positions move by one column, all inside a ${}. The emitted TypeScript is byte-identical; source maps change only inside interpolations.
