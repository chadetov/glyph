--- version: 0.1.168 month: 2026-11 date: 2026-11-23 tags: breaking headline: A loop over an array literal binds the element type ---

for s in [seen], with seen a set.Set<number>, gave s the type set.Set<set.Set<number>>, so s.has(1) was refused with "expected set.Set<number>, found number". The same happened to for w in [[1]], which typed w as Array<Array<number>>. The loop widened the element against the array literal itself and rebuilt the element's type around it.

Now a loop over an array literal binds exactly what a loop over the same array held in a let binds. That includes the index form for i, s in [...], nested arrays, records, Options and stdlib types.

Breaking

Under check --no-tsc only. The wrong element type also let through lines that misuse the real one, such as s.has(seen) inside for s in [seen]. Those exit 0 under 0.1.167's --no-tsc and 1 under 0.1.168. tsc already refused them, so a full check was red before this release too. Across 285 tracked programs nothing changed.
