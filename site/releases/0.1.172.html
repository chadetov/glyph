--- version: 0.1.172 month: 2026-11 date: 2026-11-23 tags: breaking headline: Inside a generic function, its own T is a type of its own ---

Glyph's checker did not hold a generic function to its own type parameter. Inside fn g<T>(x: Array<T>) -> Array<string>, return x passed, and so did return 5 where T is declared. Only tsc refused them, so the editor, the MCP tools and the applyEdit gate let them through. Building on 0.1.171, which records the declaration that owns each type parameter, the checker now decides a function's own T wherever that function checks a value.

A T stands where T, unknown or Nullable<T> is declared, and nowhere else. An Array<T> returned as Array<string>, a number returned as T, a U passed where T is declared, and f(5) with f: fn(T) -> T are now E0204 or E0211. A parameter a callee leaves unbound is not yours to decide and stays open, as before. A T field where Record<string, Nullable<T>> is declared is now accepted, which was a false refusal.

Two edges remain. A bounded parameter such as T: Named is decided where T is declared, but not yet as a value, because bounds are not resolved; that is the next release, 0.1.173. And a function's last expression is not yet compared with its declared return type at all, so fn f<T>(x: T) -> string { x } still passes; that is 0.1.174.

Breaking

Under check --no-tsc only. Every new refusal is one tsc already makes: fn g<T>(x: Array<T>) -> Array<string> { return x } exits 0 under 0.1.171's --no-tsc and 1 under 0.1.172, and full check was red on both. Across 285 tracked programs nothing changed.
