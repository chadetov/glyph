--- version: 0.1.173 month: 2026-11 date: 2026-11-24 tags: breaking headline: A generic bound is resolved, and a bounded T is checked as its bound ---

Glyph never resolved the bound on a type parameter. fn f<T: Nope>(x: T) -> T passed with no error even though Nope does not exist, and inside the function a T: Named was treated as if nothing was known about it. So x.nmae on a T: Named passed, and returning a T: Named where an unrelated Other is declared passed too. Only tsc caught these.

Now a bound resolves like any other type name: an unknown name is E0103, and l.Nope through a namespace is E0105. An import used only in a bound no longer draws a false "unused import" warning. A circular bound such as <T: T> or <T: U, U: T> is the new E0114, which tsc also refuses. A bound that refers to its own parameter, such as T: Cmp<T>, is still legal.

Inside its function, a bounded T passes where T or unknown is declared, and everywhere else it is checked as its bound would be. Member reads, method calls, index reads and loops over a T: B are checked against B. One false refusal goes: a Box<T> with T: Named where Record<string, Named> is declared.

Calls that pass the wrong type to a bounded parameter, such as label(5) where label<T: Named>, are not checked yet. That is 0.1.179. A generic interface's members are not checked on a value either (G461), so a bound like T: Cmp<T> does not yet guarantee anything about x.cmp(y).

Breaking

Yes. fn c<T: Nope>(x: T) -> T, a T: Named returned where Other is declared, and <T: U, U: T> each exit 0 under 0.1.172 and 1 under 0.1.173. Across 286 tracked programs the only change is the new test case for circular bounds.
