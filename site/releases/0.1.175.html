--- version: 0.1.175 month: 2026-11 date: 2026-11-24 tags: breaking headline: is Array and is Record arms narrow their value ---

A match arm such as is string or is User already narrowed the value it matched, so inside the arm the checker knew its type. An is Array<X> or is Record<K, V> arm did not. The value stayed unknown, so is Array<string> => v.lenght passed check --no-tsc and the typo surfaced only under tsc.

Those arms now narrow like any other. v.lenght is E0210 with the length suggestion, a callback passed to v.map gets the element type, and is Record<string, number> => v[k] is E0224, the same answer a declared map gets. Option, Result and Nullable still have no is check (E0300).

Reading a map of unknown

A key read on a map whose value type is unknown is no longer E0224. A missing key yields undefined, which unknown already allows, so the read is sound. The result is typed unknown, so you still narrow it before use, and putting it straight into a string is E0237. This holds however the map is spelled: written out, through a local alias, an alias of an alias, or an alias imported from another module. Before, only the first two spellings were treated as maps.

One emitted line changed in the examples: a loop over an is Array<unknown> value now uses entries() directly, since the arm has already settled the shape.

A write into a container (mut v.push(5) on an Array<string>) is still not compared with its element type. That is G471.

Breaking

Yes. is Array<string> => v.lenght and is Record<string, number> => v[k] exit 0 under 0.1.174's check --no-tsc and 1 under 0.1.175, and so does "${v[k]}" on a Record<string, unknown>. One program goes the other way: m[k] on a declared Record<string, unknown> was E0224 and now passes. Across 286 tracked programs no diagnostic or exit code changed against 0.1.174.
