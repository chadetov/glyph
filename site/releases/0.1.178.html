--- version: 0.1.178 month: 2026-11 date: 2026-11-24 headline: A deprecated built-in method draws a warning with its replacement ---

TypeScript's own library marks some built-in methods @deprecated: substr, trimLeft, anchor and the other HTML string methods. They still run and tsc --strict accepts them, so nothing told an agent that wrote one. Agents write substr often, because it is all over older code.

Calling or reading one of these on a string, an Array or a number is now warning E0244. The message quotes TypeScript's tag, and the help is worked out from the call: s.substr(1, 2) suggests s.slice(1, 3), s.substr(-2) suggests s.slice(-2), and s.trimLeft() suggests s.trimStart(). Where the rewrite is only equal for whole, non-negative arguments, the help says so, because substr(0.5, 0.6) and slice(0.5, 1.1) give different answers.

The list is read from the pinned TypeScript 6.0.3 declarations, 16 string methods today. The replacements are kept in a table that CI checks against TypeScript's tags and against node: a replacement must exist, must not be deprecated itself, and must behave the same.

Deprecated members of npm packages and node builtins are not covered, because Glyph's checker does not type those values. glyph fix does not rewrite these calls yet.

Breaking

No. E0244 is a warning and changes no exit code: s.substr(1, 2) exits 0 under 0.1.177 and under 0.1.178, which prints the warning. Across 286 tracked programs the output is identical to 0.1.177; none of them uses a deprecated member.
