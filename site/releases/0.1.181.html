--- version: 0.1.181 month: 2026-11 date: 2026-11-24 tags: breaking headline: The arguments of a mut method call are checked ---

v.indexOf(5) on an Array<string> was already refused, but mut v.push(5) on the same array passed check --no-tsc, and so did mut v.fill("x", "a"), mut v.splice("a", 1) and mut v.unshift(5). The mut path was not skipping anything. The rows Glyph generates from TypeScript's library left these methods untyped, because they take a rest parameter, are overloaded, or return this.

The generated rows now carry rest parameters, merge an overload set when one of its overloads has a rest parameter and the merged signature accepts exactly what the overloads accept, and read this as the array type. So a mut method call is checked the way the same call in value position is: the argument count as E0213, and each argument against its parameter as E0211. string.concat checks each argument too (G492), and array.concat now returns Array<T>.

A comparator passed to sort or toSorted is refused when it takes more than two parameters or returns something that is not a number, with both signatures in the message. Its parameter types are compared from 0.1.185. E0213's help now gives the range a built-in method accepts ("Pass from 2 to 3 arguments") instead of saying Glyph has no optional parameters, which was wrong for these.

A receiver the checker cannot type is still not judged, and xs.concat(["a"]) on an Array<number> still passes (G521).

Breaking

Yes. mut v.push(5) on an Array<string> exits 0 under 0.1.180's check --no-tsc and 1 under 0.1.181. Every new refusal is one tsc makes. Across the 375 programs the corpus script measures, the output is identical to 0.1.180.
