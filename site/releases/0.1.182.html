--- version: 0.1.182 month: 2026-11 date: 2026-11-24 tags: breaking headline: A primitive and an interface are compared ---

Glyph compared a record against an interface, but not a primitive. f(5) with f(h: HasName) and fn n(s: string) -> HasName { return s } both passed check --no-tsc, and glyph query assignable answered UNDETERMINED for them. Only tsc refused them.

A string, number, int, bool, string-literal union, refined primitive or array where an interface is declared is now compared through its apparent members, the way TypeScript does it. 5 has no name, so it does not satisfy HasName. "abc" has a length, so it does satisfy interface HasLen { length: number }. The other direction is simpler: an interface's value is an object, so it is refused where a string, a number or an array is declared. A bounded T: HasName returned where a string is declared is refused the same way.

The message ends with the reason, for example `number` has no member `name`, which `HasName` requires. glyph query assignable and glyph_impact now give the relation's answer for these pairings instead of UNDETERMINED.

Still left to tsc: a primitive against an interface whose members are all optional and shared with nothing (G526), Option, Result and Record against an interface (G527), an interface where Nullable<string> is declared (G528), and member reads on a bool (G507). A bigint is still typed as a number in this release; 0.1.183 fixes that.

Breaking

Yes. fn n1(s: string) -> HasName { return s } exits 0 under 0.1.181's check --no-tsc and 1 under 0.1.182. Every new refusal is one tsc makes. Across the 375 programs the corpus script measures, the only change is a new test fixture that refuses on purpose.
