--- version: 0.1.183 month: 2026-11 date: 2026-11-24 tags: breaking headline: bigint is its own type ---

Glyph's checker treated a bigint as a number. fn f() -> number { return 5n } passed check --no-tsc, a bigint passed where a number was declared and the other way round, and glyph query assignable answered COMPATIBLE for bigint against number. TypeScript refuses all of these, and at run time mixing the two throws.

Now 1n and anything declared bigint are a bigint. A bigint and a number (or an int) are not assignable to each other in either direction: E0204 at a return or let, E0211 at an argument. Arithmetic, bitwise and shift operators on two bigints give a bigint. Mixing a bigint and a number in one operator, or using >>> on a bigint, is the new E0258, because JavaScript throws a TypeError there. Comparisons like a < n stay allowed, as JavaScript allows them.

A bigint's members come from TypeScript's own declarations, so x.toFixed(2) is E0210, and a bigint where an interface is declared is checked against those members: it does not satisfy interface Fx { fn toFixed(d: number) -> string }. E0243's help for sorting a bigint array now writes a comparator that compares instead of a - b, which would not type.

Glyph has no conversion between number and bigint yet. That is G571, scheduled as std/bigint with functions that return a Result rather than throwing or silently losing precision.

Also in this release

glyph init now writes .vscode/extensions.json, so opening a new project in VS Code, Cursor, Windsurf or VSCodium offers to install the Glyph extension.

Breaking

Yes. fn f() -> number { return 5n } exits 0 under 0.1.182's check --no-tsc and 1 under 0.1.183. Every new refusal is one tsc makes. Across the 375 programs the corpus script measures, the output is identical to 0.1.182.
