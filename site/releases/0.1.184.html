--- version: 0.1.184 month: 2026-11 date: 2026-11-24 tags: breaking headline: An index read has its element's type ---

Reading an element by index gave a value with no type at all. With xs: Array<string>, return xs[0] under -> number, let n: number = xs[0], and xs[0].lenght all passed check --no-tsc. Anything read through an index was invisible to Glyph's checker, the editor and the MCP tools, and only tsc saw it.

Now xs[i] on an Array<E> is an E, and m[k] on a Record<K, V> is a V where E0224 allows the read. Aliases and bounded type parameters are read through. That element then gets every check a typed value gets: E0204 at a return or annotated let, E0211 at an argument, E0210 for a misspelled member, and a mut method call on it is checked too. A receiver the checker cannot type stays undecided.

The type of a write's place and the type of a read come from the same lookup, so let n: number = rows[0] and mut rows[0] = 5 on a type Rows = Array<string> both name string.

Two Glyph rules now reach index reads too, and tsc accepts both programs: "${rs[0]}" on an array of records is E0237, because it prints [object Object], and ms[0]["k"] on an array of maps is E0224, because the key may be missing. The same element bound by a for loop was already refused by both rules.

The index key itself is still not checked against the key type. That is G511, next.

Breaking

Yes. let n: number = xs[0] on an Array<string> exits 0 under 0.1.183's check --no-tsc and 1 under 0.1.184. Across the 375 programs the corpus script measures, the output is identical to 0.1.183.
