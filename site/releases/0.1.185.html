--- version: 0.1.185 month: 2026-11 date: 2026-11-24 tags: breaking headline: A function value's parameters are compared, and function types are printed ---

Glyph compared a function value's return type with the function type its position declared, but never its parameters. takes_cb(fn(x: number) -> string { .. }) where fn(string) -> string is declared passed check --no-tsc, and so did a callback taking a number passed to array.map over strings. When the return did differ, the message read expected `function`, found `function`.

Parameters are now compared too, the safe way round: the slot's argument has to be accepted by the function's parameter. A function taking more required parameters than the slot passes is refused; one taking fewer is fine, as in TypeScript. A generic function value like id<T> is fitted to the slot before it is compared, and if it can't be fitted it is left to tsc rather than refused. A method member of an interface is compared the same way, which is stricter than TypeScript's method bivariance on purpose.

Every message about two function types now prints both signatures and says where they part, for example expected `fn(string) -> string`, found `fn(number) -> string`: parameter 1: the slot passes a `string`, which the function's `number` parameter does not take. A sort comparator's parameter types are now checked against the array's element type as well.

glyph query assignable answers for function types instead of UNDETERMINED. glyph_impact still does not decide a function read as a value (G531), and a generic function value whose shape cannot fit (fn first<T>(xs: Array<T>) where fn(string) -> number is declared) is still left to tsc (G532).

Breaking

Yes. takes_cb(fn(x: number) -> string { return "n" }) exits 0 under 0.1.184's check --no-tsc and 1 under 0.1.185. Every new refusal is one tsc makes, except a method member's parameter, which is Glyph's stricter rule. Across the 375 programs the corpus script measures, three error messages now print signatures where they printed function; no exit code changed.
