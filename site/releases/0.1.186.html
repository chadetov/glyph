--- version: 0.1.186 month: 2026-11 date: 2026-11-25 headline: Calls inside an @example are call sites ---

glyph_impact, glyph_references and glyph_dependencies did not see a name used inside an @example or a @doc fence tagged glyph @run. Renaming a function listed every caller in the program and missed the example that calls it, and that example then failed with E0103 the next time the tests ran. A function whose only caller was another module's @example looked unused.

Those names are now CALLS and REFERENCES sites. Every entry of the two relations carries a context field: example, doc_run, or null for a site in the program. A site in a test names the declaration the annotation sits above. The index builds the same file the example gate builds and resolves it with the same front end, so a site it lists is one the gate would compile. A rename now lists the example with the E0103 it would raise, and change_signature_type decides the example's argument against the new parameter type.

Two classes are still missed, and both answers say so under not_indexed. A field access or a match inside a test is in neither FIELD_ACCESS nor MATCH_SITES (G547). The language server's references and rename read each file on its own, so an editor rename still leaves a test spelling the old name (G546). Both are scheduled.

Also in this release

Two exact-or-absent cases still expected UNDETERMINED for an imported second name of a primitive, a pairing the checker has decided since G315. They now expect WILL_FAIL, and scripts/check_exact_or_absent.py runs in CI, so a case that drifts from the checker fails the build (G548).

Breaking

No. No exit code changes: the program record 196 uses to probe this exits 0 under check --no-tsc and full check with 0.1.185 and with 0.1.186. Across the 376 programs the corpus script measures, the output is identical to 0.1.185. What changes is the answers of the three tools, which gain entries and the context field.
