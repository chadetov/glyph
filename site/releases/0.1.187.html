--- version: 0.1.187 month: 2026-11 date: 2026-11-25 tags: breaking headline: A project can ban an import path and name its own wrapper ---

A team that wraps a library, say its own HTTP client with retries and auth over axios, had no way to stop an agent from importing the raw library next to the wrapper. The import compiled, and the only defence was a code review that noticed it.

package.json can now say so under the glyph key:

"glyph": {
  "src": "src",
  "banned_imports": {
    "axios":  { "use": "http/client", "reason": "requests go through the retry and auth wrapper" },
    "std/fs": { "use": "storage", "allow_in": ["storage", "migrations/"] }
  }
}

An import of axios, or of any path under it, outside http/client is E0115 at the import path, and so is std/fs outside storage and migrations/. The help names the module to import instead and the glyph query exports --module command that lists what it offers. It never suggests adding the importing file to allow_in. The same specifier quoted inside an extern_ts body is E0115 as well, so the escape hatch does not reopen the door. check, build, the language server and the MCP glyph_diagnostics tool all report it, and each re-reads the manifest after an edit without a restart.

The glyph key is now checked

The glyph key used to accept anything. It is now a closed schema with four keys: src, banned_imports, and glyph publish's imports and audit. An unknown key or field, a src that is not a string, a use that names no project module, std/ module or declared dependency, a use that is itself banned, and an allow_in entry that names nothing are E0116. The error is reported in package.json at the key, with its JSON path.

Two edges are filed. A package.json that does not parse loses its bans along with the rest of the key (G551), and no query verb lists a project's bans yet (G552).

Breaking

Yes, for a project that writes a key under glyph that Glyph does not read. "glyph": {"src": "src", "bogus": 1} exits 0 under 0.1.186's check --no-tsc and full check, and 1 under 0.1.187 with E0116. No tracked or outside package.json we test against writes one. Across the 376 programs the corpus script measures, the output is identical to 0.1.186.
