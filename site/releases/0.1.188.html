--- version: 0.1.188 month: 2026-11 date: 2026-11-25 tags: breaking headline: A generic interface's members are checked ---

Glyph checked a value of a plain interface against the interface's members, but not a value of a generic one. Under interface Cmp<X> { fn cmp(o: X) -> number v: X }, a c: Cmp<string> let c.cmp("a") through where a string was declared, c.v where a number was, c.nope, and c.cmp(5). check --no-tsc said nothing and only tsc caught them. An F-bound such as T: Cmp<T>, accepted since 0.1.173, therefore guaranteed nothing about what a.cmp(b) takes or returns.

Now an application like Cmp<number> has the interface's members with X replaced, computed in one place. A member read, a method call, and a value passed where the application is declared are all checked against that member set, the same way a non-generic interface is. The four reads above are E0204, E0210 (it suggests cmp for cpm) and E0211, each one a refusal tsc also makes. Inside fn f<T: Cmp<T>>, a.cmp(b) takes a T and returns a number.

Variance comes from the substitution, so Box<Mode> passes where Box<string> is declared. One case is Glyph's own rule: Sink<Mode> where Sink<string> is declared, under interface Sink<X> { fn put(x: X) -> void }, is E0204, because Glyph compares method parameters the safe way round (D40) where tsc lets method parameters vary both ways. That message names the two interface types but not the two put signatures yet (G539).

glyph query assignable answers WILL_FAIL for a record that lacks an application's members, where it answered UNDETERMINED, and glyph_impact's change_signature_type runs the same check for an application of a local interface.

Breaking

Yes. The probe program for this change exits 0 under 0.1.186's check --no-tsc and 1 under 0.1.188. Every refusal it adds is one tsc makes, apart from the Sink case above. Across the 376 programs the corpus script measures, one diagnostic was added, in the test fixture written for this change.
