--- version: 0.1.189 month: 2026-11 date: 2026-11-25 headline: A type written with extern_ts or typeof is left to tsc ---

Glyph refused some programs that TypeScript accepts. With type Raw = extern_ts("\"read\"") and type Mode = "read" | "write", returning a Raw where a Mode is declared was E0204. So was an extern_ts("any") where a record or a tagged union is declared. The refusal came from the rule that compares two declared types by name: it read Raw and Mode as two different declarations. But Glyph cannot see what an extern_ts or typeof body stands for, so it has no grounds to say they differ.

Now any pairing with a name whose body is extern_ts or typeof, on either side, is left undecided, and tsc decides it on the full check. That holds at a return, an annotated let, an argument, and inside Array<...>. glyph query assignable and the glyph_assignable tool answer UNDETERMINED for these pairings, with a reason, where they answered WILL_FAIL.

A real unknown is not affected. type U = unknown where Mode or a record is declared is still E0204, and so is a string where Mode is declared.

Breaking

No. This release only removes refusals. The probe program exits 1 under 0.1.188's check --no-tsc and 0 under 0.1.189. Across the 376 programs the corpus script measures, the only difference is this release's own test fixture, where two E0204s are gone.
