--- version: 0.1.190 month: 2026-11 date: 2026-11-26 tags: breaking headline: An interface value is judged the same however its type is written ---

A value whose type is an interface reached two different checks depending on how its type was written. A plain interface (HasV) and a generic one applied to an argument (Box<number>) went down separate paths, and they often answered in opposite ways. HasV was refused where a record Ord was declared and passed where a Record<string, number> was. Box<number> did the reverse. The same kind of value got a different verdict because of its spelling.

Both spellings now go through one rule:

  • Where a record with fields, a tagged union or a modeled stdlib type is declared, both are refused (D49). A record with no fields takes both.
  • Where a map with a string, number or int key is declared, both are refused, as tsc refuses them: an interface has no index signature. The exception is a value type Glyph cannot read, an extern_ts or typeof body, which tsc may read as any. That pairing is left to tsc.
  • Where Option, Result or Array is declared, both are refused (G586). tsc refuses these too.
  • Where a Nullable is declared, the value is compared with what the Nullable holds. Box<number> where Nullable<Box<number>> is declared was a false refusal and now passes.

glyph query assignable gives the same answers. An interface imported from a sibling module is still not judged; that is G541, scheduled for 0.1.197.

Breaking

Yes. Returning a HasV where Record<string, number> or Option<number> is declared exits 0 under 0.1.189's check --no-tsc and 1 under 0.1.190. tsc already refused both on a full check. Returning a Box<number> where the record Ord is declared exits 0 under both of 0.1.189's checks and 1 now. That is Glyph's own rule for declared records (D49), which tsc does not apply. Across the 376 programs the corpus script measures, the output is identical to 0.1.189.
