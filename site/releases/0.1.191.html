--- version: 0.1.191 month: 2026-11 date: 2026-11-26 headline: E0225 fires only when a stale value reaches the write ---

E0225 catches a lost update in async code: a value is read from a place, the function waits on an await, and then the place is written with something computed from the old value. Anything that changed the place during the wait is overwritten. The rule fired whenever a place was read before an await and written after it, even when the written value did not come from that earlier read. let now = c[0] after the await, then mut c[0] = now + f, was refused, and so was mut a.balance = a.balance + f written entirely after the wait. Both read the place again after the await, so no update can be lost.

Now E0225 fires only when the written value mentions something read from the place before the await, directly or through let bindings computed from it. let first = c[0], let x = first * 2, await, mut c[0] = x is still refused through x, with the original read underlined. Every write the rule caught for a real reason before still fires.

One miss is deliberate. A binding that some mut later reassigns carries no taint, so a stale value passed through one is not reported. The checker prefers missing that case to refusing correct code.

Breaking

No. This release only removes refusals. The probe program exits 1 under 0.1.190's check --no-tsc and full check, and 0 under 0.1.191. Across the 376 programs the corpus script measures, the output is identical to the previous release.
