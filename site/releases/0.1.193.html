--- version: 0.1.193 month: 2026-11 date: 2026-11-26 tags: breaking headline: process.exit returns never ---

Glyph typed process.exit(code) as returning an untyped value. A match with one arm that exits and one that produces a number took that untyped value as its result. So let s: string = x afterwards passed check --no-tsc, and only tsc caught it.

process.exit now returns never, the type of a call that does not come back. A match whose other arms give a number is a number, so the line above is E0204. A never fits anywhere a value is expected, the same way tsc reads it:

  • a function declared -> number whose body ends in process.exit(1) is not refused for a missing return;
  • n ?? process.exit(1) is a string when n is a Nullable<string>;
  • [1, process.exit(1)] is an Array<number>;
  • a lambda that exits fits where fn() -> void is declared, and "${process.exit(1)}" is accepted.

The std/process module now has no untyped row left.

Breaking

Yes. The probe program exits 0 under 0.1.192's check --no-tsc and 1 under 0.1.193; full check already refused it through tsc. Across the 376 programs the corpus script measures, the output is identical to the previous release. All three process.exit calls in it are statements.
