--- version: 0.1.195 month: 2026-11 date: 2026-11-26 headline: Stdlib functions with an optional parameter are published as their call forms ---

A few stdlib functions take an optional last argument: string.pad_end, pad_start, string.slice, string.index_of, array.slice and json.stringify, plus set.create and collections.deque. glyph llms and AGENTS.md printed each one with a single signature in which every parameter looked required. An agent reading fn(string, number, string) -> string for pad_end had no way to know the third argument could be left out. Glyph's function types cannot spell an optional parameter, so no single signature was right.

These eight rows now publish their call forms instead, shortest first. pad_end is listed as fn(string, number) -> string and fn(string, number, string) -> string. In glyph llms --json each row carries call_forms, signature: null, and a signature_absent sentence that says which parameter may be left out. json.stringify keeps its ? slots and its signature_partial note.

The checker already enforced these rows: a missing or extra argument is E0213, and a match on string.index_of with no None arm is E0200. AGENTS.md still told agents the rows were untyped (G626), and that paragraph is rewritten to say they are modeled and to read call_forms.

Breaking

No. No program changes its exit code. pad_end(s, 4) and pad_end(s, 4, "-") pass under 0.1.194 and 0.1.195 alike. Across the 376 programs the corpus script measures, the output is identical to 0.1.194. What changes is the published signature data for these eight rows.
