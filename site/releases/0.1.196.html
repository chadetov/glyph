--- version: 0.1.196 month: 2026-11 date: 2026-11-26 tags: breaking headline: A generic bound is checked where the type parameter is bound ---

Glyph read a bound such as T: HasName inside the generic function, but never checked it where the function was called. label(o) with an o: Other that lacks name passed check --no-tsc, and so did Box<Other> written as a type. The bound was a promise the checker did not hold callers to.

Now a bound is checked wherever its type parameter gets a type (D72):

  • at a call, from the arguments or from an explicit label<Other>(o);
  • at a written type such as Box<Other>;
  • at a generic component's element.

An argument that leaves the bound is E0211, and the note says which argument bound T and which member the bound requires. An explicit type argument or a written type that leaves it is the new E0251. An F-bound such as T: Cmp<T> is checked through the type it binds.

When two literals join, as in mb("a", "c") under T: Mode, the error lands on the literal outside the bound, "c", which is where tsc puts it. An interface declared in a sibling module is not judged yet; that is G541, the next release.

Breaking

Yes. label(o) with o: Other exits 0 under 0.1.195's check --no-tsc and 1 under 0.1.196. tsc already refused it on a full check. Across the 376 programs the corpus script measures, the output is identical to 0.1.195.
