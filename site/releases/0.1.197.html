--- version: 0.1.197 month: 2026-11 date: 2026-11-26 tags: breaking headline: An interface from another module is judged by its members ---

An interface declared in one module and used in another was not checked. With pub interface HasName { name: string } in lib, passing an Other that has no name to takes(o: HasName) in main passed check --no-tsc. So did let d: HasName = o, a return, a field, and a bound T: HasName. The same program with the interface declared in main was refused. The verdict depended on which file held the declaration.

Now an imported interface is read by its members wherever it is used, under the same rule as a local one (D34). The named import and the namespace spelling lib.HasName give one verdict, and so do re-exports and second names declared in a sibling. A generic sibling interface such as Box<number> is read through its argument. Wrong argument counts like Box or Box<number, string> are E0233, as they are locally. Messages keep the interface's name. glyph query assignable and the impact tool give the same answers as the check.

A second name a module declares for an interface, type LN = HasName, is now read as that interface whether the interface is local or imported (G649, G651). The local case used to refuse a value that has the members. A Good with a name was rejected where LN was declared, and tsc accepts it. That false refusal is gone.

Breaking

Yes. Two modules with only takes(o) exit 0 under 0.1.196's check --no-tsc and 1 under 0.1.197. tsc already refused it on a full check. One program goes the other way: the Good passed where type LN = HasName is declared now checks clean. Across the 376 programs the corpus script measures, the only change is in the test fixtures written for this release.
