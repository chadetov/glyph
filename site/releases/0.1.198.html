--- version: 0.1.198 month: 2026-11 date: 2026-11-26 headline: std/bigint converts between number and bigint ---

Since 0.1.183 a bigint and a number are separate types, and Glyph had no way to convert one into the other. JavaScript's BigInt(n) throws on a fraction, and Number(b) silently loses precision past Number.MAX_SAFE_INTEGER. Neither is available in Glyph.

std/bigint adds two conversions that return a Result instead:

  • bigint.from_number(n) is Ok for a whole number and Err for a fraction, NaN or an infinity. -0 gives 0n, and 1e21 gives its exact bigint.
  • bigint.to_number(b) is Ok from -Number.MAX_SAFE_INTEGER to Number.MAX_SAFE_INTEGER and Err outside that range, including at exactly 253, which several larger values round to.

Nothing in the module throws. bigint still works as a type name next to the bigint namespace.

The help on the errors that led here now points at these functions. BigInt(x) and Number(b) are still E0103, with help that names bigint.from_number and bigint.to_number. The Number help also names number.parse(s) for text. Mixing a bigint and a number in one operator is still E0258, and its help now states the exact range to_number accepts. When the number is a fraction like 1.5, the help says no bigint holds a fraction.

Breaking

No. A program that imports std/bigint was E0104 under 0.1.197 and checks under 0.1.198. No other exit code changes. Across the 379 programs the corpus script measures, only the module's own tests and the list of std modules in one E0104 message change.
