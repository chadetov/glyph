Cases TypeScript lets through

Caught before it ships

There are 45 checked cases: 37 TypeScript cases, 5 JavaScript traps that do not exist in Glyph, and 3 holes Glyph does not close yet. Glyph refuses 28 of them when you build (23 TypeScript cases and 5 traps).

Every TypeScript example on the list passes tsc --strict with no errors. Each one is also checked against a fully configured project: every compiler flag stricter than --strict, plus typescript-eslint strictTypeChecked. For 21 of the 37 cases, nothing in that setup catches it. A compiler flag that is off by default catches 5, and a lint rule catches 11. A project has to turn each of those on, and an agent can turn it off again. In Glyph none of them is a setting.

Each entry is two programs in catches/, and the output under each one is what the tools printed. A build gate, scripts/check_catches.py, re-runs every case and fails if either half stops doing what the page says. The full TypeScript configuration it checks against is in that script.

Likely how often an AI agent writes it Severity how bad it is when it ships

The scores are our judgement, 1 to 5, drawn from published studies of agent-written code and from our own agent runs. Nobody has measured these rates directly. The list is sorted by likelihood times severity.

1

Data from outside the program

Likely 5 of 5Severity 5 of 5

A request body, a file, an API response.

TypeScriptcompiles, then runs on bad data
ts.ts
const user = JSON.parse(body) as User;
console.log(sendInvoice(user.plan));
$ tsx ts.ts
invoice for the undefined plan

Nothing checks the data. undefined travels on as a plan.

Nothing catches itnot even with every compiler flag and typescript-eslint strict on

Glyphchecked when the data arrives
glyph.glyph
let out = match json.parse<User>(body) {
  Ok(user) => send_invoice(user.plan),
  Err(issues) => "rejected: ${json.stringify(issues)}",
}
$ glyph run
rejected: [{"path":["plan"],"message":"field `plan` is required","code":"missing"}]

A body that is not a real User is an Err. The program never holds a fake one.

as User does not check anything. It tells the compiler to trust you. Glyph has no as.

2

A case nobody handled

Likely 5 of 5Severity 4 of 5

An agent adds an "archived" status. The handler that announces each status was written before it existed.

TypeScriptcompiles with no warning
ts.ts
switch (s) {
  case "todo":
    console.log("not started");
    break;
  case "doing":
    console.log("in progress");
    break;
  case "done":
    console.log("finished");
    break;
}
$ tsx ts.ts
finished
archived logged nothing

Archiving an item logs nothing. Nothing says the switch is out of date.

Lint onlycaught by the lint rule switch-exhaustiveness-check

Glyphrefused when you build
glyph.glyph
match s {
  "todo" => print("not started"),
  "doing" => print("in progress"),
  "done" => print("finished"),
}
$ glyph build
[E0200] Error: typecheck: non-exhaustive match on `"todo" | "doing" | "done" | "archived"`: missing variants "archived"
Help: Add an arm for each missing variant.

The build stops and names the case.

TypeScript checks that a switch covers every case only when the function returns a value from every branch, or with the assertNever idiom. A handler that returns nothing gets neither. In Glyph every match must cover every case, so adding a variant lists each place that has to change.

3

Trusting find with !

Likely 5 of 5Severity 4 of 5

Looking a record up by id.

TypeScriptcompiles, then crashes at run time
ts.ts
return users.find((u) => u.id === id)!.name;
$ tsx ts.ts
TypeError: Cannot read properties of undefined (reading 'name')

! tells the compiler "trust me". At run time it does nothing.

Lint onlycaught by the lint rule no-non-null-assertion

Glyphrefused when you build
glyph.glyph
return array.find(users, fn(u: User) -> bool { u.id == id }).name
$ glyph build
[E0210] Error: typecheck: type `Option<User>` has no field `name`: an `Option` has no members
Help: Open it with `match array.find(...) { Some(u) => u.name, None => <default> }`. If the absence is a JSON `null` from the wire, declare the type `Nullable<User>` (D45).

find returns an Option, so the empty case must be handled.

Without the !, tsc --strict refuses this line. The ! is what switches that check off, and it does nothing at run time. Glyph has no !.

4

An error the signature hides

Likely 4 of 5Severity 4 of 5

A function that can fail, called by code that does not know it can.

TypeScriptcompiles, then crashes at run time
ts.ts
function loadConfig(): Config {
  throw new Error("missing file");
}

const cfg = loadConfig(); // no try
$ tsx ts.ts
Error: missing file

The type says Config. Nothing says it can throw.

Nothing catches itnot even with every compiler flag and typescript-eslint strict on

Glyphrefused when you build
glyph.glyph
fn load_config() -> Result<Config, string> {
  return Err("missing file")
}

let cfg: Config = load_config()
$ glyph build
[E0204] Error: typecheck: type mismatch: expected `Config`, found `Result<Config, string>`
Help: Change the value, or the declared type, so the two agree.

Failure is part of the return type, so the caller has to handle it.

A TypeScript function's type lists what it returns, never what it throws. In Glyph, failure is part of the return type, so every caller can see it.

23

Comparing two records with ===

Likely 3 of 5Severity 3 of 5

Skipping a save when nothing changed.

TypeScriptcompiles, then compares identity, not data
ts.ts
const before = { x: 1, y: 2 };
const after = { x: 1, y: 2 };

if (before === after) skipSave();
$ tsx ts.ts
skipped false

Same data, but === asks whether they are the same object. Every save runs.

Nothing catches itnot even with every compiler flag and typescript-eslint strict on

Glyphcompares the data
glyph.glyph
let before: Point = { x: 1, y: 2 }

Two records with the same fields are equal.

5 JavaScript traps that do not exist in Glyph

Older traps that agents still hit now and then. Glyph refuses each program, but not by spotting the mistake: the feature behind it is not in the language, and the replacement is named.

  • "10,20,30".split(",").map(parseInt) is [10, NaN, NaN], because map passes the index as the number base. Glyph has number.parse, which returns a Result. Open in playground
  • A /g regex reused with .test fails every second match, because it remembers lastIndex. Glyph has no regex objects; regex.matches(pattern, text) has no state. Open in playground
  • [1, 2, 3].forEach(counter.increment) runs the method without its object. Glyph has no classes and no this. Open in playground
  • Math.max(...[]) is -Infinity. Glyph's array.max returns an Option, empty for an empty list. Open in playground
  • Array(3).map(...) returns three holes, because map skips them. Glyph has no Array(n); arrays are written as literals. Open in playground

What Glyph does not catch yet

3 holes Glyph does not close yet. Each of these compiles in Glyph today and does the same wrong thing as in TypeScript. Every one has a reproduction in catches/ and an open gap number, and the gate fails when a fix lands so the entry cannot outlive the hole.

  • requested || 3 turns a real 0 into 3. G386
  • input + 1 on a string, users.find(...).name, and a field read on unknown are caught only by the tsc step, not by Glyph's own checker, so the editor and agent tools miss them. G381, G382

Logic errors are the largest class in every study of agent-written code, and no type checker sees them: a wrong formula, or a task that was misread, compiles in Glyph as it does in TypeScript.

Glyph has one escape hatch, extern_ts, for TypeScript it cannot express. It is a fixed keyword, so grep extern_ts lists every place the rules are suspended.
