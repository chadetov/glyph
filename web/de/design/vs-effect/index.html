Glyph und Effect

Beide zielen auf TypeScript, auf das sich Menschen und Agenten verlassen können. Effect ist eine Bibliothek: Du schreibst weiter TypeScript und bekommst typisierte Fehler, verfolgte Abhängigkeiten und einen großen Werkzeugkasten. Glyph ist eine Sprache, die zu TypeScript kompiliert, und kann deshalb ablehnen, was TypeScript erlaubt, einschließlich der Casts, die die Garantien einer Bibliothek aushebeln. Effect ist sehr viel ausgereifter.

Wie Effect sich selbst beschreibt#

Die Startseite von Effect beginnt mit "Reliable TypeScript for the AI era" und sagt, dass seine "declarative patterns and strong type system make it easier for LLMs to generate correct, production-ready code" (effect.website). Die Dokumentation nennt es "an ecosystem of tools that help you build better applications and libraries", aufgebaut um einen Typ Effect<Success, Error, Requirements>, der festhält, was eine Berechnung zurückgibt, wie sie fehlschlagen kann und was sie braucht (Why Effect). Es verlangt TypeScript 5.4 oder neuer mit eingeschaltetem strict (Installation). Diese Zitate wurden am 2026-11-19 gelesen.

Der Unterschied, der aus Bibliothek gegenüber Sprache folgt#

Die Typen von Effect werden von tsc geprüft, also ist alles, was tsc erlaubt, daneben weiterhin erlaubt. Das hier kompiliert unter tsc --strict mit effect 4.1.4 und TypeScript 6. Der Cast entfernt NotFound aus dem Fehlerkanal, und das Programm meldet einen Fehlschlag aus einem Effect, dessen Typ sagt, dass er nicht fehlschlagen kann.

eff.ts: tsc --strict endet mit 0; die Ausführung gibt "Failure undefined" aus 
import { Effect } from "effect"

class NotFound {
  readonly _tag = "NotFound"
}

const find = (id: string): Effect.Effect<number, NotFound> =>
  id === "1" ? Effect.succeed(1) : Effect.fail(new NotFound())

// The error channel says NotFound can happen. A cast erases it.
const quiet = find("2") as unknown as Effect.Effect<number, never>

// And a parsed body still takes any type you name.
type User = { email: string }
const user = JSON.parse("{}") as User

console.log(Effect.runSyncExit(quiet)._tag, user.email)

Dieselbe Funktion gibt in Glyph ein Result zurück, und es gibt keinen Cast, den man schreiben könnte. Das zweite Modul wird abgelehnt, bevor irgendein TypeScript erzeugt wird.

find.glyph: baut, besteht tsc --strict 
module find

pub type NotFound = { id: string }

pub fn find(id: string) -> Result<number, NotFound> {
  return match id == "1" {
    true => Ok(1),
    false => Err({ id: id }),
  }
}
einen Cast hinzufügen: abgelehnt 
module find

pub type NotFound = { id: string }

pub fn find(id: string) -> Result<number, NotFound> {
  return match id == "1" {
    true => Ok(1),
    false => Err({ id: id }),
  }
}

pub fn quiet() -> number {
  let n = find("2") as number
  return n
}

Die Hilfe von E0013 lautet: "Glyph has no as cast ... to turn an unknown into a type, validate it with T.parse(v) or narrow it with match and is." Ein Team kann in einer Effect-Codebasis mit Lint-Regeln nah herankommen, und dieser Vergleich erklärt, warum eine Regel, die jemand abschalten kann, eine andere Garantie ist.

Was Glyph kann und eine Bibliothek nicht#

Eine Sprache entscheidet, was geschrieben werden kann. Glyph hat kein any, keinen Cast, keine Non-Null-Assertion und keinen Kommentar, der einen Fehler stummschaltet, und jedes match über einer Union muss jeden Fall abdecken. Records und Unions bringen eine Laufzeitprüfung mit, die aus der Deklaration erzeugt wird, also validiert json.parse<User>(body). Auch Effects Schema leitet einen Typ aus einer einzigen Beschreibung ab (Schema.Schema.Type<typeof Person> in seiner Einführung), sodass Typ und Validator auch dort nicht auseinanderlaufen; der Unterschied ist, dass nichts in TypeScript eine Codebasis zwingt, es zu verwenden. Der Compiler beantwortet für einen Agenten außerdem Fragen über ein Programm, etwa was eine Änderung kaputtmachen wird, über MCP oder die Kommandozeile.

Diese Seite hat nicht getestet, Effect aus einem Glyph-Modul heraus zu verwenden, und macht deshalb keine Aussage über die Kombination der beiden.
