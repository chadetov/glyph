Para agentes y para quien construye herramientas

La interfaz del compilador para agentes

Un agente puede preguntarle al compilador de Glyph qué es un símbolo, qué va a romper una edición y por qué ha fallado un build, y recibir JSON como respuesta. glyph mcp sirve once herramientas por stdio, cada una también disponible como verbo de glyph query, y glyph llms imprime la referencia del lenguaje sin conexión.

Configúralo#

glyph init escribe este .mcp.json en un proyecto nuevo, y glyph agents lo escribe (con un AGENTS.md que apunta a glyph llms) en uno existente. Cualquier cliente MCP que lea el archivo lanza el servidor; no hay puerto ni daemon.

.mcp.json, tal como lo escribe glyph init 
{
  "mcpServers": {
    "glyph": {
      "command": "glyph",
      "args": ["mcp"]
    }
  }
}

Una llamada, con su respuesta real#

Un archivo lee un campo que su record no declara (u.naem). El agente llama a glyph_diagnostics y recibe el diagnóstico del propio compilador, con los campos que sí declara el record y el record al que pertenecen. Esta es la salida de la herramienta en la 0.1.149, recortada solo donde se indica.

petición 
{
  "method": "tools/call",
  "params": {
    "name": "glyph_diagnostics",
    "arguments": {
      "path": "src/user.glyph"
    }
  }
}
resultado 
{
  "diagnostics": [ {
    "code": "E0210",
    "severity": "error",
    "stage": "typecheck",
    "message": "type `U` has no field
      `naem`; did you mean `name`?",
    "alternatives": ["name", "email"],
    "alternatives_kind": "fields",
    "cause": "user::U",
    "entity": "user::greet",
    "file": "user.glyph",
    "range": {
      "start": { "line": 9, "col": 10 },
      "end": { "line": 9, "col": 16 } },
    ...
  } ],
  "member": true,
  "module": "user",
  "not_run": [
    { "what": "tsc", ... },
    { "what": "E0104, ...", ... },
    { "what": "E0400, ...", ... } ],
  "path": "src/user.glyph",
  "project_root": "src",
  "unindexed": []
}

not_run indica lo que esta comprobación no cubrió, así que una lista de diagnostics vacía no se puede confundir con un build completo. Sin un cliente MCP, glyph query diagnostics --path src/user.glyph imprime el mismo JSON. La lista completa de herramientas, con cada verbo, está en la página de MCP.

Antes de editar: ¿qué va a romper?#

examples/apps/csvql es un motor de consultas CSV de once archivos con una unión de cuatro casos, Value. Al preguntarle qué pasa si se añade un quinto caso, glyph_impact lista 10 sitios con match en 4 archivos: 8 WILL_FAIL y 2 ABSORBS, donde un brazo comodín se tragará el caso nuevo y seguirá compilando. Añadir el caso de verdad da exactamente 8 errores E0200, en esos 8 sitios. Los 2 sitios que lo absorben no dicen nada, y por eso la respuesta los nombra.

la misma pregunta en la línea de comandos 
glyph query impact --path value.glyph --entity value::Value \
  --change add_variant --variant Blob

Después de un build en rojo: ¿qué tiene que respetar el arreglo?#

glyph check --agent imprime los diagnósticos de check --json con dos claves más en cada uno. constraints lista lo que una edición de reparación no debe romper; para la errata de arriba dice "the record's fields are closed: user::U declares name, email and no others". symbols lleva la respuesta de glyph_symbol para cada símbolo que nombra el diagnóstico, así que la siguiente edición no necesita una segunda llamada. Cuando el arreglo está totalmente determinado, glyph fix lo escribe.

Leer el lenguaje sin conexión#

glyph llms imprime la referencia del lenguaje, y /llms.txt en este sitio es el mismo documento. glyph llms --json es ese conocimiento en forma de datos, leído de las propias tablas del compilador: 77 códigos de diagnóstico, 24 nombres del preludio, 40 módulos de la librería estándar con 340 exports, 49 decisiones del lenguaje y las once herramientas. glyph llms --negative devuelve 117 programas incorrectos en la 0.1.149 (139 a partir de la próxima versión) con el código que genera cada uno, compilados cuando lo pides. scripts/check_llms_sync.py falla cuando las tablas de diagnósticos y palabras reservadas de la referencia se desvían de las del compilador.

puntos de entrada sin conexión 
glyph llms                  # the reference, as prose
glyph llms --json           # the same, as data from the compiler's tables
glyph llms --negative E0200 # wrong programs that draw E0200
glyph --explain E0200       # the long explanation of one code
