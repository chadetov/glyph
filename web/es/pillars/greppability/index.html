Buscabilidad

Un nombre, un sitio. Cada símbolo tiene exactamente una forma sintáctica en el lugar donde se declara, así que un grep normal encuentra la definición, siempre, sin índice, sin servidor de lenguaje y sin necesidad de suerte.

Por qué "¿dónde está definido esto?" es difícil

En un código TypeScript maduro, la pregunta más simple, ¿de dónde viene este nombre?, suele ser la más difícil.

Detalles sobrecargas, decoradores, fusión, ampliación, barrels

El lenguaje ofrece media docena de formas de repartir un símbolo por muchos sitios: las sobrecargas dividen una función en varias firmas, los decoradores la envuelven en otra cosa, la fusión de namespace e interface dispersa un tipo entre archivos, declare module amplía código que no es tuyo, y los barrel files index.ts lo reexportan todo, así que la ruta desde la que importas no es donde vive realmente nada.

Una persona se apaña con un LSP y la memoria muscular. Un agente hace grep: lee el repositorio como texto, y cada una de esas construcciones es un sitio donde el texto miente sobre dónde está el código.

Glyph las elimina. El resultado es un lenguaje donde la búsqueda es una primitiva fiable, no una heurística.

01 Una declaración, una forma

Una función, un tipo o un componente se declara exactamente una vez, con una sola sintaxis. No hay sobrecargas que dividan una firma ni forma de volver a declarar un nombre: dos cosas de nivel superior con el mismo nombre son un error (E0100).

E0100

La palabra clave de la declaración forma parte del nombre que buscas. grep "fn parseUser" no puede coincidir con una llamada, un import o un re-export, solo con el único sitio donde está definida.

Así que la búsqueda de una definición tiene exactamente una respuesta.

02 Sin barrel files: la ruta del import es la ubicación

Los imports de Glyph nunca reexportan, y un módulo cuyo único contenido son imports se rechaza (E0102). No hay una capa index.ts que lo blanquee.

el import te dice exactamente dónde mirar 
import myapp/users { parseUser }
//     ^^^^^^^^^^^ the file is src/myapp/users.glyph.
//     not a re-export of a re-export of a barrel.
E0102

Así que un import nombra el módulo donde vive realmente el símbolo: la ruta es la dirección.

03 Sin formas ocultas de añadir comportamiento

No hay decoradores que envuelvan una función en una capa invisible, ni fusión de namespace que junte miembros de todo el árbol, ni declare module que amplíe un tipo de terceros desde un archivo que nunca se te ocurriría abrir, ni this implícito que cambie a qué se refiere un método.

Un nombre se resuelve a una declaración, y todo lo que le da forma está a la vista en esa declaración.

04 Hasta las mutaciones se encuentran con grep

La buscabilidad no consiste solo en encontrar definiciones, también en encontrar efectos. El estado compartido vive en un std/store, y cada cambio sobre él es una llamada literal a .set( o .update(.

$ grep -rn 'tasks\.\(set\|update\)' src/ 
src/tasks.glyph:16:  tasks.update(fn(cur) { ... })
src/tasks.glyph:24:  tasks.set([])
# every place the task list can change, enumerated.
# nothing hides in an ordinary `x = ...` elsewhere.

Así que una sola búsqueda enumera toda la superficie de escritura de un estado, en lugar de ir a la caza de asignaciones repartidas por el archivo.

Un código se puede buscar con grep cuando su texto dice la verdad sobre su estructura. Cada restricción de aquí (una forma por nombre, sin re-exports, sin fusiones) existe para que una búsqueda devuelva la respuesta, no una pista.

El benchmark: en camino

La versión medible de esta afirmación es la precisión: para un símbolo dado, ¿qué fracción de las coincidencias de un grep normal son lo que realmente buscabas, y cuántos pasos necesita un agente para llegar a una definición?

Glyph todavía no se usa en el mundo real, así que el gráfico de abajo es un marcador de posición, y se rellenará con cifras reales cuando haya un código real que medir.

La ventaja crece con la escala y con la autonomía. Una persona aprende los escondites de un código; un agente que empieza de cero no. La buscabilidad es lo que permite a una herramienta (o a un compañero nuevo) orientarse leyendo, tal como es realmente el repositorio.

"Una regla de lint puede prohibir las sobrecargas y los decoradores"

En tu propio repositorio, sí. ESLint puede prohibir los namespaces, y un equipo puede acordar no usar sobrecargas.

El lenguaje lo sigue permitiendo todo, así que la garantía dura lo que dure la configuración y solo cubre el código sobre el que se ejecuta. Un grep sobre una dependencia, un archivo generado o el repositorio de otra persona no puede contar con ello.

En Glyph esas construcciones no existen, así que grep funciona igual en todos los archivos Glyph, incluidos los que nadie de tu equipo configuró.

Cómo se ve esto desde el lado del agente, encontrar una definición o cada escritura sobre un valor con una sola búsqueda, se responde en ¿Puede un agente (o yo) encontrar dónde está definido cualquier cosa?
