Tu primer programa en Glyph

Crea un proyecto, ejecútalo, después rómpelo a propósito y lee el error que te da el compilador. No hace falta saber nada de Glyph. Si has escrito un poco de TypeScript, vas a entender cada línea.

1 · Crea un proyecto#

Glyph se distribuye en npm como binario precompilado para macOS y Linux (x64 y ARM) y para Windows (x64), y necesita Node 18 o posterior. Este camino no instala nada globalmente: npx descarga el compilador para crear el proyecto, y el proyecto fija su propia copia junto con tsx y typescript, que Glyph usa para ejecutar y comprobar tipos.

terminal 
npx -y @glyphlang/glyph init hello
cd hello
npm install

Si prefieres tener glyph en el PATH, instálalo globalmente junto con las dos herramientas que usa por debajo y quita el npx de los comandos de esta página:

terminal, la alternativa global 
npm install -g @glyphlang/glyph tsx typescript
glyph doctor                    # confirms your toolchain is ready
glyph init hello
cd hello

2 · Mira lo que ha creado#

glyph init crea un proyecto inicial que ya se ejecuta: src/main.glyph; src/.types/README.md, que explica que un paquete de npm con tipos no necesita nada ahí y que el directorio es para uno que no trae tipos; un package.json; un .gitignore; y dos archivos que los agentes de programación leen por su cuenta: AGENTS.md, que remite a glyph llms para la referencia completa del lenguaje, y .mcp.json, que registra glyph mcp para que un agente pueda pedirle al compilador tipos y referencias en lugar de buscarlos. En un proyecto que ya tienes, glyph agents escribe esos dos. El package.json fija el compilador, typescript y tsx en devDependencies, así que cualquiera que clone el proyecto puede compilarlo con npm install y sin instalar nada globalmente.

Abre src/main.glyph. Es un hola mundo:

src/main.glyph 
module main

import std/io

fn main(argv: Array<string>) -> number {
  io.println("hello from glyph")
  return 0
}

Dos cosas en las que fijarse: un programa ejecuta su main(argv), y main devuelve un number, el código de salida del proceso. Devolverlo fija ese código sin obligar al proceso a terminar, así que un programa que arranca un servidor sigue atendiendo peticiones.

3 · Ejecútalo#

terminal 
npx glyph run
hello from glyph

glyph run comprobó los tipos, lo compiló a TypeScript y lo ejecutó. Ese es el ciclo que vas a repetir en el resto de la página. Si quieres ver los errores y los tipos en tu editor mientras sigues los pasos, la configuración está en Editores e integraciones.

4 · Añade algo de verdad#

Ahora sustituye el cuerpo por una decisión que importa: si enviar un pedido o no, según cómo esté su pago. Así aparecen las dos cosas que usarás todo el tiempo: una unión etiquetada (type Payment = ...) y match, que es el único condicional de Glyph.

src/main.glyph 
module main

type Payment = Pending | Paid | Failed

fn ship(p: Payment) -> string {
  return match p {
    Pending => "hold: waiting for the money",
    Paid => "ship it",
    Failed => "hold: payment failed",
  }
}

fn main(argv: Array<string>) -> number {
  print(ship(Paid))
  return 0
}
terminal 
npx glyph run
ship it

5 · Rómpelo a propósito#

Esta es la parte que muestra para qué sirve Glyph. Un ticket pide "admitir reembolsos", así que añade un caso Refunded a Payment y no toques ship. Es lo que hace un agente cuando cambia un tipo en un archivo y nunca abre el código que decide según él. Vuelve a ejecutarlo.

src/main.glyph (una palabra añadida) 
type Payment = Pending | Paid | Failed | Refunded
$ npx glyph run 
[E0200] Error: typecheck: non-exhaustive match on `Payment`: missing variants `Refunded`
    ╭─[ main:6:10 ]
    │
  6 │ ╭─▶   return match p {
    ┆ ┆
 10 │ ├─▶   }
    │ ╰───────── non-exhaustive match on `Payment`: missing variants `Refunded`
    │
    │     Help: Add an arm for each missing variant.
────╯

No se ejecutó. El TypeScript con el que se escribe casi todo el código hace lo contrario: un switch que trata los dos casos de "hold" y termina en default: return "ship it" pasa tsc --strict después de añadir el caso nuevo, y envía cada pedido reembolsado. Aquí, todo match al que le falta un caso es un error de compilación con un código estable (E0200), el punto exacto y el nombre del caso. Ejecuta glyph --explain E0200 cuando quieras la versión larga.

6 · Corrígelo#

El compilador no puede decidir qué significa un reembolso para el envío; eso lo decides tú. Añade el brazo y vuelve a ejecutarse.

src/main.glyph 
fn ship(p: Payment) -> string {
  return match p {
    Pending => "hold: waiting for the money",
    Paid => "ship it",
    Failed => "hold: payment failed",
    Refunded => "hold: refunded, nothing to ship",
  }
}
terminal (con print(ship(Refunded))) 
npx glyph run
hold: refunded, nothing to ship

Ese es el ciclo básico: escribes, ejecutas y, cuando algo está mal, el compilador te dice exactamente qué y cómo, antes de que tu código llegue a producción, no después.
