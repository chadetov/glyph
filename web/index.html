Every TypeScript example on the list passes tsc --strict with no errors. Each one is also checked against a fully configured project: every compiler flag stricter than --strict, plus typescript-eslint strictTypeChecked. For 21 of the 37 mistakes, nothing in that setup catches it. A compiler flag that is off by default catches 5, and a lint rule catches 11. A project has to turn each of those on, and an agent can turn it off again. In Glyph none of them is a setting.

One change, on a real application

examples/apps/csvql is a CSV query engine in this repository, with a Value union at its centre. Before adding a case to it, ask the compiler which places it reaches.

glyph_variants { name: "Value" } 
10 match sites across 4 files
 8 will fail compilation
 2 contain a catch-all and will silently absorb it
then add the case and run glyph check 
8 errors, E0200 non-exhaustive match. The same eight.
The two catch-all sites report nothing at all.

The prediction was right on all eight. The other two, exec::total and render::literal_text, keep compiling and send the new case wherever their catch-all points. An agent that fixes the eight errors and stops has a green build and two live bugs, and the query is what names them.
