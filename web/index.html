v0.1.180 · early preview →

Your AI agent writes it. The compiler checks it.

Glyph reads like TypeScript, with the escape hatches removed: no any, no casts, no unchecked data, every case handled. It compiles to readable TypeScript, so you keep node, npm and the code you already have.

$ npx -y @glyphlang/glyph init hello && cd hello && npm install && npx glyph run

No global install needed. To put glyph on your PATH instead: npm install -g @glyphlang/glyph tsx typescript

Cases nothing in TypeScript catches

The three highest-ranked cases that pass tsc --strict with every extra flag on and typescript-eslint strict, ranked by how often an agent writes them and how bad they are when they ship.

1

Data from outside the program

A request body, a file, an API response.

TypeScript: compiles, then runs on bad dataGlyph: checked when the data arrives

 2

A function that can fail, called by code that does not know it can.

TypeScript: compiles, then crashes at run timeGlyph: refused when you build

 3

An error nobody looked at

Calling something that can fail and moving on.

TypeScript: compiles with no warningGlyph: warned

21 of 37

Every TypeScript example on the list passes tsc --strict with no errors. Each one is also checked against a fully configured project: every compiler flag stricter than --strict, plus typescript-eslint strictTypeChecked. For 21 of the 37 cases, nothing in that setup catches it. A compiler flag that is off by default catches 5, and a lint rule catches 11. A project has to turn each of those on, and an agent can turn it off again. In Glyph none of them is a setting. There are 45 checked cases: 37 TypeScript cases, 5 JavaScript traps that do not exist in Glyph, and 3 holes Glyph does not close yet. Glyph refuses 28 of them when you build (23 TypeScript cases and 5 traps).

Your agent can ask the compiler first

examples/apps/csvql is a CSV query engine in this repository, with a Value union at its centre. Before adding a Date case to it, an agent asks the compiler's MCP server what that edit breaks. The answer, trimmed here to verdict, site and function, names ten match sites across four files.

glyph_impact { entity: "value::Value", change: { kind: "add_variant", variant: "Date" } } 
WILL_FAIL  bind.glyph:148    bind::literal_kind
ABSORBS    exec.glyph:130    exec::total
ABSORBS    render.glyph:128  render::literal_text
WILL_FAIL  value.glyph:18    value::render
WILL_FAIL  value.glyph:32    value::key
WILL_FAIL  value.glyph:44    value::is_null
WILL_FAIL  value.glyph:53    value::is_num
WILL_FAIL  value.glyph:62    value::rank
WILL_FAIL  value.glyph:71    value::num_of
WILL_FAIL  value.glyph:83    value::text_of
the change at an ABSORBS site: the catch-all becomes named arms 
 fn literal_text(v: Value) -> string {
   return match v {
     Text({ text }) => "'${text}'",
-    else => value.render(v),
+    Date({ iso }) => "'${iso}'",
+    Num({ n }) => value.render(v),
+    Bool({ flag }) => value.render(v),
+    Null => value.render(v),
   }
 }
glyph check, after all ten sites 
glyph check: 21 example(s) passed.
glyph check: 11 module(s) checked, no diagnostics.
glyph check: tsc --strict passed.

Each WILL_FAIL entry comes with the error it will raise, and adding the case alone gave exactly those eight E0200 errors. The two ABSORBS sites raise nothing: render::literal_text would have printed a date literal without its quotes, and exec::total would have counted every date as zero. An agent working from compiler errors alone fixes eight sites and stops with a green build. Asked again after the fix, the compiler answers WILL_FAIL at all ten, so the next case cannot slip past either.

Glyph does not catch everything yet. 3 known holes have a reproduction and a gap number, and logic errors pass in Glyph as they do in TypeScript. What it does not catch yet →
