AI エージェントが書く。 コンパイラが検査する。

Glyph は TypeScript のように読めて、抜け道だけがありません。any もキャストも、検証されないデータもなく、すべてのケースを扱います。読みやすい TypeScript にコンパイルされるので、node も npm も既存のコードもそのまま使えます。

$ npm install -g @glyphlang/glyph
検出できるものを見る → 10 分で始める →

ここから先へ

TypeScript を書いている何が変わり、何が変わらないか。npm パッケージをどう持ち込むか。 チームとして導入を判断したい何を保証し、何を保証しないか。やめるときのコストはどれくらいか。 エージェントやツールを作っているMCP サーバー、それが答えるクエリ、診断メッセージの形式。 根拠を見たいそれぞれの主張をどう検証しているか、どう再現できるか。 なぜ新しい言語なのか設計の考え方と、意図的に入れなかったもの。

TypeScript のどのツールも検出できないケース

追加の strict 系フラグをすべて有効にした tsc --strict と strict 設定の typescript-eslint を通過してしまうケースのうち、上位 3 件です。エージェントが書く頻度と、本番に出たときの被害の大きさで順位を付けています。各ケースはリポジトリにあるとおり英語で表示しています。

1

Data from outside the program

A request body, a file, an API response.

TypeScript: compiles, then runs on bad dataGlyph: checked when the data arrives

 2

An error the signature hides

A function that can fail, called by code that does not know it can.

TypeScript: compiles, then crashes at run timeGlyph: refused when you build

 3

An error nobody looked at

Calling something that can fail and moving on.

TypeScript: compiles with no warningGlyph: warned

37 件中 21 件

リストにある TypeScript の例は、どれも tsc --strict をエラーなしで通過します。さらに各例を、最も厳しく設定したプロジェクトでも検証しています。--strict より厳しいコンパイラフラグをすべて有効にし、typescript-eslint の strictTypeChecked も加えた設定です。37 件のケースのうち 21 件は、この設定のどれにも検出されません。デフォルトでは無効のコンパイラフラグで検出できるのが 5 件、lint ルールで検出できるのが 11 件です。これらはプロジェクトごとに 1 つずつ有効にする必要があり、エージェントが無効に戻すこともできます。Glyph では、どれも設定項目ではありません。

実際のアプリケーションでの 1 つの変更

examples/apps/csvql はこのリポジトリにある CSV クエリエンジンで、中心に Value ユニオンがあります。ケースを追加する前に、その変更がどこに影響するかをコンパイラに聞いてみます。

glyph_variants { name: "Value" } 
10 match sites across 4 files
 8 will fail compilation
 2 contain a catch-all and will silently absorb it
次にケースを追加して glyph check を実行する 
8 errors, E0200 non-exhaustive match. The same eight.
The two catch-all sites report nothing at all.

予測は 8 か所すべてで当たりました。残りの 2 か所、 exec::total と render::literal_text はコンパイルが通ったまま、新しいケースを catch-all の行き先に流します。 8 つのエラーを直したところで手を止めたエージェントには、通ったビルドと生きたままの 2 つのバグが残ります。その 2 つを指し示すのがこのクエリです。

Glyph はまだすべてを検出できるわけではありません。既知の穴 11 件には再現コードと gap 番号が付いています。また、ロジックの誤りは TypeScript と同じく Glyph でも通ってしまいます。 まだ検出できないもの →
