기둥 03 · 마무리

추상화

작고 직교하는 핵심으로 의도를 그대로 표현합니다. switch 사다리 대신 패턴 매칭, 던지는 예외 대신 Result, 튜플 대신 이름 붙은 레코드. TypeScript처럼 덧붙여 쌓인 계층이 아니라, 개념마다 좋은 방법 하나입니다.

이 페이지의 내용

  1. 방법이 너무 많다
  2. 조건문인 match
  3. 태그 유니언
  4. 예외 대신 Result
  5. 이름 붙은 레코드
  6. 일마다 기본 요소 하나
  7. 벤치마크

같은 것을 말하는 방법이 너무 많습니다

TypeScript는 덧붙이며 자랐고, 모든 계층을 남겨 두었습니다.

  • 정해진 case정해진 case 집합을 enum, 문자열 리터럴 유니언, const 객체로 모델링할 수 있습니다.
  • 모양모양은 interface, type, class로 기술할 수 있습니다.
  • 그 밖의 모든 것namespace와 모듈, 데코레이터와 고차 함수가 있고, 거의 모든 것에 관용구가 다섯 가지씩 있으며, 저마다 경계 사례가 있습니다.

사람에게는 유연함입니다. 에이전트에게는 지뢰밭입니다. 표현 방법이 많을수록 함정이 있는 것을 고를 방법도 많고, 그러면서 헷갈리지 말아야 할 관용구도 많아집니다.

Glyph의 추상화 기둥은 의도적인 빼기입니다. 일마다 날카로운 도구 하나를 두고, 가장 자연스러운 방법이 안전한 방법이 되도록 골랐습니다.

01 match가 유일한 조건문입니다

if/else 문이 없습니다. 분기는 어디서나 match이고, match는 값을 만드는 표현식입니다.

구문 하나가 불리언 검사, 유니언 분기, 값 테이블을 모두 다루므로, 어떤 분기 형태를 쓸지 고민할 필요가 없습니다.

02 태그 유니언과 패턴 매칭

"이 모양들 중 하나"를 모델링하는 방법은 태그 유니언이고, 이를 분해하는 방법은 case를 고르는 단계에서 payload도 함께 구조 분해하는 match입니다.

feed.glyph 
type Feed =
  | Loading
  | Loaded(Array<Post>)
  | Failed(string)

fn view(feed: Feed) -> string {
  return match feed {
    Loading => "...",
    Loaded(posts) => render(posts),   // posts is Array<Post> here
    Failed(msg) => msg,               // msg is string here
  }
}
자세히 더 이상 직접 쓰지 않는 것

직접 관리해야 할 판별 필드도, 문자열 태그에 대한 switch 사다리도, 모양을 되찾기 위한 분기마다의 캐스트도 없습니다.

03 예외 대신 Result

실패는 숨겨진 제어 흐름 점프가 아니라 값입니다. 실패할 수 있는 함수는 반환 타입(Result<T, E>)에서 그렇다고 밝히고, 호출 지점을 try/catch로 감싸고 올바른 곳에서 올바른 클래스가 던져지기를 바라는 대신 ? 연산자로 실패를 조합합니다.

오류 경로가 정상 경로만큼 잘 보입니다.

04 위치 기반 튜플 대신 이름 붙은 레코드

데이터는 언제나 이름 붙은 필드로 기술합니다. 모양은 정의, 생성, 사용하는 곳에서 똑같이 읽힙니다.

TypeScript: [0]과 [1]은 무엇인가? point.ts 
function origin(): [number, number] {
  return [0, 0];
}
const p = origin();
p[0]; p[1];  // x? y? row? col?
Glyph: 이름이 값과 함께 다닙니다 point.glyph 
type Point = { x: number, y: number }

fn origin() -> Point {
  return { x: 0, y: 0 }
}
자세히 축약 문법 없음, 익명 튜플 없음

객체 리터럴 축약 문법도 없고, [0]과 [1]이 무엇인지 기억해야 하는 익명 튜플에 손을 뻗을 일도 없습니다.

05 일마다 기본 요소 하나

개념에 고유한 도구가 필요하면 Glyph는 정확히 하나를 줍니다.

  • 공유 상태공유되는 변경 가능 상태는 std/store에 둡니다.
  • 핸들한 번만 닫아야 하는 파일이나 소켓 핸들은 owned 리소스입니다.
  • 반복반복은 for x in xs입니다.

각각은 이름이 있고 목적에 맞게 만든 단일 기본 요소이며, 잡다한 범용 부품에서 매번 다시 끌어내다 미묘하게 틀리는 패턴이 아닙니다.

여기서 추상화란 더 많은 도구가 아니라 더 적고 날카로운 도구를 뜻합니다. 모든 개념에는 자연스러운 형태가 있고, 그 자연스러운 형태가 쓰라고 만든 형태입니다.

벤치마크: 준비 중

이를 측정하는 방법은 표면적입니다. 프로그램을 이해하려면 독자가 개념을 몇 가지나 알고 있어야 하는지, 흔한 작업을 깔끔하게 표현하는 데 코드가 얼마나 필요한지입니다.

Glyph는 아직 실제 환경에서 쓰이지 않으므로, 아래 차트는 비교할 실제 프로그램이 충분히 쌓이면 실제 측정값으로 채울 자리 표시입니다.
