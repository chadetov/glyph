기둥 04 · 마무리

diff 안정성

한 줄을 바꾸면 diff도 한 줄입니다. 정해진 포맷 하나, 후행 쉼표, 그리고 전부 한 줄이거나 전부 요소마다 한 줄인 목록이 있고, 다시 묶이지 않으므로, 리뷰는 주변의 변동이 아니라 실제로 한 변경을 보여 줍니다.

리뷰는 diff를 읽는 일입니다

변경에 대해 믿는 거의 모든 것(리뷰, blame, revert, bisect)은 diff 위에 서 있습니다. 그래서 diff의 신호 대 잡음 비가 진짜 화폐입니다.

자세히 잡음이 어디서 오는가

대부분의 코드베이스에서 이 비율은 형편없습니다. 포매터가 줄바꿈된 줄을 다시 흘리고, import 정렬기가 블록을 뒤섞고, 이름 바꾸기가 모든 호출 지점의 공백을 건드려서, 중요한 한 줄이 중요하지 않은 쉰 줄에 묻힙니다.

에이전트는 이를 훨씬 악화시킵니다. 작은 작업을 받아도 모델은 한 가지를 바꾸려고 함수 전체나 파일 전체를 기꺼이 다시 씁니다. 정밀하게 편집하는 것보다 다시 생성하는 편이 쉽기 때문입니다. 리뷰어는 다시 쓴 코드를 원본과 비교하며 의도한 변경만 있기를 바랄 수밖에 없습니다.

Glyph는 레이아웃이 모델에게 휘저을 거리를 주지 않도록 만들어졌습니다.

01 정해진 레이아웃 하나, 선택지 없음

glyph fmt는 모든 파일을 고정된 레이아웃 하나로 다시 출력합니다. 두 칸 들여쓰기, 여러 줄 목록마다 후행 쉼표, 그리고 100열 안에 들어가는 동안은 한 줄에 두고 들어가지 않으면 요소마다 한 줄로 쓰는 목록입니다. 선택은 전부 아니면 전무입니다.

자세히 다시 묶지 않음, 허용되는 모양 하나

포매터는 줄을 채우려고 요소를 다시 묶지 않으므로, 목록이 일부는 한 행에, 일부는 다음 행에 있는 일이 없고, 필드를 추가하면 한 줄이 추가됩니다. 허용되는 모양이 정확히 하나이므로 논쟁할 것도, 도구가 따로 "고칠" 것도 없습니다.

너비 기준이 이 방식의 비용입니다. 바인딩 이름을 바꿔서 호출이 100열을 넘으면 호출이 인자마다 한 줄로 펼쳐집니다. 토큰 하나를 바꿨는데 diff는 네 줄입니다. 그 대가로 레이아웃은 코드와 그 코드가 시작하는 열에만 의존하고 다른 것에는 의존하지 않으므로, 같은 파일을 편집하는 두 에이전트가 같은 바이트로 수렴합니다.

후행 쉼표가 조용히 일을 합니다. 마지막 요소가 이미 쉼표로 끝나므로, 형제 요소를 추가해도 바로 윗줄을 절대 수정하지 않습니다. 삽입 하나, 줄 하나.

02 순서가 안정적이므로 이력을 읽을 수 있습니다

요소마다 한 줄이므로 항목을 재정렬하거나, 삽입하거나, 제거해도 그 항목의 줄만 건드리고 이웃 줄은 건드리지 않습니다.

git blame도 의미를 유지합니다. 각 줄을 마지막으로 건드린 커밋은 우연히 그 행을 다시 묶은 포맷 작업이 아니라 그 요소를 실제로 바꾼 커밋입니다.

03 barrel 파일 없음: import 변동 없음

import는 재export하지 않고 index.ts 집계 계층도 없으므로(E0102), 심볼을 추가하거나 옮겨도 모든 사용처가 import하는 barrel을 통해 파문이 퍼지지 않습니다. 편집하는 의존 관계는 의도한 것뿐이고, 나머지 import 그래프는 움직이지 않습니다.

E0102

04 생성은 덩어리가 아니라 멱등입니다

같은 원칙이 생성된 코드에도 적용됩니다. glyph gen과 glyph regen은 출력을 정해진 포매터로 다시 출력하므로, 명세가 바뀐 뒤 다시 생성하면 기계가 쓴 파일을 통째로 교체하는 대신 실제로 리뷰할 수 있는 최소한의 diff, 즉 몇 줄의 변경이 나옵니다.

명세에 필드 하나를 추가 → 다시 생성한 diff 
  type Task = {
    id: number,
    title: string,
+   done: bool,
  }
// glyph regen re-ran the recorded command; this is the whole diff.

그리고 생성된 모든 .ts에는 소스 맵이 함께 있으므로, 컴파일된 출력도 바꾼 줄까지 깔끔하게 추적됩니다.

05 "TypeScript도 Prettier로 할 수 있다"

포맷의 상당 부분은 그렇습니다. trailingComma: "all"을 설정한 Prettier는 마지막 요소에 쉼표를 붙이고 긴 목록을 한 줄에 하나씩 출력하므로, 01절의 대부분을 얻을 수 있습니다. 차이는 세 군데에 있습니다.

  • 레이아웃이 코드에만 의존합니다.Prettier는 작성자가 { 뒤에 줄을 바꿨으면 객체 리터럴을 펼친 채로 두고, 그렇지 않았으면 접습니다. 그래서 같은 객체가 처음 어떻게 입력되었느냐에 따라 두 가지로 출력될 수 있습니다. 같은 것을 쓰는 두 에이전트가 두 가지 레이아웃을 만들고, 그중 하나를 다음에 편집하면 다시 흘리기로 나타납니다. glyph fmt는 입력이 어떻게 줄바꿈되었든 { a: 1, b: 2 }를 똑같이 출력합니다.
  • 설정할 것이 없습니다.Prettier의 출력은 저장소의 설정 파일이 정하는 대로이고, 설정 파일이 없는 저장소도 있습니다. TypeScript 프로젝트를 옮겨 다니는 에이전트는 프로젝트마다 다른 레이아웃을 만납니다. Glyph 파일은 포매터에 옵션이 없으므로 모든 프로젝트에서 레이아웃이 같습니다.
  • 포매터는 파일의 의미를 바꿀 수 없습니다.glyph fmt는 자신의 출력을 파싱해서 입력의 구문 트리와 비교하는 방식으로, 저장소의 모든 예제와 퍼저에서 테스트합니다. 레이아웃에 자리가 없는 곳에 주석이 있으면, 주석을 관계없는 코드 옆으로 옮기는 대신 파일을 거부합니다(E0500).

목록 중 아직 되지 않은 것이 하나 있습니다. glyph fmt는 import를 정렬하지 않으므로, 서로 다른 곳에 import를 추가하는 두 에이전트는 여전히 서로 다른 import 블록을 만듭니다(G358).

diff 안정성은 "에이전트가 뭔가를 바꿨다"를 "에이전트가 정확히 이것을 바꿨다"로 바꿉니다. 잡음이 0이면 리뷰는 빠르고 신뢰는 값싸집니다.

벤치마크: 준비 중

이를 나타내는 숫자는 논리적 변경 하나당 diff 크기입니다. 의도한 편집 하나를 할 때 Glyph에서 몇 줄이 움직이는지를, 일반적인 포매터를 거친 같은 TypeScript 변경과 비교합니다.

Glyph는 아직 실제 환경에서 쓰이지 않으므로 아래 차트는 자리 표시이며, 참고할 실제 이력이 생기면 실제 측정값으로 채워집니다.
