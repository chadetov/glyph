Pillar 04 · The polish

Diff stability

A one-line change is a one-line diff. One canonical format, trailing commas, and a list that is either entirely inline or entirely one element per line, never repacked, so a review shows the change that was made, not the churn around it.

Review is reading diffs#

Almost everything we trust about a change (the review, the blame, the revert, the bisect) is built on the diff. So the diff's signal-to-noise ratio is the real currency. In most codebases it's terrible: a formatter reflows a wrapped line, an import-sorter reshuffles a block, a rename touches every call site's whitespace, and the one line that matters is buried in fifty that don't.

Agents make this sharply worse. Given a small task, a model will happily rewrite a whole function, or a whole file, to change one thing, because regenerating is easier for it than editing surgically. The reviewer is left to diff a rewrite against the original and hope the only real change is the intended one. Glyph is built so that the layout gives the model nothing to churn.

01 One canonical layout, no choices#

glyph fmt reprints every file in a single fixed layout: two-space indent, a trailing comma on every multi-line list, and a list that stays on one line while it fits inside 100 columns and goes one element per line when it doesn't. The choice is all-or-nothing. The formatter never repacks your elements to fill a line, so a list is never partly on one row and partly on the next, and adding a field is a single added line. Because there's exactly one legal shape, there's nothing to argue about and nothing for a tool to "fix" on the side.

The width threshold is what this costs. Rename a binding so a call crosses 100 columns and the call expands to one argument per line: a one-token edit, a four-line diff. The trade is that the layout depends on the code and the column it starts at and nothing else, so two agents editing the same file converge on the same bytes.

Reflowed style: one change, three touched lines git diff (packed formatting) 
- type User = { id: number, name:
-   string }
+ type User = { id: number, name:
+   string, email: string }
Glyph: one change, one added line git diff (canonical) 
  type User = {
    id: number,
    name: string,
+   email: string,
  }

The trailing comma is doing quiet work: because the last element already ends in a comma, adding a sibling never edits the line above it. One insertion, one line.

02 Order is stable, so history is legible#

One element per line means reordering, inserting, or removing an item touches only that item's lines, never its neighbours. git blame stays meaningful: each line's last-touched commit is the commit that actually changed that element, not the formatting pass that happened to repack the row it shared.

03 No barrel files: no import churn#

Because imports never re-export and there are no index.ts aggregation layers (E0102), adding or moving a symbol doesn't ripple through a barrel that every consumer imports. The dependency edges you edit are the ones you meant to; the rest of the import graph doesn't move.

04 Generation is idempotent, not a blob#

The same discipline extends to generated code. glyph gen and glyph regen reprint their output through the canonical formatter, so regenerating after a spec change produces a minimal diff you can actually review, a couple of changed lines, not a wholesale replacement of a machine-written file. And every emitted .ts ships a source map, so even the compiled output traces cleanly back to the line you changed.

a field added to the spec → the regenerated diff 
  type Task = {
    id: number,
    title: string,
+   done: bool,
  }
// glyph regen re-ran the recorded command; this is the whole diff.

05 "TypeScript can do this with Prettier"#

For a lot of the formatting, it can. Prettier with trailingComma: "all" puts a comma on the last element and prints long lists one per line, and that gets you most of section 01. The differences are in three places.

The layout depends only on the code. Prettier keeps an object literal expanded if its author put a line break after the {, and collapses it if they didn't, so the same object can be printed two ways depending on how it was first typed. Two agents writing the same thing produce two layouts, and the next edit to one of them shows up as a reflow. glyph fmt prints { a: 1, b: 2 } the same way however the input was wrapped.

There is nothing to configure. Prettier's output is whatever the repository's config file says, and some repositories don't have one. An agent moving between TypeScript projects meets a different layout in each. A Glyph file has the same layout in every project, because the formatter has no options.

The formatter can't change what a file says. glyph fmt is tested by parsing its own output and comparing the syntax tree with the input's, on every example in the repository and under a fuzzer. When a comment sits somewhere the layout has no line for, it refuses the file (E0500) rather than move the comment next to code it doesn't describe.

One thing on the list is not done yet: glyph fmt does not sort imports, so two agents adding an import in different places still produce different import blocks (G358).

Diff stability is what turns "the agent changed something" into "the agent changed exactly this." When the noise floor is zero, review is fast and trust is cheap.
