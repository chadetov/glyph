Respostas

O que engenheiros perguntam sobre o Glyph.

Cada resposta mostra um exemplo resolvido e termina com o que ainda não funciona. Comece pela sua dúvida. Novo no Glyph? O Comece aqui de 10 minutos é o jeito mais rápido de rodar algo pela primeira vez.

O problema que resolve#

O que a edição de um agente pode quebrar sem ninguém perceber, e o que o Glyph faz em cada caso.

01O que impede um agente de quebrar meu código sem ninguém perceber?

Sem any, sem casts, match exaustivo, tipos verificados em runtime e testes junto do código que rodam em todo build.

 02As edições do agente vão ficar limpas, ou reformatar o arquivo inteiro?

Uma mudança de uma linha é um diff de uma linha. Um layout canônico, nada reempacotado.

 03Um agente (ou eu) consegue achar onde qualquer coisa está definida?

Um nome, uma forma de declaração. O grep sempre cai nela.

Decidir se vale adotar#

Por que uma linguagem em vez de mais ferramental, e quanto custa adotá-la.

04Por que TypeScript, e não Go ou uma linguagem nova?

Porque é lá que está o seu ecossistema, e é por isso que a adoção é arquivo a arquivo.

 05Por que não só TypeScript strict + zod + eslint + ts-pattern?

Não ser opcional: a linguagem que o agente não consegue desligar na config.

 06O Glyph vale a pena se eu não uso IA?

Sim: as garantias são ganhos de engenharia comuns, que um humano aproveita diretamente.

 07Uma IA consegue escrever de forma confiável uma linguagem que mal viu?

Quase tudo o que um modelo sabe de TypeScript continua valendo, e o compilador aponta os lugares onde não vale.

 08Uma release nova do Glyph vai quebrar meu build?

Os projetos fixam a versão exata do compilador, então nenhuma release chega por acidente. glyph doctor avisa que existe uma; glyph upgrade a instala.

Usando com a sua stack#

Pacotes npm, uma aplicação existente, fronteiras de API, React.

09Posso usar minhas bibliotecas de TypeScript, JavaScript e npm?

Sim: importe qualquer pacote npm, mantenha um shim .ts escrito à mão onde precisar e importe o Glyph de volta no .ts.

 10Posso adotar o Glyph dentro da minha aplicação atual, ou é tudo ou nada?

Sem reescrever: o núcleo do domínio em Glyph, o resto em TypeScript. O TypeScript emitido é importado por uma aplicação Vite comum como qualquer outro módulo.

 11Preciso escrever um validador à mão para cada API?

Não. Declarar um tipo gera o validador dele.

 12Consigo gerar um cliente e um servidor tipados a partir da spec da minha API?

glyph gen openapi/zod/dts: código commitado e fácil de buscar.

 13Funciona com React: componentes, hooks e Context?

JSX de primeira classe, hooks e actions de reducer exaustivas.

 14Como compartilho estado mutável entre funções?

Uma store: um const cujos .set/.update são a superfície de escrita.

O que dá para construir#

A linguagem e a biblioteca padrão, por tipo de programa.

15É uma linguagem de verdade, ou um brinquedo cheio de buracos?

Visibilidade de módulos, bounds de interface, defer, um match que funciona como qualquer valor e carrega seu tipo, e uma biblioteca padrão que tem slice, pad_start e fold.

 16Posso confiar nele com dinheiro, e com entrada que eu não controlo?

Decimais e ids exatos, invariantes como tipos, injeção como erro de compilação.

 17Posso servir uma página web, ou só uma API JSON?

HTML, redirects, headers de resposta e posts de formulário, sem um servidor escrito à mão.

 18Posso escrever um programa em que alguém digita?

io.read_line devolve cada linha assim que ela chega, em vez de esperar o stdin fechar, então um REPL ou um game loop funciona.

 19Posso escrever um servidor, ou o processo simplesmente termina?

main faz o setup e retorna; o processo continua vivo enquanto houver sockets e timers pendentes, a mesma regra do Node.

 20Consigo lidar com dados binários, ou tudo é string?

std/bytes é uma sequência de octetos, com codecs que recusam entrada malformada em vez de pulá-la, e HMACs que recebem uma chave de verdade.

Trabalhando com um agente#

Perguntas que um agente faz ao compilador antes e depois de uma edição.

21O compilador consegue me dizer o que uma mudança vai quebrar antes de eu fazê-la?

glyph_impact: um veredito por local, de uma lista fechada, com o motivo, antes de você mexer no arquivo.

 22Meu agente pode perguntar ao compilador o que é um símbolo antes de escrever código?

glyph_symbol: as variantes de uma union com a sintaxe que constrói cada uma, numa só chamada. Onze ferramentas, cada uma com um verbo de glyph query.

 23Quando o build falha, o compilador diz ao meu agente como consertar?

O diagnóstico traz o símbolo culpado, as alternativas válidas e o que uma edição de reparo não pode quebrar. glyph fix aplica as que o compilador resolve sozinho.

 24A documentação que meu agente lê é gerada, ou escrita à mão e desatualizada?

glyph llms --json emite os diagnósticos, o prelude, as assinaturas da stdlib e o manual das ferramentas a partir das tabelas do próprio compilador, e um gate falha quando uma cópia escrita à mão discorda.

Erros, editores e produção#

O que você vê quando algo dá errado, do editor ao plantão.

25Como é a experiência de editor, depuração e erros?

Um language server para qualquer editor com LSP, e erros com um código estável que dizem qual é a correção.

 26Por que o Glyph detecta o que o tsc detecta, só que antes?

Contexto de await, um braço de match sem valor e um mut faltando, reportados no seu código-fonte em vez de no TypeScript emitido.

 27Quando um parse falha, eu descubro o motivo?

Qual campo, qual regra ele quebrou, o predicado where que violou e um code para usar num branch.

 28Quando quebra em produção às 3 da manhã, o que o plantão vê?

TS legível que é seu, source maps de volta para o seu .glyph e um run que reporta o mesmo que o build.
