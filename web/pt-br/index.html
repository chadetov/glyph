Seu agente de IA escreve. O compilador confere.

O Glyph se lê como TypeScript, sem as válvulas de escape: sem any, sem casts, sem dados não verificados, todo caso tratado. Ele compila para TypeScript legível, então você mantém o node, o npm e o código que já tem.

$ npx -y @glyphlang/glyph init hello && cd hello && npm install && npx glyph run

Sem instalação global. Para ter glyph no PATH: npm install -g @glyphlang/glyph tsx typescript

Casos que nada no TypeScript detecta

Os três casos mais bem classificados que passam no tsc --strict com todas as flags extras ativadas e o typescript-eslint em modo strict, ordenados pela frequência com que um agente os escreve e pelo estrago que causam quando chegam em produção. 21 de 37

Todos os exemplos de TypeScript da lista passam no tsc --strict sem erros. Cada um também é verificado contra um projeto configurado no máximo: todas as flags do compilador mais rígidas que --strict, mais o typescript-eslint strictTypeChecked. Em 21 dos 37 casos, nada nessa configuração detecta o problema. Uma flag do compilador que vem desativada por padrão detecta 5, e uma regra de lint detecta 11. Um projeto precisa ativar cada uma delas, e um agente pode desativá-la de novo. No Glyph, nenhuma delas é uma opção de configuração. No total são 53 casos verificados: 37 erros de TypeScript, 5 armadilhas de JavaScript que não existem em Glyph e 11 brechas que o Glyph ainda não fecha. O Glyph recusa 28 deles no build (23 erros e 5 armadilhas).

Uma mudança, em uma aplicação real

examples/apps/csvql é um motor de consultas sobre CSV que fica neste repositório, com uma union Value no centro. Antes de adicionar um caso a ela, pergunte ao compilador quais pontos ela alcança.

glyph_variants { name: "Value" } 
10 match sites across 4 files
 8 will fail compilation
 2 contain a catch-all and will silently absorb it
depois adicione o caso e rode glyph check 
8 errors, E0200 non-exhaustive match. The same eight.
The two catch-all sites report nothing at all.

A previsão acertou os oito. Os outros dois, exec::total e render::literal_text, continuam compilando e mandam o caso novo para onde o catch-all deles apontar. Um agente que corrige os oito erros e para ali fica com o build verde e dois bugs vivos, e é a consulta que aponta quais são.

O Glyph ainda não detecta tudo. 11 falhas conhecidas têm uma reprodução e um número de gap, e erros de lógica passam no Glyph do mesmo jeito que passam no TypeScript. O que ele ainda não detecta →
