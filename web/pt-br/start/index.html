Comece aqui · ~10 minutos

Seu primeiro programa em Glyph

Crie um projeto, rode, depois quebre de propósito e leia o erro que o compilador mostra. Não é preciso conhecer Glyph. Se você já escreveu um pouco de TypeScript, vai acompanhar cada linha.

1 · Crie um projeto#

O Glyph é distribuído no npm como binário pré-compilado para macOS e Linux (x64 e ARM) e Windows (x64), e precisa do Node 18 ou mais recente. Este caminho não instala nada globalmente: o npx baixa o compilador para criar o projeto, e o projeto fixa sua própria cópia junto com tsx e typescript, que o Glyph usa para rodar e checar tipos.

terminal 
npx -y @glyphlang/glyph init hello
cd hello
npm install

Se preferir ter o glyph no PATH, instale-o globalmente junto com as duas ferramentas que ele usa, e tire o npx dos comandos desta página:

terminal, a alternativa global 
npm install -g @glyphlang/glyph tsx typescript
glyph doctor                    # confirms your toolchain is ready
glyph init hello
cd hello

2 · Veja o que foi criado#

O glyph init cria um projeto inicial que já roda: src/main.glyph, src/.types/README.md explicando que um pacote npm tipado não precisa de nada ali e que o diretório é para um pacote que não traz tipos, um package.json, um .gitignore e dois arquivos que agentes de código leem sozinhos: AGENTS.md, que aponta para glyph llms com a referência completa da linguagem, e .mcp.json, que registra glyph mcp para que um agente possa perguntar tipos e referências ao compilador em vez de procurá-los. Num projeto que você já tem, glyph agents escreve esses dois. O package.json fixa o compilador, typescript e tsx em devDependencies, então qualquer pessoa que clonar o projeto consegue fazer o build com npm install, sem instalação global.

Abra src/main.glyph. É um hello-world:

src/main.glyph 
module main

import std/io

fn main(argv: Array<string>) -> number {
  io.println("hello from glyph")
  return 0
}

Repare em duas coisas: um programa roda a sua main(argv), e main retorna um number, o código de saída do processo. Retornar define esse código sem forçar o processo a parar, então um programa que sobe um servidor continua servindo.

3 · Rode#

terminal 
npx glyph run
hello from glyph

O glyph run checou os tipos, compilou para TypeScript e executou. Esse é o ciclo que você repete no resto desta página.

4 · Adicione algo de verdade#

Agora troque o corpo por uma decisão que importa: enviar ou não um pedido, de acordo com a situação do pagamento. Isso apresenta as duas coisas que você vai usar o tempo todo: uma tagged union (type Payment = ...) e match, que é o único condicional do Glyph.

src/main.glyph 
module main

type Payment = Pending | Paid | Failed

fn ship(p: Payment) -> string {
  return match p {
    Pending => "hold: waiting for the money",
    Paid => "ship it",
    Failed => "hold: payment failed",
  }
}

fn main(argv: Array<string>) -> number {
  print(ship(Paid))
  return 0
}
terminal 
npx glyph run
ship it

5 · Quebre de propósito#

Esta é a parte que mostra para que o Glyph serve. Um ticket pede "suportar reembolsos", então adicione um caso Refunded a Payment e não mexa em ship. É o que um agente faz quando muda um tipo em um arquivo e nunca abre o código que decide com base nele. Rode de novo.

src/main.glyph (uma palavra a mais) 
type Payment = Pending | Paid | Failed | Refunded
$ npx glyph run 
[E0200] Error: typecheck: non-exhaustive match on `Payment`: missing variants `Refunded`
    ╭─[ main:6:10 ]
    │
  6 │ ╭─▶   return match p {
    ┆ ┆
 10 │ ├─▶   }
    │ ╰───────── non-exhaustive match on `Payment`: missing variants `Refunded`
    │
    │     Help: Add an arm for each missing variant.
────╯

Não rodou. O TypeScript em que a maior parte do código é escrita faz o contrário: um switch que trata os dois casos de "hold" e termina em default: return "ship it" passa no tsc --strict depois que o novo caso é adicionado, e envia todo pedido reembolsado. Aqui, todo match que deixa um caso de fora é um erro de compilação com um código estável (E0200), o ponto exato e o nome do caso. Rode glyph --explain E0200 sempre que quiser a versão longa.

6 · Corrija#

O compilador não pode decidir o que um reembolso significa para o envio; essa decisão é sua. Adicione o braço e o programa volta a rodar.

src/main.glyph 
fn ship(p: Payment) -> string {
  return match p {
    Pending => "hold: waiting for the money",
    Paid => "ship it",
    Failed => "hold: payment failed",
    Refunded => "hold: refunded, nothing to ship",
  }
}
terminal (com print(ship(Refunded))) 
npx glyph run
hold: refunded, nothing to ship

Esse é o ciclo principal: escrever, rodar e, quando algo está errado, o compilador diz exatamente o quê e como, antes de o código ir para produção, não depois.
