Случаи, которые пропускает TypeScript

Поймано до продакшена

Всего проверенных случаев: 45. Из них случаев в TypeScript: 37, ловушек JavaScript, которых нет в Glyph: 5, и дыр, которые Glyph пока не закрывает: 3. При сборке Glyph отклоняет 28 из них (случаев TypeScript: 23, ловушек: 5).

Все примеры на TypeScript из списка проходят tsc --strict без ошибок. Каждый из них дополнительно проверяется на проекте с максимально строгой настройкой: все флаги компилятора строже --strict плюс typescript-eslint strictTypeChecked. Из 37 случаев такая настройка не ловит 21. Флаг компилятора, выключенный по умолчанию, ловит 5, правило линтера ловит 11. Каждый из них проект должен включить сам, и агент может снова его выключить. В Glyph ни одна из этих проверок не является настройкой.

Каждая запись это две программы в catches/, а вывод под каждой из них напечатан самими инструментами. Проверка при сборке, scripts/check_catches.py, перезапускает каждый случай и падает, если какая-то из половин перестаёт делать то, что написано на странице. Полная конфигурация TypeScript, с которой идёт сравнение, лежит в этом скрипте.

1

Данные извне программы

Вероятность 5 из 5Тяжесть 5 из 5

Тело запроса, файл, ответ API.

TypeScriptкомпилируется, а потом работает на плохих данных
ts.ts
const user = JSON.parse(body) as User;
console.log(sendInvoice(user.plan));
$ tsx ts.ts
invoice for the undefined plan

Данные никто не проверяет. undefined идёт дальше под видом тарифа.

Ничто не ловитдаже со всеми флагами компилятора и typescript-eslint в строгом режиме

Glyphпроверяется при поступлении данных
glyph.glyph
let out = match json.parse<User>(body) {
  Ok(user) => send_invoice(user.plan),
  Err(issues) => "rejected: ${json.stringify(issues)}",
}
$ glyph run
rejected: [{"path":["plan"],"message":"field `plan` is required","code":"missing"}]

Тело, которое не является настоящим User, становится Err. Поддельного значения в программе не бывает.

as User ничего не проверяет. Он просит компилятор поверить вам на слово. В Glyph нет as.

2

Необработанный вариант

Вероятность 5 из 5Тяжесть 4 из 5

Агент добавляет статус "archived". Обработчик, который сообщает о каждом статусе, был написан до его появления.

TypeScriptкомпилируется без предупреждений
ts.ts
switch (s) {
  case "todo":
    console.log("not started");
    break;
  case "doing":
    console.log("in progress");
    break;
  case "done":
    console.log("finished");
    break;
}
$ tsx ts.ts
finished
archived logged nothing

Архивирование ничего не пишет в лог. Ничто не говорит, что switch устарел.

Только линтерловит правило линтера switch-exhaustiveness-check

Glyphотклонено при сборке
glyph.glyph
match s {
  "todo" => print("not started"),
  "doing" => print("in progress"),
  "done" => print("finished"),
}
$ glyph build
[E0200] Error: typecheck: non-exhaustive match on `"todo" | "doing" | "done" | "archived"`: missing variants "archived"
Help: Add an arm for each missing variant.

Сборка останавливается и называет вариант.

TypeScript проверяет, что switch покрывает все варианты, только если функция возвращает значение из каждой ветки, или с идиомой assertNever. Обработчик, который ничего не возвращает, не получает ни того, ни другого. В Glyph каждый match обязан покрыть все варианты, поэтому добавление нового варианта перечисляет все места, которые нужно изменить.

Доверие к find через !

Вероятность 5 из 5Тяжесть 4 из 5

Поиск записи по id.

TypeScriptкомпилируется, а потом падает во время выполнения
ts.ts
return users.find((u) => u.id === id)!.name;
$ tsx ts.ts
TypeError: Cannot read properties of undefined (reading 'name')

! говорит компилятору «поверь мне». Во время выполнения он ничего не делает.

Только линтерловит правило линтера no-non-null-assertion

Glyphотклонено при сборке
glyph.glyph
return array.find(users, fn(u: User) -> bool { u.id == id }).name
$ glyph build
[E0210] Error: typecheck: type `Option<User>` has no field `name`: an `Option` has no members
Help: Open it with `match array.find(...) { Some(u) => u.name, None => <default> }`. If the absence is a JSON `null` from the wire, declare the type `Nullable<User>` (D45).

find возвращает Option, поэтому пустой случай нужно обработать.

Без ! tsc --strict отклоняет эту строку. Именно ! выключает эту проверку, а во время выполнения он ничего не делает. В Glyph нет !.

Ошибка, которую прячет сигнатура

Вероятность 4 из 5Тяжесть 4 из 5

Функция, которая может завершиться ошибкой, и код, который об этом не знает.

TypeScriptкомпилируется, а потом падает во время выполнения
ts.ts
function loadConfig(): Config {
  throw new Error("missing file");
}

const cfg = loadConfig(); // no try
$ tsx ts.ts
Error: missing file

Тип говорит Config. О том, что функция может бросить исключение, ничего не сказано.

Ничто не ловитдаже со всеми флагами компилятора и typescript-eslint в строгом режиме

Glyphотклонено при сборке
glyph.glyph
fn load_config() -> Result<Config, string> {
  return Err("missing file")
}

let cfg: Config = load_config()
$ glyph build
[E0204] Error: typecheck: type mismatch: expected `Config`, found `Result<Config, string>`
Help: Change the value, or the declared type, so the two agree.

Ошибка входит в возвращаемый тип, поэтому вызывающий код обязан её обработать.

Тип функции в TypeScript перечисляет, что она возвращает, но никогда то, что она бросает. В Glyph ошибка входит в возвращаемый тип, поэтому её видит каждый вызывающий.

save(user); // returns { ok: false }

Фильтр, который пропускает всех

Вероятность 4 из 5Тяжесть 4 из 5

Проверка каждого пользователя асинхронным вызовом прав доступа.

TypeScriptкомпилируется, а потом выдаёт неверный ответ
ts.ts
const active = names.filter(
  async (n) => await isActive(n));
$ tsx ts.ts
[ 'ada', 'mallory' ]

Ничего не отфильтровывается.

Только линтерловит правило линтера no-misused-promises

Glyphотклонено при сборке
glyph.glyph
let active = array.filter(names, async fn(n: string) -> bool { await is_active(n) })
$ glyph build
[E0211] Error: typecheck: argument type mismatch: expected `function`, found `async function`
Help: `array.filter` does not wait for its callback. Await each call in a loop, `for n in names { ... await is_active(n) ... }`, or run them together with `task.all`.

Асинхронная функция не является ответом «да или нет».

Асинхронная функция возвращает Promise, а любой Promise считается истинным. Фильтр прав доступа, построенный так, пропускает всех.

function isUser(x: unknown): x is User {

Потерянное обновление через await

Вероятность 3 из 5Тяжесть 5 из 5

ts.ts
const before = a.balance;

Glyph замечает чтение и запись вокруг ожидания.

Пока один вызов ждёт fee(), другой может обновить баланс. Первый затем записывает устаревшее значение.

Значение вне списка

Вероятность 3 из 5Тяжесть 4 из 5

API начинает присылать статус, которого ваш код никогда не видел.

TypeScriptкомпилируется, а потом работает на плохих данных
ts.ts
type Account = { status: "active" | "banned" };

const body = '{"status":"deleted"}';
const acc = JSON.parse(body) as Account;
$ tsx ts.ts
status deleted

"deleted" считается одним из двух. Каждая проверка status теперь неверна.

Ничто не ловитдаже со всеми флагами компилятора и typescript-eslint в строгом режиме

Glyphпроверяется при поступлении данных
glyph.glyph
type Account = { status: "active" | "banned" }

let out = match json.parse<Account>(body) {
  Ok(acc) => "status ${acc.status}",
  Err(issues) => "rejected: ${json.stringify(issues)}",
}
$ glyph run
rejected: [{"path":["status"],"message":"field `status` must be \"active\" | \"banned\"","code":"type"}]

Проходят только перечисленные значения.

В TypeScript union вроде "active" | "banned" существует только во время компиляции. Во время выполнения ничто не мешает третьему значению. Glyph проверяет это при поступлении данных.

Glyphотклонено при сборке
glyph.glyph
return Conn.parse(v)
$ glyph build
[E0304] Error: emit: cannot validate `Conn`: field `sock` has type `Socket`, which has no runtime check
Help: Split the wire type from the domain type: parse a record whose fields are all checkable, then build this one from it.

Для сокета нет проверки во время выполнения, поэтому Glyph отклоняет Conn.parse, а не генерирует проверку, которая не может быть верной.

Разделите тип для передачи и доменный тип: разберите поля, которые можно проверить, а затем постройте запись вокруг сокета.

Строка заказа, где может быть только целое число.

TypeScriptкомпилируется, а потом работает на плохих данных
ts.ts
type Order = { qty: number };

const text = '{"qty": 1.5}';
console.log((JSON.parse(text) as Order).qty);

В TypeScript один number. Отправляется половина товара.

Glyphпроверяется при поступлении данных
glyph.glyph
type Order = { qty: int }

let out = match json.parse<Order>(text) {
  Ok(o) => "qty ${o.qty}",
  Err(issues) => "rejected: ${json.stringify(issues)}",
}
$ glyph run
rejected: [{"path":["qty"],"message":"field `qty` must be int","code":"type"}]

int это отдельный тип, и он проверяется.

В TypeScript один тип number и для целых, и для дробных чисел. В Glyph есть int, и он проверяется при поступлении данных.

Ловушки JavaScript, которых нет в Glyph: 5

Старые ловушки, в которые агенты всё ещё иногда попадают. Glyph отклоняет каждую такую программу, но не потому, что замечает ошибку: возможности, из-за которой она возникает, в языке нет, а замена названа.

  • "10,20,30".split(",").map(parseInt) даёт [10, NaN, NaN], потому что map передаёт индекс как основание системы счисления. В Glyph есть number.parse, который возвращает Result. Открыть в песочнице
  • Регулярное выражение с /g, повторно использованное в .test, не срабатывает на каждом втором совпадении, потому что помнит lastIndex. В Glyph нет объектов регулярных выражений; у regex.matches(pattern, text) нет состояния. Открыть в песочнице
  • [1, 2, 3].forEach(counter.increment) выполняет метод без его объекта. В Glyph нет классов и нет this. Открыть в песочнице
  • Math.max(...[]) равно -Infinity. array.max в Glyph возвращает Option, пустой для пустого списка. Открыть в песочнице
  • Array(3).map(...) возвращает три дыры, потому что map их пропускает. В Glyph нет Array(n); массивы записываются литералами. Открыть в песочнице

Что Glyph пока не ловит

Дыры, которые Glyph пока не закрывает: 3. Каждая из этих программ сегодня компилируется в Glyph и делает ту же ошибку, что и в TypeScript. У каждой есть воспроизведение в catches/ и открытый номер gap, а проверка падает, когда появляется исправление, так что запись не переживёт саму дыру.

  • requested || 3 превращает настоящий 0 в 3. G386
  • input + 1 на строке, users.find(...).name и чтение поля у unknown ловит только шаг tsc, а не собственная проверка Glyph, поэтому редактор и инструменты агента их не видят. G381, G382

Логические ошибки составляют самый большой класс во всех исследованиях кода, написанного агентами, и их не видит ни одна проверка типов: неверная формула или неправильно понятая задача компилируются в Glyph так же, как в TypeScript.

В Glyph есть одна лазейка, extern_ts, для TypeScript, который он не может выразить. Это фиксированное ключевое слово, поэтому grep extern_ts показывает все места, где правила приостановлены.
