Код пишет ваш ИИ-агент. Проверяет компилятор.

Glyph читается как TypeScript, но без лазеек: нет any, нет приведений типов, нет непроверенных данных, каждый случай обработан. Он компилируется в читаемый TypeScript, так что node, npm и ваш код остаются с вами.

$ npx -y @glyphlang/glyph init hello && cd hello && npm install && npx glyph run

Глобальная установка не нужна. Чтобы glyph был в PATH: npm install -g @glyphlang/glyph tsx typescript

Случаи, которые в TypeScript не ловит ничто

Три случая с самым высоким рейтингом среди тех, что проходят tsc --strict со всеми дополнительными флагами и typescript-eslint в режиме strict. Рейтинг учитывает, как часто агент их пишет и насколько они опасны в продакшене.

1

Данные извне программы

Тело запроса, файл, ответ API.

TypeScript: компилируется, а потом работает на плохих данныхGlyph: проверяется при поступлении данных

Ошибка, которую прячет сигнатура

Функция, которая может завершиться ошибкой, и код, который об этом не знает.

TypeScript: компилируется, а потом падает во время выполненияGlyph: отклонено при сборке

TypeScript: компилируется без предупрежденийGlyph: предупреждение

21 из 37

Все примеры на TypeScript из списка проходят tsc --strict без ошибок. Каждый из них дополнительно проверяется на проекте с максимально строгой настройкой: все флаги компилятора строже --strict плюс typescript-eslint strictTypeChecked. Из 37 случаев такая настройка не ловит 21. Флаг компилятора, выключенный по умолчанию, ловит 5, правило линтера ловит 11. Каждый из них проект должен включить сам, и агент может снова его выключить. В Glyph ни одна из этих проверок не является настройкой. Всего проверенных случаев: 49. Из них случаев в TypeScript: 37, ловушек JavaScript, которых нет в Glyph: 5, и дыр, которые Glyph пока не закрывает: 7. При сборке Glyph отклоняет 28 из них (случаев TypeScript: 23, ловушек: 5).

Агент может сначала спросить компилятор

В этом репозитории лежит examples/apps/csvql, движок запросов к CSV. В его центре union-тип Value. Прежде чем добавить в него вариант Date, агент спрашивает MCP-сервер компилятора, что сломает эта правка. Ответ (здесь он сокращён до вердикта, места и функции) называет десять мест с match в четырёх файлах.

Каждая запись WILL_FAIL сообщает, какую ошибку она вызовет, и добавление одного варианта дало ровно эти восемь ошибок E0200. Два места ABSORBS не сообщают ничего: render::literal_text вывел бы литерал даты без кавычек, а exec::total считал бы каждую дату нулём. Агент, который опирается только на ошибки компилятора, исправит восемь мест и остановится на зелёной сборке. Если спросить снова после исправления, компилятор отвечает WILL_FAIL во всех десяти местах, так что и следующий вариант не проскочит.

Glyph пока ловит не всё. Известных дыр, у каждой из которых есть воспроизведение и номер gap: 7. Логические ошибки проходят в Glyph так же, как в TypeScript. Что он пока не ловит →
