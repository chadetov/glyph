Для агентов · Model Context Protocol

Подключите агента к компилятору Glyph

glyph mcp запускает сервер Model Context Protocol с одиннадцатью инструментами для вашего проекта: что такое символ; что сломается, если его изменить; можно ли подставить значение одного типа туда, где объявлен другой; от чего зависит объявление; что экспортирует модуль; диагностики, проверенные внутри проекта; тип под курсором; где определено имя; все ссылки на него; все места match по union; поиск символов. Каждый из них также доступен как команда glyph query, так что агент без MCP-клиента задаёт те же вопросы и получает те же байты.

Зачем это агенту#

Агент, который правит кодовую базу, обычно работает вслепую. Он читает файлы, угадывает типы и узнаёт, сломал ли что-то, только после сборки. Для редактора Glyph уже отвечает на эти вопросы. glyph mcp даёт агенту те же ответы прямо от компилятора, без разбора вывода сборки и без чтения всех файлов, чтобы понять, кто что вызывает. Два инструмента отвечают на вопросы, которые редактор никогда не задаёт: glyph_symbol возвращает варианты union с синтаксисом, который создаёт каждый из них, а это именно то, что нужно агенту перед тем, как написать match; glyph_impact отвечает, что сломает правка, ещё до того, как она сделана.

Настройка#

Запустить его может любой MCP-клиент. Укажите клиенту бинарный файл glyph с подкомандой mcp и передайте корень проекта аргументом или запускайте из каталога проекта. Сервер говорит на MCP через stdio, поэтому ни порта, ни демона нет.

конфигурация MCP-клиента (общая) 
{
  "mcpServers": {
    "glyph": {
      "command": "glyph",
      "args": ["mcp", "/path/to/your/project"]
    }
  }
}

При первом подключении клиент вызывает initialize и tools/list; сервер сообщает об одиннадцати инструментах ниже. Позиции, которые вы отправляете, следуют соглашению LSP: line с нуля и character с нуля в единицах кода UTF-16. Диапазоны диагностик возвращаются так же, как их печатает glyph check --json: line и col с единицы плюс байтовый offset.

Описание каждого инструмента содержит контракт, который нужен в момент вызова, а полное руководство лежит в glyph llms --json под ключом tools, по имени инструмента, рядом с командой glyph query для каждого. Раньше этот ответ содержал все руководства: одиннадцать инструментов, 31 446 байт описаний в ответе размером 45 509 байт. Теперь это 8 627 байт в ответе на 20 386 байт, и ничего не удалено. Каждая сессия платит за tools/list при подключении, а за руководство только когда запрашивает его. Этот документ генерируется из собственных таблиц компилятора, и тест валит сборку, если в нём назван инструмент, которого этот сервер не предоставляет.

Одиннадцать инструментов#

инструменты, которые предоставляет glyph mcp 
// everything the compiler holds about one symbol: kind, identity,
// visibility, a record's fields, a union's variants with payloads and
// construction syntax, parameters and return, interface members,
// whether a `match` over it must be exhaustive, its `@example`.
// The identity reaches the stdlib: std/result::Result answers with
// Ok(T) and Err(E), and `path` is null beside the reason why
glyph_symbol(entity)                       // or (path, line, character)

// what breaks if you make one named change to one declaration:
// add_variant, remove_variant, rename, change_arity,
// change_signature_type, remove. One verdict per site
glyph_impact(entity, change)

// can a value of `from` go where a `to` is declared? Asked of the
// checker's own comparison. Each side is a `module::name` or a
// Glyph type spelling read in the scope of `path`
glyph_assignable(path, from, to)

// every diagnostic for one file, checked inside its project, in the
// shape `glyph check --json` prints, plus what was not checked
glyph_diagnostics(path)

// the type at a position: an expression, a declaration name, a
// parameter, an annotation, a variant, or a binding
glyph_hover(path, line, character)

// where the name is defined, following imports across modules,
// with the `module::name` so the answer chains into glyph_impact
glyph_definition(path, line, character)

// every edge into a symbol across the project, split by relation
// (CALLS, REFERENCES, GENERATED_FROM), each with its provenance
glyph_references(path, name)               // or by position

// every `match` site over one tagged union and which variants each
// site's arms name, with the union's own variants
glyph_variants(path, name)

// search top-level declarations and union variants by name, each
// entry with its identity, `pub`, kind and one-line signature
glyph_symbols(query)

// what one declaration depends on: every declaration its own source
// names, split by relation (CALLS, REFERENCES, FIELD_ACCESS), each
// edge with both ends and its provenance. The mirror of references
glyph_dependencies(entity)

// what one module makes visible to an importer: every `pub`
// declaration and every variant a `pub` union hoists, each with
// its identity, kind and signature
glyph_exports(module)

Посмотрите сами#

tools/call для glyph_diagnostics на файле с опечаткой в поле возвращает собственную диагностику компилятора, тот же тип Rust, который сериализует glyph check --json, внутри обёртки, которая также говорит, что проверка не покрыла.

запрос 
{
  "method": "tools/call",
  "params": {
    "name": "glyph_diagnostics",
    "arguments": { "path": "src/user.glyph" }
  }
}
результат (JSON-содержимое инструмента) 
{
  "path": "src/user.glyph",
  "module": "user",
  "project_root": "src",
  "member": true,
  "diagnostics": [
    {
      "code": "E0210",
      "severity": "error",
      "stage": "typecheck",
      "message": "type `U` has no field `naem`; did you mean `name`?",
      "help": "Check the field name for a typo,
        or add the field to the type.",
      "entity": "user::greet",
      "file": "user",
      "range": {
        "start": { "line": 9, "col": 10, "offset": 99 },
        "end":   { "line": 9, "col": 16, "offset": 105 }
      },
      "union": null,
      "missing_variants": null
    }
  ],
  "unindexed": [],
  "not_run": [ ... ]
}

Файл проверяется внутри своего проекта, поэтому неверное поле у импортированной записи и match без части веток по импортированному union сообщаются здесь так же, как их сообщает glyph check. То, что инструмент не смог покрыть, указано в ответе, а не оставлено на ваше предположение: member говорит, доходит ли обход проекта до файла, unindexed называет файлы проекта, которые не разбираются, а not_run называет три проверки, которые делает glyph check, а эта нет: tsc; E0104 для импорта несуществующего модуля, которому нужен взгляд сборки на node_modules; и E0400 для упавшего @example, что решается запуском сгенерированного проекта. Тест запускает обе поверхности на шести проектах и сравнивает JSON ключ за ключом, так что расхождений быть не может.

glyph_references работает по всему рабочему пространству: спросите о символе, и вы получите его объявление, каждое использование и привязку import в каждом импортирующем модуле, во всех файлах. Он использует ту же межфайловую идентичность, что и переименование в редакторе, поэтому ответ покрывает весь проект, а не только файл, из которого вы спросили.

Нет MCP-клиента? Те же вопросы в командной строке#

У каждого инструмента есть команда glyph query, которая принимает аргументы инструмента как флаги и печатает его JSON в stdout. Отвеченный вопрос завершается с кодом 0; отклонённый пишет причину в stderr и завершается с кодом 2. Команды идут через ту же точку входа, что и MCP-клиент, а интеграционный тест задаёт обеим поверхностям один и тот же вопрос и сравнивает ответы как текст, так что команда, которая переформатировала бы или сократила ответ, его не пройдёт.

те же одиннадцать вопросов без клиента 
glyph query symbol       --path src/main.glyph --entity orders::OrderStatus
glyph query impact       --entity orders::OrderStatus --change add_variant --variant Refunded
glyph query assignable   --path src/main.glyph --from 'Nullable<int>' --to int
glyph query diagnostics  --path src/main.glyph
glyph query hover        --path src/main.glyph --line 9 --character 6
glyph query definition   --path src/main.glyph --line 9 --character 6
glyph query references   --path src/orders.glyph --name create
glyph query variants     --path src/orders.glyph --name OrderStatus
glyph query symbols      --query order
glyph query dependencies --path src/main.glyph --entity main::build
glyph query exports      --path src/main.glyph --module orders

// the same two, asked about a module the compiler carries
glyph query symbol       --path src/main.glyph --entity std/result::Result
glyph query exports      --path src/main.glyph --module std/result

Когда сборка уже красная#

Инструменты отвечают на вопросы, заданные до правки. После неё читать нужно glyph check --agent: он печатает диагностики check --json с двумя дополнительными ключами у каждой. constraints это инварианты, которые исправляющая правка должна сохранить, а symbols это ответ glyph_symbol для каждого символа, упомянутого в диагностике, так что следующей правке не нужен второй вызов. Для match без части веток это значит, что варианты union с их полезной нагрузкой приходят вместе с ошибкой, которая их запросила, вместе с фразой о том, что ветка else отказалась бы от гарантии, ради которой эта диагностика существует. Где исправление определено полностью, glyph fix записывает его и сообщает, от чего отказался. Есть пошаговый разбор всего цикла с настоящим выводом.

Текущее состояние#

Уже работает

Сервер glyph mcp [root] через stdio с одиннадцатью инструментами: glyph_symbol, glyph_impact, glyph_assignable, glyph_diagnostics, glyph_hover, glyph_definition, glyph_references (по всему рабочему пространству), glyph_variants, glyph_symbols, glyph_dependencies и glyph_exports. У каждого есть команда glyph query, печатающая тот же JSON. Ответы берутся из собственных запросов компилятора, и каждый факт, которого у инструмента нет, равен null, а рядом стоит фраза <key>_absent с объяснением. Hover отвечает на имени, объявленном в другом модуле, так что и у импортированной функции в месте вызова, и у поля, прочитанного из импортированной записи, есть тип. Идентичность сущностей доходит до стандартной библиотеки: Result из прелюдии это std/result::Result, то есть модуль, под которым его регистрирует резолвер и из которого эмиттер пишет импорт, поэтому glyph_symbol на нём отвечает Ok(T) и Err(E), а glyph_exports на std/result перечисляет его поверхность. Исходного кода на Glyph за ним нет, поэтому path и range равны null с этой причиной, а не отсутствуют.

В работе

Инструменты только читают: переименовать или применить правку через MCP нельзя. Сторона записи живёт в командной строке, это glyph fix. Сервер пересканирует проект при каждом вызове, а не держит кэшированный индекс, и пропускает файлы, которые не разбираются. Ответ tools/list занимает 20 386 байт, было 45 509, и это всё ещё контекст, за который каждая сессия платит при подключении.

Помимо инструментов, агент может читать описание языка и диагностик без сети: llms.txt это текст, glyph llms --json те же знания как данные из собственных таблиц компилятора, а glyph build --json пакетный путь для диагностик с кодами по всему дереву.
