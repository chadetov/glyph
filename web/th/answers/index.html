Glyph v0.1.152
  • ทำไมต้อง Glyph

    เหมาะกับใคร

    • สำหรับคนสร้างเอเจนต์เซิร์ฟเวอร์ MCP และคิวรีที่ตอบได้
    • สำหรับคนที่มาจาก TypeScriptอะไรเปลี่ยน และอะไรเหมือนเดิม
    • สำหรับทีมรับประกันอะไร และการนำมาใช้ต้องแลกกับอะไร

    การออกแบบ

    • การออกแบบหลักสี่ข้อ และสิ่งที่ตั้งใจตัดออกไป
    • สี่เสาหลักตรวจสอบได้ ค้นหาได้ด้วย grep นามธรรม และ diff ที่คงที่
    • Glyph เทียบกับ Effectเปรียบเทียบภาษากับไลบรารี
    • ทำไมไม่ใช้ ReScript, Gleam หรือ Elm?ภาษาที่มีชนิดข้อมูลสามภาษาที่คอมไพล์เป็น JavaScript
    • Glyph เทียบกับ TypeScript ที่ใส่เครื่องมือครบสิ่งที่ tsc แบบ strict, zod และ eslint ยังปล่อยผ่าน
  • เรียนรู้

    เริ่มต้นใช้งาน

    • เริ่มได้ใน 10 นาทีติดตั้ง เขียนโปรแกรม แล้วรัน
    • คำตอบ 28คำถามที่วิศวกรถามบ่อย พร้อมตัวอย่างประกอบ
    • เอกสารอ้างอิงภาษาสเปกฉบับเต็มบน GitHub
    • ร่วมพัฒนาคอมไพเลอร์สร้างขึ้นอย่างไร และช่วยได้อย่างไร

    เชื่อมต่อเอเจนต์

    • เซิร์ฟเวอร์ MCPเชื่อมเอเจนต์ของคุณเข้ากับคิวรีของคอมไพเลอร์
    • ถามคอมไพเลอร์ค้นสัญลักษณ์ ชนิด หรือผลของการเปลี่ยนแปลงก่อนแก้ไข
    • llms.txt สำหรับเอเจนต์ทั้งภาษาในไฟล์เดียวที่เอเจนต์อ่านได้
  • จับอะไรได้บ้าง
  • หลักฐาน

    ตรวจสอบอย่างไร

    • ข้อกล่าวอ้างถูกตรวจสอบอย่างไรfixture และ CI gate ที่อยู่เบื้องหลังแต่ละข้อกล่าวอ้าง
    • การทดสอบความแข็งแรงเอเจนต์ที่พยายามทำให้พัง และสิ่งที่พวกมันเจอ
    • Benchmarkหลักสี่ข้อในรูปตัวเลข พร้อมข้อควรระวัง
    • สิ่งที่ยังจับไม่ได้ช่องโหว่ที่รู้แล้ว แต่ละจุดมีโค้ดสำหรับทำซ้ำ
    21 จาก 37กรณีของ TypeScript ที่ไม่มีอะไรในโปรเจกต์ที่ตั้งค่าเต็มที่จับได้ดูว่าจับอะไรได้บ้าง

อ่านเป็นภาษาอังกฤษ

ภาษา: ไทย·อ่านเป็นภาษาอังกฤษ

หน้านี้เป็นฉบับแปล ฉบับภาษาอังกฤษคือฉบับอ้างอิง แจ้งปัญหาเกี่ยวกับคำแปล

คำตอบ

สิ่งที่วิศวกรถามเกี่ยวกับ Glyph

แต่ละคำตอบมีตัวอย่างประกอบ และปิดท้ายด้วยสิ่งที่ยังใช้ไม่ได้ เริ่มจากตรงที่คุณสงสัยได้เลย ถ้าเพิ่งรู้จัก Glyph เริ่มที่นี่ใน 10 นาทีเป็นทางที่เร็วที่สุดในการลองครั้งแรก

ปัญหาที่แก้#

การแก้ของเอเจนต์ทำอะไรพังได้โดยไม่มีใครสังเกต และ Glyph ทำอะไรกับแต่ละเรื่อง

01อะไรกันเอเจนต์ไม่ให้ทำโค้ดของฉันพังแบบเงียบๆ?

ไม่มี any ไม่มี cast match ต้องครบทุกกรณี type ที่ถูกตรวจตอนรัน และเทสต์ที่อยู่ข้างโค้ดซึ่งรันทุกครั้งที่ build

 02การแก้ของเอเจนต์จะสะอาด หรือจัดรูปแบบไฟล์ใหม่ทั้งไฟล์?

การแก้หนึ่งบรรทัดคือ diff หนึ่งบรรทัด มี layout มาตรฐานแบบเดียว ไม่มีอะไรถูกจัดกลุ่มใหม่

 03เอเจนต์ (หรือฉัน) หาได้ไหมว่าอะไรถูกนิยามไว้ที่ไหน?

หนึ่งชื่อ หนึ่งรูปแบบ declaration grep เจอมันเสมอ

ตัดสินใจว่าจะใช้หรือไม่#

ทำไมต้องเป็นภาษาแทนที่จะเป็นเครื่องมือเพิ่ม และการนำมาใช้มีต้นทุนอะไร

04ทำไมต้อง TypeScript ไม่ใช่ Go หรือภาษาใหม่?

เพราะ ecosystem ของคุณอยู่ที่นั่น และนั่นคือเหตุผลที่นำมาใช้ทีละไฟล์ได้

 05ทำไมไม่ใช้แค่ TypeScript แบบ strict + zod + eslint + ts-pattern?

ความเป็นข้อบังคับ: ภาษาที่เอเจนต์ปิดผ่านการตั้งค่าไม่ได้

 06Glyph คุ้มไหมถ้าฉันไม่ได้ใช้ AI?

คุ้ม: การรับประกันเป็นประโยชน์ทางวิศวกรรมตรงๆ ที่คนได้รับโดยตรง

 07AI เขียนภาษาที่แทบไม่เคยเห็นได้อย่างน่าเชื่อถือหรือ?

สิ่งที่โมเดลรู้เกี่ยวกับ TypeScript ส่วนใหญ่ใช้ต่อได้ และคอมไพเลอร์บอกจุดที่ใช้ไม่ได้

 08รุ่นใหม่ของ Glyph จะทำให้ build ของฉันพังไหม?

โปรเจกต์ pin คอมไพเลอร์ไว้แบบตายตัว จึงไม่มีรุ่นไหนเข้ามาโดยบังเอิญ glyph doctor บอกว่ามีรุ่นใหม่ glyph upgrade อัปเกรดให้

ใช้กับ stack ที่คุณมี#

แพ็กเกจ npm แอปที่มีอยู่ ขอบเขตของ API และ React

09ใช้ TypeScript, JavaScript และไลบรารี npm ที่มีอยู่ได้ไหม?

ได้: import แพ็กเกจ npm ไหนก็ได้ เก็บ shim .ts ที่เขียนเองไว้ตรงที่จำเป็น และ import Glyph กลับเข้าไปใน .ts

 10นำ Glyph มาใช้ในแอปที่มีอยู่ได้ไหม หรือต้องเปลี่ยนทั้งหมด?

ไม่ต้องเขียนใหม่: แกนของโดเมนเป็น Glyph ส่วนที่เหลือเป็น TypeScript แอป Vite แบบมาตรฐาน import TypeScript ที่ emit ออกมาได้เหมือน module อื่นๆ

 11ต้องเขียน validator ด้วยมือให้ทุก API ไหม?

ไม่ต้อง การประกาศ type จะ generate validator ให้

 12generate client และ server ที่มี type จากสเปก API ได้ไหม?

glyph gen openapi/zod/dts: โค้ดที่ commit ได้และ grep หาได้

 13ใช้กับ React ได้ไหม: component, hook และ Context?

JSX, hook และ action ของ reducer ที่ต้องครบทุกกรณี รองรับเต็มที่

 14จะแชร์ state ที่เปลี่ยนค่าได้ระหว่างฟังก์ชันอย่างไร?

store: const ที่มี .set/.update เป็นช่องทางเขียน

สร้างอะไรได้บ้าง#

ภาษาและ standard library แยกตามประเภทของโปรแกรม

15นี่เป็นภาษาจริง หรือของเล่นที่มีช่องโหว่?

การมองเห็นของ module, interface bound, defer, match ที่ใช้เป็นค่าได้ทุกที่และมี type ของมัน และ standard library ที่มี slice, pad_start และ fold

 16ไว้ใจมันกับเรื่องเงิน และกับ input ที่ควบคุมไม่ได้ได้ไหม?

ทศนิยมและ id ที่แม่นยำ invariant ในรูป type และ injection เป็น compile error

 17ให้บริการหน้าเว็บได้ไหม หรือได้แค่ JSON API?

HTML, redirect, response header และ form post โดยไม่ต้องเขียน server เอง

 18เขียนโปรแกรมที่ผู้ใช้พิมพ์โต้ตอบได้ไหม?

io.read_line ตอบกลับทีละบรรทัดที่เข้ามา แทนที่จะรอให้ stdin ปิด REPL หรือ game loop จึงใช้ได้

 19เขียน server ได้ไหม หรือ process จะจบไปเลย?

main เตรียมการแล้ว return process ยังทำงานต่อตราบที่ยังมี socket และ timer ค้างอยู่ ซึ่งเป็นกฎเดียวกับที่ Node ใช้

 20จัดการข้อมูลไบนารีได้ไหม หรือทุกอย่างเป็น string?

std/bytes คือลำดับของ octet พร้อม codec ที่ปฏิเสธ input ที่ผิดรูปแทนที่จะข้ามไป และ HMAC ที่ใช้ key จริง

ทำงานกับเอเจนต์#

คำถามที่เอเจนต์ถามคอมไพเลอร์ก่อนและหลังการแก้

21คอมไพเลอร์บอกได้ไหมว่าการเปลี่ยนแปลงจะทำอะไรพัง ก่อนที่ฉันจะแก้?

glyph_impact: คำตัดสินหนึ่งข้อต่อจุด จากรายการที่ปิดไว้ พร้อมเหตุผล ก่อนที่คุณจะแตะไฟล์

 22เอเจนต์ของฉันถามคอมไพเลอร์ได้ไหมว่าสัญลักษณ์คืออะไร ก่อนเขียนโค้ด?

glyph_symbol: variant ของ union พร้อม syntax ที่ใช้สร้างแต่ละตัว ในการเรียกครั้งเดียว มีสิบเอ็ดเครื่องมือ แต่ละตัวมีคำสั่งย่อยของ glyph query

 23เมื่อ build ล้มเหลว คอมไพเลอร์บอกเอเจนต์ไหมว่าต้องแก้อย่างไร?

diagnostic มีสัญลักษณ์ที่ผิด ทางเลือกที่ถูกต้อง และสิ่งที่การแก้ต้องไม่ทำพัง glyph fix เขียนการแก้ที่คอมไพเลอร์ตัดสินได้เอง

 24เอกสารที่เอเจนต์อ่านถูก generate ขึ้นมา หรือเขียนด้วยมือและล้าสมัย?

glyph llms --json emit diagnostic, prelude, signature ของ stdlib และคู่มือเครื่องมือ ออกมาจากตารางของคอมไพเลอร์เอง และมี gate ที่ fail เมื่อสำเนาที่เขียนด้วยมือไม่ตรงกัน

error, editor และ production#

สิ่งที่คุณเห็นเมื่อมีอะไรผิด ตั้งแต่ใน editor จนถึงตอน on-call

25ประสบการณ์ด้าน editor การดีบัก และ error เป็นอย่างไร?

language server สำหรับ editor ที่รองรับ LSP และ error ที่มีรหัสคงที่ซึ่งบอกวิธีแก้

 26ทำไม Glyph จับสิ่งที่ tsc จับได้ แต่เร็วกว่า?

บริบทของ await, arm ของ match ที่ไม่มีค่า และ mut ที่ขาดไป รายงานเทียบกับซอร์สของคุณแทนที่จะเป็น TypeScript ที่ emit ออกมา

 27เมื่อ parse ไม่ผ่าน ฉันจะรู้ไหมว่าเพราะอะไร?

field ไหน ผิดกฎข้อไหน ขัดกับ predicate where ตัวไหน และ code สำหรับแตก branch

 28เมื่อพังบน production ตอนตีสาม คนที่ on-call เห็นอะไร?

TS ที่อ่านได้และเป็นของคุณ source map ที่ชี้กลับไปยัง .glyph และ run ที่รายงานแบบเดียวกับ build
