Glyph v0.1.165
  • ทำไมต้อง Glyph

    เหมาะกับใคร

    • สำหรับคนสร้างเอเจนต์เซิร์ฟเวอร์ MCP และคิวรีที่ตอบได้
    • สำหรับคนที่มาจาก TypeScriptอะไรเปลี่ยน และอะไรเหมือนเดิม
    • สำหรับทีมรับประกันอะไร และการนำมาใช้ต้องแลกกับอะไร

    การออกแบบ

    • การออกแบบหลักสี่ข้อ และสิ่งที่ตั้งใจตัดออกไป
    • สี่เสาหลักตรวจสอบได้ ค้นหาได้ด้วย grep นามธรรม และ diff ที่คงที่
    • Glyph เทียบกับ Effectเปรียบเทียบภาษากับไลบรารี
    • ทำไมไม่ใช้ ReScript, Gleam หรือ Elm?ภาษาที่มีชนิดข้อมูลสามภาษาที่คอมไพล์เป็น JavaScript
    • Glyph เทียบกับ TypeScript ที่ใส่เครื่องมือครบสิ่งที่ tsc แบบ strict, zod และ eslint ยังปล่อยผ่าน
  • เรียนรู้

    เริ่มต้นใช้งาน

    • เริ่มได้ใน 10 นาทีติดตั้ง เขียนโปรแกรม แล้วรัน
    • คำตอบ 28คำถามที่วิศวกรถามบ่อย พร้อมตัวอย่างประกอบ
    • เอกสารอ้างอิงภาษาสเปกฉบับเต็มบน GitHub
    • ร่วมพัฒนาคอมไพเลอร์สร้างขึ้นอย่างไร และช่วยได้อย่างไร

    เชื่อมต่อเอเจนต์

    • เซิร์ฟเวอร์ MCPเชื่อมเอเจนต์ของคุณเข้ากับคิวรีของคอมไพเลอร์
    • ถามคอมไพเลอร์ค้นสัญลักษณ์ ชนิด หรือผลของการเปลี่ยนแปลงก่อนแก้ไข
    • llms.txt สำหรับเอเจนต์ทั้งภาษาในไฟล์เดียวที่เอเจนต์อ่านได้
  • จับอะไรได้บ้าง
  • หลักฐาน

    ตรวจสอบอย่างไร

    • ข้อกล่าวอ้างถูกตรวจสอบอย่างไรfixture และ CI gate ที่อยู่เบื้องหลังแต่ละข้อกล่าวอ้าง
    • การทดสอบความแข็งแรงเอเจนต์ที่พยายามทำให้พัง และสิ่งที่พวกมันเจอ
    • Benchmarkหลักสี่ข้อในรูปตัวเลข พร้อมข้อควรระวัง
    • สิ่งที่ยังจับไม่ได้ช่องโหว่ที่รู้แล้ว แต่ละจุดมีโค้ดสำหรับทำซ้ำ
    21 จาก 37กรณีของ TypeScript ที่ไม่มีอะไรในโปรเจกต์ที่ตั้งค่าเต็มที่จับได้ดูว่าจับอะไรได้บ้าง

Benchmark

หลักฐานสองแบบ

มีคำถามสองข้อที่ควรวัด และเราแยกมันออกจากกัน เชิงโครงสร้าง: Glyph ปฏิเสธอะไรโดยการออกแบบที่ TypeScript ยอมรับ? ข้อนี้พิสูจน์ได้วันนี้ ดังที่แสดงด้านล่าง ความน่าเชื่อถือ: เอเจนต์ปล่อย defect ใน Glyph น้อยกว่าในชุด TypeScript แบบ strict ที่ตั้งค่ามาอย่างดีจริงหรือไม่? นั่นคือตัวเลขที่ตัดสินว่าจะนำมาใช้หรือไม่ และเรายังไม่มี มันเป็นงานศึกษาที่เรากำลังสร้าง และเราจะไม่แต่งตัวชี้วัดทางอ้อมให้ดูเหมือนเป็นคำตอบนั้น (การเปรียบเทียบที่แท้จริงไม่ใช่ Glyph กับ TS แบบดิบๆ แต่เป็น Glyph กับ TS แบบ strict + zod + eslint + ts-pattern)

เชิงโครงสร้าง: พิสูจน์ได้จากการออกแบบ

ไม่ใช่สถิติ แต่เป็นการสาธิตเป็นคู่ แต่ละคู่คือกรณีที่ Glyph ปฏิเสธและ tsc --strict ยอมรับ ทำซ้ำได้จากไดเรกทอรี benchmarks

ตรวจสอบได้: บั๊กที่ทำให้คุณเสียหาย
จับได้ทั้งคู่ตอนคอมไพล์

ความผิดพลาดสองอย่างที่เอเจนต์ทำอยู่ตลอด (variant ของ match ที่ขาดไป และการ cast ผ่าน as unknown as) ถูก Glyph ปฏิเสธ และ tsc --strict ยอมรับ ทั้งสองเป็นกรณีที่ตรวจแล้วใน catches/ (non-exhaustive-match, E0200; as-unknown-as, E0013) ซึ่ง build gate รันซ้ำ โค้ดผิดที่คอมไพล์ผ่านคือความล้มเหลวที่แพง Glyph ไม่ยอมให้เกิด

ค้นหาได้ด้วย grep: หนึ่งชื่อ หนึ่งที่
เจอ 1 จุดทุกครั้ง

ทุกสัญลักษณ์มีรูปแบบ declaration แบบเดียว: ไม่มี overload, decorator หรือ namespace ที่ merge กันให้มันกระจัดกระจาย

$ grep -n "fn welcome" main.glyph
15: fn welcome(user: User) -> Result<string, string> {
diff ที่คงที่: รีวิวได้โดยค่าเริ่มต้น
1 บรรทัด → 1 บรรทัด

การแก้ Glyph หนึ่งบรรทัดให้ diff ของ TypeScript หนึ่งบรรทัดผ่าน transpiler และ glyph fmt ไม่สร้างความวุ่นวายเพิ่ม diff คือการเปลี่ยนแปลง ไม่ใช่สิ่งรบกวนรอบๆ

ความปลอดภัยปกติทำให้โค้ดยาวขึ้น: Go และ Rust ซึ่งเป็นแถวอื่นที่มี static type และจัดการ error แบบชัดแจ้ง ยาวที่สุด Glyph มีทั้งสองอย่างแต่ไม่ได้ยาวขึ้น: 436 token เทียบกับ 478 ของ TypeScript น้อยกว่าประมาณ 9% เท่ากับ Python น้อยกว่า Go ประมาณ 23% และน้อยกว่า Rust 30% นับด้วย cl100k_base จริงบนโปรแกรมที่ผ่าน glyph check พร้อม tsc ส่วนที่นำอยู่ในฟังก์ชันที่มี control flow จริง (parse_user, 132 ต่อ 174) ส่วน slugify ที่มีบรรทัดเดียว Glyph ยาวกว่า (67 ต่อ 47) เพราะไม่มี regex literal สามฟังก์ชันเป็นตัวอย่างที่เล็ก ตัวเลข 341 ก่อนหน้านี้วัดจาก fixture ที่คอมไพเลอร์ไม่ยอมรับ และถูกถอนออกแล้ว ดูวิธีวัดและข้อควรระวัง →

ความน่าเชื่อถือ: งานศึกษาที่เรากำลังสร้าง

ผลเชิงโครงสร้างข้างบนเป็นเหตุผลที่จะคาดหวังว่า Glyph ช่วยได้ ไม่ใช่หลักฐานว่ามันช่วยจริง หลักฐานคืองานศึกษาเชิงเปรียบเทียบ: เอเจนต์ตัวเดียวกัน งานที่สมจริงชุดเดียวกัน เขียนครั้งหนึ่งด้วย Glyph และอีกครั้งด้วย TypeScript แบบ strict ที่ใส่เครื่องมือครบ (tsconfig strict + typescript-eslint + ts-pattern + zod) ให้คะแนนด้วยจำนวน semantic defect ที่หลุดออกไปและอัตราที่ build เขียวในครั้งเดียว นั่นคือตัวเลขที่ผู้รีวิวห้าคนบอกเราว่าจะทำให้เขาเปลี่ยนใจ เราจึงกำลังสร้างมัน และจนกว่ามันจะมี แท่งกราฟเหล่านี้เป็นแค่ที่ว่างรอไว้ ไม่ใช่ข้อกล่าวอ้าง
