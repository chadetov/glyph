กรณีที่ TypeScript ปล่อยผ่าน

จับได้ก่อนขึ้น production

รวมทั้งหมดมี 50 กรณีที่ตรวจแล้ว ได้แก่ กรณีของ TypeScript 37 กรณี กับดักของ JavaScript ที่ไม่มีใน Glyph 5 กรณี และช่องโหว่ที่ Glyph ยังปิดไม่ได้ 8 กรณี Glyph ปฏิเสธ 28 กรณีในจำนวนนี้ตอน build (กรณีของ TypeScript 23 กรณี และกับดัก 5 กรณี)

ตัวอย่าง TypeScript ทุกตัวในรายการผ่าน tsc --strict โดยไม่มี error และแต่ละตัวยังถูกตรวจกับโปรเจกต์ที่ตั้งค่าเข้มที่สุดอีกชั้น คือเปิด compiler flag ทุกตัวที่เข้มกว่า --strict และใช้ typescript-eslint strictTypeChecked ด้วย จาก 37 ข้อ มี 21 ข้อที่ไม่มีอะไรในการตั้งค่านั้นจับได้เลย compiler flag ที่ปิดอยู่โดยค่าเริ่มต้นจับได้ 5 ข้อ และกฎ lint จับได้ 11 ข้อ ทั้งสองอย่างโปรเจกต์ต้องเปิดเอง และเอเจนต์ก็ปิดกลับได้ ใน Glyph ไม่มีข้อไหนเป็นตัวเลือกในการตั้งค่า

แต่ละรายการคือโปรแกรมสองตัวใน catches/ และ output ใต้แต่ละตัวคือสิ่งที่เครื่องมือพิมพ์ออกมาจริง build gate ชื่อ scripts/check_catches.py รันทุกกรณีซ้ำ และจะ fail ถ้าฝั่งใดฝั่งหนึ่งไม่ทำตามที่หน้านี้บอก การตั้งค่า TypeScript ฉบับเต็มที่ใช้ตรวจอยู่ในสคริปต์นั้น

กรณีของ TypeScript 37 ข้อ

โอกาสเกิด เอเจนต์ AI เขียนแบบนี้บ่อยแค่ไหน ความรุนแรง เสียหายแค่ไหนเมื่อหลุดขึ้น production

คะแนนเป็นการประเมินของเราเอง จาก 1 ถึง 5 อิงจากงานศึกษาที่ตีพิมพ์เกี่ยวกับโค้ดที่เอเจนต์เขียน และจากการรันเอเจนต์ของเราเอง ยังไม่มีใครวัดอัตราเหล่านี้โดยตรง รายการเรียงตามโอกาสเกิดคูณความรุนแรง

ข้อมูลจากนอกโปรแกรม

โอกาสเกิด 5 จาก 5ความรุนแรง 5 จาก 5

request body ไฟล์ หรือ response จาก API

TypeScriptคอมไพล์ผ่าน แล้วทำงานกับข้อมูลที่ผิด
ts.ts
const user = JSON.parse(body) as User;
console.log(sendInvoice(user.plan));
$ tsx ts.ts
invoice for the undefined plan

ไม่มีอะไรตรวจข้อมูลเลย undefined ถูกส่งต่อไปในฐานะแพ็กเกจ

ไม่มีอะไรจับได้แม้จะเปิด compiler flag ทุกตัวและใช้ typescript-eslint แบบ strict แล้วก็ตาม

Glyphถูกตรวจเมื่อข้อมูลเข้ามา
glyph.glyph
let out = match json.parse<User>(body) {
  Ok(user) => send_invoice(user.plan),
  Err(issues) => "rejected: ${json.stringify(issues)}",
}
$ glyph run
rejected: [{"path":["plan"],"message":"field `plan` is required","code":"missing"}]

body ที่ไม่ใช่ User จริงจะเป็น Err โปรแกรมไม่มีวันถือของปลอมไว้

as User ไม่ได้ตรวจอะไรเลย มันแค่บอกคอมไพเลอร์ให้เชื่อคุณ Glyph ไม่มี as

case ที่ไม่มีใครจัดการ

โอกาสเกิด 5 จาก 5ความรุนแรง 4 จาก 5

เอเจนต์เพิ่มสถานะ "archived" แต่ handler ที่ประกาศแต่ละสถานะถูกเขียนก่อนที่สถานะนี้จะมี

TypeScriptคอมไพล์ผ่านโดยไม่มีคำเตือน
ts.ts
switch (s) {
  case "todo":
    console.log("not started");
    break;
  case "doing":
    console.log("in progress");
    break;
  case "done":
    console.log("finished");
    break;
}
$ tsx ts.ts
finished
archived logged nothing

การ archive รายการไม่ log อะไรเลย ไม่มีอะไรบอกว่า switch ล้าสมัยแล้ว

จับได้เฉพาะ lintจับได้ด้วยกฎ lint switch-exhaustiveness-check

Glyphถูกปฏิเสธตอน build
glyph.glyph
match s {
  "todo" => print("not started"),
  "doing" => print("in progress"),
  "done" => print("finished"),
}
$ glyph build
[E0200] Error: typecheck: non-exhaustive match on `"todo" | "doing" | "done" | "archived"`: missing variants "archived"
Help: Add an arm for each missing variant.

build หยุดและระบุชื่อ case

TypeScript ตรวจว่า switch ครอบคลุมทุก case ก็ต่อเมื่อฟังก์ชันคืนค่าจากทุก branch หรือใช้ idiom assertNever เท่านั้น handler ที่ไม่คืนค่าอะไรไม่ได้ทั้งสองอย่าง ใน Glyph ทุก match ต้องครอบคลุมทุก case การเพิ่ม variant จึงแสดงรายการทุกจุดที่ต้องแก้

โอกาสเกิด 4 จาก 5ความรุนแรง 4 จาก 5

ฟังก์ชันที่อาจล้มเหลว ถูกเรียกโดยโค้ดที่ไม่รู้ว่ามันล้มเหลวได้

TypeScriptคอมไพล์ผ่าน แล้ว crash ตอนรัน
ts.ts
function loadConfig(): Config {
  throw new Error("missing file");
}

const cfg = loadConfig(); // no try
$ tsx ts.ts
Error: missing file

type บอกว่าเป็น Config ไม่มีอะไรบอกว่ามัน throw ได้

Glyphถูกปฏิเสธตอน build
glyph.glyph
fn load_config() -> Result<Config, string> {
  return Err("missing file")
}

let cfg: Config = load_config()
$ glyph build
[E0204] Error: typecheck: type mismatch: expected `Config`, found `Result<Config, string>`
Help: Change the value, or the declared type, so the two agree.

ความล้มเหลวเป็นส่วนหนึ่งของ return type ผู้เรียกจึงต้องจัดการ

TypeError: Cannot read properties of undefined (reading 'toLowerCase')

body ที่ parse แล้วได้ type โดยไม่มีการตรวจ

โอกาสเกิด 4 จาก 5ความรุนแรง 4 จาก 5

อ่าน request body ใส่ตัวแปรที่มี type

TypeScriptคอมไพล์ผ่าน แล้วทำงานกับข้อมูลที่ผิด
ts.ts
const user: User = JSON.parse(body);
$ tsx ts.ts
undefined

annotation เป็นสัญญาที่ไม่มีอะไรรักษา JSON.parse คืนค่า any body รูปร่างไหนก็ผ่านได้

จับได้เฉพาะ lintจับได้ด้วยกฎ lint no-unsafe-assignment

Glyphถูกปฏิเสธตอน build
glyph.glyph
let user: User = json.parse(body)
$ glyph build
[E0204] Error: typecheck: type mismatch: expected `User`, found `Result<unknown, Array<Issue>>`
Help: Change the value, or the declared type, so the two agree.

กับดักของ JavaScript 5 ข้อที่ไม่มีใน Glyph

กับดักเก่าๆ ที่เอเจนต์ยังเจออยู่เป็นครั้งคราว Glyph ปฏิเสธทุกโปรแกรมในกลุ่มนี้ แต่ไม่ใช่เพราะจับความผิดพลาดได้ ฟีเจอร์ที่เป็นต้นเหตุไม่มีอยู่ในภาษา และมีการบอกชื่อสิ่งที่ใช้แทน

  • "10,20,30".split(",").map(parseInt) ได้ [10, NaN, NaN] เพราะ map ส่ง index ไปเป็นฐานของตัวเลข Glyph มี number.parse ซึ่งคืนค่าเป็น Result เปิดใน Playground
  • regex แบบ /g ที่ใช้ซ้ำกับ .test จะพลาดทุกการจับคู่ครั้งที่สอง เพราะมันจำ lastIndex ไว้ Glyph ไม่มี regex object และ regex.matches(pattern, text) ไม่มี state เปิดใน Playground
  • [1, 2, 3].forEach(counter.increment) รัน method โดยไม่มี object ของมัน Glyph ไม่มี class และไม่มี this เปิดใน Playground
  • Math.max(...[]) ได้ -Infinity ส่วน array.max ของ Glyph คืนค่าเป็น Option ซึ่งว่างเมื่อ list ว่าง เปิดใน Playground
  • Array(3).map(...) คืนช่องว่างสามช่อง เพราะ map ข้ามมันไป Glyph ไม่มี Array(n) array เขียนเป็น literal เปิดใน Playground

สิ่งที่ Glyph ยังจับไม่ได้

ช่องโหว่ 8 ข้อที่ Glyph ยังปิดไม่ได้ แต่ละข้อคอมไพล์ผ่านใน Glyph วันนี้ และทำสิ่งที่ผิดแบบเดียวกับใน TypeScript ทุกข้อมีโค้ดสำหรับทำซ้ำอยู่ใน catches/ และมีหมายเลข gap ที่ยังเปิดอยู่ gate จะ fail เมื่อมีการแก้ลงมา รายการจึงอยู่นานกว่าช่องโหว่ไม่ได้

  • requested || 3 เปลี่ยน 0 ที่เป็นค่าจริงให้กลายเป็น 3 G386
  • forEach(async ...) ทิ้ง promise ทุกตัว งานจึงเสร็จหลังโค้ดที่พึ่งพามัน และไม่มีอะไรเตือน G384
  • xs.sort(...) ภายใน helper เรียงลำดับ array ของผู้เรียกใหม่ โดยไม่มี mut กำกับ G380
  • .sort() กับตัวเลขจะเรียงแบบข้อความ: 100,25,9 G388
  • การอัปเดตที่หายไปข้าม await บน c[0] ทั้งที่การเขียนแบบเดียวกันลง field ถูกปฏิเสธ G390
  • input + 1 กับ string, users.find(...).name และการอ่าน field จากค่า unknown ถูกจับได้เฉพาะในขั้น tsc เท่านั้น ไม่ใช่โดยตัวตรวจของ Glyph เอง editor และเครื่องมือของเอเจนต์จึงมองไม่เห็น G381, G382, G392

logic error เป็นกลุ่มที่ใหญ่ที่สุดในทุกงานศึกษาเกี่ยวกับโค้ดที่เอเจนต์เขียน และไม่มี type checker ตัวไหนมองเห็น: สูตรที่ผิด หรืองานที่อ่านโจทย์ผิด คอมไพล์ผ่านใน Glyph เหมือนที่ผ่านใน TypeScript

Glyph มีทางออกฉุกเฉินอยู่ทางเดียวคือ extern_ts สำหรับ TypeScript ที่ Glyph เขียนแทนไม่ได้ มันเป็น keyword ตายตัว grep extern_ts จึงแสดงทุกจุดที่กฎถูกยกเว้น
