เอเจนต์ AI ของคุณเป็นคนเขียน คอมไพเลอร์เป็นคนตรวจ

Glyph อ่านแล้วเหมือน TypeScript แต่ไม่มีทางหนีทีไล่: ไม่มี any ไม่มีการ cast ไม่มีข้อมูลที่ยังไม่ได้ตรวจ และต้องจัดการทุกกรณี คอมไพล์เป็น TypeScript ที่อ่านง่าย คุณจึงใช้ node, npm และโค้ดที่มีอยู่ได้ตามเดิม

$ npx -y @glyphlang/glyph init hello && cd hello && npm install && npx glyph run

ไม่ต้องติดตั้งแบบ global ถ้าต้องการให้ glyph อยู่ใน PATH: npm install -g @glyphlang/glyph tsx typescript

ดูว่าจับอะไรได้บ้าง → เริ่มได้ใน 10 นาที →

  1. 01เขียน TypeScript อยู่แล้วอะไรเปลี่ยน อะไรเหมือนเดิม และแพ็กเกจ npm ใช้ต่อได้อย่างไร
  2. 02กำลังตัดสินใจแทนทีมรับประกันอะไร ไม่รับประกันอะไร และถ้าจะเลิกใช้ต้องแลกกับอะไร
  3. 03สร้างเอเจนต์และเครื่องมือเซิร์ฟเวอร์ MCP คิวรีที่ตอบได้ และรูปแบบของ diagnostic
  4. 04ขอดูหลักฐานแต่ละข้อกล่าวอ้างถูกตรวจสอบอย่างไร และจะทำซ้ำเองได้อย่างไร
  5. 05ทำไมต้องมีภาษาใหม่เหตุผลเบื้องหลังการออกแบบ และสิ่งที่ตั้งใจตัดออกไป

21 จาก 37

ตัวอย่าง TypeScript ทุกตัวในรายการผ่าน tsc --strict โดยไม่มี error และแต่ละตัวยังถูกตรวจกับโปรเจกต์ที่ตั้งค่าเข้มที่สุดอีกชั้น คือเปิด compiler flag ทุกตัวที่เข้มกว่า --strict และใช้ typescript-eslint strictTypeChecked ด้วย จาก 37 ข้อ มี 21 ข้อที่ไม่มีอะไรในการตั้งค่านั้นจับได้เลย compiler flag ที่ปิดอยู่โดยค่าเริ่มต้นจับได้ 5 ข้อ และกฎ lint จับได้ 11 ข้อ ทั้งสองอย่างโปรเจกต์ต้องเปิดเอง และเอเจนต์ก็ปิดกลับได้ ใน Glyph ไม่มีข้อไหนเป็นตัวเลือกในการตั้งค่า รวมทั้งหมดมี 50 กรณีที่ตรวจแล้ว ได้แก่ กรณีของ TypeScript 37 กรณี กับดักของ JavaScript ที่ไม่มีใน Glyph 5 กรณี และช่องโหว่ที่ Glyph ยังปิดไม่ได้ 8 กรณี Glyph ปฏิเสธ 28 กรณีในจำนวนนี้ตอน build (กรณีของ TypeScript 23 กรณี และกับดัก 5 กรณี)

เอเจนต์ถามคอมไพเลอร์ก่อนได้

examples/apps/csvql เป็น query engine สำหรับไฟล์ CSV ที่อยู่ใน repository นี้ โดยมี union Value เป็นแกนกลาง ก่อนจะเพิ่ม case Date เข้าไป เอเจนต์จะถาม MCP server ของคอมไพเลอร์ว่าการแก้ไขนี้ทำให้อะไรพังบ้าง คำตอบ (ตัดมาเฉพาะผลตัดสิน ตำแหน่ง และฟังก์ชัน) ระบุจุด match สิบจุดในสี่ไฟล์

 fn literal_text(v: Value) -> string {
   return match v {
     Text({ text }) => "'${text}'",
-    else => value.render(v),
+    Date({ iso }) => "'${iso}'",
+    Num({ n }) => value.render(v),
+    Bool({ flag }) => value.render(v),
+    Null => value.render(v),
   }
 }

แต่ละรายการ WILL_FAIL บอก error ที่จะเกิดขึ้นมาด้วย และเมื่อเพิ่มแค่ case อย่างเดียวก็ได้ error E0200 แปดตัวนั้นพอดี ส่วนสองจุด ABSORBS ไม่รายงานอะไรเลย render::literal_text จะพิมพ์ literal วันที่ออกมาโดยไม่มีเครื่องหมายคำพูด และ exec::total จะนับทุกวันที่เป็นศูนย์ เอเจนต์ที่ทำงานจาก error ของคอมไพเลอร์อย่างเดียวจะแก้แปดจุดแล้วหยุดพร้อม build สีเขียว เมื่อถามซ้ำหลังแก้แล้ว คอมไพเลอร์ตอบ WILL_FAIL ทั้งสิบจุด case ถัดไปจึงหลุดรอดไปไม่ได้เช่นกัน

Glyph ยังจับไม่ได้ทุกอย่าง ช่องโหว่ที่รู้แล้ว 8 จุด มีโค้ดสำหรับทำซ้ำและหมายเลข gap กำกับไว้ และ logic error ก็ผ่าน Glyph ได้เหมือนที่ผ่าน TypeScript สิ่งที่ยังจับไม่ได้ →
