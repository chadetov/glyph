参与贡献

编译器的实现方式，以及如何参与

编译器是一个由十二个 crate 组成的 Rust 工作区，放在一个公开仓库中，许可证为 MIT 或 Apache-2.0。目前最有帮助的是附带小型复现的 bug 报告。对语言本身的改动要先从 issue 开始，因为每条规则都对应一项带编号的设计决策。

编译流水线#

glyph build 进行词法分析、语法分析、名称解析、类型检查并生成 TypeScript，然后对生成的代码运行 tsc --strict。中间几个阶段在 salsa 上以增量查询的方式运行，所以重新检查时会复用没有因编辑而失效的结果。

一个 .glyph 文件依次经过各个 crate 
glyph-lexer → glyph-parser → glyph-resolver → glyph-typechecker → glyph-emit → tsc --strict
                (glyph-ast)        └──────── glyph-db (salsa) ────────┘
Crate作用
glyph-lexer词法单元、关键字、有意义的换行、模板字面量
glyph-ast语法树类型，每个节点都带有源码范围
glyph-parserPratt 解析器，覆盖规范中的每项决策，包括 JSX
glyph-resolver名称解析、模块图、跨模块导入检查、prelude
glyph-dbsalsa 查询流水线和跨文件失效
glyph-typechecker穷尽性检查、?、泛型、owned、运行时描述符、标准库模型
glyph-emitTypeScript 代码生成、描述符生成、表达式级别的 source map
glyph-formatterglyph fmt：一种排版，保留注释，幂等
glyph-lsp语言服务器和 MCP 服务器，共用一个分析层
glyph-cliglyph 可执行文件和所有子命令
glyph-wasm编译成 WebAssembly 的编译器，用于运行 Playground
glyph-runtime一个占位 crate；测试改为通过代码生成器和 tsx 运行

glyph-compiler/README.md 有完整的 crate 说明和当前的测试数量。

构建和测试#

rust-toolchain.toml 固定了 Rust 1.95。有些测试会调用 tsc 和 tsx，所以也要安装它们。CI 会以“警告即错误”的方式运行 clippy，而 cargo build 和 cargo test 都不会运行它，所以推送之前请先运行这个脚本。

在克隆的仓库中 
npm install -g tsx typescript
cd glyph-compiler
cargo build --release -p glyph-cli      # target/release/glyph
cargo test --workspace
cd .. && python3 scripts/check_clippy.py  # the exact clippy command CI runs

# after an intentional syntax-tree change
INSTA_UPDATE=always cargo test -p glyph-parser --test snapshots

新增的诊断要附带一个放在 tests/negative/ 下的程序，它必须以该错误码失败。声称 Glyph 能发现某个 TypeScript 漏掉的问题，要放进 catches/，在那里有一个检查会运行两半程序。

计划了什么，哪些还有问题#

docs/roadmap/releases.md 是发布路线图：每个已发布版本做了什么，接下来的版本要做什么。docs/dogfooding-gaps.md 是 gap 清单，记录了构建真实应用时发现的每项限制，每项都有编号（G 加数字）和状态标记。一个带复现的未解决 gap 是很好的切入点。

Issue 和 pull request#

工具链修复、诊断、文档和示例可以直接提 pull request。对语法或语义的改动要从 issue 开始，较大的改动要走 docs/rfcs/ 中的 RFC 流程；为了“方便”而放宽某条规则的 PR 很可能会被拒绝，因为限制本身就是目的。一个 pull request 只处理一个 gap，通常一到三个提交，并给每个提交签名（git commit -s）。main 是受保护分支，只允许 rebase 合并。完整规则见 CONTRIBUTING.md，标有 good first issue 的 issue 适合作为第一次贡献。

许可证#

MIT 或 Apache-2.0，任你选择（LICENSE-MIT、LICENSE-APACHE）。贡献按同样的双许可证接受，由 sign-off 行确认。
